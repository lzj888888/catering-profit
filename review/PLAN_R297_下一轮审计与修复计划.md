## 2 最终执行清单

### D1 · M1-B9「术语值被当机器键」（**真缺陷，最高优先**）

- **现象**：业务逻辑用**中文字面量**匹配术语值。全仓扫描 **共 3 处**（规模已摸清）：
  - `pages/month/input.js:689` 费用侧「外卖活动补贴」**手改上锁**判定；
  - `pages/month/input.js:1230` 收入侧补贴 → 费用侧**自动带出**的定位；
  - `pages/m3/dishreview/index.js:395` `bm.actualFlag === '偏高' / === '偏低'` —— **这处最危险**：`actualFlag` 是**云端返回**的字符串（`bf.benchmark.actualFlag`），而 `'偏高'` 是 `TERMS.indLevels.warn`（`terms.js:888`）⇒ **前后端靠中文字符串做接口契约**，两端还可能由不同人改 ⇒ 任一端改文案，`buffet_flagClass` 静默变空 ⇒ **「成本偏高」的警示色静默丢失**（老板看不到红色告警，以为没问题）。
- **危害（静默失效）**：TERMS 改名 ⇒ 上述逻辑**同时静默失灵**：上锁失效（手改被自动值覆盖）+ 补贴带不出 + **警示色丢失** ⇒ **利润算错/风险看不见，零报错**。
- **为什么这是老坑重现**：与项目既有血泪教训**同型** ——「**细项名当机器键 ⇒ 改名静默失效**」（M2 的 `BANDS` 那条原文如此）。
- **守卫盲区**：`check_page_terms` 只管「`TERMS.x.y` 键**存在**」，**不管「用术语的*值*做字面量比较」** ⇒ 正是缺口。
- **修法（两级，本轮做「轻修」）**：
  - **轻修**：在 `terms.js` 增设「**语义锚点**」常量（`TAKEOUT_SUBSIDY_ITEM` / `FLAG_HIGH` / `FLAG_LOW`），让 `items` 数组与 `indLevels` **引用它**、三处业务逻辑也引用它 ⇒ **改名只改一处、三处自动跟随**；并在注释明示 `FLAG_*` 是**跨端契约值，改值必须两端同步**。
  - **重修（登记待拍板）**：把 `actualFlag` 契约从「中文串」改为**稳定 code**（`high/low`）、文案由前端映射 —— 这才是根解，但要动云端+前端+存量数据，属重构。
- **验收**：新判据（业务逻辑不得用「TERMS 里存在的术语值」作字面量比较）+ **变异证明**（把 name 改名 → 判据必红）。

## 执行中新踩到的坑（已沉淀）

1. **判据③ 的精确形态**：`含中文 且 ∈ 术语值集`（合取）—— 只判"∈ 值集"会被术语表里的

2. **`stripComments` 会把字符串内容替换成空格** ⇒ 任何"要看见字面量"的判据复用它就**全盲**
   （"命中 0"与"探测器坏了"长得一样）。另写 `stripCommentsKeepStr`。
3. **守卫会被自己的说明注释绊倒**（同族本轮 3 例）⇒ 凡扫文本的判据**先剥注释**，
   且**必须配正样本证明判据真的会命中**。
4. **`check_expense_item_seed` 的解析正则用 `\s*` 连接 `label: '…',` 与 `items: [`，不跨注释**
   ⇒ 往 `items:` 前塞注释会让整个 category 解析失败（marketing 整类消失）。注释必须放 `category:` **之前**。
