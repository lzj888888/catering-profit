# NOTE · R425（2026-10-21）· M1 分平台佣金小计接金额体检（队列 #31）

## 1 现状（改前）

M1 月度录入页的金额体检（#25 / R419）只挂在 `updateRow` 上：
`updateRow(..., { amountYuan })` → 本行写完 → `this.checkAmounts()` → 扫 `incomeGroups ∪ expenseGroups`。

而「分平台佣金小计」是**独立 handler**：

```
onMkByPlat(e)  →  list[idx] = { amountYuan: e.detail.value }  →  setData  →  syncMkPlat()
```

它**不经 updateRow**，也**不在 `incomeGroups/expenseGroups` 里**（`twMkByPlat` 是独立数组），
所以体检的两条腿（触发点、扫描面）**都摸不到它**。

## 2 为什么不是"少提示一次"

`syncMkPlat()` 用 `mkByPlatTotal(list)`（内部走 `api.yuanToFen`，fail-soft 读不成即 0）算出合计，
然后**主动覆写营销段「佣金」那一行**的 `amountYuan`：

```js
const target = total.toFixed(2);           // 读不成的按 0 ⇒ 合计 0.00
rows[ri] = { ...rows[ri], amountYuan: target };
```

⇒ 老板粘贴「12,000」：
1. `mkByPlatFilled` 判"填过"（只看非空）⇒ `active = true`；
2. `mkByPlatTotal` 判 0 ⇒ `target = '0.00'`；
3. **佣金整行被清成 0.00**，利润随之虚高，**零报错**。

与 #25 的差别：那条是"这一格少算 40%"，这条是"**另一行被覆盖成 0**"——影响面更大且更隐蔽。

## 3 改法（只暴露，不改数）

- `checkAmounts()` 增扫 `twMkByPlat`：与两组 rows **同一个计数**、同一句提示（`t.amountBadTip`）。
  刻意**不**做静默清洗、**不**改 `yuanToFen`、**不**阻止写入 —— 与 #24/#25 同一原则：
  猜着替老板"修好"比不修更糟，页面必须如实说出来。
- `onMkByPlat` / `clearMkByPlat` 补 `this.checkAmounts()`：
  前者是本 handler 唯一的触发点；后者让"清空"后计数能回落（否则提示挂着不走）。
- **无新增可见文案**（复用 `ui.amountBadTip`）⇒ terms 双副本零改动；**未改 wxml** ⇒ 免出码、免部署。

## 4 守卫（`tools/check_amount_input.js` 33 → 37 条）

| 断言 | 守什么 |
|---|---|
| ②-19 | `onMkByPlat` 函数体可取下（fail-closed） |
| ②-20 | 函数体内**真调用** `checkAmounts(`（不经 updateRow ⇒ 不在这里调就永不触发） |

| ②-22 | `clearMkByPlat` 同样重算（坏值清掉后提示要能消失） |

判据一律用 `bodyOf()` 取**函数体**再判（不全文 grep），避开 R299 恒真第①型"腿锚错地方"。

## 5 本轮横向排查发现的**同类缺口（未修，已登队列 #42）**

`subpkg/biz/month/input.js` 里还有 4 个写金额但**不经 updateRow 或不经 amountYuan** 的入口：

| 行 | handler | 写哪 | 是否被体检覆盖 |

判据盯的是"字段名"而不是"这一格是不是钱"。
