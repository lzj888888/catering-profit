# R555 · 找铺面三件实用改动（元/㎡ · 默认列按场景 · 安全/上限租金）

日期：2026-10-28 · 目标（李老师原话）：「帮选址人员用着真的觉得好用、实用、好填写好算」

---

## 一、做了什么

| # | 改动 | 为什么是"好用" |
|---|---|---|
| 1 | 月租金单元格加第二行 **元/㎡/月** | 中介报「8000/月 60㎡」和「8000/月 45㎡」完全是两回事；只给总租金没法比两个铺子。面积是已有输入 ⇒ 一个除法，**零新增填写** |
| 2 | **默认列按场景分**：找铺面把「回本月数」放回默认列，换掉「月人工费」 | R548 把回本移出默认列对**已有店铺**是对的（钱已花），对**找铺面**恰好相反——他正要投钱。而人工费在找铺面时是猜的，价值低 |
| 3 | 可承受租金从**单值**改成「**最稳** + **上限**」两个数 | 找铺面时毛利率只能按行业带猜，不同毛利率能扛的租金差 1~2 档。单值会让老板把"最乐观情况"当成"我的情况" |

### 1. 元/㎡/月

`rentPerM2 = 租金 ÷ 面积`（面积 ≤ 0 则不显示）。同字号 ≥28rpx（AD-G1），只用颜色弱化。

### 2. 默认列

| 场景 | 默认 6 列 |
|---|---|
| 已有店铺 | 到手毛利率 / 人工人数 / **月人工费** / 保本月营收 / 目标月营收 / 抗跌空间 |
| 寻找店铺 | 月租金（含元/㎡）/ 到手毛利率 / 人工人数 / 保本月营收 / 目标月营收 / **回本月数** |

两场景都恰好 6 列；被换下的那一列**仍在「更多列」里**，不丢。

### 3. 安全 / 上限租金

按**每个毛利率档**分别算「保本营收 ≤ 预估营收 的最高租金」，再取：
- **最稳** = 各档里最小的那个（低毛利率也扛得住）
- **上限** = 各档里最大的那个（毛利率做到最高时可到）

实测（8 档租金 × 毛利率 55/60/65）：

| 预估月营收 | 结论 |
|---|---|
| 33000 | 租金 ≤ **7000** 元最稳（毛利率 55% 就扛得住）；毛利率能做到 65% 时最多 **10000** 元 |
| 30000 | 租金 ≤ **5000** 元最稳 … 最多 **8000** 元 |
| 25000 | 租金 ≤ **3000** 元最稳 … 最多 **5000** 元 |
| 20000 | 这排租金档都扛不住（最低那档也要做到 22400 元/月才保本） |
| 没填 | 提示"填了才能算"，**不编结论** |

## 二、没做的两条（附理由）

**① 转让费进结论** —— 不做。原因：R555 已把「回本月数」放进找铺面的默认列，
老板填了转让费/装修就能直接看到"几年回本"；结论框已有三行（租金/杠杆/抗跌），再塞一句会挤，
而且"转让费 15 万要 X 个月回"本质上就是那一列。**放到表里比塞进一句话更好用。**

**② 找铺面扫「外卖占比」** —— 不做（本轮）。原因：会多一维 ⇒ 组合数翻倍（8 档租金 × 3 档外卖 = 24 行），
而找铺面时外卖占比本来也未知（他还没接手这个铺子）。**找铺面的核心不确定性是毛利率，不是外卖占比**（实测：
租金 +233% 保本只 +74%，而毛利率 −8 点保本 +14%）。若将来要做，应作为「结构试算」的独立入口，不进主矩阵。
