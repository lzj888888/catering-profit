## 2. 交付一：快速录入出汇总（结论：需要，且已做）

**为什么需要**：分项模式早就有「小计 + 合计 + 配平」三件套，**快速模式下面什么都没有** ——
每平台填一个数、填完没有任何回显，用户无法自查"是不是每个平台都填了、加起来多少"。这是**同一页里的不对称**。

改动（`pages/month/input.wxml` 快速分支 + `pages/month/input.js::syncTakeoutSum`）：
- 快速分支下方给 `合计（各平台相加）` + `已填 N / M 个平台` + 一句口径说明；
- `syncTakeoutSum()` 改为**按模式取数**：快速 = `Σ incomeGroups[takeaway].rows[].amountYuan`，
  分项 = `Σ takeoutDetailRows[].subtotal`（原先只算分项，快速模式该字段恒 "0.00"）；
- `load()` 后**无条件**算合计（原先 `if (takeoutMode === 'detail')` 才算）；
- `updateRow()` 里改外卖组金额即重算（快速模式的数字走的就是这条路径）；
- **配平仍只在分项模式**：快速模式那一个数里含活动补贴、拆不出来，硬算会系统性偏低
  （已写进 `totalAutoHint` 文案告知用户「要核对请切分项」）。

**实测（真机模拟器运行时读数，非截图判读）**：全填 → `11110.00` / `已填 4 / 4 个平台`；
只填两个 → `3345.67` / `已填 2 / 4 个平台`；全填 0 → `0.00` / `已填 0 / 4 个平台`。详见 `runtime_readings.txt`。

**过程中被实测推翻的一处**：dev 载入态外卖组只有 **1 行**（整类总额），此时显示「已填 1 / 1 个平台」纯噪音
⇒ 抽出纯函数 `filledLabel(tpl, filled, total)`：`total ≤ 1` 返回空串（不显示该句）。真机读数里 `takeoutFilledText = ""` 即此。

## 3. 交付二：粘贴到 0 不再被当成空

原页面写 `r[field] = res.sum ? res.sum.toFixed(2) : ''` —— 提取到 **0** 时判为"空"，
金额框什么都不显示（0 是合法金额：零打包费、零补贴都可能是 0）。
- 抽纯函数 `pasteFillValue(res)`（`utils/takeaway.js`）：判据改为「**有没有提取到数字**」而非「数字非零」；空/纯表头 → `''`。
- 边界自测 7/7：`"0"→0.00`、`"0\n0"→0.00`、`"2380.00"→4380.00`、`"1,234.56"→1234.56`、空/纯表头/只含合计行 → `''`。
