## 1 🔴 缺陷 T3 · 挂牌价反算读旧结果（静默错数 · 直接害钱）

### 1.1 缺陷（回源码取证）

修复前 `pages/takeaway/index.js::onReverse()`：

```js
const cf = this.data.result ? this.data.result.cash.dish_cost_fen : 0;
const cp = this.data.result ? this.data.result.cash.pack_cost_fen : 0;
const pStar = reverseListedPrice({ dish_cost_fen: cf, pack_cost_fen: cp, ... });
```

而 `this.data.result` **只由 `onCalc()`（点「计算」）产生**。⇒ 两条错路：

1. **没点过「计算」直接点「反算」** ⇒ `cf = cp = 0`。而
   `utils/takeawayDerive.js::reverseListedPrice` 的分子是
   `cf + cp + m + s + d + deliveryCustomer − packFee`
   ⇒ **完全没有食材成本与包装成本** ⇒ 反算出的挂牌价**严重偏低**，
   而界面照常显示「反算挂牌价：¥X」——**零报错**。
   → **老板照它定价就是亏本卖**（这是本仓"静默错数"里危害最直接的一类：错的数会变成经营动作）。
2. 点过「计算」后**改了菜品 / 数量 / 打包**再点反算 ⇒ 用的是**上一次的旧成本**（同一族：读了派生/缓存值但没校验新鲜度）。

**为什么界面不拦**：`index.wxml:117-122` 的反算区块**无条件渲染**（`<view class="sec">{{t.reverseTitle}}</view>` +
`<button bindtap="onReverse">`，**没有 `wx:if="{{result}}"`**）⇒ 未计算态下按钮就能点。

### 1.2 修法

**按当前录入自算**（同一份纯单源，零新增口径），不再读 `this.data.result`：

```js
const order = this.buildOrder();
if (order.items.length === 0) { wx.showToast({ title: TK.dishPick, icon: 'none' }); return; }   // 与 onCalc 同一句
const cur = calcTakeawayOrder(order, (id) => this.lookup(id));
… dish_cost_fen: cur.cash.dish_cost_fen, pack_cost_fen: cur.cash.pack_cost_fen …
```

> 为什么"未选菜品就提示并返回"是必要的：否则 `dish_cost_fen` 仍是 0 ⇒ 用**零成本**算出一个"看着合理"的挂牌价，
> 比不显示更坏（同 `pages/m3/hub.js` 的「**不替用户编数**」纪律）。

## 2 🔴 缺陷 T4 · 同一付费能力的两个入口墙不一致

- `m3_takeaway` 在本仓**没有云端校验点**（纯前端试算、不落库）⇒ 它**唯一的墙就是页面入口**
  （`check_paywall_coverage` 里 `m3_takeaway` 的 `at: null` + why 已登记这一点）。
- 而页面里：`onCalc()` **过** `fetchEntitlement`（未开通走 `openPaywall('takeaway')`），
  `onReverse()` **不过** ⇒ **未开通用户可直接用反算拿到同一份付费价值**。

**修法**：`onReverse` 与 `onCalc` **逐字对齐**（先 `fetchEntitlement`，未开通 `openPaywall('takeaway')` 并 return）
—— 不新增付费能力、不自造判断分支（守 R159 口径）。

## 3 新建判据 `check_paywall_coverage.js::L8`（页面级付费入口，22 断言）

| 腿 | 判据 |
|---|---|
| **L8-①** 🔴 | 页面里**任何调用付费能力纯函数**（`calcTakeawayOrder` / `reverseListedPrice`）的方法，其**同一方法体内**必须出现 `fetchEntitlement` ⇒ 「同页面同能力的所有入口口径一致」成为机器可判的不变量 |
| **L8-②** | 扫描面下界：`Page({})` 顶层方法体解析到 ≥15 个（防抽取失效 ⇒ ① 恒真）。实测 32 个 |
| **L8-③** | **反恒真**：无墙样本必须判红、有墙样本必须判绿（同一段判据逻辑正负互证） |
| **L8-④** 🔴 | `onReverse` 必须**自己调 `calcTakeawayOrder`** 且**不得读 `this.data.result`**（T3 的输入新鲜度） |
| **L8-⑤** | **反恒真**：把「读 `this.data.result` 的旧实现」喂给 ④ ⇒ 必须判不通过 |

**为什么判据写在"付费墙"守卫里**：T3 与 T4 同一轮发现、同一处代码；而 **L8-④ 的真正语义
是"付费结果的输入新鲜度"**，与本守卫的其它腿同属"页面入口的正确性"。若将来出现同类入口，L8 会自动覆盖。
