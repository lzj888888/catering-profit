### 8.4 🆕 双实现对拍：330 处不等（**P3 · 当前不外显**）

`pages/card/edit.js::manualNetUnitWan`（前端）与 `saveCostCard/service.js::netUnitCostWan`（后端）
是**同一语义的两处实现**：

```
[前端] Math.round((元 * 10000) / (y/100))
[后端] Math.round((分/100) / 1 / (y/100) * 10000)
```

**对拍 606,500 组 ⇒ 330 组不等（0.054%）**。反例：`元=1.15, y=32` ⇒ 前端 **35938** / 后端 **35937**。
真因 = **浮点结合律**：后端 `1.15/0.32*10000` 得 `35937.499999999996`，前端 `11500/0.32` 得 `35937.5`。

- 🔵 **为什么当前不外显**：`pages/card/edit.js:292` 保存时**始终传 `net_unit_cost`（前端算的值）**，
  而后端 `index.js` 是 `(ln.net_unit_cost !== undefined) ? ln.net_unit_cost : netUnitCostWan(...)`
  ⇒ **有快照即直传、不重算**。330 处偏差只在"只传 `unit_price_fen+yield_rate`"的路径（复制/回填等非典型）才显现。
- 🔵 量级：1 万分之元 = **0.01 分**。
- 🔵 **建议（未执行）**：把该公式收敛为**单一单源**，或引擎层做定点化。**不阻塞本批**。

### 8.5 🆕 `yield_rate = 0` ⇒ 后端 `Infinity`（**P3 · 不可达**）

`netUnitCostWan(分,1,0)` = `(分/100)/1/0*10000` = `Infinity`。
但 `validate.js:53` 要求 `yr > 0 && yr <= 100` ⇒ **入口先拦，该分支不可达**；前端另有 `Number(y)||100` 兜底。
🔵 **建议（未执行）**：引擎层加 `if (!(yieldRate > 0)) throw INVALID_PARAM` 做**纵深防御** —— 引擎应自守，不假设调用方已校验。

### 8.6 🆕 环境坑：`core.autocrlf=true` ⇒ 内容相同的文件也标 `M`

本轮实测：`git status --short` 报 14 个 `M`，但对其中多数（如 `saveCostCard/validate.js`，120 行）**`git diff` 零差异**。
⇒ **以 `git status` 为判据的守卫（如 A15）存在"行尾符噪音假红"风险**。
🔴 纪律：判断"是否真改"**必须用 `git diff` / `--numstat`**，不能只看 `git status`。（`git add` 后 stat 缓存刷新，噪音自消。）
