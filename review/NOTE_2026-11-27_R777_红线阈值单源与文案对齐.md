## 一、本轮最重要的一件事：R6 的文案和判据早就不是一回事了

R772 我把结果页 `sigR6` 改成：

> 租约不到 **1 年**到期，续租可能大涨（涨幅超过**三成**），会明显推高成本

而 R6 的判据当时还是：

```js
const hit = m <= 3 && inc >= 20 && r < 0;   // 剩 3 个月 / 涨 20% / 已经亏损
```

**文案说的三个数和代码用的三个数，一个都不对。** 后果有两头：

- 老板看到"会触发"的解释，实际条件严得多 ⇒ 该报的没报（剩 8 个月、涨 35%、净利率 4% 的店在文字上"应该报警"，实际静默通过）
- 反过来，谁要是照着文案去核代码，会以为系统坏了

这不是第一次：`sigR2` 写着「连亏超过**可扛上限**」，而 R615 早就把这个概念删了。**两次都是人工翻代码翻出来的**，那就一定会有第三次。

## 二、做法：阈值集中 + 中文文案反向比对

### 1. 阈值从判据里抽出来（`diagnosisEngine.REDLINE_TH`）

```js
const REDLINE_TH = {
  R1: { months: 1 },
  R2: { bleedPct: TUNABLE.bleedRateWarnPct, safeMonthsKey: 'cashSafeMonthsByBiz' },
  R3: { triggerKey: 'structural_loss' },
  R4: { lookbackMonths: 12 },
  R5: { months: 3 },
  R6: { leaseMonths: 12, increasePct: 30, netMarginPct: 5 },
  R7: { ratio: 4 },
};
```

7 条红线的 `check` 全部改成引用常量，`evidence` 全部改成插值。改完 `REDLINES` 数组里**一个非 0 的裸阈值比较都没有**（`<= 0` 这类符号判断放行）。

### 2. 新守卫 `tools/check_redline_sync.js`（14 条断言）

| 段 | 内容 |
|---|---|
| A | **抽取器自证**：7 种中文阈值表达都能抽对（`不到 1 年`→12、`三成`→30、`4 倍`→4、`两成`→20、`3 个月`→3、`5%`→5、`这个月`→1）；无数字文案不得抽出噪声 |
| B | **逐条比对**：每条红线的中文文案抽出的数字，必须 ∈ 该条常量集合（含 R4 的食安窗口与补录问法对表） |
| C | **反向**：REDLINES 区内非 0 裸阈值比较必须为零；`REDLINE_TH` 已导出且字段齐备；聚合入口已导出 |
| D | **覆盖面**：引擎红线 = 文案键 = 常量表三方编号一致；terms 双副本字节一致；「可扛上限」这类已撤销概念不得回流 |

### 3. 变异回灌（守卫自证能抓）

| 变异 | 结果 |
|---|---|
| 常量改 `increasePct: 30 → 20`（模拟"改代码不改文案"） | ❌ B-R6 文案多出 30 ≠ 常量 |
| 文案改「三成 → 两成」（模拟"改文案不改代码"） | ❌ B-R6 文案多出 20 ≠ 常量 |

两个方向都红，还原后 14/0。

## 三、M1 指标对照卡：茶饮那处是真冲突

先查 `BANDS[*].rent` 的**上沿**与诊断 `BIZ_HARD.rentHealthy`（健康线）是否同值：

| 业态 | BANDS.rent 上沿 | 诊断健康线 | |
|---|---|---|---|
| 快餐 / 正餐 / 火锅 | 15 | 15 | ✅ |
| **茶饮** | **18** | **22** | ❌ |
| **兜底 other** | **18** | 15（并集取最大应为 22） | ❌ |

后果：**茶饮房租 20%**，M1 判「偏高」（超 18），诊断判「健康」（低于 22）——同期两个相反结论。根因是 R776 把茶饮放宽到 22/25 时，`BANDS` 这张表没跟上。

### 改法（连 M2 一起，因为守卫钉着）

`BANDS` 的上沿同时被 `levelOf` 当成"好的分界线"，所以不能只改一边：

1. `BANDS.cafe.rent` `[9,18] → [9,22]`；`BANDS.other.rent` `[8,18] → [8,22]`（other 是"并集取最大"，cafe 到 22 它必须跟到 22，否则兜底收紧成漏判）
2. 规范 JSON（`开发规范v1.0_ModuleM2_选址沙盘.md` M2.4b）同步 —— A-③ 双向对表直接判红，这正是它该干的事
3. **连带 M2 默认占比变了**（`utils/bizPreset.js`，G-③ 立刻报出期望值）：
   - 茶饮：房租中值 13.5 → 15.5 ⇒ `utility 15 → 13`、`manage 44 → 39`
   - 兜底：房租中值 13 → 15 ⇒ `utility 27 → 23`、`manage 46 → 40`

### 新守卫（`check_indicator_ref` F 段，4 条）

- F-① 引擎可读（防扫空恒绿）
- F-② **4 个实名业态：`BANDS.rent` 上沿 ≡ `rentHealthy`、`BANDS.labor` 上沿 ≡ `laborWarn`**
- F-③ 兜底 other = 4 类的最大值（派生量，不许自定）
- F-④ **原病例回归**：茶饮 20% 必须判 `ok`（不再是 `warn`）
