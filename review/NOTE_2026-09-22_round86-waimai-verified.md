## 3 抓到的缺陷与修复

### 🔴 P1 粘贴提取把「账期 / 日期 / 时间」当金额（算错钱）
实测：`extractPaste('2026-09')` → **sum=202**；`'2026-09-21\t1234.56'` → **202**；`'13:45'` → **13**。
风险面真实：`PITFALLS §7` 已记美团账单含「**归属账期**」列 ⇒ 商家粘「账期 + 金额」两列即静默算错，
而 UI 仍提示「已提取并填入」⇒ **用户不会察觉**。
**修**：新增 `stripNonMoney()`（抹掉 `YYYY-MM` / `YYYY-MM-DD` / `YYYY年M月D日` / `HH:MM` / ≥11 位长单号），`firstNumber` 前先过它。

### 🔴 P1b 首数字正则会**截断 ≥4 位整数**（更隐蔽，同样算错钱）
原式 `/-?\d{1,3}(?:,\d{3})*(?:\.\d+)?|-?\d+(?:\.\d+)?/` —— 分支一先命中 `\d{1,3}` 就返回，
⇒ `4380.00` 得 **438**、`1234.56` 得 **123**。而平台账单最常见的写法恰恰是**无千分位**的 `4380.00`。
**它的自测用例（`1,234.56` / `2,000`）全部带千分位 ⇒ 天然测不出**（这是"自测覆盖面被作者习惯带偏"的典型）。
**修**：改 `-?(?:\d{1,3}(?:,\d{3})+|\d+)(?:\.\d+)?`（千分位形态与纯数字二选一，先吃满整数再谈小数）。

### 🔴 P5 自动带出被「误锁」⇒ 费用侧不跟随（配平与利润都错）
```
if (g.rows[ri].twCarryLock) return;
if (cur && cur !== target) { ...twCarryLock = true; return; }   // ← 误判
```
`cur` 是**回读的旧值**（上次保存的补贴合计），`target` 是**本次实时合计**。用户改了**收入侧**补贴
⇒ `cur≠target` ⇒ 被误判为"用户手改了费用侧"⇒ **加锁、锁死旧值** ⇒ 费用侧不更新、配平恒偏。
**典型触发**：跨月二次录入（上月存 100、本月改到 200 ⇒ 费用侧仍停 100）。
**修**：只认 `twCarryLock`（真·本会话手改费用侧）；`cur === target` 时幂等返回。

### 🟠 P2 配平读费用走中文硬编码项名（单源违规）
`mrow('外卖平台佣金')` 等三处写死中文 ⇒ 违反本仓「页面零硬编码、项名走单源」；单源改名即**静默读到 0**、配平恒偏。
**修**：terms 立 `takeawayMode.reconcileRoles`（角色→显示名），页面按角色取用；自测加断言「roles 的值 ∈ marketing items」。

### 🟠 P4 promo 高亮由**文案内容**驱动（脆弱耦合）
`promo: /推广中心/.test(note)` ⇒ 改文案即失效。
**修**：terms 立 `takeawayMode.promoItem`，按项名判。

### 🟡 P3 注释与实现不符（陈述面 ≠ 实然，新一例）
terms 注释写「按 **item_key** 挂」，实际按**中文显示名**挂 ⇒ 已改正注释。
