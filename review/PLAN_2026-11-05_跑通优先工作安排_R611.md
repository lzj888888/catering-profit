## 1. 把「跑通」定义成可验收的东西（fail-closed）

「跑通」不能是感觉，必须是**能回填的文字证据**。分五层，**不过上一层不进下一层**：

| 层 | 判据（可机器/可回填） | 现状 | 证据 |
|---|---|---|---|
| **L0 源码自洽** | 237/237 门禁 + 0 生产路由断链 + 0 缺云函数 + 0 TODO | 🟢 过 | 本轮实扫：生产跳转 59 条零断链（4 条命中全在 `_归档_过程件_2026-11-02/` 的废弃诊断脚本，非生产）；`api.call` 28 个名字全部有云函数目录；`pages/subpkg/utils` TODO=0 |
| **L1 逻辑自测** | 页面桩真跑生产源码 + 纯函数变异测试 | 🟢 过 | `check_m1_new_cards` 12 断言 / 18 场景 / 5 变异全红；批次 3 运行时守卫 12/0 |
| **L2 真云链路** | 云函数部署到 dev + 一次真 `callFunction` 往返 + 数据库读回 | 🟡 **无近期证据** | 云函数 11 月零改动 ⇒ 理论上不需重部署，但**「理论」不是证据**；`smokeTest` 注释自写「价值只在跑到真云上」；最近真云回执停在 9~10 月 |
| **L3 真机端到端** | 手机上走完「建店 → 录入 → 保存 → 结果数字对 → 导出有反馈」并回填 | 🔴 **零** | 4 张真机单结果区全空；R609 单自己写着「今天新增的界面，一次都没在手机上看过」 |
| **L4 正式环境** | prod 环境建成 + 播种 + `ACTIVE_ENV` 切换 + dev/prod 隔离回读 | 🔴 未建 | `ENV_MAP.prod = 'catering-prod-xxxxxxxx'` 占位符；`CHECKLIST_正式版发布前必做.md` 实测账号下只有 1 个环境 |

> 🔴 **L2 和 L3 可以在同一次 10 分钟真机会话里一起证掉**：真机连 dev 环境走主链路时，`callFunction → 云函数 → 数据库 → 结果页` 整条链天然被跑一遍。
> 所以不需要拆成两个战役，**唯一的主线动作就是一次真机最小闭环**。

### 什么算「跑通了」（缺一不算）

1. 一张 `CHECKLIST_跑通最小闭环_R611.md` **逐条回填**（✅ / ❌＋现象文字），不是"看着能用"；
2. 回填里包含**至少一个可复算的数字**（如：收入、成本、利润三数对得上）；
3. 有任何 ❌ ⇒ 我修完再出码重跑，**不带已知问题往下走**；
4. 门禁仍 237/237。

## 2. 主线换轨（这是本轮最重要的决定）

```
旧（R610，作废）          备案倒计时  →  11/20 上线  →  收钱
                          ↑ 代码被当成"已完成"，只等墙钟

新（R611）                跑通闸门  →  上线  →  收钱
                          ↑ 平台手续并行起跑，不占主线、不设死日期
```

**三条硬规矩**：

- **① 不再用日历倒排。** 上线日 = `MAX(跑通证据齐, 备案下发, prod 建好) + 提审 1~7 工作日`。备案 1~20 工作日不可压缩，写死 11/20 只会逼着自己在没跑通时提审。
- **② 等执照的 3 天 + 等备案的墙钟时间，全部用来跑通与稳定性。** 不是干等。
- **③ 跑通证据不齐，不提审。** 这是 fail-closed 闸门，不因"备案下来了别浪费"而放行。
