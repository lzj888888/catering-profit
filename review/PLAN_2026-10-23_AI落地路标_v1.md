# PLAN · AI 落地路标 v1（2026-10-23）

> 触发问题：「AI 这块还需要考虑哪些？AI 是预埋后期才上吗？个体执照能把 AI 玩明白吗？一年内没 AI 的会被淘汰」
> 本文只回答一件事：**接下来 6 个月，AI 该以什么顺序进这个产品**。不写代码。

---

## 〇、一句话结论

**AI 已经预埋好了，但现在还不能上——卡的不是技术，也不是执照，而是「当前小程序是个人主体」。**

个人主体永远开不了「深度合成」类目（微信硬规则）。个体工商户**可以**开，而且有一条不用自己备案的捷径（CloudBase 云开发 AI，资质由腾讯云提供）。所以真实顺序是：

> **主体（个人 → 个体户）→ 类目（深度合成-AI问答）→ 才轮到模型。**

在主体没变之前，最有价值的事是 **L0/L1（规则 + 模板）** 和 **「导出可被 AI 直接读懂的诊断包」**——这两件零资质、零成本、零幻觉，且今天就能做。

## 一、现状：AI 已经预埋了什么（不是"以后再说"）

| 已落地 | 位置 | 说明 |
|---|---|---|
| 授权模型两张表 | `cloudfunctions/initDb/collections.js`（2026-10-21 建） | `shop_ai_consent`（谁授权/哪个店/哪些用途/何时撤）+ `shop_ai_insight`（T+1 预计算结论） |
| 授权/撤回三函数 | `getAiConsent` / `grantAiConsent` / `revokeAiConsent` | **授权是状态不是一次性勾选**，撤回必须能一次性清掉派生数据 |
| 三条边界 | `review/ADR_2026-09-28_AI接口预留决策.md` | ① 数据机读化（raw + facts 双件套）② **LLM 不碰数字** ③ 文案与计算分离 |
| 成长计划权益 | `review/NOTE_2026-09-28_round169` | **已报名成功**，10 亿混元 token + 10 万张生图**已到账** |
| 场景分级 | `review/NOTE_2026-09-28_round168` | 9 个候选场景里，**只有 1 个**（异常利润多因素归因）判定"唯一适合 LLM"，排在三期 |

理由（ADR 实证）：provider 未定 + 无调用方 + 本仓加一个 common 文件 = 11→12 份同步 × 42 处 + A15 逐条登记 + 42 个函数重部署。

## 二、主体：这是唯一的硬门槛（今天查证）

### 2.1 事实

| 事实 | 依据 |
|---|---|
| 当前小程序主体 = **个人**（`杜**`） | `NOTE_2026-09-28_round169` 后台实读 |
| **个人主体开不了「深度合成-AI问答」类目** | 微信规则；多来源一致 |
| **个体工商户可以开** | 腾讯云官方 2026-07-07：「持有营业执照的个体工商户可申请添加深度合成类目，CloudBase 提供相应算法资质」 |
| 个人主体**不能**直接在备案里改成个体户 | 微信开放社区：需注销备案 + 用执照重新注册 + 重新备案 |
| 个人 → 企业/个体户的「主体变更」通道存在，但**需公证 + 双方主体存续 + 审核** | 微信主体变更规则；不保证一次过 |

### 2.2 结论与风险

- **能走通的路**：个体工商户营业执照 → 微信认证（300 元/年）→ 申请「深度合成-AI问答」类目 → 用 **CloudBase 云开发 AI** 的算法资质提交。
- **最坏情况**：主体变更被驳回 ⇒ 只能**新注册一个个体户小程序**并迁移（AppID 变、名称/历史/微信支付商户号都要重配，老用户要引导跳转）。
- ⚠️ 这个风险**与 AI 无关也需要面对**：个人主体**无法开通微信支付** ⇒ 现在所有付费转化（M1 升级、M3 开通）其实都没有真金链路。**主体是商业化前置，不是 AI 前置。**

> 所以真正的待办不是"要不要上 AI"，而是"**什么时候把主体从个人换成个体户**"。这一条同时解决：AI 类目 + 微信支付 + 备案。

## 三、三条 AI 路径（按合规成本排序）

| 路径 | 合规 | 个体户可行 | 成本 | 什么时候用 |
|---|---|---|---|---|
| **A · CloudBase 云开发 AI（混元）** | 腾讯云提供算法资质，不出云开发环境 | ✅ **可行** | 已有 10 亿 token 免费额度 | **首选**，L1 内嵌问答 |
| **B · 第三方 API 出站（火山/DeepSeek）** | 我方即"服务提供者"，需算法备案/登记；个体户缺"算法安全责任人（正式员工）" | ⚠️ 高风险 | 单次 0.003 元，但合规成本高 | 除非 A 不能满足，暂不做 |
| **C · 外部 AI 协作（把 facts 交给豆包/元宝/WorkBuddy）** | **零合规**（用户自己拿去问，我们不提供服务） | ✅ 现在就能做 | 0 | **过渡期主力**，见第四节 |

**A 与 B 的差别不是钱，是责任方**：A 的责任在平台侧（腾讯云已备案），B 的责任在我方。

## 四、C 路径：我认为最被低估的一条（今天就能做）

老板要的不是"和小程序聊天"，是"**告诉我该动哪一下**"。而"该动哪一下"是确定性的。

所以先做这个闭环：

```
小程序导出 ──▶ 一份「AI 诊断包」（结构化 facts + 现成问题）
                    ↓
        老板丢给任何 AI（豆包/元宝/WorkBuddy）
                    ↓
              拿到针对性建议
```

**为什么这条值钱**：
1. **零资质、零成本、零幻觉风险**（我们不生成内容，只提供已算好的数字）；
2. 别人导出的是 Excel 表格，我们导出的是**能被 AI 直接读懂的诊断包**——这是差异，不是功能；
3. 它天然符合 ADR 边界 1（raw + facts）和边界 2（LLM 不碰数字）：AI 拿到的是**已经算好的数字**，只负责组织语言；
4. 老板用惯了以后，再上内嵌 AI 是"顺手"，不是"教育"。

**诊断包里放什么**（全部是已有数据，不需要新接口）：
- 门店口径：城市层级 / 业态 / 营业天数 / 面积
- 月度事实：营收、可变成本、固定成本、真钱利润、毛利率、保本额、安全边际
- 菜品事实：各菜成本 / 售价 / 毛利 / 毛利率 / 销量占比
- 渠道事实：堂食 / 外卖 / 团购 的到手率与毛利
- 已算好的判断：低于业态带的项、异常项（这些**由引擎判定**，不让 AI 判）
- 5 个现成问题（老板可直接复制）：为什么这个月利润掉了？哪道菜在拖后腿？房租占比安全吗？…

## 五、落地顺序（我的建议）

| 阶段 | 做什么 | 需要谁 | 前置 |
|---|---|---|---|
| **P0（本周，0 成本）** | ① 导出「AI 诊断包」（第四节）② L0 决策语句纯函数 `buildInterpretation(facts)` | 我 | 无 |
| **P1（主体变更，2~6 周）** | 个人 → 个体工商户；微信认证；小程序备案 | **李老师**（要执照/法人） | 工商状态正常 |
| **P2（主体到位后 1~2 周）** | 申请「深度合成-AI问答」类目 → CloudBase AI 接一个只读问答 | 我 + 你 | P1 完成 |
| **P3（数据够了再说）** | LLM 做「异常利润多因素归因」——**唯一被判定真的需要 LLM 的场景** | 我 | 账单导入跑满 1 个月 + ≥3 类模板覆盖不住的提问 |

**P3 的触发条件不放松**（ADR 已定）：LLM 只出候选根因，**所有数字回 L0 引擎重算**，未通过复核的条目直接丢弃不渲染。

## 六、AI 必须考虑的 8 件事（合规清单，按会踩到的先后排）

1. **AI 标识**（2025-09-01 起强制）：对话页**全程固定**展示「AI 生成，仅供参考」，每条回复加角标。放角落小字＝驳回。
2. **域名**：普通接口加 request 合法域名；**流式输出还要加 socket(wss) 域名**（只配 request ⇒ 真机流式挂掉）。
3. **数据授权**：已有 `shop_ai_consent` —— 必须"可撤回"，撤回时清 `shop_ai_insight`。
4. **数据出境**：走 CloudBase AI 不出微信环境；走第三方 API 就是出站，要额外说明。
5. **幻觉**：铁律 —— LLM **不碰任何金额/占比/阈值**，只组织语言。
6. **成本**：禁止超时自动重试（双份烧 token）；同 `shop_id + month + hash(facts)` 命中缓存不再调。
7. **降级**：`ai_enabled=false` 时产品不能降级（L1 模板永久兜底）—— 这是验收判据。
8. **留存**：交互日志留存（合规要求至少 3 年），投诉举报入口要在协议里写明。

## 七、明确不做（防过度设计）

| 不做 | 为什么 |
|---|---|
| 现在建 AIProvider / 模型枚举 | provider 已定为 CloudBase（A 路径），等真调用时再抽一次到位 |
| 「AI 聊天」入口放首页 | 老板没数据时问不出有价值的问题，问出来也是泛泛而谈，反而伤信任 |
| 让 AI 改数字 / 自动调价 | 违反 ADR 边界 2，且改错了没人能追溯 |
| 第三方 API 出站（近期） | 合规责任转到我方，个体户材料短板明显 |

## 八、待李老师拍板（3 件，都有时限感）

1. **主体变更的时间表**：这条同时卡着 AI 类目、微信支付、小程序备案 —— 我建议**排在所有功能之前**。
   （风险要提前说清：变更需公证、可能被驳回；驳回的兜底是重新注册 + 迁移。）
2. **P0 先做哪个**：我建议「导出 AI 诊断包」优先于「内嵌问答」——前者零资质，且能被真实验证。
3. **C 路径是否接受**：老板把数据交给外部 AI（豆包/元宝）分析，你接受吗？（这决定 P0 的形态）
