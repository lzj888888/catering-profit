# NOTE · round211 —— 原料「空模板」方案的判断与落地

> 起因＝李老师提问：「原料库有了批量导入，**提前做好一张带表头带字段的空模板**（Excel 之类）让客户下载、
> 下载后填写、再回传回来，这样好还是不好？」「这个表格也要设计合理，让客户换算方便，有必要吗？」

---

## 一、先纠正一个前提：这不是从零起步

查仓库后确认三件事，决定了本轮的结论：

1. **解析器早就吃 Excel 复制出来的格式。** `utils/materialBatch.js::splitRow` 的分隔符优先级是
   `Tab（Excel 复制）> 逗号 > 分号 > 多空格`，并且**首行表头自动跳过**（须同时含名称类与价格类词才认，
   避免把「炸鸡腿 名称待定」误当表头吃掉真数据）。也就是说，"搬运电子表格内容"这条路已经通了。
2. **「上传文件 → 云函数解析」也有现成管线。** 外卖销量账单已跑通 `wx.chooseMessageFile → uploadFile →
   importSalesBill → 预览 → 入库`（`cloudfunctions/importSalesBill`，云端已带 `xlsx` 依赖）。
   不是新物种，只是那套管子目前只长得像"账单"，不像"原料"。
3. **仓内至今零处 `wx.downloadFile`。** ⇒ 「下载」是全新能力；而最后一步还是要粘贴回来。

---

## 二、判断：有必要，但**顺序不能反**，且第一阶段不应该碰下载

三条候选路排序：

| 路 | 做什么 | 真实成本 | 走到"导进来"要几步 | 结论 |
|---|---|---|---|---|
| **A** | 页内「复制表头+示例」按钮 + 一份模板文件（发给客户/进引流包） | 极小，零新依赖零包体积 | 粘贴 2 步 | **先做** |
| **B** | 小程序内下载模板文件 | 需一处托管 + 新的 wx API 面 | 下载→跳去 WPS→保存→填→回来粘 | 暂不做 |
| **C** | 上传 xlsx 回填（走账单那条管子） | 中：新解析器 + 云端依赖 + A15/core10/隐私/契约四处同步 | 选文件→解析→确认 | 待定 |

选 A 的理由不是它便宜，而是**它覆盖掉了 C 的大部分收益而几乎不带副作用**：
客户不知道填什么才是真正卡住那一步的（尤其是「换算系数」这个词本身），
模板解决的是**认知问题**，不是**传输问题**。传输问题在粘贴这条路里已经被 Tab 分隔符解决了。

🔴 **不在这一轮动 C 的理由**：现在客户在手机还是电脑上录原料的占比还没被证过。
如果主体在手机上，C 是负优化（在微信里翻聊天找文件比粘贴慢得多）。
先把 A 放出去，用真实填回来的样本验证需求存在，再上 C 不迟 —— 这是 fail-closed，不是拖延。

## 三、模板怎么才算"设计合理"（本轮的真正设计点）

换算系数是**唯一的认知门槛**。老板不懂这个术语，但他一定知道"一箱里有多少、一件有多重"。
⇒ 设计成**不提术语、只问人话**：

```
A 原料名称* | B 规格/品牌 | C 采购单位*(下拉) | D 采购单价(元)* | E 换算系数 | F 出成率(%)
                                              ↑ 这列 = IF(G,H 都填了, G*H, "")   ← 自动算出来
G【助手】一包有几件 | H【助手】每件多少克/毫升   ← 老板只需要答这两问
```

- **E 列是公式**，客户复制出来的是**计算结果的值**，粘贴回小程序就是裸数字。
- E 列数字格式设为 `0`：**不带千分位**。`2,4000` 这类串会被 `isNumLike` 判非法 —— 这是会真实炸的一个点。
- **C 列数据有效性下拉**，源引自隐藏 sheet「单位选项」（16 项，与 `utils/units.js::PURCHASE_UNITS` 同源概念）。
  这直接从源头掐掉了"单位不在可选池"这个最高频报错。
- 有通用换算的单位（斤/两/千克/公斤/克/毫升/升）**说明里明确写「可以留空」** —— 系统会自动带出，
  别逼老板算 1 斤 = 500 克。
- 「辅助列只能放在第 7 列之后」这个约束是被 `pickColumns` 的位置语义保住的：取的就是前 6 个位置，
  客户整行复制带上 G、H 也不影响。

产出物（样品，未进代码）：`原料批量录入模板.xlsx` / `.csv`（UTF-8 BOM，双击不乱码）/ `页内一键复制片段.txt`。

## 四、顺手挖出来的一条真 bug（也是本轮唯一的代码改动）

模板做出来之后，**拿它去喂真实解析器**，CSV 版当场炸了：

```
修复前：行数 43，合格 3 —— 剩下 40 条全是 row2+ 的「缺名称」红行
```

原因：留出给老板填的空行，被复制过来是 `,,,,,`。它**不是空白**（逗号不属于 whitespace），
`splitRow` 开头的 `!s.trim()` 拦不住 ⇒ 被当成一条"全空的数据行" ⇒ 每行产出一条假错行。

**讽刺的地方**：模板越贴心（留的空行越多），预览页的红海越壮观。这是只有真做模板才会撞到的问题。

修复（`utils/materialBatch.js::parsePaste`，一句）：

```js
if (cells.every((c) => String(c == null ? '' : c).trim() === '')) { blankLines += 1; continue; }
```

空行不是坏数据 —— 它压根不是数据。

## 五、守卫：给既有套件补 3 条（23 → 26，未新增套件）

`tools/check_material_batch.js`：A-⑩ 逗号空行 / A-⑪ 分号空行 / A-⑫ 40 行模板压力。

**本轮两次变异都栽在"守护者自己的假绿"上，这条教训比修复本身值钱**：

| 轮 | 样本 | 结果 | 为什么 |
|---|---|---|---|
| 第 1 次 | 纯 Tab 空行 `\t\t\t\t\t` | 删掉修复代码**照样绿** | `splitRow` 开头的 `!s.trim()` 已经拦掉了它 —— `trim()` 吃 tab |
| 第 2 次 | 「空格+Tab」空行 `" \t \t "` | 照样绿 | 同上，全是 whitespace，一样被 trim 成空 |

⇒ 真正会漏网的**只有带可见分隔符的空行**（`,,,,,` / `;;;;;`），因为分隔符不是空白字符。
这也是继 R204（样本用逗号 ⇒ 没覆盖到空格分支）、R210（负样本没传 name ⇒ 两个错误码撞车）
之后**第三次踩同一类坑**：

> 🔴 **变异打不红时，第一嫌疑永远是"样本根��没走到被检的那行代码"，其次才是"守卫太弱"。**

最终变异回灌 **3/3 全部点名目标断言**：M1 删整句→⑩⑪⑫ / M2 跳过但不计数→⑩⑪⑫ / M3 `every`→`some`（真数据被吞）→⑩⑪⑫。
