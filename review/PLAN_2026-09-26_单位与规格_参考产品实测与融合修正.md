## 2. 参考产品实测结论

### 2.1 页面结构（菜品成本计算页）

```
菜品名称*
食材清单 (1项)
  └ 食材卡片                            [删除]
      食材名称*           如：牛肉、土豆
      采购单价* [0.00]    采购单位 [克 ▼]      ← 两列并排
      单次用量* [0]       用量单位 [克 ▼]      ← 两列并排
      损耗率(%) [0]       食材加工过程中的损耗比例，如切配损耗
  + 添加食材

目标毛利率(%) [60]     餐饮行业建议毛利率：60%—70%
────── 结果区 ──────
该项成本 ¥xxxx
成本 xxxx元
建议售价 ¥xxxx        （按目标毛利率反推）
60.0%                 （实际毛利率）
单份毛利 ¥xxxx
成本占比分析           （各食材占比 + 金额）
```

### 2.2 单位池（**实测可见，未确认穷尽**）

首次打开采购单位下拉可见：`克 / 千克 / 毫升 / 升 / 个`
再次打开（选中「个」后）可见：`升 / 个 / 份 / 斤 / 两`

⇒ 合并去重 **至少 8 项**：`克 千克 毫升 升 个 份 斤 两`
⇒ **采购单位与用量单位共用同一个池**（两个 picker 的可见项完全一致）
⇒ 两个都是**带 ▼ 的下拉**（原生 picker 外观）

### 2.3 换算机制（实测）

| 输入 | 结果 |
|---|---|
| 采购 60 元/**个** + 用量 100 **千克** | 该项成本 **¥6,000,000.00** |

反推：它把 `100 千克 = 100000 克`，再乘 `60 元/克` ⇒ **非重量单位（个）与重量单位（克）混用时，它按 1:1 静默硬算，不报警、不给提示。**

> 🔴 这是**缺陷**，不是可借鉴的设计。咱们要**反过来做**：同类混用要给提示（见 §4-E）。

### 2.4 优点清单（值得借鉴）

| # | 优点 | 价值 |
|---|---|---|
| P1 | 采购单位/用量单位**都是带 ▼ 的 picker** | 一眼看出「可点、可选」，不用猜 |
| P2 | 单位池**含非重量单位**（个/份/斤/两） | 鸡蛋按个、豆腐按份、肉按斤 —— 老板的真实语言 |
| P3 | 结果区完整：成本 → 目标毛利率 → **建议售价** → 实际毛利率 → **单份毛利** | 老板要的决策数字一次给全 |
| P4 | **成本占比分析**（每个食材占总成本比例） | 直接看出「哪个原料最吃钱」 |
| P5 | **行业建议毛利率 60%–70%** 提示 | 免去"该定多少"的茫然 |
| P6 | 录入极简：单价+单位、用量+单位、损耗率 → 3 个输入出结果 | 门槛低 |

### 2.5 缺陷清单（要避开）

| # | 缺陷 | 后果 |
|---|---|---|
| D1 | 非重量单位 × 重量单位**静默 1:1** | 成本 600 万也不报警（实测） |
| D2 | 下拉是**滚动居中**式 —— 同一个下拉两次打开看到的选项不同 | 用户困惑「我的选项呢」 |
| D3 | **无「换算系数」入口**（池里只有单件单位） | 「1 箱 = 24 瓶」这类**表达不了** |
| D4 | 无出成率（只有损耗率） | 净料率算不进去 |
| D5 | 无规格（大份/小份） | 一菜多价做不了 |

## 4. 修正清单（融合后）

> 原则：**引擎口径一字不改**。全部落在「录入层入参变换」+「文案」+「视觉」，不新增集合、不改 `calcCostCard` 系列公式。

### A. 用量单位池与采购单位池对齐 ← 修正 ① 的实质

- `QTY_UNITS` 扩为与 `PURCHASE_UNITS` 同池（或至少补 `斤/两/个/份/只/条/瓶/包`）
- `QTY_FACTOR` 补：`斤:500`、`两:50`、`个/份/只/条/瓶/包/箱/桶:1`
- **代价**：零引擎改动；`qty_unit` 不落库，老数据零影响
- **风险**：`箱/桶` 这类没有通用倍率，选它当用量单位等价于「1:1 当量」，**须配 E 项护栏**提示
- **守卫**：`tools/check_unit_convert.js` 断言数需同步（倍率表扩项后 L2 的样本要补）

### B. picker 补下拉箭头 ← 修正用户第 ② 问（视觉层）

- `.picker` 加右侧 `▾`（伪元素或 `<text>`），并给输入框边框，做成「可选」外观
- **代价**：纯样式，零逻辑；`pages/card/edit.wxss` 一处生效
- ⚠️ 字号下界 28rpx（项目红线），箭头图标不受字号约束

### C. 采购单位形态：加箭头视觉，保留自由填 ← 修正用户第 ② 问（交互层）

- 现在 `<input>` + chips 的设计**是刻意的**：参考产品的 picker **选不出「箱/桶/提」**（D3 缺陷），而老板真要按箱买
- 且项目有前车之鉴：**picker 弹层 × 键盘 = 真机死结**（PITFALLS §6）
- 融合做法：把单位行做成「输入框 + 右侧 ▼」，点 ▼ 展开/收起 chips 行 ⇒ **既有箭头暗示，又能自由填**
- **代价**：`pages/material/edit.wxml` + `.wxss` 小改；不动 chips 数据源

### D. 换算系数的基准词动态化 ← 修正用户第 ① 问

- 现文案：`换算系数（→克）` 恒定；实际含义 = 「1 采购单位 = ? 克」
- 改为**随采购单位联动**：`1 斤 = ___ 克` / `1 升 = ___ 毫升`
- 计数族（个/瓶/箱/桶）→ 显示 `1 箱 = ___ 个`（即"一箱装几个"）
  - ⚠️ **口径说明必须写进规范**：引擎仍把该数当「倍数」，数学上「1箱=N个」与「1箱=N克当量」等价（用量也按「个」填）
- **代价**：`i18n/terms.js` **双副本**（`miniprogram/i18n/terms.js` ≡ `specs/dev-specs/i18n/terms.js`，改后 `cp` + `diff -q`）+ `pages/material/edit.js` 一行
- 🔴 **此项触碰规范口径**（`matConvert` 语义从"→克"扩为"→同族基准"），**需先拍板**

### E. 计量族不匹配护栏 ← 反过来做，避开参考产品的坑（D1）

- 场景：原料档案里采购单位 = `个`（计数族），菜品卡里用量单位选了 `克/千克`（重量族）
- 做法：**黄色提示**（不拦截）——「该原料按『个』采购，用量建议也按『个』；若要按克用，请先在档案里填换算系数」
- **代价**：`pages/card/edit.js` 的 `refreshSpecHints()` 扩一条判据（该函数已在算 `spec_hint`）
- **价值**：这是参考产品**实测会算成 600 万**的那个坑，咱们主动堵上

### F.（可选，暂不做）成本占比分析

- 参考产品的结果区有「成本占比分析」（各食材占总成本比例）
- 咱们 M3 结果区已有成本/毛利/毛利率/建议价
