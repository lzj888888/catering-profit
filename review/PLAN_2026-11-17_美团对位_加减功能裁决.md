### 2.1 一个豆包没算进去的数：老板的真实门槛

```
硬件（青春版买断）        ≈ 2099
主收银（智能版）          ≈ 2500 / 年
门店库存（成本卡所在模块） ≈ 1498 / 年   ← 豆包漏了这层
```

**这层加价对我们有利**：老板不是"花 2500 买个收银"，是"花 6000 才拿到成本卡"。25.9/月 的对比更好讲，而且完全可查证，不需要贬低对方。

## 三、我的一句话判断

**豆包的战略结论我认（不抢收银、不抢选址的准、不抢成本卡完整度，护城河是"私人终端 + 固定成本 + 敢下判决"），但它给的落地方案里，成本最高的一件（美团报表导入）我反对，最能立住的一件（私密性表达）它漏了。**

## 五、要加的三件（都是"输出层"，不动引擎）

### 5.1 【最高性价比】一句私密承诺

**改哪**：首页首屏一句；录入房租/人工那一屏一句。
**写什么**（建议）：
```
首页：这些数只有你能看到，员工和店长看不到。
录入页：这里填的数不会给任何人看。
```
**为什么值**：这是我们唯一**结构性**优势的唯一可感知证据——收银机装在前台，服务员、店长、厨师都能按，所以老板的房租、人工、私账**本来就不敢往里输**。这个道理我们从来没在界面上说过一个字。
**成本**：两句文案 + 一个守卫。**风险**：零（前提见下）。
**配套红线**（写进产品原则，比功能重要）：
> **永不做"多人协作录成本"。** 那一做，等于把收银机搬到手机上，自毁护城河。

### 5.2 M2 的"一页纸判决"

**加什么**：结论页最上面一行判决，三行理由，三行否决项。
```
【判决】这个铺子：可以签 / 有条件签 / 不建议签
【三条理由】租金超健康线 X% / 同品类 Y 家且客单更低 / 回本 Z 个月
【一句话】"你在这里最可能死在第 N 个月，原因是……"
```
**为什么值**：判据我们**全都有**（`matrix.js` 有保本营业额、租金占比、回本；`openCash.js` 有可撑月数），现在只是把它们摊在矩阵里让老板自己读。**老板不看表，看一句话。**
**不加什么**：不做半径切换、不做热力、不做商圈雷达图——**没数据就别画图**，画了就是冒充。这三处若要显示，必须标"实地估算，非平台数据"。

### 5.3 M2 → M1 的单一出口

**加什么**：M2 判决页底部一句话 + 一个跳转：
```
"铺子签了，第一个月怎么活？→ 算一遍月度盈亏"
```
**为什么值**：M2 定位是**引流品**（豆包这条我认）。引流品最怕**没有出口**——免费送完，人走了。现在 M2 免费、永不弹窗，但出口在哪我没找到。这不是加功能，是补一条**转化路径**。

### 5.4 附赠（内容侧，不占开发）
M2 的"现场四看"做成**一张可打印的纸**（500m 内同品类几家 / 饭点进去坐了几桌 / 有没有贴转让 / 客人在哪条路上走）。这是唯一能**替代**热力数据的真办法，而且天然是三个号的视频素材。**不用开发，做成一张图/一张表就够。**

## 六、明确不加的五件，以及为什么不加

### 6.1 美团报表 xlsx 导入 —— 我反对豆包这条

豆包把它称为"最低摩擦的导入路径、最快能变成产品的一块、最好的销售话术"。**我不同意，三条理由：**

1. **技术上会崩**：美团导出的是多级表头 + 合并单元格 + 各店列名不统一的 xls/xlsx。小程序里解析它，出错不是"报个错"，是**数字悄悄算错**——数据错了，信任就没了，这比没有功能严重得多。
2. **战略上自伤**：做"导进来我就算"=把自己定义成"更好的算账工具"。这正是豆包自己判的必输阵地。**一边说别当算账工具，一边做算账工具的导入，自相矛盾。**
3. **商业上白送**：导入放免费版，人导完就走；放付费版，没人为了试一下先付钱。

**替代方案**：保持"三个数"极简路径（营业额 / 食材 / 房租人工）。真要做批量，**只认我们自己的模板**，且只服务"多店 + 月度批量"的付费场景，排在支付接通之后。**不做美团格式解析。**

### 6.2 不做成本卡的"完整体系"
堂食/外卖/加料三类卡、出品仓库、盘点、理论 vs 实际消耗、串货预警 —— 这是把我们的用户假想成连锁店。**我们的用户是没系统的夫妻店，他连成本卡都懒得填。** 加这些，等于给 5% 的用户花 80% 的成本。

### 6.3 不做选址的"准"
热力、商圈实时客流、同品类流水指数：数据在平台手里。买不到、爬不得。**爬数据是合规红线，碰一次全盘皆输。**

### 6.4 不做套餐"设计"
我们算"这个套餐毛利多少、引流款亏不亏"，这就够了。设计组合需要平台销量数据，做不出来。

### 6.5 不做多人协作 / 自动抓数
前者自毁护城河（§5.1），后者是合规红线。

## 七、我和豆包的两处分歧（比功能更影响结局）

### 7.1 对外不能说"它算不出净利润"

豆包的核心话术是「**美团的利润表缺你最大的一笔支出：房租和人工**」。
**这句有风险**：如果美团记账本真能手工记房租人工（豆包自己也标了"待核"），这句话就**可被当场打脸**——老板一句"我记了啊"就把我们堵死。

**我建议换成不可攻击的版本**：
> 「它要你自己一笔一笔记，记了也只有数，没有结论。而且它不做摊销——装修、设备、押金按月摊，它没有这个概念。」

这句话是**结构性事实**（摊销它确实没有），不依赖"它能不能记"，怎么说都站得住。

### 7.2 不建议把"它不做是因为利益冲突"讲成主句

豆包的金句「它要是劝你关店，它自己的佣金就少了」——**内部判断可以，对外讲就是动机揣测**，正好踩它自己定的"说事实不说动机"三条。
**对外只留一句事实**：它给数据，不给判决。
（内部写产品定位可以照豆包的原话，那没问题。）
