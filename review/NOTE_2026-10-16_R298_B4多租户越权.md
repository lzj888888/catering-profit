## 3 两个真缺陷

### 3.1 `checkQuota` 缺归属校验（越权读）

- **契约**：`user+shop`；**代码**：只有 user。
- **可达性**：`shop_cost_card` **没有 `user_id` 字段**（只有 `created_by`，无跨店索引）⇒ 成本卡维度**只能按 `shop_id` 计数**
  ⇒ 这里没有别的隔离手段，归属校验是**唯一**那道门。
- **行为级实证（修前）**——不是静态推断：

  ```
  调用者 OPENID : openid_B（用户 B）
  传入 shop_id  : shop_aaaaaaaaaaaa（用户 A 的店）
  A 店成本卡    : 3 张 calculated + 1 张 draft
  出参          : {"code":"SUCCESS","data":{"user_id":"u_B","used":3,"free_limit":20,...}}
  ```
  ⇒ 用户 B 拿到了 A 店的成本卡数（`used=3`）。

- **修法**：`validateInput` 之后补
  `const owner = await assertShopOwner(db, shopId, userId); if (owner.error) return fail(owner.error, owner.msg);`
  ——与其余 26 个函数的**同一形态**，不新造轮子。
- **修后行为**：`{"code":"FORBIDDEN"}` ✅（同一探针复跑）。
- **对前端零影响**：`checkQuota` 在仓内**零前端调用点**（契约 §9 已登记为「已部署但零出现」的函数之一）。

### 3.2 `verifyTangshi` 无来源校验（跨租户暴露）

- **实证链**：本函数自身的头注写着触发方式是
  `mp.evaluate(() => wx.cloud.callFunction({ name:'verifyTangshi', data:{} }))`
  —— `mp.evaluate` 走的正是**客户端通道** ⇒ 「不是业务接口」≠「客户端调不到」。
- **暴露内容**：`{ count, sumFen, sumYuan, shopIds, distinctDishKeys, seqMin, seqMax, where }`
  —— 聚合值 + **所有命中店铺的 `shop_id` 列表**（他人租户标识）。
- **为什么守卫没抓到**：`tools/check_fn_public_surface.js` 的 `PUBLIC_FNS` 把它登记为
  `mustSelfGuard: false`，理由写的是「不读 OPENID、不写库」。
  🔴 **那句只回答了「它自己会不会写坏数据」，没回答「别人能不能调它」** —— 豁免理由答错了题。
- **修法**（沿用 R215 既定定式，与 `payExpireNotify` / `smokeTest` 同款）：
  ```js
  const ctx = cloud.getWXContext();
  if (ctx && ctx.OPENID) return { ok: false, code: 'FORBIDDEN', msg: '...' };
  ```
  「有用户 OPENID 即客户端调用 ⇒ 拒绝」；云控制台「测试」与 `cli` 调用**没有**用户上下文
  ⇒ 诊断能力不受影响。
- **同批**把登记表改为 `mustSelfGuard: true`，并同步契约表「鉴权」格补注加固事实。

**教训**：`(变异没红)` 与 `(守卫没盖住)` 在日志上**长得一模一样**（都显示 `RC=0`），

## 8 本轮新踩的坑（已沉淀）

1. 🔴 **契约表解析必须按「未转义竖线」切**：`|` 在 markdown 表格里可写 `\|`，
   而本表「入参」格里有 `'cc'\|'user'\|'shop'\|'all'` 这类联合类型。
   朴素 `split('|')` + 取 `[4:]` 会把列**整体切歪** —— 我第一版 Python 探针就因此把
   `smokeTest`（鉴权 = `无`）误判成「契约含 shop」，**凭空多出 1 个假候选**。
   ✅ 正解：`split(/(?<!\\)\|/)` + 取 `parts[length-2]`，并**用自证样本钉住**（E-⑦/E-⑨）。
2. 🔴 **本仓不是全 LF**：`specs/dev-specs/★知识存储点_2026-09-10.md` 是 **CRLF**（实测 1235 个 CR）。
   批量脚本里写「文件应无 CR」的断言会在此停手 —— **方向是对的（fail-closed）**，
   但正确做法是**读时记下 CR 数、写回后核对一致**，而不是假定 LF。
3. 🔴 **`s.count(b'\r')` 用在 `str` 上会 TypeError**：写在我自己的补丁脚本里，
   因为**写盘语句在断言之后**，所以只是白跑、无损 —— 这正印证了「两阶段写入（先全量校验、后统一落盘）」的价值。
4. 🔴 **证据脚本的仓根解析不能用固定层数回退**：`review/evidence/<批次>/*.py` 与 `_probe_tmp/*.py`
   层级不同，按 2 层回退会落到 `review/` ⇒ `FileNotFoundError`。
   ✅ 定式：**向上找仓根哨兵**（`verify_all.js`）。
5. 🔴 **同一件事犯两次**：E-⑦/E-⑧ 写完以为「转义处理已被自证」，实测没有（M6）——
   **自证样本必须"只差被测项"**，否则自证本身是假绿。
