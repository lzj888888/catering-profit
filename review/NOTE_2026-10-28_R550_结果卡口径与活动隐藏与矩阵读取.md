# R550 · 三处修复（结果卡毛利率口径 / 活动模块隐藏 / 矩阵「读取」按钮）

日期：2026-10-28 · 触发：李老师当面三条反馈

## 1 测算结果卡：「菜品毛利率 62 + 合计扣点 2%」说法错

李老师原话：「菜品毛利率就是菜品毛利率 64，2% 是管理费用，不能体现菜品毛利率下降 2 个点」。

**核实成立，而且是两处错叠在一起**：
- 引擎出参 `margin_rate` 实际是**边际贡献率** = 1 − (食材成本率 + 平台点) = 64 − 2 = **62**；
- 前端却挂「**菜品毛利率**」这个标签 ⇒ 老板看到"毛利率变成 62 了"。

**改法（只动前端显示，引擎与契约零改动）**：拆成三行，各自身份分明。

| 行 | 取数 |
|---|---|
| 菜品毛利率 | `marginPct`（**用户填的原值 64**） |
| 平台扣点 + 其他杂支 | `result.platform_pct`（原「合计扣点」，原名看不出扣的是什么） |
| 实际可用毛利率 | `result.margin_rate`（引擎真正用来算保本线的那个数） |

## 2 「做活动会怎样」→ 隐藏（不是删）

李老师原话：「先删除或者隐藏，这个功能牵扯面比较大，而且不好统计真实数据」。

**选隐藏（`utils/featureFlags.js::PROMO_ENABLED = false`）**，理由：
- 「牵扯面大」的具体含义是——它要老板填两个反常识的数（折扣后实收率、活动成本率），
  这两个数只能从收银日报/活动台账手工倒推；**填错一个，整张试验台的结论全错且不报错**。
  与其给一个"看着专业、其实靠猜"的模块，不如先藏。
- 删代码的代价：`utils/promoImpact.js`、`promoOf()`、`terms.m2.promo*` 一整套要一起删，
  将来想恢复等于重写 ⇒ 按本项目既有做法（`BILL_IMPORT_ENABLED`）**只藏入口**。

改动落点：`goMatrix`… 不涉及。仅 ① 开关文件；② 沙盘页 `promoOn` + `onCalc` 里
`promoRes: PROMO_ENABLED ? this.promoOf(...) : null`；③ wxml 卡片 `wx:if` 加 `&& promoOn`。

## 3 矩阵页「读取我填的数据」按钮 —— **为什么不落实（真因）**

李老师：「对于已有店铺，有按钮可以读取已经填写的数据，比如经营类型 装修 设备等，还有清除按钮，
现在看没有落实呢，你看下原因。」

**两条真因，都记在这里**：

1. 🔴 **我把它做成了"进页自动带、不加按钮"**（R548，采纳豆包建议）。这偏离了李老师的原始要求，
   而我在当时的汇报里只说"不加导入按钮"，没有明确标出"这与你说的按钮方案不同"。
2. 🔴🔴 **更要紧的：经营类型和城市根本没带**。R548 只带了房租/人数/毛利率/目标 + 8 项投入 +
   4 个年限，**没带 `presetKey` / `cityIdx`** ⇒ 所以他看不到"读取经营类型"的入口是必然的，
   而且矩阵页的业态会用自己那套默认值（两个页面的业态可能不是同一个）。

**改法（R550）**：
- 新建 `utils/matrixSeed.js` 做**种子契约单源**（`KEY` + `GK` 字段映射）。
  为什么必须单源：读的写的是两个页面，各写一份键名映射，一定会出现
  「首页存 `dcY`、矩阵页读 `decorY`」这种**静默不生效**（本项目反复踩的病）。
- 首页 `goMatrix()` 改为 `writeSeed()` 写 storage（**URL 不再传值**，只留 `mode`）——
  避免"URL 一份、storage 一份"的双真相。种子里现在含 `presetKey` / `cityIdx` / 8 项投入 /
  4 个年限 / 4 个扫描种子 / `other` / **`marginScope`（R549 口径）**。
- 矩阵页 `readSeed()` / `applySeed(seed, silent)`：进页自动读一次（silent，不弹 toast），
  按钮再读一次（非 silent，弹"已读取"）。
- 按钮区变成两个并列动作，语义分开：
  - **「读取我填的数据」** = 把首页填的经营类型、城市、装修、设备、人工等一起拉过来；
  - **「清除重填」** = 只把档位恢复成按他店里算出的基准值，**不动**这些投入。
