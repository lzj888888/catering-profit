## 3 🔴 三条结构性发现（比"细节"更根本）

### 3.1 首页「寻找铺面」是一整套**不可达死分支**，R290 与 R234 两次拍板方向相反

**代码事实**：
- 首页 Tab「寻找铺面」`onTab()`（`index.js:613-625`）：`if (mode === 'reverse') { wx.navigateTo('/pages/sandbox/matrix?mode=reverse'); return; }` —— **直接跳矩阵页，不改本页 mode**
- `data.mode` 全文只在 `onTab`（L626）赋值，而该行只在 mode ≠ 'reverse' 时可达 ⇒ **首页 `mode` 恒为 `'forward'`**
- ⇒ `index.wxml` 里所有 `mode === 'reverse' ? … : …`（L45/46/62/370/372/385）**永远走 forward 分支**
- ⇒ `index.js` 里 reverse 分派、`reverseResult`（只声明不赋值）等同族死分支

**这意味着**：
1. **R234「反推小白化 v1.4」做的那套小白表单**（5 问 → 出保本 / 房租上限）**在界面上完全不存在** —— 它被 R290「找店直接进矩阵」覆盖了，但代码没删，只留了死分支。
2. **我今天 R320 修的 4 处 reverse 文案，一半是无效的**（forward 那半有效：「打算请几个人」→「现在几个人」，已生效；reverse 那半不可达）。

**这才是 M2 最该先解决的问题**：不是缺功能，而是**同一件事有两套实现，其中一套是死的**，且两次拍板互相覆盖。

### 3.2 「寻找铺面」把小白直接丢进最专业的页面

矩阵页要求填 **4 个维度的档位**：租金 / 人工 / **毛利率** / 目标利润。

- 找店小白**不知道**毛利率（这是他要问的答案，不是他要填的输入）
- 他要填「人工档位」也很勉强（还没雇人）

⇒ 结果是：**想在 A 区（已有铺面）用的老板一路顺畅；想找铺子的小白第一步就撞墙。**
而 R234 正是为解决这件事做的（"小白只填易填的隐藏指标"），做完又被 R290 绕过。

### 3.3 分类不清：三个页面各有一套"对比/方案"实现

| 页面 | 作用 | 状态 |
|---|---|---|
| `matrix` | 多维档位扫描 | ✅ 主入口 |
| `compare` | 多方案对比（读快照） | 与 list 重复 |
| `list` | 我的方案 + 并排对比 + 导出图片 | 功能更全 |

审计 B2 已登记两页取数口径不同（历史反推方案会显示两套数）。**两份对比实现 = 结构性隐患**，不是 bug。

## 5 整改方案（按"先修地基再补细节"）

### P0-1 定一条路：找店走「小白 3 问」还是「直接矩阵」〔**必须你拍板**〕

两条路代码都在，但只能留一条。我的建议：**恢复小白 3 问为入口，矩阵降为"进阶"**。

理由（老板视角）：找店第一个问题永远是「**这个铺子能不能做**」，不是「扫 5 个租金档位」。
3 问就够：**① 月租金 ② 面积/大概几个座位 ③ 想每月赚多少** → 直接出「保本营收 + 这个租金扛不扛得住」。
矩阵留在第二屏：「想看别的租金档位？→ 去扫一遍」。

> 若你选"保留直接矩阵"，我就把首页那套死分支**全删掉**（约 120 行 JS + 3 块 wxml），仓库立刻干净，
> 但找店小白这条路就维持现状（一进来填四维度）。

### P0-2 删除首页 reverse 死分支（无论 P0-1 选哪条都要做）

现状是"两套实现，一套死的"，留着只会让后来的人（包括我）在死代码上白改。
判据：删除后 `grep 'mode === .reverse.' pages/sandbox/index.wxml` 为 0；门禁全绿；**无用户可见变化**（因为本来就不可达）。

### P0-3 修我自己的守卫缺陷（R320 遗留）

R320 我加的「每个 `*Rev` 文案必须被引用」只能证明"有引用"，**证明不了"可达"** —— 死分支里的引用同样能过。
⇒ 改成：`*Rev` 必须出现在 `mode === 'reverse' ?` 三元里 **且** 该页面 `mode` 有真实赋值路径；或直接随 P0-2 一起删掉这批文案。

### P1-1 矩阵页对小白「降维」

进入矩阵时，**毛利率维度默认收起**（用业态 BANDS 中值，标「按行业默认，可展开改」），只留 **租金 / 目标利润** 两个维度。
→ 小白也能扫「租金 8000/10000/12000，各要卖多少才回本」。
风险：动了矩阵的默认行为，需守卫锁「默认维度集合」。

### P1-2 `BANDS.manage` 单店口径〔需拍板〕

现取 BANDS 中值（manage 5–10%，连锁口径）⇒ 单店管理费偏高（一线快餐 50㎡ 算到 1.5 万/月）。
三选一：① 保持（保守，保本线偏高）② 取带下沿 ③ 单店/连锁双分档。
我倾向 **②取带下沿**（改动最小、方向最保守可控）。

### P2-1 两页合一：`compare` 并入 `list`

消除"两份对比实现"，顺带解决历史反推方案两套数的问题。

### P2-2 矩阵「独立水电维度」〔需拍板〕

现在水电 = 房租 × 系数派生。要独立扫描就得改引擎契约（成本高）。我建议**不加**（"等"是软化表达，倒推已成立）。
