# R578 · 月度录入完成度（队列 #101）—— 用现有数据算，不新增采集

> 起因：第一档三条之一。原描述是「首月录入完成率埋点（北极星指标）」，
> 落地时撞到一个硬约束，于是改了做法——**这个改动本身比功能更值得记**。

---

## §0 一句话

**没有埋一个点，但老板从此知道自己还差几组没填。**
全局完成率仍算不出（需要管理端聚合），但「完成率低」的**直接原因**被解决了：
不是老板懒，是他以为填完了。

---

## §1 为什么放弃埋点

原方案：在录入各步打点上报，算首月完成率。

撞上两件事：

1. **全仓现在零埋点能力** —— 要新跑通一条上报链路（云函数 + 集合 + 权限 + 采集口径）。
2. 🔴 **上报 = 新增数据收集**，而隐私政策正是**上线硬阻塞项**（还有 1 处占位未填）。
   为一个指标去动上线门槛，性价比明显不对。

两司（豆包 / DeepSeek）分别给的结论一致：

| | 豆包 | DeepSeek |
|---|---|---|
| 店铺 ID 算不算个人信息 | **算**（能关联到注册账号/手机号就按个人信息处理） | **算**，「服务端记录不是法外之地」 |
| 有没有不新增采集的办法 | 有：**用已有店铺/账单数据聚合** | 有：**从现有店铺表和账单表跑数**，只存聚合结果 |
| 若要持久化「店-月-完成项数」 | 必须按最小字段声明并获同意 | 必须声明并获同意，不能当匿名数据 |

⇒ **采纳「用已有数据」路线**，本轮不碰隐私政策一个字。

---

## §2 做了什么

### 2.1 纯函数 `utils/entryCompletion.js`

- **零 IO、零网络、不写库、不上报**（守卫 B-⑤ 钉死：不许 require wx/api）。
- 口径：核心 4 组 = **堂食 / 外卖 / 运营费用 / 人工费用**
  （来源是 `TERMS` 里 `core: true` 的组，不在这里另立清单）。
- 组内**至少一行金额 > 0** 即算该组已填。

🔴 **两个刻意的判断**：

| 情形 | 处理 | 为什么 |
|---|---|---|
| 金额填 **0** | **不算已填** | 免租期、自有物业、公司代缴水电都是真实情形。误催一次，老板会认为系统在瞎报，之后所有提示都不信了 |
| 组名缺失 | **不回落成英文 key** | `dine_in` / `takeaway` 出现在界面上就是事故。宁可不显示组名，也不能露英文 |

### 2.2 页面提示（`subpkg/biz/month/input.js` + `.wxml`）

位置在「填写口径」折叠块之后、复制上月按钮之前：

```
还差 2 组没填：人工费用、运营费用
```

- **只提示、不阻断**：不进 `saveLedger` 入参、不参与任何计算（守卫 B-③）。
- **四组全填完 ⇒ 整条不渲染**（不打扰已经填完的人）。
- **算在独立方法 `refreshCompletion()` 里**，由摘要刷新在 `try/catch` **之后**调用：
  云调用失败时这条提示仍要显示 —— 那恰恰是失败时最有用的信息（守卫 B-④）。
  ⚠️ 为什么拆成独立方法：`refreshCalcSummaries` 被 A8-⑤ 约束「函数体不得出现 groups 字面」
  （防后端值覆盖未保存草稿），而完成度必须**读** groups ⇒ 读写分开守。  A8-⑤ 首跑就红在这里，是对的。

## §3 守卫（第 224 套件，15 条）

`tools/check_entry_completion.js`

| 段 | 断言 |
|---|---|
| A 行为（8） | 全空 0/4 / 单组 / 四组满 / **填 0 不算** / 负数不算 / **缺名不露英文** / labelMap 兜底 / 模块可加载 |
| B 静态（5） | 真 require 真调用 / wxml 真渲染 / **不参与保存** / **算在 try 前** / **零采集** |
| C 反恒真（2） | 改坏「填 0」判定 ⇒ A-④ 必翻转；空输入必须 0/4 |

首跑即抓到我自己一处判据写坏：B-④ 原本用一条跨行长正则，
会先命中 `onShow` 里的**调用处**（`this.refreshCalcSummaries();`）而不是定义处 ⇒ 假红。
改成「取定义段 + 比两个 indexOf 的先后」，语义清楚且不会锚错地方。

## §4 这一轮没做到的（如实）

**全局完成率仍然算不出来。** 因为：

- 它需要跨店聚合（「多少家店首月填完了 4 组」），而聚合要在管理端做；
- 我不能访问云端数据库，也没有管理后台的写权限；
- 用现有数据算单店的完成度**只能解决"老板不知道"**，解决不了"我知道行业水平"。

⇒ 如果李老师要看全局数，两条路：
1. 管理端加一个只读聚合页（读 `ledger` 表按 4 组判定，零新增采集）；
2. 先积累数据，用现有导出的账离线算（我可以写脚本）。

两条都不需要改隐私政策。**但都要等有人真的在用。**
