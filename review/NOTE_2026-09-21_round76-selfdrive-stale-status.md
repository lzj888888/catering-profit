## 3. 新守卫 `tools/check_stale_status.js`（R109，SUITES 81 → **82**）

**判据（四条腿）**

1. **扫描面 = 活文档面** `specs/**.md`（工作树递归；坑⑱：一律不用 `git ls-files`）。
   `review/` 是**历史档案**、进 W 段**弱面明示**不判红（§1 的两处误报正是排除它的理由）。
2. **形态**：`^#{2,4}\s` 小节标题含 STALE 词（`待修|待办|未落|排队|未处置|未闭环`）**且标题不带闭环标记**，
   而同节正文含闭环标记（`已闭环|已修复|已收口|已全部修复|已处置|已落地|闭环判据`）⇒ 命中。
   - **只扫 2~4 级标题**：`#` 一级是文档主标题（如"…决策与待办总览"含 STALE 词属正常，纳入会立刻误报本文件自身）。
   - **「未完」刻意不进 STALE 表**：`★知识存储点 §8「⏳ 未完事项清单」` 正是"标题说未完、正文一片 ✅"的**合法**形态。
3. **划删段剥离**：先 `replace(/~~[^~]*~~/g,'')` 再找闭环标记 ⇒ 闭环词落在 `~~…~~` 内不计（"作废但留痕"），
   落在段外仍计（明确的当前态陈述）。
4. **前提守卫**：S1 活文档面非空（30 个 .md ≥ 20 / 603 个标题 ≥ 300）+ N1~N3 五组正负样本互证 + S2 自失效护栏。
