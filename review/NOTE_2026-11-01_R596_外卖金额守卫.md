## 一、怎么发现的

R594/R595 扫的是 `api.yuanToFen(` 调用点。本轮换一条路径：扫**页面自己转分**的写法
（`Number(v) || 0` / `parseFloat` / `Math.round(...*100)`）。

- `subpkg/biz/groupon/index.js`：**已有守卫**（R443 加过，5 处 `amountInput/checkAmounts`，`onCalc` 前 `checkAmounts() > 0` 就 return）⇒ 不是漏网。
- `subpkg/biz/takeaway/index.js`：grep `amountInput|checkAmounts|classifyAmount` = **0** ⇒ 真漏网。

## 二、为什么是真漏网

`takeaway/index.js::buildOrder()` 用 `fen = (v) => Math.round(Number(((Number(v) || 0) * 100).toFixed(10)))`：

| 入口 | 读不成「1,200 / １２００ / 88元」的后果 |
|---|---|
| 佣金率 `commission_rate` | `Number()||0` ⇒ 佣金按 0 ⇒ **到手虚高**，零报错 |
| 配送费 / 配送补贴 / 营销 / 打包费 / 顾客配送费 | 全部按 0 ⇒ 到手虚高，零报错 |
| 商家/用户补贴 `s_user/s_merchant.amount_yuan` | 按 0 ⇒ 补贴少算 / 方向错 |
| 打包单价 `packs[].unit_price_yuan` | 按 0 ⇒ `filter(fen > 0)` 直接把该行**丢掉** |
| 目标利润 `targetProfitYuan` | 按 0 ⇒ 反算挂牌价偏低 |

`onReverse`（挂牌价反算）尤其危险：读不成按 0 ⇒ 反算价偏低 ⇒ **老板照它定价就是亏本卖**（R299 已修过"用旧成本"，本轮补"读不成"）。
