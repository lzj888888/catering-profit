## 一、数据不足时，终于说清「红线判过没有」

### 问题（又一处注释与代码不一致）

`diagnosisEngine.js` 在 R774 就写着：

> 覆盖率不足且没有红线命中时才退到「数据不足」……至少可以告诉老板"红线都判过了，没发现问题"，**由前端按 `redlineUnjudged` 的数量分两种说法**（见 result.js planInsufficient）。

但前端 `planInsufficient` 一直只按 `missAutoCount` / `miss` 分两种（缺记账项 / 缺要查的项），**从来没读过 `redlineUnjudged`**。结果：老板数据不足时只看到「账还不够」，白来一趟。

### 改法

新增两条文案（`terms.diagResult`，双副本）：

- 全部红线都判过：**「能查的几项硬指标都查过了，没发现致命问题；只是评分项数据不够，还算不出分数。」**
- 有未判定：`"还有 {n} 项硬指标因为缺数据没能判断——这些不能算「没问题」，补上才能下结论。"`（`{n}` 由页面填真实条数，不写死）

`result.js` 新增 `planRedlineNote`，与 `planInsufficient` **并列**（不是互斥：先说缺什么数据，再说硬指标状态）。

### 页面桩实跑（不靠自述）

| 场景 | 输出 |
|---|---|
| 数据不足 + `redlineUnjudged=[]` | 「能查的几项硬指标都查过了，没发现致命问题……」 |
| 数据不足 + 2 条未判 | 「还有 **2** 项硬指标因为缺数据没能判断——这些不能算「没问题」……」 |
| 非数据不足（watch） | 空字符串 |

### 守卫

`check_redline_sync` D-④：文案必须有「没发现致命问题」/ `{n}` / 「不能算」，且 `result.js` 两个键都得引用。**这是核心原则**——把"没数据"说成"安全"是这套模型最危险的谎。

## 二、处方层分档文案纳入阈值守卫

`survivalTier` 的边界 `3/6` 与 `TIER_TEXT` 的「撑不到 3 个月」「3–6 个月」「6 个月以上」原本**各自写死**——和 R777 抓到的 R6 完全同族：改判据不改文案就飘。

改法：

```js
const SURVIVAL_TIER_TH = { urgent: 3, cautious: 6 };
function survivalTier(months) {
  if (months === null) return 'unknown';
  if (months < SURVIVAL_TIER_TH.urgent) return 'urgent';
  if (months < SURVIVAL_TIER_TH.cautious) return 'cautious';
  return 'steady';
}
const TIER_TEXT = {
  urgent: `账上的钱撑不到 ${SURVIVAL_TIER_TH.urgent} 个月：…`,
  cautious: `还能撑 ${SURVIVAL_TIER_TH.urgent}–${SURVIVAL_TIER_TH.cautious} 个月：…`,
  steady: `还能撑 ${SURVIVAL_TIER_TH.cautious} 个月以上：…`,
};
```

常量一改，判据和文案**同时**跟着变，不需要记得同步两处。

`check_redline_sync` E 段 4 条：E-① 边界行为（2.9→急 / 3→可试 / 5.9→可试 / 6→稳）；E-② 文案月数 == 常量；E-③ **源码级 TIER_TEXT 区内不许出现写死的「N 个月」**；E-④ 数据不足时 `unknown` 文案必须为空（不许凭空说"还能撑 X 个月"）。

**变异回灌**：把 urgent 文案改回写死的 `3 个月` ⇒ E-③ 和 E-② 同时判红（14 通过 / 4 失败）；还原后全绿。

## 三、M2 与诊断的「能撑几个月」区分

M2 开店沙盘算的是 **周转金 ÷ 每月固定支出**（店还没开、没有净亏损），诊断算的是 **现金 ÷（经营亏损 + 月供本金）**。同名不同义。

M2 原本的文案其实已带上下文（「钱够不够开」「开完还能撑」），但标题 `cashTitle: '钱够不够开 · 能撑几个月'` 没有。改成 **「钱够不够开 · 周转金能撑几个月」**，三个字点明口径，零逻辑变动。

## 四、分数曲线那项：实测后决定**不改**（这是本轮的判断，不是遗漏）

上一轮我登记的是「健康线踩线只有 55 分 vs 标签说合理，要重排曲线并留口径切换标记」。这次先算清楚，结论是**不该动**：

### 实测：一家各项都踩健康线的店

营收 100 万/月、净利 8 万（8%）、现金 40 万、毛利率 64%（优秀线）、人工 20%、**房租 15%（健康线）**、租期 30 个月、无借贷：

```
总分 88.7 → 等级「健康」  覆盖率 85
profit 76 / loss 100 / cash 100 / grossMargin 100
labor 100 / rent 55 / district 85 / lease 100 / debt 100
```

**房租单项 55 分，但总分 88.7、结论「健康」——决策是对的。**

### 不改的四条理由

1. **没有导致误判**：红线已优先于覆盖率，等级判定正确；分数只用来区分灰度，单项 55 分不影响结论。
2. **note 已经带档位**：R776 时 rent 项 note 已改成「房租占比 15.0%（**健康**）」，老板读的是这个标签，不是裸数字。
3. **R776 刚改过房租曲线**，历史分数已经断过一次；再改会二次断裂，反复横跳的代价比"读感不够好"大得多。
4. 李老师定的原则是「**红线是判决，分数是辅助证明**」——辅助分不需要完美刻度，够排序就行。

### 唯一残留的读感问题

诊断结果页的 11 项指标卡仍显示裸分 `55`（`scoreText: String(Math.round(sc))`），同一页下面 note 写「（健康）」。这个不一致**不影响决策**，属于表达层，记在这里不藏着；将来若要统一，做法是改指标卡展示（加档位标签），**不是重排打分曲线**。
