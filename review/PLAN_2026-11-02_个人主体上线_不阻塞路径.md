## 4 提审前必须过的 5 关（不过就是驳回）

### 4.1 ✅ 剪贴板申报（本轮已修，必须去后台勾）

**问题**：代码有 3 处剪贴板调用（`subpkg/biz/card/import.js` 读、`subpkg/biz/takeaway/index.js` 与 `subpkg/biz/month/result.js` 写），
但隐私指引写的是「❌ 剪贴板」。微信把剪切板列为隐私接口，未申报会**直接驳回**
（原话：「小程序内涉及收集"剪切板"相关接口或组件，请完善《用户隐私保护指引》」），运行时也会 `api scope is not declared`。

**本轮已做**：
- 隐私指引新增第 8 项「剪贴板内容」，写清「仅用户主动点粘贴/复制、不后台读取、不落库」；收集项 7 → 8；
- 守卫 `tools/check_privacy_collection.js` 补了两个盲区：① API 清单缺剪贴板；② **扫描面根本不含 `subpkg/`**（所以一直判绿）；
- 扫描面 52 → 176 个源码文件，真变异验证（删掉第 8 行 ⇒ 红 2 项；还原 ⇒ 复绿，md5 一致）。

**李老师要做的**：mp 后台 → 设置 → 基本设置 → 服务内容声明 → 用户隐私保护指引 → 更新 → 增加信息类型 → **「读取剪贴板」+「写入剪贴板」**，用途照抄文档第 8 项。

### 4.2 ✅ 付费入口在提审版本降级（已落地 2026-11-02）

**问题**：原来点付费会弹「套餐 + 联系客服开通」。对审核员而言，页面出现价格 + 引导联系客服 = **诱导线下支付**风险
（微信运营规范明确禁止引导站外/私下交易）；个人主体还会被判「虚拟商品未接入虚拟支付」。

**已做**（不是建议，是已提交的代码）：
- `utils/featureFlags.js::PAYWALL_ENABLED = false`（单源开关，含「为什么必须整体关」的三条理由）；
- 三道闸门：`openPaywall()`（先于报价弹窗）→ `onConfirm()`（防 deep link 直调建单）→ `pay/orders.js::onRenew` + `showRenew`（续费入口不展示）；
- 关闭态唯一文案 `TERMS.pay.notOpen*`：「功能完善中 · 将在后续版本开放」，**零价格、零支付、零客服**；
- 守卫 `tools/check_paywall_coverage.js` L9-①~⑥（单源 / 闸门位置 / 文案值禁词 / 两道纵深 / 反恒真），真实变异 **3/3 全红**；
- 门禁 **227/227**。

上线后接个人虚拟支付（或升级主体拿商户号）把开关改回 `true` 即恢复售卖，**前端其余一行不改**。

### 4.3 类目只能选「工具」，不要选餐饮

选「餐饮」相关类目会要《食品经营许可证》。本产品是**测算工具**，不是餐饮服务：
首选 **工具 → 效率**（备选 工具 → 计算器）。简介照 `上线材料_提审材料包_v1.md` §5 的草稿。

### 4.4 AI 入口

个人主体不能申请「深度合成」类目。项目 AI 层已冻结，`subpkg/biz/ai/consent` 只是**授权管理页、无 AI 生成调用**
（全仓唯一调用是 `getAiConsent`）。保留可行，但审核备注需写明「当前版本不含 AI 生成内容」。
若后续要开 AI 问答，必须先升个体户/企业并申请该类目 + 算法备案。

### 4.5 prod 环境（发布前硬动作）

现在 `ACTIVE_ENV='dev'`，发布前必须在控制台建 prod 并切过去，否则正式用户数据写进开发库。
清单见 `CHECKLIST_正式版发布前必做.md` §2（A~F）。
