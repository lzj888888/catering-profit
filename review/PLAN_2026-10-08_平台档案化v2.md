## 一、现状（生产代码实测，非推断）

单文件 = `utils/billParse.js`（148 行，4 个导出）。关键常量：

```js
const COL = {
  taobao:  { billDate:'账单日期', net:'结算金额',   orderType:'订单类型', refund:'退单' },

const SHEET  = { taobao:'外卖账单明细', meituan:'订单明细' };
function detectPlatform(header) {           // 🔴 单一特征列、且先判淘宝
  if (cols.indexOf(COL.taobao.net)  >= 0) return 'taobao';    // 「结算金额」
  if (cols.indexOf(COL.meituan.net) >= 0) return 'meituan';   // 「商家应收款」
  return null;
}
function guessHeader(rows) { /* 前 5 行里「非空文本格最多」的那一行 */ }
```

`parseBillMatrix` 内：`sheets[SHEET[platform]]` 按**表名字符串键**取 sheet；
`qty` 美团恒 `1`/行、淘宝按 `订单类型==='退单'` 判 `0`。

## 二、三份真样例的实测结果

| 样例 | 形态 | `detectPlatform` | `parseBillMatrix` | 缺口 |
|---|---|---|---|---|
| 美团**商品**表（10 行） | CSV/GBK/14 列 | `null` | — | 编码 · 列名 · 日期格式 |
| 京东**订单级**（115 行） | xlsx/**两级表头**/82 列 | `null` | 0/0/0 | 无京东判据 |
| 京东 **SKU 级**（0 行） | xlsx/27 列/长表 | **`"taobao"`** 🔴 | 0/0/0 | **跨平台串味** |

🔴 **风险是非对称的**：订单级返回 `null` ⇒ 被「无法识别账单平台」拦下（**安全**）；
SKU 级返回 `"taobao"` ⇒ **能走通并算出错数**（合成变体实测：qty 4 vs 真值 2、bizDate 全空），
本次仅靠「甲级门禁恰好校验 bizDate」+「sheet 名恰好不匹配」两道**偶然护栏**兜住。

## 三、设计原则（沿用既定「引擎零改动」法）

- ❌ 不动计算引擎；✅ 只做**入参变换 + 平台档案**。
- 新增 **`PLATFORM_PROFILE` 档案表**：把散在 `COL`/`SHEET`/`parseBillMatrix` 里的平台知识**收归一处**。
- 🔴 **判据必须能区分同名列** —— 京东与淘宝都有「结算金额」（见 §四 P1）。

```js
const PLATFORM_PROFILE = {
  taobao: {
    sheet: '外卖账单明细',
    require: ['账单日期', '结算金额'],        // 全部命中才算（签名，非单列）
    deny:   ['应结金额', '对账单业务类型'],    // 🔴 命中任一即排除 ⇒ 与京东分家
    net: '结算金额', billDate: '账单日期',
    rowFilter: null,                          // 淘宝退单冲减，整表取
    qtyRule: 'perRow_exceptRefund',
  },
  meituan: {
    sheet: '订单明细',
    require: ['账单日期', '商家应收款'],
    net: '商家应收款', billDate: '账单日期',
    rowFilter: { col: '交易类型', eq: '外卖订单' },
    qtyRule: 'perRow',
  },
  jd_order: {                                 // 新增
    sheet: null,                              // 🔴 京东表名不固定 ⇒ 改为「按签名找 sheet」
    require: ['应结金额', '对账单业务类型'],
    net: '应结金额', billDate: '账期时间',
    rowFilter: { col: '订单类型', eq: '正向订单' },
    headerRule: 'twoLevel',                   // R1 分组 / R2 真列名
    qtyRule: 'perOrderNo',                    // 🔴 按订单号去重，不可按行数计
    indivisible: '保险单',                    // 标记整行取、不可分解
  },
  jd_sku: {                                   // 新增（长表）
    require: ['结算金额', 'sku名称', '费用类型'],
    deny: ['账单日期'],                       // 🔴 SKU 表无「账单日期」列
    net: '结算金额', billDate: '账期时间',
    rowFilter: { col: '费用类型', ne: '保险单' },
    qtyRule: 'perOrderNo',
  },
};
```

## 四、修复清单（P1–P8，逐条可独立验收）

| # | 修复项 | 位置 | 说明 |
|---|---|---|---|
| **P1** | 🔴 `detectPlatform` 改**多列签名 + deny 排除** | `billParse.js:41` | 京东 SKU 表与淘宝同有「结算金额」；靠 `deny:['应结金额']` 分家。**这是最高优先级**（唯一会静默错账的一条） |
| **P2** | 新增 `jd_order` / `jd_sku` 档案 | `PLATFORM_PROFILE` | 含独有列 `应结金额` / `对账单业务类型` / `账期时间` |
| **P3** | **两级表头**支持 | `guessHeader` | 京东 R1 是分组行（"商家基础信息"×5…），R2 才是真列名。判据：若相邻两行**非空格数相同且 R1 值大量重复** ⇒ 取 R2 |
| **P4** | sheet 选取改**按签名找** | `parseBillMatrix:80` | 京东表名不固定（`com.jd.o2o…` / `sku对账单下载`），硬编码 `SHEET[platform]` 失效 |
| **P5** | 京东行过滤 | `parseBillMatrix` | 订单级按「订单类型=正向订单」；SKU 级按「费用类型」 |
| **P6** | 🔴 订单数按**订单号去重** | `parseBillMatrix` | 长表「一行一费项」，按行数计 ⇒ 虚高（实测 4 vs 2） |
| **P7** | 美团**商品表**形态 C 列名扩展 | `importSalesBill/service.js::detectDishShape` | 真表头 `商品名`/`商品销量`/`商品销售额`，判据现只认 `商品名称`\|`菜品名称` + `销量` + `销售额` |
| **P8** | `normalizeDate` 认**紧凑格式** `YYYYMMDD` | `importSalesBill/service.js` | 美团真样例是 `20260910`，现有只认 `YYYY/MM/DD`、`YYYY-MM-DD`、`YYYY.MM.DD` |

⚠️ **P7/P8 与 P1–P6 相互独立**：加 BOM 只救编码，救不了列名（R242b 实测）。
⚠️ **编码那条不在本方案**：美团 CSV 是 GBK，`xlsx@0.18.5` 读无 BOM 的 CSV 走单字节 ⇒ 中文全乱。
属**上传侧**问题（建议：`wx.chooseMessageFile` 取到后若非 xlsx 则在端上转 UTF-8+BOM，或提示用户另存 xlsx），不在 `billParse` 层解决。
