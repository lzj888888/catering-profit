# R359 · 已有店铺页：算失败时不清旧表，等于把旧数字当新结果

> 日期：2026-10-19 · 与 R358 同族（矩阵页）· 判据 B15 · 纯 `.js` 改动

## 一、问题

`pages/sandbox/index.js::onCalcPresetFwd` 的 `catch` 原来只有两句：

```js
this.setData({ loading: false });
this.setData({ calcError: e.msg || '' });
```

而结果区的渲染条件是 `wx:if="{{mode === 'forward' && result && !result.red_alert}}"` ——
**`result` 还在，卡片就照样渲染**。于是：

> 老板改了房租/人数/毛利率 → 点「开始测算」→ 云调用失败
> → 屏幕上仍是**上一次**的保本数、指标条、坪效人效、回本卡，
> 只是上方多了一行 `err-hint`。他会认为「这就是刚算出来的」。

比矩阵页更危险：矩阵页只有一张表，一眼能看出是旧的；这里卡片多、数字多，
且「改了输入 ⇒ 数字变了」符合直觉，**旧数字看起来完全合理**。

## 二、改法

失败分支把成功时写入过的那批状态**整套清回去**（不是只清 `result`）：

```js
this.setData({
  loading: false, calcError: e.msg || '',
  result: null, bands: [], bandsRaw: [], marginBand: '',
  verdict: null, profitLadder: null, promoRes: null, fixedBreak: null,
  crowd: null, eff: null, indicators: [], payback: null, presetAssumptions: [],
});
```

| 为什么逐个清 | 对应渲染条件 |
|---|---|
| `result` | 结果卡片 `result && !result.red_alert` |
| `bands` / `bandsRaw` / `marginBand` | 参考区间卡 `bands.length` |
| `verdict` | 主结论卡 `verdict && verdict.level !== 'na'` |
| `profitLadder` / `crowd` / `eff` / `payback` | 各自 `wx:if` 卡片 |
| `indicators` | 指标区 `indicators.length` |
| `promoRes` / `fixedBreak` / `presetAssumptions` | 活动卡 / 固定费用构成 / 假设卡 |

**漏一个的后果是页面自相矛盾**（保本数没了、指标条还挂着），比整页空白更让人困惑。
`M2_RED_ALERT` 分支**不动**：它本来就把 `result` 换成 `{red_alert:true}`，不存在旧值。

## 三、判据（`tools/check_m2_matrix.js` B15，171 → 173）

两条腿：
1. **找准块**：按花括号配平找「含 `calcError` 的 `catch`」；找不到 ⇒ 直接判红（fail-closed，不许静默跳过）。
2. **逐键覆盖**：成功时写入的 13 个派生键，在失败分支里**每一个**都必须被赋成清空值
   （`null` / `[]` / `''`）。少一个就在消息里点名是哪个键。

### 变异（`review/evidence/r359_mut.py`，3/3）

```
[抓到了] M1 整块退回旧 catch            → 点名 13 个键全缺
[抓到了] M2 只漏清 payback              → 点名 payback
[通过]   M3 语义不变（red_alert 分支改多行）→ 173/173（不误伤）
```

> ⚠️ 变异脚本首版有个自伤 bug：M3 把「替换片段」当成整份源码写回，`index.js` 一度只剩十几行
> （`finally` 已还原）。**变异必须回写完整源码**，改完立刻用 `node -e "require(...)"` 或
> `git diff --stat` 验一下文件完整性。

## 五、没做的（如实）

- 输入校验类失败（未选业态 / 缺必填）**仍保留旧表**：那类提示指向具体缺什么，且此时
  `result` 未必与当前输入相关。要不要一并清，留给下一轮连同「失败态视觉」一起定。
- 没有做「保留旧表 + 标注这是上次结果」的方案：那需要改 wxml（多一块提示区），
  且与矩阵页 R358 的「清空」口径不一致；本轮先统一为**清空**。
