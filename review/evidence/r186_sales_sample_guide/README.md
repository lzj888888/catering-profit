## 三 关键路径摘要（完整版见指南）

- **堂食 · 美团收银**：`pos.meituan.com` → 报表中心 → 菜品报表 → 菜品销售统计 / **套餐销售统计（统计方式选「套餐明细」）** → 右上【导出】
  - ⚠️ **导出只能 PC 端**（POS 端只能打印、App 只能看）
  - ⚠️ 菜品销售统计**不含**打包费/配送费（在「销售品项统计」）
- **外卖 · 美团**：`waimai.meituan.com` → 经营分析/数据中心 → 商品分析 → 导出（🔴 别点「订单明细/账单/结算」）
- **外卖 · 饿了么/淘宝闪购**：商家后台 → 数据中心 → 销售数据/商品销量 → 导出

### 6.1 🔴 三条会直接坑到解析的官方口径

来源：美团餐饮系统帮助文档「如何使用菜品排行报表」`rms.meituan.com/FAQ/FAQDetail/3298`（**官方一手**，强于"路径未亲验"那一级）

| # | 事实 | 后果 |
|---|---|---|
| 1 | **单品金额之和 ≠ 营业额**（官方明写：抹零 / 减免 / 免找零 / 会员优惠、外卖红包 / 满减**都无法分摊到菜品**） | 🔴 **绝不能拿「单品营收之和 == 总营收」当校验** —— 会误判成"导入错了" |
| 2 | **外卖菜名可能显示为 `-`**（门店绑了外卖但**没建「外卖菜品 ↔ 店内菜品」映射**） | 正好是 `shop_dish_mapping` 要补的洞；`-` **不许当菜名入库**，须单列提示 |
| 3 | **套餐默认按"一道菜"统计**（官方例：「拉面套餐（含拉面+卤蛋）」记为**套餐 1 份**，不拆子菜） | 要子菜品必须选 **「套餐明细」** 统计方式 |

💡 附带发现：美团收银绑外卖后，菜品销售统计**同时含店内 + 外卖**（筛选项「业务」）⇒ 一张表可能覆盖两类；
但外卖部分菜名可能 `-`、金额是**原价**（未扣平台优惠）⇒ 外卖仍建议从平台后台导，两边交叉印证。

🔴 **金额单位未定**：API 文档示例 `dishSaleCnt=3` / `dishSaleAmt=308000`，若单位是「分」则 3080 元 ÷ 3 份不合理，
疑为「厘（0.001 元）」⇒ **必须拿真表反推**。这正是"非要真表不可"的理由。
