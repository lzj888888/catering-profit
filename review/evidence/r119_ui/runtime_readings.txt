（**读的是页面实例的 this.data**，不是截图判读）。原始脚本：`_gui/_r119_*` / `mpauto/r119_page_check.js`。

## 1. 载入态（只读，dev 环境真实数据）
```
route      = pages/month/input     month = 2026-09      loading = false
takeoutMode = fast
takeoutSumYuan = "2500.00"         takeoutFilledText = ""（外卖组只有 1 行 ⇒ 按设计不给「已填 1 / 1」）
incomeGroups[takeaway].rows = [{ subItem: "", amountYuan: "2500.00" }]
takeoutDetailRows = 美团外卖 / 淘宝闪购 / 京东外卖 / 其他外卖（4 个平台行，小计均空）
```
⇒ 结论：`load` 路径在**快速模式**下确实算了合计（旧代码只在分项模式算 ⇒ 这里会是 "0.00"）。

## 2. 交互态（模拟「4 个平台行」的用户常态，走页面自己的 setData + syncTakeoutSum）
| 场景 | 各平台金额 | takeoutSumYuan 实得 | takeoutFilledText 实得 |
|---|---|---|---|
| 全填 | 1111 / 2222 / 3333 / 4444 | **11110.00** | **已填 4 / 4 个平台** |
| 只填两个 | 1000.00 / 2345.67 / 空 / 空 | **3345.67** | **已填 2 / 4 个平台** |
| 全填 0（合法边界） | 0 / 0 / 0 / 0 | **0.00** | **已填 0 / 4 个平台** |
| 0 与数混合 | 0 / 1234.56 / 空 / 空 | **1234.56** | **已填 1 / 4 个平台** |

另一条独立读数（保持会话那轮）：四个平台 4380.00 / 2760.00 / 1280.50 / 690.00 ⇒ **9110.50**、**已填 4 / 4 个平台**。

⇒ 「全填 0」不再被吞、不崩、不误填；合计 = 各平台相加，与手算一致。
