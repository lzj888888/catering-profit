# 一、项目背景与设计目标
## 1.1 产品定位
店算小程序是面向餐饮老板的经营核算工具，包含三大模块：
M2 选址沙盘：永久免费，用于开店前选址评估
M1 月度盈利核算：付费模块，用于每月经营利润核算
M3 菜品成本卡：付费模块，用于菜品成本核算、定价与标准化
M1与M3打包付费，不拆卖，无买断，纯时效制。定价：单次月包25.9元/31天，季包69元/90天，年包199元/365天，按月自动订阅19.9元/31天。
## 1.2 M3模块目标
M3菜品成本卡模块的核心目标是：
帮餐饮老板精准核算每道菜的真实成本（含主料、辅料、调料、燃气、人工、包装）
基于成本反算建议售价，辅助定价决策
标准化菜品配方，作为后厨SOP操作手册
支持套餐组合成本核算
食材涨价时自动预警，帮老板及时调价

# 二、套餐功能设计（从83分到100分）
## 2.1 初始方案评估：自由组合套餐（62分）
最初提出的"自由组合套餐"方案，评估为62分。核心问题：
"自由组合"在实际餐饮中用得很少，80%的餐厅是固定套餐（A/B/C套）
计算本身没有壁垒——套餐成本=几个单品成本相加，老板拿计算器都能算
套餐的核心难点不是算，是定价策略（引流品/利润品/折扣率），工具算不出来
对当前阶段（v1.0未上线）是分心，扩大战线
## 2.2 改进方案：勾选成本卡出套餐（83分）
改进为"勾选已有成本卡→改系数→生成套餐卡"，评估提升至83分。核心优势：
数据复用：老板已录了成本卡，勾选就能组合，零额外录入成本
匹配真实场景：固定套餐（A套/B套/商务套）就是几个单品的组合
产出物清晰：生成一张"套餐卡"，和单品卡并列，能看成本、毛利率、能导出打印
开发量小：逻辑就是几张卡的成本汇总+售价反算
扣分项：套餐专属分量（套餐里的菜是6成量）、只算不策（不给定价建议）、赠品可能没成本卡。
## 2.3 增强方案：加2个功能到92分
在83分基础上，加以下2个轻量功能，可达到92分：
### ① 定价助手（反算售价+折扣率）
老板输入目标毛利率（如60%），自动反算建议售价
同时显示：单点总价=X元，套餐价=Y元，相当于Z折，顾客省了W元
加一句判断："折扣率88%，吸引力偏弱，建议75%-82%区间"
开发量：极小，加个输入框和几个公式
### ② 成本快照+涨价提醒
套餐生成时自动保存"定价成本快照"
食材价格变动后，显示"定价时成本X元，当前成本Y元，毛利率从A%降至B%"
毛利率跌破阈值自动标红提醒
开发量：中等，需存快照数据，但逻辑不复杂

## 3.1 价格自动传导机制
原料涨价（生抽8.5→9.2）→ 所有引用生抽的半成品成本自动更新 → 所有引用该半成品/原料的菜品卡成本自动更新 → 所有引用该菜品的套餐卡成本自动更新。
成本快照保留历史数据，不覆盖。毛利率跌破阈值自动标红提醒。
## 3.2 架构设计要点
M1与M3不打通：M1是按月汇总数据，M3是明细单价，数据粒度不同，强行打通维护成本极高。M3独立运行，自己创造数据入口和使用场景。
通用卡不做N种卡：一张通用成本卡+业态模板预设值，覆盖所有场景。模板只是"预设默认值+字段显示优先级"，没有模板也能用。
半成品是核心枢纽：油辣子、高汤、卤水、火锅底料等批量制作的东西，先做半成品卡，自动变成虚拟原料，被单品卡引用。这是覆盖火锅、麻辣烫、小面、卤菜等业态的关键。

# 四、L1 标准原料库——解决辅料混杂的一劳永逸方案
餐饮老板最头疼的问题之一：同一个东西N种叫法。辣椒/辣椒段/海椒/糍粑辣椒，酱油/生抽/一品鲜/味极鲜/复制酱油——如果让老板自己建原料，一定会建出一堆重复数据，成本核算永远对不上。
解决方案："标准原料库 + 别名智能匹配 + 原料/规格分离"三层架构。

## 4.2 标准名+别名智能匹配
系统内置餐饮行业最常用的200-300种标准原料，每个原料有唯一标准名，同时支持多个别名：
标准名"生抽酱油"，别名：一品鲜、味极鲜、酱油、鲜酱油
标准名"干辣椒"，别名：海椒、辣椒、干海椒
标准名"干辣椒段"，别名：辣椒段、干椒段
用户输入原料时，使用"输入框+实时搜索匹配"：
输入"一品鲜"→ 下拉显示"生抽酱油（匹配别名：一品鲜/味极鲜/酱油）"
输入"海椒"→ 显示"干辣椒（匹配别名：海椒/辣椒）"
匹配不到时：提示"未找到标准原料，是否新建？"，新建时必须选择分类
新建的原料进入"店铺私有原料库"，可"提交为公共标准原料"（后台审核后加入公共库）
核心逻辑：用标准名做后台统一，用别名做前台兼容。老板用自己习惯的名字就能匹配到，匹配不到的才新建且有分类约束，不会出现重复数据。这就是一劳永逸的方式。
## 4.3 原料与规格分离
原料是抽象概念，规格是具体采购单位，两者必须分开：

# 五、L2 半成品与调料包（虚拟原料）
火锅的底料、麻辣烫的高汤、小面的油辣子、卤菜的卤水——这些都是先批量做，再被单品引用。如果不做半成品机制，每张小面卡都要重复列"油辣子"的10种原料，数据冗余且维护噩梦。
## 5.1 半成品成本卡→自动生成虚拟原料
流程：
先做一张"半成品成本卡"（和普通菜品卡一样的结构，标记为"半成品"）
例如"油辣子"：菜籽油500g + 干辣椒200g + 花椒20g + 白芝麻30g，批量出品1000g
算出单位成本：0.89元/50g（一碗小面的用量）
半成品卡保存后，自动在原料库里生成一个"虚拟原料"，名字叫"油辣子（自制）"，单位成本自动同步
做"重庆小面"成本卡时，直接在原料里选"油辣子（自制）"，输入用量50g，成本自动算
## 5.2 调料包机制
小面一碗有12-15种调料，每种几分钱，如果逐行列在成本卡里，卡片会有20行，老板看着头疼。调料包机制：
创建一个"调料包"（半成品的简化版，不涉及加工过程，只是组合引用）
例如"小面碗底料"= 盐2g + 味精1g + 鸡精1g + 生抽10g + 花椒面1g + 猪油5g + 姜蒜水15g + 榨菜10g + 芽菜5g + 香油2g
算出"小面碗底料 1份"的成本：1.85元
做小面成本卡时，只需要列3行：面条150g + 小面碗底料1份 + 油辣子50g
后台保留完整明细，点击"展开"可以看到15种调料的具体用量和成本
调料包 vs 半成品的区别：调料包只是"把多行合并成一行显示"，没有加工过程，不生成库存；半成品是真实加工出来的，有出品量、有库存、可以单独售卖。小面碗底料用调料包，油辣子用半成品，各司其职。
## 5.3 循环引用拦截
POC2已验证：半成品引用原料，原料又引用半成品（如"红油"引用"辣椒"，"辣椒"又引用"红油"），系统直接拦截报错（BOM_CYCLE_DETECTED），防止死循环。

## 6.2 四个新机制
### 机制1：加工系数（统一出成率和增重系数）
之前只有"出成率"（缩水），但炸鸡裹粉、包子加水后面团是增重的。统一为"加工系数"：
加工系数<100%：生肉→熟肉缩水（卤菜65%）、毛菜→净菜缩水（85%）
加工系数>100%：肉裹粉后增重（130%）、面粉加水后增重（160%）
公式统一：实际耗用原料 = 配方用量 ÷ 加工系数
卤菜：要1斤熟肉，需要1÷0.65=1.54斤生肉
炸鸡：要130g裹粉鸡排，需要130÷1.3=100g生肉
### 机制2：组件分组（解决皮馅分离、鱼+底料+配菜）
有些菜品不是简单的"原料列表"，而是有固定结构组件。成本卡允许定义"组件分组"，每个组件有自己的小计，最后汇总：
包子 = 面皮组件 + 馅料组件
烤鱼 = 鱼组件 + 底料组件 + 配菜组件 + 烤纸耗材
奶茶 = 茶汤组件 + 奶基底组件 + 糖浆组件 + 小料组件 + 包装组件
组件不是固定的，老板可以自己定义组件名。系统只提供"分组+小计"的能力。这样一张通用卡就能适配所有有结构的菜品。
## 机制3：耗材分类（解决竹签、烤纸、炸油、包装）
在主料/辅料/调料/半成品之外，增加"耗材包装"大类：
包装类：打包盒、袋、杯、盖、吸管、封口膜
耗材类：竹签（烧烤）、烤纸/锡纸（烤鱼）、炸油（炸鸡，按炸制重量分摊）、一次性手套
炸油的特殊处理：炸油是批量的（一锅500元），按炸制重量分摊（炸800斤肉），作为"半成品/虚拟原料"，单位是"每斤炸制品分摊多少油钱"。炸鸡卡引用"炸油"虚拟原料，输入炸制重量，自动算油成本。
### 机制4：可选加价项（解决加小料、加配菜）
奶茶加珍珠+2元、烤鱼加配菜+5元——顾客可选的加价项，不是固定配方。成本卡上加"可选项"区域：
□ 加珍珠：成本0.3元，加价2元，毛利1.7元
□ 加椰果：成本0.4元，加价2元，毛利1.6元
□ 加配菜（土豆+魔芋）：成本2元，加价5元，毛利3元
顾客选了就加进总成本和售价，没选就不加。覆盖奶茶加小料、烤鱼加配菜、火锅加蘸料等场景。

## 7.1 各业态核心痛点摘要
### 炒菜
主料+辅料+调料三段式，单份出品
调料用量小但种类多（10种左右），净料率换算麻烦
真实数据：鱼香肉丝主料占60%，调料10种但只占成本8%
### 火锅
锅底是独立成本单元（底料+红油+调味粉），成本6-100元不等
鸳鸯锅两边配比不同；锅底损耗5-8%
涮品按份/按克，素菜100-120g，荤菜60-100g
真实数据：重庆老火锅锅底5斤油+1斤料，成本超100元；地摊火锅锅底成本6-15元
### 麻辣烫
高汤和底料都是大锅熬的，必须分摊到单碗
菜品按斤/按串自选模式
真实数据：骨汤底25斤水+3000g猪筒骨+1200g老母鸡+1500g鸡架，单碗汤底成本0.8-3元
### 粉面（小面等）
调料种类极多（12-15种），每种几分到几角，油辣子是最贵调料
面条成本低（0.7-0.8元），调料占大头（2.5-3.5元）
臊子/浇头是批量做的半成品
真实数据：一碗素小面总成本3-4元，油辣子单碗0.6-0.8元
### 卤菜/大锅菜
出成率是核心（生10斤熟6.5-8.5斤），生货→熟货缩水
卤汤/卤水循环使用，香料包用4锅才换，必须分摊
批量出品，按份/按斤卖
真实数据：猪头肉生货13元/斤，出成率70%，熟货成本18.5元/斤+卤制成本1元/斤=19.5元/斤
### 烧烤
腌制是批量的（腌肉料+肉），腌料是复合调料
按串卖，每串克重小（15-20g肉/串），穿串有损耗和人工
炭火/燃气成本远高于炒菜；竹签是耗材
撒料/刷油是复合调料；蔬菜缩水率高
真实数据：牛肉串28元/斤穿32串，每串肉0.88元+人工0.2元+炭火调料0.15元=1.2元/串，卖3元
### 炸鸡/炸串
裹粉率是核心（肉100g裹完粉130g），裹粉增加重量但成本低
油炸用油分摊（一锅油500元炸800斤肉，0.4-1.2元/份），油反复用
腌制是批量半成品；酱料/撒粉是复合调料
包装成本高（占总成本10-15%）
真实数据：炸整鸡成本约7.3元（鸡5元+裹粉0.8+油0.4+酱料0.6+包装0.5），卖24.9元
### 早餐/包子
皮馅分离是核心（皮55g+馅40g，或皮50g+馅30g）
面团批量（1斤面+300g水=800g面团，按剂子克重算出个数）
馅料批量；按个/按笼卖；粥/油条配套
报废率高（早上卖不完扔掉）
真实数据：包子皮0.038-0.15元/个+馅0.3-0.5元/个=总成本0.6-0.9元/个，卖1.5-2元
### 奶茶/饮品
茶汤批量泡（1kg茶泡180-250杯），按杯分摊；4小时倒掉
小料批量煮（珍珠2小时倒掉），保质期损耗高
包装成本占比极高（杯+盖+吸管+封口膜，0.3-0.8元/杯，占15-25%）
杯型规格（中杯500ml/大杯700ml）；加小料是加价项
真实数据：一杯500ml珍珠奶茶总成本约2.1元，卖10-15元
### 烤鱼/纸包鱼
鱼出成率差异大（活鱼现杀70-80%，冻开背鱼95%+）
按条/按斤混合卖；底料批量（1kg出8-10条，单条5-8元）
配菜垫在鱼下面（4-6元/份）；烤纸/锡纸是耗材
真实数据：纸包鱼2斤黑鱼15元+调料5-8元+配菜4元+烤纸+燃气=25-30元，卖58-68元
### 小龙虾
双重损耗：运输死亡率（5-10%）+熟虾缩水（出肉率35%）
底料用油量极大（油焖大虾），油是成本大头
按斤/按份卖；季节性价格波动极大（5月8-10元/斤，9月30-40元/斤）
真实数据：3斤活虾→成品需约4.3kg活虾，原料成本约62.5元
## 7.2 v1只做3种业态模板
v1不做11种全做，先做3种核心模板：通用单份模板（炒菜/盖浇饭）、批量出品模板（卤菜/大锅菜/高汤）、粉面模板（小面/螺蛳粉）。其余8种用通用卡+组件分组+加工系数硬扛，等有真实用户数据后再针对性加模板。

# 九、L5 套餐卡
套餐卡的本质是"成本卡的组合视图"，不是新模块。
## 9.1 套餐卡生成流程
勾选2-5张已有成本卡（鱼香肉丝+米饭+例汤）
每个被勾选的菜品可以改"套餐系数"（如套餐里的鱼香肉丝是0.6份量）
允许加"套餐专属项"（送小菜、打包费等，不需要有成本卡，手填名称和成本）
自动汇总：套餐总成本、建议售价（按目标毛利率反算）、对比单点总价的折扣率
保存为"套餐卡"，和普通菜品卡并列，能导出打印
## 9.2 定价助手（v1.1加）
输入目标毛利率，自动反算建议售价
显示单点总价、套餐价、折扣率、顾客省了多少
给出吸引力判断（折扣率88%偏弱，建议75-82%）
## 9.3 成本快照与变动提醒（v1.1加）
套餐生成时保存定价成本快照
食材涨价后自动对比，显示毛利率变化
跌破阈值标红提醒

# 十、客户留存策略
## 10.1 核心判断：M3单独是低频工具
成本卡天生是低频工具——老板录完菜单，可能一个月才改一次。纯M3的留存预估：第1个月80%，第2个月25-35%，第3个月10-20%，半年后5-10%。这个留存率撑不起25.9元/月的订阅。
M1与M3不打通（数据粒度不同，维护成本极高），M3必须独立创造留存机制。
## 10.2 M3独立留存四大支柱
### 支柱1：把成本卡变成"全店的操作手册"（最强支柱）
成本卡不只是算成本，还是后厨标准配方SOP
每张卡显示：每种原料放多少克、切什么形状、烹饪步骤、火候时间、装盘要求
做一个"后厨视图"（大字体、只显示配方和步骤，不显示成本），厨师做菜时拿手机看
新员工培训直接看卡，不用老师傅口传心授
使用频率从"老板每月看一次"变成"厨师每天看多次"
开发量极小：成本卡加几个字段+一个后厨视图
### 支柱2："今日菜价"轻量入口（解决价格数据来源）
外部批发价自动推送：接入当地农批市场价格API，每周一推"本周猪肉+8%、青椒-5%，您菜单里有6道菜用到猪肉，点此一键更新"
老板点"确认更新"，所有相关菜品成本自动重算
采购小票拍照识别：老板采购后拍一张小票，OCR识别食材名和价格，自动更新原料库（10秒）
核心：把"更新价格"从"老板要记得去做的任务"变成"系统推过来、老板点确认的动作"
### 支柱3：上新菜+调价（天然高频场景）
上新菜：老板想加一道菜，第一反应是"成本多少、该卖多少钱"，打开M3算一下
调价：食材涨价了、隔壁店降价了、想做促销了，需要重新算毛利率
首页最显眼位置放"➕ 上新菜算成本"、"💰 调价算新毛利"两个入口
### 支柱4：数据锁定（弱留存但必须有）
老板录了20道菜的标准配方，这是核心资产
即使不常打开，数据存在这里，换工具要重新录，迁移成本高
配合"超出额度只读"，制造续费动力

## 11.5 免费额度：M3设8张
建议M3免费额度设8张（不是3张）：

到期当天：超出额度的卡变为只读，卡片上显示"🔒 续费编辑"，点击跳续费页
到期后每次打开只读卡：顶部一行小字"该卡为只读，续费后可编辑"，不弹窗
提醒但不骚扰，限制但不删除。让老板在正常使用中自然感受到"免费版不够用了"，而不是被弹窗轰炸逼走。

# 十三、风险与注意事项
## 13.1 录入门槛是生死线
所有餐饮成本工具的头号死亡原因，不是算不准，是老板录了3张卡就放弃了。一张鱼香肉丝要填15行，老板在手机上戳10分钟。v1必须把录入时间从10分钟降到2分钟：
内置100道常见菜品模板库，选一个改改采购价和用量就行
复制改用法：做了鱼香肉丝，复制一张改改名和几行就是宫保鸡丁
语音录入（v2）：说一句话生成一张卡
从一道菜开始的onboarding：不要让老板一上来建整个菜单，先算一道最卖座的菜
## 13.2 不要和库存绑死
很多餐饮软件一上来就做"成本卡→自动扣库存→盘点差异"，对小餐饮老板来说太重了。他们根本不做精细库存管理。v1成本卡独立运行，就是算成本、定售价、看毛利。库存打通是v2/v3的事（专业模式高阶功能）。
## 13.3 不要做社区/资讯
餐饮老板社区冷启动极难，没有内容就是空城，反而显得产品没人用。每日资讯内容生产成本高，老板不需要每天看。v1专注工具本身，不要分心做内容。
## 13.4 不要贪全（11种业态v1只做3种）
虽然设计了11种业态模板，但v1全做是个坑。每种模板的预设值、字段显示优先级、示例数据都要仔细调。v1先做3种核心模板（通用单份、批量出品、粉面），其余用通用卡硬扛。等有真实用户了，看用户集中在哪些业态，再针对性加模板。
## 13.5 金额存储规则
一律用分为单位整数存储，展示时÷100保留2位，禁止浮点数存金额。POC2宫保鸡丁口径已锁定：明细行精确值累加、最终总成本round到分=9.75，反算售价(60%毛利)=24.38，毛利率65.18%，毛利18.25。
## 13.6 成本快照不随原料价变动
菜品成本卡生成时保存成本快照，后续原料价格变动不影响历史快照。当前成本实时重算，与快照对比显示变动。这是POC2已验证的机制。

# 十四、总结
M3菜品成本卡模块的设计可以用一句话概括：
后台极度标准化（标准名/规格分离/虚拟原料/循环拦截），前台极度自由化（别名匹配/调料包/模板默认值/系数覆盖）。老板感受到的是"怎么输都行、怎么方便怎么来"，但后台数据是干净的、可统计的、可联动的。
