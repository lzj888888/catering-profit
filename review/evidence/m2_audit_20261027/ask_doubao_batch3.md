# 店算小程序 · 补问 1 条（基线口径）

## 背景
小程序给餐饮老板算保本。历史上有一份审计基线写着：

> 「老板在首屏填了房租之后，手填的水电费/管理费会被"按房租比例派生"的估算顶掉，导致保本被高估：
> 房租 3000 时高估 25%，房租 30000 时高估 108%。」

但现在用真实代码实跑，得到两组不同的数：
- 只有水电费被派生（管理费按老板填的 0 算）：高估 **+20% / +38%**
- 水电费 + 管理费都被派生：高估 **+89% / +116%**

只有第二组接近历史基线里的 +108%。而第二组现在只发生在「场景矩阵」页（那页确实会把管理费一起派生），在「已有店铺」单页已经不成立。

## 问题
① 这应该理解成"历史基线过期了，要改成一个数"，还是"本来就是两个场景，应该分开记两组数"？
② 更重要的：**要不要在界面上告诉老板"这个保本数是按哪种口径算的"**（比如标一句"水电/管理费为行业估算值"）？还是说老板不关心口径、只关心结论，标了反而添乱？

请给：①一个明确选择（改成一个数 / 分成两组数）②对第 ② 问的明确态度（要标 / 不要标）③各一句理由。简短即可。
