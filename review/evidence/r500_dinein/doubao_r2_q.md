# 第 2 轮 · 落地取舍（你第 1 轮已定：堂食填折后成交额、按消费月、按订单去重不按账户去重）

## 我已决定的三条（别推翻，只挑刺）
1. 堂食快速录入 = **当月已消费堂食的折后成交额**（含储值消费、挂账、团购核销；剔除未结账大额、储值充值、外卖、扣手续费后的到账额）
2. 提示要写清「系统内 + 系统外相加填这一个数」，系统外从微信/支付宝账单、现金交班记录取
3. 跨月一律按消费/核销月，次月到账不算收入（与现有团购核销口径一致）

## 问你四个取舍（给判断，别客套）

**Q1 要不要把「快速录入」拆成两个框**（① 收银系统里的堂食已结账折后额 ② 没进系统的现金/个人码收款），小程序内部相加？
- 拆：老板不用心算，但多一个框、多一次填写动作，还得改数据结构
- 不拆：一个框，但老板要自己加两个数
小餐饮老板（一个人管店、没会计）哪个更不容易错？

**Q2 值不值得做「粘贴导入」**：让老板从收银系统 APP 复制「收款构成/支付方式」那段文字，粘进小程序，自动识别现金/微信/支付宝/银行卡各自的金额并填进分项渠道？
代价：要写一个按渠道名匹配金额的解析器（我们有外卖粘贴的经验：踩过「合计行被当明细」导致翻倍的坑）。
你觉得对月流水 5~20 万的单店老板，这个功能真会用吗？还是多数人连复制都嫌麻烦？

**Q3 分项渠道默认列出 7 个渠道**（现金、微信、支付宝、银行卡、储值卡、挂账、团购核销），但多数小店只用到 2~3 个。默认全列是不是填表负担？
- 全列：老板一眼看到"哦还有挂账这种"，但空行多、要滚
- 默认只给常用的 3 个 + 「添加渠道」自选：轻，但老板可能不知道储值消费也算收入
你怎么选？

**Q4 你上轮指出「外卖填优惠前 ⇒ 营业收入分母被做大、成本率偏低」，建议给一行「净营业收入」。**
我现在有两个选择：
- A 现在就动：在月度结果页加一行「净营业收入 = 收入合计 − 商家承担补贴」，成本率按它算
- B 先不动指标口径，只在结果页加一句说明「营业收入含外卖补贴，看成本率请扣掉补贴」
考虑到：所有历史月份的展示都会变、且老板已经习惯了现有成本率数字。你建议哪个？还是都别动、只登记？
