你是资深小程序 UI/交互专家。背景：餐饮老板用的微信小程序「店算」，M3「菜品成本卡编辑页」要快速录 100 多道菜，每道菜要填：菜名、售价、品类、明细行（原料名 / 单价 / 出净率 / 用量）。

老板真机反馈（原话要点）：
1. 输入框框很大、字很小，看着空。
2. 「单价」占了两行：上面一个输入框、下面「元/斤」单位又占一个格子 ⇒ 一行变两行，整页拉很长。
3. 下方「菜品分类」那些标签 chip，格子留得太窄：前面文字够大，后面的数字（如 0）显示不全。
4. 整体松松垮垮，录一个菜要拉很久。
5. 期望：批量录入原料时，在输入框长按就能粘贴进来。

现状（我查证过的）：
- 单价 = 数字输入框 + 右侧 picker（元/斤等），同一行并排（`.price-wrap`），但下方还有「出净率」一行独立的输入框。
- 分类 chip 是横向排列的小标签。
- 明细行是「原料名 / 单价 / 出净率 / 用量」四行一组，多行重复。

请给**可直接落地的改法**（不要泛泛而谈），按优先级回答：
A. 单价与单位：怎么合并成一行且不丢「单位可选」这个能力？给出具体的布局写法（rpx 尺寸、flex 比例、字号）。
B. 明细行四行一组太占地方：能不能压成两行或一行？给出字段分组与具体尺寸（标签宽、输入框宽、字号、行高、间距）。
C. 分类 chip 格子太窄导致数字显示不全：给具体的 padding / min-width / 字号 / 换行策略。
D. 「框大字小」：输入框高度、内边距、字号的具体建议值（要满足微信小程序最小触控 88rpx、字号 ≥28rpx 的红线）。
E. 长按粘贴：微信小程序里 input 与 textarea 长按粘贴的差别，批量录入场景该用哪个控件、注意什么。
F. 有没有你推荐的现成 UI 规范/组件范式（如 Fitts 定律、表单密度）能套用，列 3 条最关键的。
