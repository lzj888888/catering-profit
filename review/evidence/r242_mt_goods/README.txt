【四道独立阻断（机器判据，probe_mt_goods.out.txt）】
  ① 🔴🔴 **编码**：xlsx 0.18.5 读无 BOM 的 CSV 走单字节路径 ⇒ `日期`→`ÈÕÆÚ`、`煮小酥肉`→`ÖóÐ¡ËÖÈâ`
       （GBK 双字节被逐字节当 Latin-1 解）。**中文全毁 ⇒ 后面判据再对也没用。**
  ② 🔴 **形态**：`detectDishShape` = **null**。真列名是 `商品名` / `商品销售额`，
       而判据要求精确等于 `商品名称` / `销售额`（见 service.js:258-261）。
  ③ 🔴 **平台**：`detectPlatform` = **null**。它只认 `结算金额`(淘宝) / `商家应收款`(美团)，
       商品表这两个都没有 ⇒ index.js:72 直接回「无法识别账单平台」。
  ④ 🔴 **日期**：`normalizeDate('20260910')` ⇒ **原样返回**（只认 `YYYY/MM/DD`、`YYYY-MM-DD`、`YYYY.MM.DD`）
       ⇒ 即便前三关放行，也会被甲级门禁 fail-closed 拦。

【顺带查实的三件事（都是实测，不是推断）】
  · 🔴 商品名里有 **源端就已损坏**的字符：`来点辣椒?吗` 的 `?` 是**原文 0x3F 两个字节**，
    不是传输/编码转换造成的。⇒ 菜名映射表若按字面匹配，这条**必然匹配不上**。
  · ✅ **「订单交易额」是整单口径且逐行重复**：0910 四行全是 83.8，Σ整列=335.2（真实只有 83.8）。
    ⇒ 引擎注释里「🔴 严禁用订单交易额（整单口径⇒重复计钱）」**判据正确**，本次真样例正面印证。
  · ✅ **占比列自洽**：每日 `销量占比` / `销售额占比` 和均 = 1.0000 ⇒ 可用作独立交叉校验锚点。
    Σ商品销售额：0910=73.00 · 0912=145.20 · 0913=51.80（与订单交易额 83.8/… 不等 ⇒ 商品口径不含打包费）。
  · 0 元商品：`来点辣椒?吗` 共 4 份（0910×1 + 0912×3）⇒ 正是引擎 `zeroAmountQty`（v1.7 C-5）要单列的那类。
  · 10 行里有 **4 行是套餐**（`【超豪华】耙牛肉套餐（有米饭哦）` / `【超实惠】耙牛筋套餐（含米饭）`）
    ⇒ 直接连到 M3 套餐域与「套餐售价反算」。

【这份数据对「平台档案化」增量规范的输入（待李老师拍板后才动代码）】
  1. 平台识别不能只看账单列名 ⇒ 需要**按表型分档**（账单表 / 商品表是两种表）。
  2. 形态 C 列名判据需从「精确等名」改为**别名表**（商品名≡商品名称、商品销售额≡销售额、门店id≡门店编号）。
  3. 日期归一需增 **紧凑 8 位 `YYYYMMDD`**。
  4. 编码：云端 `xlsx` 读 CSV **必须显式处理 GBK**（或按 BOM 判 + 无 BOM 时嗅探），否则中文全毁。
  5. CSV 单表没有 sheet 名 ⇒ 现有「按 sheet 名白名单放行」这条路对 CSV **天然不适用**。
