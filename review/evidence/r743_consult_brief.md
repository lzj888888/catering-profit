# R743 会诊简报 · M1 真实账目「零数据错误」

## 项目
「店算·盈利分析」微信小程序。M1 = 月实际利润，是**店铺真实账目**（老板据此报税、给会计、做经营决策），零数据错误红线。

## 架构事实（实测，非自述）
- 云函数各自独立打包，跨函数 require 在云端 MODULE_NOT_FOUND ⇒ 摊销引擎 `amountForMonth` 有 4~5 份**逐字同源副本**（getLedger / saveLedger / getAmortSchedule / calcAmortize / calcMonthlyProfit 的 service.js）。
- 金额全程「分」整数（INT）。数据库 `shop_amortize.value_fen`，引擎读 `total_value`，靠 Controller 映射。R739 曾因漏映射导致结果页摊销恒 ¥0.00。
- 摊销直线法：月额 = round(原值/月数)，末月尾差倒挤；提前终止的未摊余额作残值，不摊进末月。
- 归档 = 只读冻结：归档月利润读**落库快照**，未归档月**现算**（台账逐笔）。R740 拆掉了「2026-11 前不计摊销」的时间闸门。
- 全仓 6 处 `shop_amortize` 读取都带 `{shop_id}`；saveAsset 新增/编辑/删除都过归档锁（区间锁，判据 = 已归档月里存在 month >= 起摊月）。
- 幂等：saveLedger/saveAsset 用 client_request_id（**可为空**，空则不约束）。
- 守卫：322 个 CI 套件，本地 `node verify_all.js`，含变异回灌（改坏源码看断言是否转红）。
