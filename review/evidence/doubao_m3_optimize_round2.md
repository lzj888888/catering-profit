## 三步执行

### 1. O2：折“分析明细”，不折“风险状态”

**判读：如果折叠后只剩一个“更多分析”入口，就和红线冲突，不能这么上。**

可落地折中：

- 覆盖率、自助餐人均食材成本的**关键值和齐全状态常驻折叠区外**；
- 趋势图、归因、明细拆解等重内容放进“更多分析”；
- 折叠入口最多 1 次点击展开，点风险状态也能直接定位到对应明细。

常驻风险条直接写成：

- 数据齐全：  
  `● 数据齐全｜覆盖率100%｜自助餐人均食材成本 ¥18.60`
- 数据部分缺失但仍算出了值：  
  `● 数据不完整｜覆盖率82%，缺3天｜自助餐人均食材成本 ¥18.60，仅供参考`
- 关键字段缺失、无法计算：  
  `● 缺数据｜覆盖率82%，缺3天｜自助餐人均食材成本 ¥--，缺采购数据`

折叠入口标题不要只写“更多分析”，要带风险：

- 无风险：`数据完整性与更多分析`
- 有风险：`数据完整性与更多分析（2项风险）`，并配红点/数字角标

交互规则：

- 有红线风险时，折叠区默认展开；
- 数据齐全时可默认收起，但风险条必须常驻；
- 覆盖率不是 100%、自助餐成本关键字段缺失时，不能出现绿色“数据齐全”；
- 状态未知用“缺数据/未生成”，不要用灰色让老板误以为正常。

实现上就是：

```text
<RiskStrip ... />              // 常驻，不随折叠隐藏
<Collapse defaultOpen={hasRisk}>
  趋势、归因、明细、建议等
</Collapse>
```

这样老板 0 次点击就能看到“全不全”，1 次点击能看明细，不违反红线。

### 2. O4：按“功能付费”写，不按“数据时长”写

**判读：“免费试1次/升级解锁全月数据”这句作废，会误导。**

你们的真实边界是：

- 成本卡：永久免费
- 原料库：永久免费
- 外卖分析/经营复盘/对账：付费

入口标签建议直接写：

| 功能 | 标签 |
|---|---|
| 成本卡 | `永久免费` |
| 原料库 | `永久免费` |
| 外卖分析 | `付费` |
| 经营复盘 | `付费` |
| 对账 | `付费` |

付费功能锁页/弹窗文案：

```text
[外卖分析] 为付费功能

成本卡、原料库永久免费，你已录入的数据可继续免费查看和编辑。

开通「[套餐名]」后，可使用：
· 外卖分析
· 经营复盘
· 对账
```

主按钮：

```text
开通「[套餐名]」 ¥XX/月
```

次按钮：

```text
查看权益与续费规则
```

如果付费报告要调用免费功能里的数据，写清楚：

```text
将使用你已录入的成本卡、原料库数据生成报告；报告功能需开通。
```

禁止使用：

- `免费试1次`，除非真的配置了一次试用权益；
- `升级解锁全月数据`，因为你们卖的是功能，不是把老板自己的数据锁一个月；
- `升级后数据不丢失` 这类暗示不升级可能丢数据的说法；
- 只有锁图标、不标“付费”的模糊入口。

如果线上已经存在“免费试1次/解锁全月数据”这类与实际权益不符的文案，应按支付合规风险提级，不用等 O4 正常排期。

### 3. 优先级：真 P0 插队，但不能把“碎问题”都叫 P0

**判读：10-14 真机如果发现真 P0，不机械坚持 O1–O3 先做，先修 P0。**

P0 只认这类：

- 崩溃、白屏、卡死、核心流程走不通；
- 金额、成本、覆盖率算错；
- 数据齐全状态错误或红线项被隐藏；
- 付费权益、扣费、续费文案与实际不符；
- 数据丢失、保存失败、隐私或资金风险。

处理顺序：

1. 真机问题先定级，不当场扩需求；
2. 真 P0 立即插队，修复后必须真机回归；
3. 如果 P0 和 O1–O3 在同一模块，合并到对应 O 项一起改，避免重复动代码；
4. 如果 P0 与 O1–O3 无关，单独出补丁；
5. P0 清完后，仍按 `O1–O3 → O4–O5` 继续；
6. 样式错位、间距、非阻断性文案问题归 P1/P2，不允许插队。

如果 O1–O3 本身也是已定 P0，就放进同一个 P0 池，按“资金/数据错误 > 红线不可见 > 阻断使用”排序，而不是按编号机械执行。

## 最终判读

1. **O2 不矛盾，但只能折明细，不能折风险状态。** 覆盖率和自助餐人均食材成本的关键值、齐全度必须常驻，明细 1 次点击展开。  
2. **O4 原付费文案作废。** 写“成本卡、原料库永久免费；外卖分析、经营复盘、对账为付费功能”，不得写“免费试1次/解锁全月数据”。  
3. **真 P0 优先插队。** P0 修复并回归后，再继续 O1–O3、O4–O5；P1/P2 碎问题不打乱原顺序。
