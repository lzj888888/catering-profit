1. 账单模块 LLM 触发判据 & 降级路径

同意：规整导出 CSV/Excel 账单，绝对不该上 LLM，结构化列解析确定性脚本准确率更高、无幻觉、无 token 成本。

LLM 触发判据（全部满足才启用 LLM）

输入不是标准导出文件：手机截图、拍照、复制粘贴乱文本、PDF 扫描件；

平台改版，列名新增 / 改名，固定映射表匹配命中率低于阈值（建议阈值：<85%）；

无法自动识别正负冲销、合并行、跨行备注，确定性解析抛出无法修复异常；

只要能拿到标准导出文件，永远走确定性解析，不调用 LLM。

降级路径

LLM 抽取结构化数字 → 送入原有确定性校验（勾稽校验：优惠前总额−各类补贴−佣金 = 商家到手）；校验不通过，直接拒绝入库，返回原始文本片段，提示老板手动修正，LLM 输出绝不直接落库。

2. AI 三层降级架构 L0/L1/L2

L0：确定性规则（基础层，默认优先执行）

职责：账单解析、金额计算、勾稽校验、成本卡计算、保本测算、数据存储、报表导出。

触发：所有标准文件录入、常规计算。失败：报错，阻断保存，提示字段异常。

L1：模板 + 槽位填充（首选自然语言层，优先于 LLM）

职责：固定场景解读、常规异常归因，预写多套话术模板，变量从 L0 计算结果填充。

覆盖比例目标：≥90% 用户日常月度场景。

触发条件：可匹配预设指标组合（如：外卖到手率＜58%、人工占比＞30%）。

上升到 L2 判据：指标组合不在模板库内，且历史同门店无同类案例，模板匹配命中率 = 0，才调用 L2；其余全部停在 L1。

L2：LLM（长尾兜底层，极少触发）

职责：只处理 L1 模板覆盖不到的长尾组合归因、自然语言解读；不做任何数值运算，所有数字全部由 L0 传入作为固定上下文。

触发：L1 模板匹配失败。失败降级：直接回退 L1 兜底通用话术，不重试 LLM，不阻塞页面。

3. 归因原始数据锚点（工程化形态）

数据结构：归因结论绑定一组{指标名，当期值，上期值，明细ID集合}。

界面形态：

归因文字每一处数字，做成可点击热区；

点击热区直接弹窗，展示该指标对应的原始账单明细行（例如：“商家补贴上涨”→弹窗列出淘宝闪购 3 类补贴合计，展示三列原始金额）；

弹窗内保留原始来源标记：来自哪份账单文件、平台名称、订单行数；

归因文案禁止出现任何不在锚点内的衍生数字；LLM 生成文案只能引用传入锚点字段，禁止编造新指标。

一句话约束：文案里出现的每一个数字，都必须可以一键跳转到原始明细核对。

4. 预设经营建议库，可执行建法

条目来源

真实餐饮小店案例（1-3 家夫妻店），从你实操咨询案例沉淀；

绑定单一指标 / 指标组合，禁止单条建议同时依赖 3 个以上指标；

每条建议绑定：触发条件、参考区间、可落地动作、反面提醒。

触发规则

布尔规则匹配，不使用权重模糊匹配。示例：

触发：外卖商家补贴占营收＞30%；建议：检查平台一口价活动，核算活动单单品毛利，评估是否缩减超抢手活动；反面提醒：不要直接全部关停活动，会影响订单量。

防废话约束（硬性）

禁止 “控制成本、提升营收” 这类无动作条目；

每条建议必须附带可执行小动作；

每条附带风险提醒（避免老板一刀切操作）；

建议库定期灰度：上线后跟踪用户点击查看率，如果一条建议 30 天点击率＜5%，直接删除。

核心结论：LLM 从 “能力” 降级为故障兜底工具；产品主体全部 L0+L1，L2 只处理 10% 以内长尾场景，且全程不碰数字。
