总输入 token=1000×4×1500=6,000,000；总输出 token=1000×4×600=2,400,000

DeepSeek V4-Flash 空闲：6M×1.5 +2.4M×4.5=9+10.8=19.8 元 / 月；对比 19.9 基线：费用接近持平

你的假设校验：1000 活户每月 4 次 AI 解读，L2 仅长尾触发，你的假设偏激进（实际调用量会远低于此）；L1 覆盖≥90% 场景，真实 LLM 调用量仅为假设值的 10% 左右。

2、成本临界点（沿用单次输入 1500、输出 600token，mini 模型）

单次总 token 成本 = (1500×0.4 +600×4)/1e6 = 0.0036 元 / 次

月成本破 100 元：100 ÷0.0036 ≈ 27778 次调用 / 月；按每人每月 4 次 → 活户≈6944 人

月成本破 1000 元：1000 ÷0.0036≈277778 次调用 / 月；按每人每月 4 次 →活户≈69444 人

4、成本控制手段（按省幅排序，可省一个数量级标★）

★结果缓存去重：相同门店 + 相同月份数据摘要，缓存 LLM 返回文本，不重复调用；可减少 70~95% 调用量（省一个数量级）

★数据未变更不生成：M1 数据无修改，直接复用上次 L2 解读结果；长尾场景收益极高（省一个数量级）

L1 模板优先，严格 L2 触发门槛：90% 场景不走 LLM，基础削减 90% 调用量

Prompt 压缩：精简 JSON 摘要，剔除不相关字段，降低输入 token

失败不重试：LLM 调用失败直接回退 L1 兜底话术，禁止重试

异步排队：云函数异步任务，避开高峰，可选用低价时段（DeepSeek）

5、隐性成本逐条评估

云函数 GBs 资源量：LLM 调用增加执行时长，消耗 GBs；1000 活户规模下影响很小，上万用户才会显著超标

外网流量：云开发 AI 内网调用几乎无外网流量；自建 API 会产生外网出流量，基线 2GB 额度足够初期

冷启动：云函数冷启动会拉长 LLM 响应，用户感知明显，影响体验，不直接增加账单，但损害转化

超时重试：如代码写自动重试，会双倍消耗 token，直接拉高账单，属于高危坑

数据库读次数：缓存方案会增加 DB 读；合理设计缓存 key，增量可控，初期影响小

流式实现复杂度：流式会增加云函数驻留时长，抬高 GBs 消耗；L2 长尾建议关闭流式，一次性返回
