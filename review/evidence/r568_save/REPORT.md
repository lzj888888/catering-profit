## 2 抓到的真 bug（已修）

**现象**：新建 → 选「热炒荤菜」→ 只得到**调料一行**。猪肉/青椒没出现。
**后果**：只填售价就能保存成功 ⇒ 一张 38 元的菜成本只有 ¥0.51、毛利率 **98.66%**
（截图 `e2_list_crop.png` 就是这个数）。品类预填承诺的「示例主料」不在，等于**成本系统性低估**。

**根因**（`subpkg/biz/card/edit.js::onPickCategory`）：

```js
const wasEmpty = this.data.lines.length === 0;   // ← 恒假
```

新建页 `load()` 初始化就塞了一行空原料行（`emptyLine()`），所以 `length === 0` **永远不成立**，
下面 ③「空卡补示例主料」整段成了**死代码**。上一轮（R566）只验证了「导入页 `from_draft` 预填」这一路，
那条路草稿自带明细行，恰好绕过了这个判据，所以没暴露。

**修法**：判据改成「**没有任何已填内容**」，并在空卡时先把出厂空行丢掉再预填：

```js
const isBlankLine = (l) => !material_id && !material_name && !qty;
const wasEmpty = this.data.lines.length === 0 || this.data.lines.every(isBlankLine);
let lines = wasEmpty ? [] : this.data.lines.slice();
```

**复验**（`report_fix.json`，11/11）：
- 选品类后 3 行齐全，无残留空行；
- 未补价直接保存 ⇒ 被「单价」toast **拦住**（fail-closed，不再能落一张只有调料的卡）；
- 补价后保存 ⇒ 列表成本 **¥3.63**、毛利率 **90.45%**（38 元售价），不再是 98.66% 的假数。

## 3 过程中排除的两个「假 bug」

1. **保存无反应**：一度以为保存坏了。装钩子抓真实返回后证明云端 `SUCCESS` 且落库，
   失败的那两次是**模拟器 appservice 被重启**（页面栈归零、白屏）导致，不是产品问题。
   根因见 §4-1。
2. **预填没生效**：`waitRoute` 一匹配就回读，此时 `load()` 还没跑完 ⇒ 读到空表单。
   加「等 `loading===false` 且表单项有内容」的窗口后全部正常。**这是取证方法的坑，不是产品坑。**

## 4 工具态坑位（本轮新踩，已写进记忆）

1. 🔴🔴 **往项目目录里写脚本/截图会触发 IDE 自动重编译** ⇒ 模拟器 appservice 重启、
   页面栈归零、自动化 evaluate 连环超时。**本轮「通道反复挂」的真正主因就是这个**。
   ⇒ 取证脚本一律放**项目外**（如 `~/.workbuddy/binaries/node/mpauto/r568/`），产出也写项目外，
   最后一次性搬进 `review/evidence/`。
2. 🔴 **`mp.screenshot` 在模拟器卡死时会毒化整条连接**（R567 已记）；本轮改用 `win_gui shot`
   截 IDE 窗口 → PIL 裁剪放大模拟器区域，稳定可用（`e1/e2` 两张即此法）。
3. 🔴 **360 屏保会整屏抢占并让截图超时**：点右上「关闭」→ 再 `ShowWindow(hwnd,9)` 还原 IDE。
4. 🔴 **`waitRoute` ≠ 页面加载完成**：路由一变就读 data，读到的是 load 前的空表单。
5. 🔴 **裸调 `wx.cloud.callFunction` 必须自带 `shop_id`**（删除卡曾回 `INVALID_PARAM`），
   带上 `shop_id` 后 `deleted:true` 正常。
6. 🔴 **列表行字段名是 `name / total_cost（元字符串）/ price_fen / margin`**，
   不是云端原始名（`dish_name / total_cost_fen / gross_margin_pct`）—— 映射层做过转换，读错会判成"空"。
