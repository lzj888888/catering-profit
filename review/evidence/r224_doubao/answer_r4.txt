Q8

原提到的 “火锅水电燃气 8~12%”，分母是门店淡季 / 低营收工况下的实际月度营收（接近保本附近的真实营收，不是理论保本计算值，本质和保本营收是同一量级）。

来源等级：我的估算，针对炭火、重锅老火锅，生意差的时候营收萎缩，但空调、汤锅、冰柜基础能耗降不下来，固定刚性水电占比被动冲高；不是满产正常经营的占比。

两份 BP 案例恰好印证：同样一笔刚性水电 3600 元，营收掉到保本 43269 时占比 8.32%；正常做到 11 万营收占比仅 3.27%。

补充：小鸡快跑卤鸡半自助 BP 正常经营 14.5 万营收，水电 7500，占比仅 5.17%【文档自述】，落在本仓内部锁定 4‑6% 区间。8‑12% 是低流水风险情景区间，不是常态经营区间。

Q9

建议：店算所有 “XX 占营收比” 派生指标，分母统一使用【当前测算情景下的目标月营收】（引擎输出的本次情景的营业额）。

理由：

指标口径唯一，不会同一套成本跑出多套占比，便于横向对比不同铺面、不同业态；

小白用户关心的是：我做到这个生意规模的时候，各项成本占我营收多少，而不是拿保本营收做一个极端参考数字；

完全复用引擎本次输出的营收结果，不需要额外引入第二个分母变量，上层计算简单，减少口径 bug。

注意：水电燃气本身在系统内部是成本金额（上层按 cost_meta 算出的固定金额，进入 fixed_items）；“水电燃气占营收比” 仅仅是后置展示派生指标，不参与引擎任何计算，只用来给人看，不参与数学运算。

Q10

会出现，而且是客观现实：刚性水电金额不变，营收越低，展示出来的占比越高；保本附近 8%、正常经营 4%，两个数字全部数学正确，不是算错。

UI 表达方案（不修改引擎，只处理展示层）

派生指标行补充小字注释：

💡提示：水电燃气为刚性开销，营业额越低，该占比数值会被动抬高。

在【本次测算假设】折叠面板增加说明：

部分成本为刚性固定开销，不受营业额变化影响；当门店营收下滑，该类成本的营收占比会自动上升。

做情景对比的时候，直接同时展示多组情景下的「营业额‑水电金额‑水电占比」，让用户直观看到：同样水电金额，不同营业额，占比发生变化。

严禁：把展示用的派生占比反向回写进引擎入参，派生占比只做阅读，不参与计算。

最容易做错的一条 + 做错后果

第 6 条（cost_meta 成本形态，上层预处理后喂引擎）是风险最高最容易做错的一条。

做错场景：

1）面积、人工人数变更事件发生时，上层没有完整重算全部 cost_meta 成本项，复用旧的 fixed_items 入参传给引擎；

2）敏感性扫描的时候上层自己套数学公式算结果，没有完整走「上层形态计算→生成入参→调用引擎」完整链路。

后果：页面 UI 展示的水电、杂费金额，和真正喂给引擎计算的金额不一致；出现 “界面看是 A，引擎拿 B 做运算” 的隐形口径裂缝，所有保本、利润结果全部失真；该类 bug 属于隐性逻辑 bug，单条数字看不出错误，只有做多情景对比才会暴露，回归测试很难抓。

简短收口总结

水电燃气占营收比，统一以当前情景目标月营收作为分母，它仅为展示派生指标，不参与引擎运算；刚性成本随营收下降占比抬升是客观现象，靠 UI 注释做风险提示。

9 条定案除第 2、8 条少量补充文案约束之外全部可采纳落地；cost_meta 上层预处理链路为最高风险点，测试必须覆盖：修改面积、修改人数、敏感性扫描全链路，校验喂入引擎的 fixed_items 明细和 UI 展示明细完全对齐。

所有特殊情景（保底扣点、刚性成本占比漂移、半自助折算冻结）全部上层 UI / 状态标记解决，坚守引擎源码零改动的仓内硬约束。
