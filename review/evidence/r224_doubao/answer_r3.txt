问题 A：业态参数包是否引入「成本形态」概念

结论：必须引入成本形态标记，不在引擎新增字段，仅在上层渠道层做元数据标记。

字段定义（全部属于业态参数包元数据，不入引擎入参）

每条成本项增加结构体标记cost_meta：

json

{

 "cost_key":"水电燃气",

 "cost_form":"fixed|area_linear|headcount_linear|revenue_rate|step",

 "params":{...}

}

fixed固定金额：params:{base: 数字}

area_linear面积线性：params:{base: 基础金额，per_sqm: 每平米增量}，例火锅面水电：base=2600，per_sqm=20

headcount_linear人头线性：params:{per_person: 单人金额}，例员工餐 = 人数 ×600、人工 = 人数 ×4500

revenue_rate营收百分比：params:{rate: 小数}，例品牌管理费 3%

step阶梯：params:{steps:[{"trigger": 阈值，"value": 金额},…]}，例卤鸡火锅水电随租金档位阶梯

不引入的替代方案弊端（排除）

如果不做形态标记，只能预算死固定金额写入 fixed_items：

1）用户修改面积、人数后，水电、员工餐、杂费不会联动刷新；必须人工改一堆数字，复现不了两份 BP 里的动态模型；

2）做情景扫描、敏感性测试只能手动多套业态包，维护爆炸。

约束：所有形态运算全部上层渠道层完成，输出最终金额喂给引擎的 fixed_items /var_items；引擎只认金额、费率，完全零改动。

问题 C（硬问题组，引擎零改动前提下）

我方方案复述：业态包标记成本形态；上层渠道层根据面积、人头预计算成金额，喂入引擎 fixed_items；引擎只接收金额。

C1：上层做面积 / 人头→金额预处理，敏感性分析会不会出现口径裂缝？如何防范

风险真实存在：

敏感性分析如果是上层循环遍历面积 / 人数，每迭代一次，上层要重新跑一遍形态计算，生成一套全新 fixed_items 入参，再调用引擎。

风险裂缝场景：上层只改界面显示，忘记同步重算整套 fixed_items 入参直接复用旧入参给引擎；页面展示一套，引擎计算另一套，结果不一致。

✅三道防御手段（全部上层实现，不改引擎）

单源输入原则：面积、人工人数为全局唯一真值；任何触发面积、人工人数变更事件，必须完整重算全部cost_meta形态项，生成全新 fixed_items 数组再调用引擎；禁止复用旧的 fixed_items。

输出回显校验：引擎返回计算结果后，上层把喂给引擎的 fixed_items 全部回显在【测算明细‑原始入参】折叠面板，用户 / 测试可直接核对：引擎收到的水电、杂费金额是否和当前面积 / 人数计算结果一致。

敏感性扫描不做引擎外数学模拟；每一组扫描变量，都完整执行一次「上层形态计算→生成入参→调用引擎」全链路，不在上层直接硬套公式算保本，所有扫描点全部走真实引擎调用，杜绝上层、引擎两套公式。

禁止：上层自己写一套保本公式做敏感性，只把初始值丢给引擎；所有数据结果来源必须是引擎输出。

C2：转让费、备用金计入总投资做回本分母；转让费可回收、备用金是流动资金，是否高估回本？如何处理

业务事实：

1）转让费：部分铺面到期转出可以回收【公开调研‑红餐网】；会计上属于长期待摊按租期摊销；但个体老板现金视角，开店一次性真金白银付出去。

2）备用金：是开业爬坡期流动资金，不是沉没投入，门店存续可以保留，关门可以收回【公开调研‑慧运营】。

两份 BP 文档是民间投资测算，直接全额计入总投资分母，会系统性高估回本周期。

✅折中方案（兼顾 BP 习惯，又不失真，上层 UI 处理，引擎不动）

M3 建店投入页面，把总投入拆成两组：

A 组「刚性沉没投入」：装修、设备、证照、开业营销；按期摊销。

B 组「可回收类资金」：转让费、押金、开业备用金。

UI 提供复选开关：

☑️把转让费、备用金计入总投入（参考民间开店 BP 习惯）

□ 不计入（仅统计装修设备等沉没资产，适合评估真实资产回收）

文案强制提示：

⚠️转让费后期转让有可能收回；备用金属于运营流动资金，闭店可回收；勾选计入会拉长测算回本周期，仅用于模拟全部现金的回笼。

预览卡片（M2）：业态包预填充的参考总投入，默认沿用 BP 习惯勾选计入全部，同时把上述提示带上；正式 M3 允许用户取消勾选，重新计算回本。

不修改引擎；上层根据开关，选择是否把 B 组金额加入总投入再做除法。

C3：卤鸡火锅文档两处写 “店铺管理费 3%”，是否同一笔钱重复计算？

判定：是同一笔费用，不是两笔；文档两处只是表述位置不同，不能配置两处参数。

原文解析：

1）一处：参数定义：店铺管理费按营业额 3%（属于 var_items 营收扣点费率）；

2）二处：结果说明行 “含店铺管理费用 3% 计入保本线”，只是验算说明文本，不是第二条成本科目。

验算：5.66万 ÷ (53%‑3%) =11.32万，只用扣减一次 3%，如果再额外叠加一笔固定金额管理费，保本营业额会进一步抬高，与文档 11.3 万结果对不上。

✅参数包处理规则：

业态参数包只配置一处：营收扣点费率 = 3%（归入 var_items）；结果输出文案写明 “本测算已包含店铺管理费（营收 3%）”，不新增第二条管理费科目。

禁止：同时配置一笔 var_items 费率 3%，再加一笔 fixed_items 固定金额管理费，造成重复扣减。

本轮纪要摘要（便于内部存档）

1.A：业态参数包需要增加cost_meta成本形态元标记（fixed /area_linear/headcount_linear /revenue_rate/step）；形态运算全部上层执行，输出金额喂引擎 fixed_items/var_items，引擎源码零改动。

2.B：输出三层模式字段可见性完整表格；半自助特殊原始参数仅 L3 可见；L1/L2 展示等效折算后值，用户手动改写后触发标记与告警；建店投入全部归属 M3，M2 仅做只读预览参考。

3.C1：上层预处理存在口径分裂风险；三条防御：变更面积 / 人员必须重算整套 fixed_items；引擎入参明细回显；敏感性扫描每个点完整走 “上层计算‑调用引擎”，禁止上层私自模拟保本。

4.C2：转让费、备用金存在可回收属性，全额计入分母会高估回本；上层 UI 做复选开关，两套口径可选，M2 预览默认沿用 BP 习惯全部计入，附带风险提示，M3 可自由切换。

5.C3：卤鸡火锅两处 “管理费 3%” 为同一笔，一处是参数，一处是结果说明；参数包仅保留 var_items 营收扣点一份，禁止重复配置科目。
