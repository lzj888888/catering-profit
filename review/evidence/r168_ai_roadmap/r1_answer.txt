Q1｜全景清单（价值从高到低）
1. 外卖活动补贴测算
【场景一句话】给定目标毛利，试算活动满减 / 补贴上限，避免活动亏钱。
【用户看到】输入活动方案，返回预估单品毛利、保本补贴阈值、亏损风险标记。
【落地难度】需要更多数据（历史销量、成本卡）
2. 菜品结构优化：菜单取舍（推 / 保留 / 下架）
【场景一句话】结合毛利、销量、连带，筛选菜品，识别 “高销低毛利引流菜、低销高毛利潜力菜”。
【用户看到】菜单优先级清单，附带每道菜对门店整体利润贡献，标注不能直接下架的引流款。
【落地难度】需要更多数据（菜品连带销售数据）
3. 进价波动自动重算菜品净料成本
【场景一句话】原料进价变动，批量更新 BOM 菜品 / 套餐成本。
【用户看到】原料调价后，自动刷新所有关联菜品毛利清单。
【落地难度】现在就能做（规则 BOM 引擎）
4. 损耗 & 出成率异常预警
【场景一句话】对比理论耗用 vs 实际盘点倒轧，识别食材异常损耗。
【用户看到】损耗超标菜品列表、预估浪费金额。
【落地难度】需要更多数据（库存盘点数据）
5. 备货量参考建议
【场景一句话】基于历史销量，给出食材备货区间。
【用户看到】分食材备货上下限，标注节假日 / 外卖大促浮动系数。
【落地难度】需要更多数据，远期
6. 异常利润归因（多因素耦合，定位当月亏损主因候选）
【场景一句话】当月利润大幅下滑，给出一组候选根因清单，按贡献权重排序。
【用户看到】候选原因列表，附带每项因素对利润影响金额（由引擎复核）。
【落地难度】远期
7. 反推套餐定价（锁定目标毛利）
【场景一句话】给定套餐结构，反推保本售价、推荐售价区间。
【用户看到】套餐定价区间，不同售价下毛利测算。
【落地难度】现在就能做（规则穷举）
8. 同类门店对标参考
【场景一句话】同品类门店毛利区间参考。
【用户看到】对标分位值，提示门店当前位置。
【落地难度】远期，需要跨门店脱敏数据集
Q2｜6 维打分，三档划分
6 维：高熵 / 组合爆炸 / 难核验 / 高代价 / 外部常识 / 规则难穷举
(a) 适合 LLM：仅异常利润多因素归因
理由：多变量耦合、组合爆炸；规则很难穷举全部因素组合；LLM 用来生成候选根因，数字交给 L0 引擎复核。
(b) 规则 / 统计足够，上 LLM 属于浪费：
进价波动重算成本、损耗预警、套餐定价反推、外卖补贴保本测算、备货参考、菜品结构评分排序。
理由：指标固定、可核验、业务逻辑可固化，穷举 + 评分函数完全覆盖；LLM 不提升结果准确度，徒增合规与成本风险。
(c) 伪需求：同类门店对标参考
理由：门店面积、商圈、人工房租差异巨大；简单对标极易误导老板；外部基准数据口径不一致，核验成本极高，决策代价高。
Q3｜分工边界
1. 架构判断：该分工成立，是安全可行的架构。LLM 只产出候选方案、文字解释、因素候选；全部数值交由确定性引擎重算，未复核数字直接丢弃，守住数字可信的命门。
2. 尖锐问题回答：单纯 “组合生成 + 毛利目标对齐”，穷举 + 评分函数足够完成。
LLM 唯一不可替代价值：自然语言组织多候选方案、解释复杂因果关系，把一堆结构化指标翻译成经营逻辑；不是计算，是推理归纳、组织候选根因，适合多因素耦合的归因场景。
如果没有多因素耦合归因场景，LLM 没有不可替代价值。
Q4｜差异化变现（美团无法复刻，2-3 个形态）
1. 【菜单利润诊断】用户一键生成菜单优化清单：识别引流菜、高毛利潜力菜、亏损菜；同时绑定菜品真实净料成本 + 套餐连带贡献。美团仅有订单销售数据，不知道食材进价、净料率、后厨损耗，算不出真实菜品利润，只能看销售额。
2. 【外卖活动保本沙盘】输入活动满减、补贴方案，自动联动菜品 BOM 成本，算出保本补贴上限、预估门店净利变化。美团只能看订单流水，没有后厨真实成本，只能看营收，无法判断活动是否真赚钱。
Q5｜最狠反方（3 条致命风险 + 对策）
1. 风险：基础数据质量差（盘点不准、原料录入随意），AI 归因输出完全错误，老板信任崩塌。
怎么办：AI 输出前置 R168 甲乙丙三级自检；丙级校验不通过，直接隐藏 AI 候选方案，不展示。
2. 风险：AI 给出方案，老板不执行；功能好看但不带来续费，投入产出差。
怎么办：AI 方案必须附带小范围试点建议，不输出大刀阔斧一次性改动；指标埋点追踪用户是否落地操作，不看 AI 点击，看后续菜单 / 活动修改行为。
3. 风险：外卖平台补贴、活动规则频繁变更，AI 历史知识库快速失效，归因 / 测算口径出错。
怎么办：规则引擎维护活动口径，LLM 不存储业务规则；规则变更只改 L0，LLM 仅做候选归纳，不承载业务口径。

1、三期路线
一期（无 LLM，当前启动）
做什么：完善 BOM 净料成本、外卖账单结构化导入；落地 R168 甲乙丙自检、raw+facts 双件套、buildInterpretation 单一出口；锁死成本 / 补贴 / 损耗口径。
老板看到：一键导入外卖账单、菜品 / 套餐成本核算、L1 模板告警解读、数据校验报错提示。
靠什么算：L0 确定性规则引擎。
进入下一期触发：账单导入稳定，菜品成本卡录入量达标，R168 丙级自检通过率稳定≥95%。
二期（L0 能力扩充，仍无 LLM）
做什么：菜单利润评分、外卖活动保本沙盘、库存倒轧损耗预警；完善 facts 附带 sourceId 溯源，补齐埋点采集业务问题类型。
老板看到：菜品利润排名、活动保本测算、食材损耗告警。
靠什么算：穷举 + 评分函数。
进入下一期触发：高频多因素利润波动问题，规则模板无法覆盖占比≥12%；用户高频提交多因素归因诉求。
三期（引入 LLM 归因）
做什么：LLM 仅生成利润波动候选根因清单、文字解释；所有数值交由 L0 引擎复核。L1 兜底，R168 前置校验。
老板看到：利润大幅波动时，候选原因列表（数字可溯源）；AI 标识。
靠什么算：LLM 生成候选，L0 引擎复核所有数值。
进入触发：二期指标全部达标，个体户深度合成类目资质办妥。
2、上 LLM 的 3 条可测量触发条件
1. 用户月度利润波动类查询中，规则模板无法覆盖的场景占比≥12%
2. R168 丙级自检通过率稳定≥95% 持续 2 个月（底层数据可信）
3. 付费用户调研，多因素利润归因诉求占比≥20%
#3、LLM 防错代码约束
1. LLM 禁止输出任何最终数值，仅输出候选原因、文字描述、指标名称
2. LLM 输出提到的全部指标，送入 L0 引擎重算；未通过复核的条目直接丢弃不渲染
3. 所有展示项必须绑定 sourceId；R168 丙级自检不通过，直接隐藏 LLM 全部输出
4. L1 模板永久兜底，LLM 模块可一键全局开关关停
#4、放弃信号（2 条）
1. 持续 3 个月：R168 丙级自检通过率＜85%，用户录入数据质量无法改善
2. 二期上线后，用户极少使用菜单 / 活动沙盘功能，对应模块使用率＜5%
