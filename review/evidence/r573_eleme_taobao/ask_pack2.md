## Q4 · 「饿了么」和「淘宝闪购」在系统里应该是几个平台键？

**已证事实**（本轮机器验证，非推断）：
同一份年月账单 xlsx，156 行 × 88 列，其中「配送方式」列 **156/156 行全是「蜂鸟配送」**
（蜂鸟是饿了么自营配送）。营业额（商品+打包）6585.08、商家承担补贴 −2069.70、
技术服务费 −158.71、配送服务费 −577.02、结算金额 3779.65，逐行零误差。
⇒ **淘宝闪购的账单就是饿了么那套账单，是同一个东西的两个名字。**

**系统现状**：代码里平台枚举同时存在 `taobao` 和 `eleme` 两个键（还有 meituan / jd_order / jd_sku / pos / other），
UI 上也给老板两个可选项。**目前 `eleme` 从未被任何真实数据验证过**，当时定的是"没样例就不列名"。

**风险**：老板一家店在饿了么 App 里导出的账单，可能今天选「饿了么」明天选「淘宝闪购」，
同一笔营收被拆成两个渠道，单店月度外卖毛利会被拆散看不全。

请回答：
1. 应该**物理删掉** `eleme` 键？还是**保留两个显示名、底层合并成一个键**？还是**保留两个键、只在汇总时合并**？
   请选一种并说为什么（考虑：老板的认知习惯、未来饿了么更名、已落库的历史数据）。
2. 如果有的老数据已经落在 `eleme` 键下（目前没有，但设计上要留），迁移该怎么做才不丢账？
3. UI 上给老板看的名字该写什么？（候选："饿了么"、"淘宝闪购"、"饿了么（淘宝闪购）"）老板更认哪个？

## Q5 · 账单里有一列是另外两列的重复汇总，怎么防老板抄重？

**已证事实**：同一份账单里同时存在三列：

| 列名 | 当月合计 |
|---|---|
| 平台服务费 | −735.73 |
| 技术服务费 | −158.71 |
| 配送服务费 | −577.02 |

**逐行比对 156 行，「平台服务费 = 技术服务费 + 配送服务费」不相等行数 = 0**，合计侧也零误差。
⇒ 平台服务费是**冗余汇总列**，不是第三笔费用。
若老板把三列都抄进费用，当月净额 3779.65 会算成 3043.92，**少 735.73 元 = 营收的 11.17%**
（一个本来微赚的月会被判成明显亏损）。

生产解析代码没踩这个坑（它直接取净额列），但**老板手工录入、或照着账单 Excel 抄**时会踩。

请回答：
1. 防呆该做在哪一层？候选：**A 录入时软提示**（填了平台服务费且同时填了子项 ⇒ 提醒"这笔已经包含在里面了"）；
   **B 硬拦截不许保存**；**C 不拦，只在导出/结果页加一句提示**；**D 干脆不提供"平台服务费"这个录入框**。请选并说为什么。
2. 如果选 A，提示语怎么写老板才会信、不会觉得是软件多管闲事？（他可能会说"我账单上明明写着这么多钱"）
3. 这类"账单里有冗余汇总列"的情况，美团/京东是不是也有？如果没有实证请你说"不知道"，别推。
