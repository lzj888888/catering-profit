### 1.2 核心升级点（来自小面表）

⇒ 本次「升级」= 把静态表变成 **动态场景矩阵生成器**：选业态+城市 → 设维度档位（房租×人工×毛利率×目标利润）→ 批量调生产引擎 → 出对比综合表 → 可导出为经营佐证。

## 三 核心新能力 G1：场景矩阵生成器（小面表升级）

### 3.1 形态（推荐）
两种视图都给，不二选一：
- **明细表**：每行 = 一个参数组合，N 行；列含维度列+结果列（对齐小面表，但加毛利率维度）。
- **透视表**：行=月租金档、列=目标利润档，单元格=主输出（日营业额），毛利率/人工做顶部切换器（对齐小面表原貌）。

### 3.2 扫维度与默认档位（升级核心 = 毛利率可变）
| 维度 | 默认档位（推荐） | 来源 |
|---|---|---|
| 月租金 | 3000/4000/5000/6000/7000/8000/9000/10000（8 档） | 照搬小面表 |
| 人工(人) | 2/3（2 档） | 照搬小面表 |
| **菜品毛利率** | **45/55/60/65（4 档）** | 🔴 **升级点**：小面表缺此项 |
| 目标月利润 | 保本(0)/赚1万/赚1.5万（3 档） | 照搬小面表 |
| 面积 | **不作为扫维度**（R223 已证面积对保本零影响） | 仅作全局输入+坪效口径 |

⇒ 默认 8×2×4×3 = **192 行**（比小面表 144 多 48，正是"毛利率能否变"带来的增量信息）。用户可增删任意维度的档位（自由输入档位值）。

### 3.3 输出列（每行结果）
| 列 | 来源 | 说明 |
|---|---|---|
| 维度列 | 各扫维度的取值 | 租金/人工/毛利率/目标 |
| 保本月营收 | `calcSandbox.break_even_monthly_fen` | 核心 |
| 保本日营收 | `break_even_daily_fen` | 小面表"日保本营业额"对应 |
| 目标月营收 | `target_monthly_fen` | = (固定+目标利润)/边际 |
| 房租占比 | `indicators.rent.pct` | "房租吃掉营业额几成"（豆包改名） |
| 回本月数 | `payback_months` | 建店总投÷目标利润 |
| 日客流 | `monthly_traffic÷openDays`（reverse 派生） | 反推口径 |
| 翻台/周转 | 可选列（默认关） | 单品业态才建议开 |

### 3.4 计算下沉（铁律不变）
- 前端**不编公式**：每个组合经 `assembleItems(preset, input+override, coef)` 装配成 clean 入参（纯函数、零 wx），再批量送云。
- 新增云函数 **`calcMatrix`**：入参 = 一组 clean 参数（N 个），**循环调用既有 `calcSandbox`/`calcSandboxReverse`**，返回 N 行结果。**引擎 `service.js` 一行不改**（与 R219/R223/R234 同一套路：产品语义大改、引擎零改）。
- 红警处理：`calcSandbox` 已对 `composite_var_rate≥100` 返回 null → 矩阵里对应格显示「—/不可行」，不编造。

### 3.5 为什么能"升级"小面表（而非另起炉灶）
- 小面表的 `边际贡献率=1−45%−5%−5%−2%` 与本仓 `cost_meta` 的 `revenue_rate` 形态**同构**；本仓已用参数包表达（utility5%/manage5%/other2% + grossMargin）。
- 所以"改业态/改毛利率"= 换 `preset` + 改 `gross_margin_pct` 入参，**矩阵自动跟着变**，彻底消灭小面表"参数写死、0 公式"两个硬伤。

## 四 双人群差异化（G3）

### 4.1 Case A（forward · 已有店）显示规则
- 显示 **坪效 = 月营收÷面积**、**人效 = 月营收÷人工成本**、**翻台**（用 `turn_rate`，按业态切桌周转/座位周转话术，R237 已就绪）。
- 摊销年限可改：**已具备**（buildRows.years）。
- 不考库存差/固定资产：本仓模型本就不含库存，建店投入走摊销不进月固定（R219 口径），天然契合。

### 4.2 Case B（reverse · 找店小白）显示规则
- **坪效/人效/翻台默认隐藏**（李老师：「小白不懂，没装修也不知道桌数」）。
- 反推只产出：最高可扛房租 + 日保本额 + 日客流 + 客流难度标签（轻松/有点难/很难，R234 已落地）。
- 这些指标在 B 下标记为「选填/不展示」，A 下才展开 → 同一套 L1/L2/L3 输入，按 `mode` 决定展开深度（R234 已共用装配，仅需补展示开关）。

### 4.3 字段差异一览
| 字段 | Case A（已有店） | Case B（找店小白） |
|---|---|---|
| 真实房租 | 必填（算保本） | 必填（算可扛上限） |
| 坪效/人效/翻台 | 显示 | 隐藏 |
| 摊销年限 | 可改 | 可改（影响回本，不影响保本） |
| 毛利率 | 老板已知，直接填 | 默认参数包带出，可改 |
| 矩阵生成器 | 可用（"用我的真实数据填一行，再批量看邻域"） | 可用（"不同房租/人工下我该要多少营收"） |

## 五 核心新能力 G2：多候选铺面横向对比

### 5.1 形态（推荐）
- 在 B（寻找铺面）基础上，新增 **「方案对比」入口**：把当前正在看的几个铺子（A/B/C…）存为 `site_select` 方案（已有 `savePlan` 机制），同屏出**对比卡矩阵**。
- 对比卡每行一个候选铺：房租 / 保本日营收 / 目标月营收 / 房租占比判定（划算/压力偏大/不推荐）/ 日客流 / 客流难度。
- 顶部一句结论：「按你这目标，**C 铺租金最划算，B 铺客流压力最大**」。

### 5.2 复用
- 直接复用 `savePlan`(sandbox_type='site_select') + `getPlan` 取回 → 不新增集合。
- 对比卡数据全部来自 `calcSandbox`/`calcSandboxReverse` 出参 → 引擎零改。
