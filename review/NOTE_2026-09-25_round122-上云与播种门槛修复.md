## 三、缺陷：`feature_permissions` 播种被「`subscription_plan` 整表为空」总闸卡住

```js
// 旧实现 cloudfunctions/initDb/index.js
const cnt = await db.collection('subscription_plan').count();
if (cnt.total === 0) {
  await db.collection('subscription_plan').add({ data: SEED_PLANS });
  await db.collection('feature_permissions').add({ data: SEED_FEATURES });   // ← 被总闸卡住
}
```

**后果链（本轮真实阻断）**：

1. dev 早播过种 ⇒ `subscription_plan` 非空 ⇒ **重跑 initDb 也不插 `plan_free` 行**；
2. A1 新引入的 `plan_free`（`limits: { shop:1, cost_card:5, hard_shop:200, hard_card:2000 }`）
   **只在本地代码里**，云端 `feature_permissions` 无此行；
3. `checkQuota/index.js` 读不到 `limits` ⇒ `fail(SYSTEM_ERROR,'配额配置缺失')`；
4. **`pages/card/index.js:63` 在成本卡列表页 onLoad 就调 `checkQuota`** ⇒ 用户一进 M3 就报错。

**修复（两层）**：

| 层 | 内容 |
|---|---|
| 判定粒度「整表 → 整行」 | 新增 `seedFeaturePermissions()`：按 `(plan_id, feature_key)` 取已存在集合，**缺失者补插、已存在者跳过**；行数达分页上限 1000 时 **fail-closed 拒绝盲目补插** |
| 轻量补种通道 | 入参 `{ only: 'seed_missing' }` ⇒ **只补种、不建表不建索引、立即返回**。理由：默认路径要跑 25 次 `createCollection` + 40 次 `createIndex`，线上默认 timeout 可能只有 3s（R86 未闭环）⇒ 补种请求常**走不到播种就被超时掐死**，会误判成「播种逻辑坏了」 |

幂等语义**未削弱**：R20 `tools/check_idempotency.js:63` 登记的「灌种子前先查集合是否已初始化 ⇒
重复执行不产生第二条种子」**仍然成立**（判定只是从整表细化到整行）。全量门禁 **103/103 RC=0**（`review/evidence/gate_r122.txt`）。
