# R368 · 活动试验台：所有活动能不能归成几个量？（与豆包对抗评审的合并结论）

> 2026-10-20 · 李老师提问：啤酒免费 / 前3天8折后4天6折 / 锅底除外 / 抽奖 …
> 「无论哪种活动最终都影响盈亏平衡指标，但我们好像没法深度验证它对毛利率的影响。」

## 一、结论先行

1. **他的判断成立**：任何活动最终只落到「保本营业额 / 目标利润」两个数上。
2. **不需要为每种活动建模**——它们只改三个量，而且都在「占营业额 %」这一层，可以**线性叠加**。
3. **但有一条口径红线**：折扣**不能**塞进「菜品毛利率」。（见第三节，这是本轮最硬的结论）
4. **技术上零引擎改动**：保本 = F/m 是纯公式，F 与 m 都在页面已有的 `result` 里；前端闭式即可算。
   ⚠️ 反过来「塞进 var_items 走引擎」这条路人走不通：`validate.js:128` 对 key 有白名单
   （`takeawayComm/grouponComm/cardFee/other`），塞新键直接被拒；塞进 `other` 又会与预设的
   「其他损耗 2%」撞键、并污染「其他费率」指标。

## 二、三个量（修正版）

```
m      = (菜品毛利率 − 渠道费率)/100        ← 已有
m'     = m − (让利率 p + 赠品率 g)/100      ← 活动后
保本'  = F / m'
目标'  = (F + 目标利润) / m'
利润(在营收 R') = R' × m' − F
```

| 活动形态 | 折算成什么 | 算法 |
|---|---|---|
| 打折 / 满减 / 第二份半价 | 让利率 p | `p = (1 − 折扣率) × 参与流水占比 w` |
| 前 3 天 8 折、后 4 天 6 折 | 让利率 p（期间加权） | `d_eff = (3×0.8 + 4×0.6)/7`，再乘 w |
| 锅底除外 / 酒水除外 | 降低 w | w = **参与打折的流水占比**（不是人数占比） |
| 啤酒免费 / 赠酒 | 赠品率 g（**变动**成本） | `g = 赠品成本 ÷ 营业额` |
| 抽奖 / 转盘 | 赠品率 g（期望值） | `期望成本 = 中奖率 × 奖品价值 × 参与人次` |
| 引流（发券、达人探店） | 只改 R' | `R' = R × (1 + 客流增幅)` ← **假设，不是事实** |

## 三、口径红线：「让利」不能记进「毛利率」

引擎里 `m = (G − 渠道费率)/100`，而 **G 同时是行业对标的那个毛利率**
（`indicatorRef.js:311` 直接拿 `grossMarginPct` 去比行业带）。

如果把折扣并进 G：
- 老板会看到「你的毛利率 57%（行业 55~65，正常）」，但这 57 是打折打出来的，
  他的**菜单定价与采购成本一点没变**；
- 反过来，真实毛利率 65%、打 8 折后 57%，系统会告诉他「毛利率偏低，优化菜品结构」——
  **建议完全指错方向**。

【豆包】同判：「营收端折扣让利错归入成本端的菜品毛利率，与行业通用的成本端毛利率口径不符，
应单独核算让利率，不得调整原菜品毛利率基准。」

⇒ **让利率与毛利率必须分账**。这也是为什么活动必须**旁路算**、不能并进主结果。

## 四、边界：三个已知的"算不准"

1. **w 是静态假设，而活动会改变客群结构**。两个方向的偏差都存在，不能拍一个符号：
   - 【豆包】「价格敏感型引流客群更倾向消费折扣菜品，实际 w 通常高于静态取值」
     ⇒ 低估让利、**高估活动盈利**；
   - 【我】火锅「锅底除外」时，点锅底的客人菜品消费更高 ⇒ 除外条款保护的是高客单，
     用固定 w 会**高估**让利。
   ⇒ 净方向取决于哪个机制主导。**只能给区间，不能给单点**（建议：w 上浮/下浮 10% 各算一次）。
2. **抽奖按期望值算，方差极大**。期望月成本可能很低，但某天爆一个大奖就是真金白银的现金流出。
   ⇒ 输出里必须注明"按期望值，实际波动大"。
3. **分时段折扣 + 引流衰减**：`d_eff` 按天加权是对的，但把"前 3 天爆满、后 4 天空转"
   平均成一个数，会掩盖**现金流的时间分布**。保本月度数没错，但老板会误以为整月均匀。

## 五、哪类活动**不该**用这个模型算（算了会误导）

| 活动 | 为什么不能算 | 该怎么说 |
|---|---|---|
| 储值卡 / 预售券 | 收钱 ≠ 收入（是负债），跨期履约 | 「这是现金流工具，不是当月损益，别混着看」 |
| 网红探店 / 品牌曝光 | 无法归因到单月流水 | 「这笔记在品牌，不记在保本」 |
| 团购核销（平台券） | 平台抽成 + 核销周期 + 退款，是现金流口径 | 「按到账算，不按核销算」 |

【豆包】同判：品牌宣传/公益公关类、跨期履约的储值与长周期会员权益类，单期口径会错配，不适用。

## 六、如果要做，我建议的形态

**不做活动模板库**（火锅花样永远追不上），做**三个输入 + 三层输出**：

输入（老板填得出来的）：
1. 折扣率（或直接填"让利率"），配一个「参与打折的流水占比」处理除外；
2. 赠品/奖品月成本；
3. 预计多来多少客人（选填，给三档：不动 / +10% / +30%）。

输出（三层，逐层回答一个问句）：
1. **这次活动让出去多少**：让利额、保本上移百分之几；
2. **要卖多少才不亏**：打平需多卖多少（现有能力）；
3. **要月赚 X 还要做到多少**：接 R367 的目标反推口径。

架构上继续**旁路**：主结果永远是"不做活动"，试验台只给对照 —— 这样指标口径不被污染。
