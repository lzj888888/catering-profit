# 菜品模板数据来源与口径（**内部文档 · 不对外展示**）

> 建立：2026-11-10（R674）
> 用途：万一有人质疑「你这克数哪来的」，我们拿得出方法与依据。
> 🔴 **不在小程序界面展示** —— 对外只保留一句统一说明（见下），指向具体来源容易扯皮。

---

## 一、对外口径（界面上老板看到的唯一一句）

> 数据为行业常见配比，由公开资料整理，仅供参考；各店用料差异大，请按自家实际调整

代码位置：`miniprogram/i18n/terms.js` → `TERMS.card.templateHint`
守卫：`tools/check_dish_templates.js` 的 T-⑱

**为什么不写具体来源：**

| 说法 | 问题 |
|---|---|
| 「来自网上资料」 | 太随意，老板会想"网上抄的能信吗" |
| 「来自《XX 菜谱》」 | 指向具体权利人，容易扯皮；记错更糟 |
| **「行业常见配比，由公开资料整理」** | 说的是**事实**（业内通行），**不指向任何人** |

最后半句「请按自家实际调整」既是免责，也提醒老板这是**起点不是答案**。

## 二、内部的来源方法论（这才是可追溯的部分）

每道菜的数据不是凭空写的，按以下三类之一取得：

| 类型 | 内容 | 依据强度 |
|---|---|---|
| **A 行业标准** | 出净率 / 净料率（猪里脊 92%、叶菜 70–80%、整鱼 60–75%）、损耗率区间 | 强 —— 餐饮成本核算教材通行概念 |
| **B 公开菜谱配比** | 配料组成与用量区间（宫保鸡丁 = 鸡丁 + 花生 + 干辣椒；糖醋比 2:1） | 中 —— 多个公开菜谱交叉 |
| **C 商用配方参考** | 门店出品量级（非家庭份）、精确到克的表示方式 | 中 —— 量级可信，具体数值各店不同 |

**明确没做的事：**

| 事项 | 为什么不做 |
|---|---|
| 爬取美团/大众点评销量排行 | 数据不公开，爬虫有法律风险；**编一个"热门榜"比没有更危险**（看起来更权威） |
| 抄录某个付费配方课程 | 侵权；且视频里的克数要一集集记，记错比不做更糟 |
| 给固定单值（如"花椒 2 斤"） | 花椒品种麻度差 2.5 倍，必须带品种 + 区间 |

**已做的交叉验证：**

- 火锅底料：4 个公开来源交叉，辣椒占油 8–10%、花椒 1.25–3.2%
  - 差异原因是**花椒品种**（红花椒/青花椒/茂汶椒麻度差很大）⇒ 模板写「红花椒 30–60g」，区间 + 品种一起给
  - 另一个 AI 给的数系统性偏高 20–50%（辣椒 12%、花椒 4%）⇒ 取搜索来源作下界、它作上界
- 行业出净率：3 个来源交叉，取**区间下沿**（保守）而非中值
  - 为什么取保守：低估出净率 ⇒ 成本算得高 ⇒ 老板不会误以为赚钱

## 三、数据口径（每条模板都遵守）

| 口径 | 规定 |
|---|---|
| **用量单位** | 门店**单份出品量**（不是家庭份） |
| **价格** | 🔴 **模板绝不预填任何金额**（R138 红线①）—— 价格随行就市，只能老板自己填 |
| **不写「适量」** | 必须给克数或区间；"适量"等于没填 |
| **老汤类** | 按**每份分摊量**填，不是"每锅新汤量"（否则卤味成本虚高几倍） |
| **补盐量** | 不给固定值 —— 取决于老汤循环次数与蒸发量，模板写「按老汤咸度补」 |
| **锅底类** | 三层：炒料 + 每锅油 + **打锅辅料**（葱姜/醪糟/冰糖/鸡精/盐），第三层最易漏 |
| **饮品** | 按**中杯**（约 400–500ml）；大杯比中杯贵 30–50% |
| **面条** | 干湿换算：干面 150g ≈ 湿面 180g，各店采购规格不同 |

## 四、已知的局限（诚实登记）

1. **具体克数各店差异极大** —— 同一个"宫保鸡丁"，不同店鸡丁可能 150g 也可能 220g。所以：
   - 我们给的是**能算出一个合理成本量级**的起点
   - 不是"标准答案"，老板必须按自家改
2. **品类覆盖仍是抽样** —— 41 道覆盖常见菜，但不能覆盖所有店的菜单。不在库里的菜，老板自己填
3. **没有真实销量数据** —— 我们不知道哪个菜"卖得最好"，所以**不做什么"招牌菜排行"**
4. **成本量级已抽查**（R673）：宫保鸡丁约 11 元/份、鱼香肉丝约 9 元/份，售价 28–35 时毛利率 60–70%，落在餐饮合理区间
