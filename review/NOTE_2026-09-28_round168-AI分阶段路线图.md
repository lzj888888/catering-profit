# R168 · AI 分阶段最终方案（李老师定调版）

> **前提（2026-09-28 李老师钉死，不再讨论）**
> 1. 主体：**个体工商户**（一开始就按这个设计）。
> 2. 节奏：**前期不上 AI，后期肯定上**；「不带 AI 的小程序不算成熟小程序」。
> 3. 方向：**用全量数据做业务模型改革** —— AI 自动匹配成本、反推引流套餐定价、做市场判断。
> 4. 护城河：**美团只有销售端数据**（订单、销售额、评价、流量），**没有商家真实成本**（进价、净料、损耗、房租、人工）；**我们同时握有成本端 + 销售端**。
> 5. 命门：**数字必须准**。餐饮老板对算错账零容忍。
>
> **来源**：与豆包桌面版 3 轮沟通（2026-09-28，原会话「店算小程序AI价值判断」）+ 我方独立核验。
> 原始问答见 `review/evidence/r168_ai_roadmap/`。

> **只预留数据，不预留代码。**
> **一期用规则引擎把数字做准；二期把规则能力扩到"菜单评分 + 活动沙盘 + 套餐定价反推"；三期才让 LLM 上场，且只做"多因素归因候选"，所有数字回填确定性引擎复算。**

## 二、AI 以后做什么（能力全景 · 按价值排序 · 含豆包判据打分）

**同一个问题问了豆包两遍**：第一版给"能做什么"，第二版用 6 维判据（高熵 / 组合爆炸 / 难核验 / 高代价 / 需外部常识 / 规则难穷举）逐条打分。结论高度收敛。

| # | 能力 | 豆包判据档位 | 落点期 | 靠什么算 | 老板看到什么 |
|---|---|---|---|---|---|
| 1 | **进价波动自动重算**菜品/套餐成本 | **(b) 规则就够** | **一期** | L0 规则（BOM 引擎） | 原料一调价，所有关联菜品毛利自动刷新 |
| 2 | **反推套餐定价**（锁定目标毛利） | **(b) 规则就够** | **一期/二期** | 穷举 + 评分 | 保本售价 + 推荐售价区间 + 不同售价下毛利 |
| 3 | **外卖账单结构化导入** | （我方补充，最高优先级） | **一期** | 确定性解析 | 一键导入，不再手抄 |
| 4 | L1 模板告警解读 | (b) 规则就够 | **一期** | 模板 + 槽位 | 数据异常提示、口径报错 |
| 5 | 外卖活动补贴保本测算 | (b) 规则就够 | **二期** | 穷举 + 评分 | 保本补贴阈值、亏损风险标记 |
| 6 | 菜品结构优化（菜单取舍 推/留/砍） | (b) 规则就够 | **二期** | 穷举 + 评分 | 菜单优先级清单 + 利润贡献 + 不能下架的引流款 |
| 7 | 损耗 & 出成率异常预警 | (b) 规则就够 | **二期** | 规则（配方损耗 vs 盘点损耗双口径） | 损耗超标菜品列表 + 预估浪费金额 |
| 8 | 备货量参考建议 | 远期 | 三期后 | 统计 | 分食材备货上下限（含节假日/大促系数） |
| 9 | **异常利润多因素归因** | **(a) 唯一适合 LLM** | **三期（LLM）** | **LLM 出候选 + L0 复核全部数字** | 候选根因清单（按贡献权重排序，数字可溯源） |
| — | 同类门店对标参考 | **(c) 伪需求** | **不做** | — | — |

### 2.1 判据打分结果（豆包原结论）

- **(a) 适合 LLM —— 只有一项：异常利润多因素归因。**
  理由：多变量耦合、组合爆炸、规则很难穷举全部因素组合。**LLM 只用来生成候选根因，数字交给 L0 引擎复核。**
- **(b) 规则/统计足够，上 LLM 属于浪费**：进价波动重算成本、损耗预警、套餐定价反推、外卖补贴保本测算、备货参考、菜品结构评分排序。
  理由：指标固定、可核验、业务逻辑可固化，**穷举 + 评分函数完全覆盖；LLM 不提升准确度，只徒增合规与成本风险。**
- **(c) 伪需求：同类门店对标参考。**
  理由：门店面积、商圈、人工房租差异巨大，简单对标**极易误导老板**；外部基准口径不一致、核验成本极高、决策代价高。

### 2.2 最尖的一刀

> **豆包 Q3 原话**：「单纯『组合生成 + 毛利目标对齐』，穷举 + 评分函数足够完成。**LLM 唯一不可替代价值 = 自然语言组织多候选方案、解释复杂因果关系，把结构化指标翻译成经营逻辑。如果没有多因素耦合归因场景，LLM 没有不可替代价值。**」

**这就是我们上 LLM 的唯一理由，也是三期唯一的入场券。**

**红线**：带「经营行动建议」的输出必须走规则模板；**LLM 只允许做「现象归纳 + 候选原因」**。

## 三、现在可以做什么（一期清单，零 LLM）

一期**一行 AI 代码都不写**，但下面 5 件既是产品价值、也是将来 AI 的地基：

1. **外卖账单确定性导入**（优先级最高）。目前靠手工录入，是最大摩擦点；与 AI 无关，但决定用户留存。
2. **BOM 净料成本落地**（含"进价波动自动重算"）—— 这是后面一切测算的输入。**豆包判定：现在就能做。**
3. **反推套餐定价（保本价 + 推荐区间）** —— 豆包判定"现在就能做（规则穷举）"，可在一期末或二期初落地。
4. **raw + facts 双件套**：raw 存原始账单 + 采集元信息；facts 存已绑定 sourceId 的指标。**唯一真正"过期不候"的就是 raw。**
5. **口径锁死 + 数据可信度三级门禁**（见 §四）。

### 数据可信度三级门禁（甲 / 乙 / 丙）

本轮与豆包共创，正名并落地：

| 级别 | 校验什么 | 不通过的后果 |
|---|---|---|
| **甲级**（前置门禁） | 通道连通（DB / 云函数无超时、返回非空）、Schema 校验（字段名/类型/数值范围双向匹配）、关键指标非空 | **直接阻断**，不进入核算 |
| **乙级**（业务质量） | 数值范围、勾稽关系（收入 − 成本 − 费用 = 利润 等） | 出告警、标记可疑 |
| **丙级**（算量可信） | 三方对账、口径一致性、明细可回溯 | **隐藏依赖它的解读 / AI 输出** |

> **丙级门禁是第三期上 LLM 的硬前置**：通过率需稳定 ≥95%。

## 四、前期不上 AI 怎么做（数据地基）

### 4.1 数据层：现在必须开始规范采集

**成本卡（必须字段）**
`原料 ID`、`原料采购单价`、`单位`、`毛料用量`、`净料产出`、`净料率`、`损耗率`、`辅料分摊`、`BOM 版本号`、`更新时间`、`sourceId`

**外卖账单（必须字段）**
`订单日期`、`渠道`、`优惠前营收`、`平台补贴`、`商家自补贴`、`打包费`、`平台佣金`、`配送费`、`实付金额`、`关联菜品明细 ID`、`记录版本号`、`sourceId`

**⚠️ 过期不候（以后补不回来，必须现在留）**
- 每日**订单菜品明细**
- **盘点快照**
- **原料进价变更快照**

> 历史单据无法回溯重建。**这是全方案里唯一真正时间敏感的项。**

### 4.2 口径层：现在必须锁死、写进规范

| 项 | 锁定的口径 |
|---|---|
| **补贴** | 平台补贴 / 商家自补贴**分开存储**；统一从**优惠前营收**扣减计算毛利 |
| **打包费** | **单独字段**，可配置是否计入收入 / 成本（⚠️ 待真实美团账单确认列义，见 §九） |
| **佣金、配送费** | 渠道维度费用；**不计入菜品 BOM 原料成本**，属渠道分摊费用 |
| **损耗** | 区分配方预设损耗（BOM）与盘点实际损耗（库存倒轧）**两套口径，不可混用** |
| **净料率** | 固定定义 = 净料重量 ÷ 毛料重量；**净料成本公式永久锁定** |

> 豆包原话：口径不锁死，将来 AI 算出来的数会自相矛盾。

### 4.3 接口层：现在**刻意不做**（做了才是浪费）

| 不做的事 | 为什么现在做是浪费 |
|---|---|
| LLM 入参组装接口 | 改公共模块代价大（42 个云函数 + `cx_*` 副本同步）；远期直接在 `buildInterpretation` 内新增分支，**外部调用不变** |
| AI 候选方案持久化集合 | 独立集合，上线 LLM 时新建即可，**无需提前建空字段** |
| AI 专用埋点字段 | 埋点只在 LLM 分支内部，**不侵入现有 facts 结构** |
| 跨门店对标数据集对接钩子 | 远期业务 + 本身是伪需求，**预设无价值** |

**三层执行原则**：数据层**现在就做**；口径层**现在就锁**；接口层**现在不做**。
> 与 R166 ADR 一致：**不建抽象层，只锁三条边界** —— LLM 不碰数字、文案与计算分离（单一出口 `buildInterpretation`）、数据结构化。

## 五、后期怎么上（三期路线）

### 5.1 三期定义（豆包原案）

**一期（无 LLM，当前启动）**
- **做什么**：完善 BOM 净料成本、外卖账单结构化导入；落地三级门禁、raw + facts 双件套、`buildInterpretation` 单一出口；锁死成本 / 补贴 / 损耗口径。
- **老板看到**：一键导入外卖账单、菜品 / 套餐成本核算、L1 模板告警解读、数据校验报错提示。
- **靠什么算**：L0 确定性规则引擎。
- **进入下一期的触发**：账单导入稳定 + 菜品成本卡录入量达标 + **丙级门禁通过率稳定 ≥95%**。

**二期（L0 能力扩充，仍无 LLM）**
- **做什么**：菜单利润评分、外卖活动保本沙盘、库存倒轧损耗预警、**套餐定价反推**；facts 补齐 sourceId 溯源；埋点采集"业务问题类型"。
- **老板看到**：菜品利润排名、活动保本测算、食材损耗告警、套餐定价区间。
- **靠什么算**：**穷举 + 评分函数**。
- **进入下一期的触发**：高频多因素利润波动问题中，**规则模板无法覆盖的占比 ≥12%**。

**三期（引入 LLM 归因）**
- **做什么**：LLM **仅**生成利润波动的候选根因清单与文字解释；**所有数值交由 L0 引擎复核**；L1 兜底；三级门禁前置校验。
- **老板看到**：利润大幅波动时的候选原因列表（数字可溯源）+ AI 标识。
- **靠什么算**：LLM 出候选 → **L0 引擎复核所有数值**。
- **前置条件**：二期指标全部达标 + **个体工商户的"深度合成"类目资质办妥**。

### 5.2 "该上 LLM 了"的 3 条可测量触发条件

1. 用户月度利润波动类查询中，**规则模板无法覆盖的场景占比 ≥12%**
2. **丙级门禁通过率稳定 ≥95%，持续 2 个月**（底层数据可信）
3. 付费用户调研中，**多因素利润归因诉求占比 ≥20%**

### 5.3 LLM 防错红线（可直接写进代码的 5 条约束）

1. **LLM 禁止输出任何最终数值**，只输出候选原因、文字描述、指标名称。
2. LLM 提到的全部指标，**送入 L0 引擎重算**；未通过复核的条目**直接丢弃不渲染**。
3. 所有展示项**必须绑定 sourceId**；丙级门禁不通过 → **隐藏 LLM 全部输出**。
4. **L1 模板永久兜底**；LLM 模块**可一键全局开关关停**。
5. **方案必须附小范围试点建议**，不输出大刀阔斧的一次性改动；**埋点追踪"是否落地"**——不看 AI 点击，看后续菜单 / 活动是否真的改了。（豆包对策：防"AI 给了方案老板不执行"）

### 5.4 放弃信号（一出现就该停）

1. 持续 3 个月：**丙级门禁通过率 <85%**，用户录入数据质量无法改善。
2. 二期上线后，**菜单 / 活动沙盘功能使用率 <5%**。

## 六、差异化：为什么平台做不了

| | 美团 / 饿了么 | 我们 |
|---|---|---|
| 销售端数据 | ✅ 有（订单、销售额、评价、流量） | ✅ 有（账单导入） |
| **成本端数据** | ❌ **没有**（进价、净料率、损耗、房租、人工） | ✅ **有** |
| 能算"这个套餐亏不亏" | ❌ 只能看卖得好不好 | ✅ 能算真实毛利 |
| 能算"活动该不该上" | ❌ 只能给平台侧 ROI | ✅ 能给商家侧保本线 |
| 能归因"为什么这个月利润掉了" | ❌ 只能归因到流量 / 评分 | ✅ 能归因到成本 / 结构 / 活动 |

### 两个具体产品形态（豆包提，直接可用）

1. **【菜单利润诊断】** —— 一键生成菜单优化清单：识别引流菜、高毛利潜力菜、亏损菜；每道菜绑定**真实净料成本 + 套餐连带贡献**。
   → 美团**不知道**食材进价、净料率、后厨损耗，**算不出真实菜品利润**，只能看销售额。
2. **【外卖活动保本沙盘】** —— 输入活动满减 / 补贴方案，自动联动菜品 BOM 成本，算出**保本补贴上限**与预估门店净利变化。
   → 美团**只能看订单流水**，没有后厨真实成本，**无法判断活动是否真赚钱**。

**一句话**：平台是"卖场"，我们是"账房"。**只有同时握住成本与销售两端，才谈得上"经营决策"** —— 这是别人抄不走的根。

## 七、合规（个体户 + AI）

- **主体**：个体工商户已定 —— 同时解开**微信支付 / 交易类目 / web-view** 三个限制，**付费墙才跑得通**。
- **三期上 LLM 前必须办**：申请微信小程序「**深度合成 - AI 问答**」类目 + 算法备案。
  - ⚠️ **存疑未决**：个体工商户能否申请该类目，来源存在冲突（微信服务市场官方回复说"变更为个体工商户后可申请"，另一篇腾讯云文章称"仅企业主体"）⇒ **以后台实际可选类目为准，不对外承诺**。
- **休眠代码无忧、但别预埋**：法规只约束"向境内公众提供"，休眠代码不算；但**微信代码审核会扫代码文本，检出 AI 调用代码可能被问询** ⇒ **一期不要预埋任何 AI 调用代码**（这也正是"不预留代码"的合规理由）。
- **AI 标识**：三期上线时必须给 LLM 输出加 AI 标识。

## 八、立即可做的 5 件事（不需要等美团数据）

1. **锁口径**：把 §4.2 的五条口径写进 `specs/` 开发规范。
2. **建三级门禁**：甲级（通道 + Schema + 非空）先落地，乙级（勾稽）、丙级（对账）随后。
3. **raw 先留全**：账单导入时，raw + 采集元信息（平台名 / 期间起止 / 符号约定 / 列名映射来源 / 明细行唯一 ID）一并落库。
4. **账单导入开工**：这是"现在可以做什么"里价值最高的一件。
5. **BOM 净料成本收尾**：把 M3 缺的菜品级净料补齐；顺带把"进价波动自动重算"做出来（豆包判定"现在就能做"）。

## 十、证据与复现

- **原始问答**：`review/evidence/r168_ai_roadmap/`（p1–p3 提问 + r1–r3 回答 + 通道脚本）
