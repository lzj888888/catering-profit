## 2. 抓到的真缺陷（R1-7）

**现象**：批量录入预览列表里，**第一行点不动**（点它不会取消勾选）。

**根因**：`batch.wxml:48` 写的是 `data-i="{{index}}"`，这里的 `index` 是 `wx:for` 的**内置索引，从 0 起**。而 `batch.js` 原文：

```js
const i = Number((e.currentTarget && e.currentTarget.dataset && e.currentTarget.dataset.i) || -1);
```

`0 || -1` 在 JS 里等于 `-1` ⇒ `rows[-1]` 是 `undefined` ⇒ 直接 `return`。**第一行永远点不动**，第二行往后正常。

**为什么它危险**：这正是李老师反复报过的「点不动」同型（R705 那批的根因是「按钮没有可操作对象」）。老板看到第一行亮着勾、点一下没反应，会以为整个列表坏了。

**修法**（一行语义，不动选中规则）：

```js
const raw = e && e.currentTarget && e.currentTarget.dataset ? e.currentTarget.dataset.i : undefined;
const i = Number(raw);
if (!Number.isInteger(i) || i < 0) return;
```

**守住**：`B-④` 断言「第一行能切换」+ `D-7` 变异（把判定改回 `if (!i || i < 0) return;`）必须转红。

## 4. 三处如实登记

1. **我的样本先选错了两次**。第一版用 `坏行,abc` 当脏行，实测它是 `ok=true`、单价静默 0 —— 一度以为是「静默当 0」的 bug。读 `pickColumns` 才确认：两列且第 2 列不是数字时，那是**合法的「名称 + 规格」形态**（单价允许留空），不是脏行。改用四列 `坏行,,斤,abc` 才真正触发「单价不是数字」。**判定：产品无此 bug，是我样本选错**。
2. **`L-⑫` 判据原本绑死在 R1-4 这个 id 上**。R1-4 修完后判据永久失去对象 —— 要么逼人把状态改回 deferred（假装修了），要么常红。已改为「认任意一条真写了『桩』的 P0/P1 待办」，并如实开新票 **R1-8**（桩型仍只占 15.2%）。放宽的只是「哪张票」，没放宽「必须真有一张」。
