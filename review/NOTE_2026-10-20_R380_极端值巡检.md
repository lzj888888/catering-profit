# R380 · 极端值与空态巡检（引擎层）

> 2026-10-20 · 上一轮承诺的"自选动作"。目的：0 / 空 / 极大 / 边界百分比 / 反向毛利这些输入下，
> 引擎会不会吐出 NaN、Infinity、`¥0.00 假数`，或给出**方向错**但看起来正常的结论。

## 一、怎么测的（可复跑）

`review/evidence/r380/edge_probe.js`：直接 `require` 两个**纯函数引擎**（不经过页面、不经过模拟器），
对 20 组极端输入逐个扫描输出里的非有限数、`-0`、含 `NaN/Infinity/undefined` 的字符串。

```bash
node review/evidence/r380/edge_probe.js
```

## 二、结果

### M2 `calcSandbox`（11 组）

| 场景 | 结果 |
|---|---|
| 全零（毛利 0 / 无固定 / 无建店） | `red_alert=true`（拒绝出数，不是给 0） |
| 毛利 0% / 100% / 1% / 99.99% | 无 NaN；0% 走 `red_alert` |
| 租金 0 / 租金 1 亿 | 无 NaN |
| 目标利润为负 / 实际营收为负 | 引擎不炸（**入口 `validate` 用 `fen()` 要求非负整数分**，负值根本进不来） |
| 建店年限 0 / 100 | 无 NaN（年限 0 = 不摊销） |

### M3 `calcCostCard`（9 组）

| 场景 | 结果 |
|---|---|
| 空明细 | `unitCost=0 / margin=100%` ← **见下方结论 ②** |
| 数量 0 | 同空明细（0 成本 100% 毛利） |
| 数量 1e9 | `unitCost=1.45e11 分 / margin=-3.8e9%`（荒谬但方向正确，不静默） |
| 净料成本 0 | 0 成本 100% 毛利 |
| 售价 0 / 售价<成本 | margin 0 / -14400%（方向对） |
| **损耗 100%** | **`unit_cost_fen=Infinity`、`gross_profit_fen=-Infinity`** ← 见结论 ① |
| 批量产出 0（mode B） | 不炸（`batchOutput>0?…:1` 兜住） |
| 非法 mode | 抛 `INVALID_PARAM`（R81 的引擎断言，符合预期） |

## 三、结论

### ① 唯一一处非有限值：损耗 100% ⇒ Infinity（**目前打不到，但有纵深缺口**）

- 引擎 `calcBom/service.js:121`：`divisor = 1 - lossPct/100` ⇒ 100 时除零。
- **两个入口都拦住了**：`calcBom/validate.js:62` 与 `saveCostCard/validate.js:111`
  都要求 `lossPct ∈ [0,100)` ⇒ 老板填 100 会在入口被拒。
- ⚠️ 但**引擎本身没有断言**（对比：`mode` 在引擎里有断言，R81 立的规矩）。
  而 `calcCostCard` 属**引擎禁区·禁改源码**，所以这轮**没有动它**。
- ⇒ 登记为**防御纵深缺口**：一旦有人把某处 validate 的 `>= 100` 放宽成 `> 100`，
  引擎会静默产出 `Infinity` → 落库时 JSON 化成 `null` → 成本变 0 → 毛利虚高。**这是最危险的形态。**

**建议判据（未落地，等排期）**：在 `check_m3_engine_parity.js` 加一组行为断言 ——
`require` 两个 validate，喂 `loss_pct: 100` 必须都返回错误；再断言"若绕过 validate 直接喂引擎，
输出含非有限值"作为**前提证明**（证明这条判据不是恒真）。

### ② 空明细 = 100% 毛利（**保存路径打不到，预览路径可能显示**）

- `saveCostCard/validate.js:40` 有 `lines.length === 0 ⇒ 直接拒`；
- 但 `calcBom` 是纯计算，空数组照样返回 `margin=100`。前端编辑页在"一行都没填"时若触发试算，
  吸底条会出现 `成本 ¥0.00 · 毛利率 100%`。
- ⇒ 需要真机确认一次（模拟器这轮不稳定）。若真出现，修法是在页面侧加"无有效行就不试算"，
  **不在引擎里加**（引擎禁区）。

### ③ 数量没有上界（`qty > 0` 即可，1e9 也放行）

不是静默错误（结果会大得离谱、方向正确，老板一眼能看出），所以**不建议加硬上限**——
加错上限会把"批量腌制 100 斤"这种真实场景挡掉。若要加，只能给"提示"不能给"拒绝"。

- **页面空态**没跑：模拟器这轮不稳定，等真机走查一起看。
