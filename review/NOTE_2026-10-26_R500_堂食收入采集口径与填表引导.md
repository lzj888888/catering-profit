## 0 一句话结论

**堂食收入 = 当月已消费堂食的「折后成交额」，按消费日算月份；系统内 + 系统外相加，按订单算一次。**
引导要回答老板真正的两个问题：**去手机上点哪抄**、**那个「营业收入」能不能直接抄**。

## 1 取证：三家收银系统手机端到底给什么数（官方文档，不是推测）

| 系统 | 入口 | 能抄到的数 |
|---|---|---|
| **美团管家 APP** | 报表 → 营收概览 → **月报** | 实收金额、订单数；店内：应收金额、实收金额、就餐人数、单均价；优惠指标（优惠合计/店内优惠/会员优惠/免单/减免/抹零）；**收款构成（各支付方式占比）**；财务概览含支付方式流水明细 |
| **客如云 掌上 APP** | 首页 / 每日对账单 / 营业概况 | ⚠️ 首页「营业收入」**含已结账 + 未结账 + 会员卡余额支付 + 挂账支付**；每日对账单有总收款、实际打款、团购核销额、外卖平台金额、**现金及记账金额**、预付金抵扣、手续费；跨天营业有「打款尾差」 |
| **哗啦啦 老板通** | 按日/周/月 | **实收**达成；**收入分类 = 营业额按支付构成/业务构成/渠道构成/收入构成拆分** |

行业通用口径（连锁最佳实践）：净营业额 = 含税销售额 − 退款 − 折让，**排除储值卡充值**；**储值充值 ≠ 消费**（把充值当营业额是最常见坑）；实收按支付成功时间。

## 2 豆包两轮结论

**第 1 轮**
1. **填折后成交额**（不填优惠前）：老板只填一个数时，折后口径最省事也不会错；填优惠前就必须另录一笔折扣费用，否则利润虚高。
2. **收银系统首页「营业收入」不能直接抄**：它混了未结账、会员卡余额、挂账（客如云实证）。
3. **现金/个人码：按订单去重，不按账户去重** —— 订单进了系统就按系统算一次；没进系统才用现金/个人码补，别两边都加。
4. **消费月 ≠ 到账月：一律按消费/核销月确认**，次月到账只是收回欠款。

**第 2 轮（四个取舍）**
- Q1 快速录入拆两个框（系统内 / 未进系统）：**拆**
- Q2 粘贴导入（复制「收款构成」自动填渠道）：**现在别做**（收款构成是**收款口径**，与我们的消费口径不一致；解析错会产生"看起来很准确"的错误，外卖粘贴已踩过翻倍坑）
- Q3 渠道默认列 7 个还是 3 个：**默认 3 个 + 快捷添加**
- Q4 净营业收入：**上**，但只能扣外卖商家承担补贴，**不能重复扣堂食折让**；历史数据可靠才重算

## 3 我的裁决（采纳 / 降级 / 不动，附理由）

| 建议 | 裁决 | 理由 |
|---|---|---|
| 折后成交额 + 未结账剔除 + 消费月口径 | ✅ **采纳**（文案层） | 与现有 `incomeScope.dine_in` 方向一致，本轮补齐缺失的三条 |
| 「从哪抄」三家路径对照 | ✅ **采纳** | 本轮**最高收益**项：老板看完知道去点哪，不用猜 |
| 首页「营业收入」别直接抄 | ✅ **采纳** | 客如云实证会虚高，属静默算错钱 |
| 系统内 + 系统外「按订单算一次」 | ✅ **采纳（文案层）** | 现金混合的主要错法就是两边都加 |
| 挂账「当月算收入、收回不记二次」 | ✅ **采纳**（补 `channelNotes`） | 收钱时更像收入，最容易搞反 |
| **Q1 拆两个框** | ⚠️ **降级为引导，不改 UI 结构** | 加一个金额框要动 `rows` 装配（`normalizeDineRows` 会补齐全集 7 条）+ 落库字段 + G10b 断言 ⇒ 结构性改动。本轮先用文案讲清"两个数相加填这里、各从哪取"，已消除主要错误；是否改结构**待李老师拍板**（#81） |
| **Q3 默认 3 个渠道** | ⚠️ **不采纳本轮，改走轻量减负** | 与"补齐全集"实现 + G10b 断言直接冲突。改为在提示里写「只填你有的，没有的留空、不用填 0」+「拆不开就回快速录入」⇒ 同样减负、零结构风险。真机确认空行是否真是负担后再议（#82） |
| **Q4 净营业收入** | ⚠️ **登记，本轮不动** | 改指标 = 所有历史月展示变化 + 触碰结果页受守区域。豆包也说了正确算法（只能扣外卖商家承担补贴，**不能**连堂食折让一起扣）⇒ 已写进 #83，等李老师确认老板是否接受成本率数字变化 |
| **Q2 粘贴导入** | ❌ **不做**（与豆包同） | 收益 < 风险，登记 #84 备选 |

## 4 落地清单

**文案（terms 双副本，md5 全等 `20621a16…`）**
- `incomeScope.takeaway`：**修旧口径** —— 原句教「商品总价+打包费+商家承担补贴**三项相加**」，正是 R497 推翻的填法（补贴加进收入、费用侧又扣一次 ⇒ 抵消 = 一分没扣）。改为「商品总价 + 打包费 = 优惠前总额，补贴/佣金/配送走费用侧」
- `incomeScope.dine_in`：补「未结账一律不算（不论金额）」「按消费日出餐日算月份，不按到账日」
- `dineMode.fastHint`：重写 —— 折后成交额 + **三家从哪抄** + 三不抄（首页营业收入 / 充值 / 到账月）+ 系统内系统外相加原则 + 个人账单要剔转账红包提现
- `dineMode.detailHint`：补「从收款构成抄」「只填你有的、没有留空」「拆不开就回快速录入」「按订单算一次」
- `channelNotes`：新增「个人/单位挂账消费」注（当月算收入、收回不记二次）

**样式**：`.hint-fold-body` 加 `white-space: pre-wrap` —— 否则 `\n` 分段在 WXML 里塌陷成一行，三家路径对照变成一坨。

**守卫**：`tools/selftest_batch8b.js` 新增 **G12 组 6 条**（188 → 194）
- G12-1 takeaway 不得再教「三项相加」且必须说「优惠前总额」
- G12-2 堂食口径必须含「未结账 / 充值 / 消费 / 到账」四个语义锚
- G12-3 fastHint 必须给 ≥2 家收银系统 + 手机上看得见的字段名
- G12-4 必须说清「系统内 + 系统外、别两边都加」
- G12-5 挂账注必须说「当月算收入」+「收回不再记一次」
- G12-6 `.hint-fold-body` 必须 `pre-wrap`（样式与文案的隐性依赖）

**变异证明** `_mut_r500.py`：**6/6 转红** + 还原复绿 194/0。
⚠️ 踩到一个坑：JS 源码里 `\n` 是**字面两字符**，Python 里写 `'\n'` 是真换行 ⇒ 锚点永远匹配不到（M3 首轮 SKIP），必须 raw 字符串。
