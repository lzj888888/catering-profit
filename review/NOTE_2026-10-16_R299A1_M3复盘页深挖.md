## 2 🔴 缺陷 D1 · 覆盖率「道数」用两个命名空间混算

### 2.1 缺陷

云函数对两类行写 `name` 时**语义不同**：

| 行类型 | 出处 | `name` 实际是什么 |
|---|---|---|
| **已匹配**（ranked） | `service.js:95` `name: card.name \|\| dishKey` | **成本卡名** |
| **未匹配**（unmatched） | `service.js:86` `name: dishKey` | **销量表原始菜名** |

而前端把两者塞进**同一个 Set**（修复前 `index.js:351-360`）⇒ 「共 N 道」与「已算 M 道」**一起算错**：

- 菜品「可乐(罐)」「可乐(瓶)」都挂到卡「可乐」⇒ ranked 两行 `name` 都是「可乐」⇒ Set 只剩 1 个
  ⇒ **「共 N 道」少 1**、「已算 M 道」同样少 1；
- 卡名与某未匹配菜名碰巧同名时，两个数**一起错**（Set 合并、未匹配数却照减）。

**危害**：用户可见的错数，直接削弱"先建哪道最划算"的判断 —— 而这正是 R264 做覆盖率的**唯一目的**。

### 2.2 为什么既有守卫没抓到

`check_dishreview_engine.js` 的 **12-④** 原文只断言：

```js
check('12-④ 道数按菜名去重…', /dishNames\.add/.test(pageSrc) && /dishNames\.size/.test(pageSrc));
```

—— 只问「用没用 Set 去重」，**不问「去重用的那个字段在两侧是不是同一命名空间」**。
与 R298Y 的「守卫只守分支在不在，不守分支到不到」**同族**。

### 2.3 修法（纯前端，零云端改动）

服务端**本来就返回** `dish_key`（`service.js:94`），是前端 `fmtRanked` 把它 **discard** 掉了。
⇒ `fmtRanked` 带出 `dishKey`，覆盖率三侧（堂食 / 各外卖平台 / 未匹配）**统一按 `dishKey` 去重**。
保留原公式语义（共 = 两侧并集；已算 = 共 − 未匹配数），**只统一命名空间**。

### 2.4 判据升级（12-④）

新判据 = 「`fmtRanked` 函数体内带出 `dishKey` + 三侧都按 `x.dishKey` 去重（实参级）+ 旧命名空间不得复活」。
⚠️ 两条**防恒真**的细节（都是本轮变异实测逼出来的）：

1. **必须钉住实参**：只数 `dishKeys.add(` 次数时，把实参换成 `x.name` 照样 3 次 ⇒ 判据恒真。
2. **`dishKey:` 那条腿必须锚定在 `fmtRanked` 函数体内**：同文件 `pushUnmatched` 里另有一处
   `dishKey: x.dish_key || nm`，全文匹配时把 `fmtRanked` 那行**删掉判据照样绿**（变异 M3 抓到）。

## 3 🔴 缺陷 D2 · 出参 `truncated` 前端零消费 ⇒ 静默少行

### 3.1 缺陷

`cloudfunctions/common/dataAdapter.js:49-52`（`listAll` 的契约原文）：

> · `truncated === false` ⇒ data 就是**全部**命中行；
> · `truncated === true`  ⇒ data 已达 `LIST_TOTAL_CAP` 且仍有剩余 ⇒ 调用方**必须**把这个事实
>   透传到出参（**可见降级**），**不得当作"取全了"继续算**。

`LIST_TOTAL_CAP = 20000`。**服务端照做了**（`getDishReview` / `getCostCard` / `getSalesBills` /
`manageShop` 的出参里都有），**但前端零消费**（`grep truncated pages/ utils/ miniprogram/` = 空）。

⇒ 数据一超上限：复盘榜 / 账单列表 / 成本卡列表**静默少行**，页面照常渲染、零提示。
这就是 M3-B6「导出只取前 1000 行 ⇒ 静默少卡」的**同一个恶**，只是从"服务端截断"换成了"客户端不消费"。

**更讽刺的一处**：`getCostCard/index.js:88-92` 的注释白纸黑字写着
「R157：可见降级标记 …… **前端可据此提示**，而不是像以前那样"看着少了几张卡"却无从判断」
—— 前端从未据此提示。

**同类第二处（服务端侧的"写读取方 ≠ 修好"）**：`manageShop::onStats` **丢掉了** `scanMonthly` 算好的
`truncated`（同文件 `op=reset` 路径**用了**它 ⇒ `decideReset` fail-closed）。
而 `onStats` 的 `months` 会被前端直接写进「将永久删除 **N 个月**数据」的确认框
⇒ 用户在**被低估的后果量级**上点确认。

### 3.2 修法

1. **新增单源** `utils/dataHealth.js`：`isTruncated(res)`（判 `res.truncated === true`）。
2. **云函数**：`manageShop::onStats` 补出参 `truncated: !!st.truncated`（**加性改动**，旧前端忽略新字段，安全）。
3. **文案**：`TERMS.ui.dataTruncated`（**双副本同步**）+ 全局样式 `.warn-line`（`app.wxss`，多页共用单源）。
4. **消费点**：复盘页（3 处读取 → `_setTrunc` 汇总去重）、成本卡列表、店铺清点确认框。

> 🔴 `_setTrunc(source, v)` 为什么必须**汇总**而不是三处各写一次 `setData({truncated})`：
> 后一次读取会把前一次的标记**覆盖掉** ⇒ 提示时有时无，比不提示更难查。

### 3.3 新守卫 `tools/check_truncated_surfaced.js`（20 断言）

| 面 | 判据 |
|---|---|
| ① **生产者面** | 从 `cloudfunctions/*/index.js` 的 `ok({...})` 里**实扫**出真的回了 `truncated` 的函数（**不写死名单**）。⚠️ 必须同时认 `truncated:` 与**简写** `truncated,` —— 首版只认冒号 ⇒ 漏掉 `getSalesBills`（"探测器坏了与命中 0 长得一样"）。 |
| ② **契约面** | `dataAdapter` 的「必须透传 / 可见降级 / `LIST_TOTAL_CAP` 是显式常量」原话仍在（要求被删 ⇒ 判据前提消失）。 |
| ③ **消费者面（fail-closed 登记表）** | 每个碰过 emitter 的**页面文件**：**要么**消费、**要么**在 `EXEMPT` 里带 `why` ⇒ 未表态即判红。且登记表**无僵尸键**（文件改名后豁免悄悄失效）**无空转键**（豁免表变成躲避修复的垃圾桶）。 |
| ④ **反恒真 + 正样本** | 未消费样本必须判不通过；三个真消费点为正样本。 |

**登记（4 条，各带 why）**：`pages/m3/hub.js` / `pages/recon/index.js` / `pages/takeaway/index.js` /
`pages/card/edit.js` —— 都是「只取 length 或作 code→name 辅助映射」，不渲染"看似完整的清单"。

**判据的粒度边界（如实登记）**：判据粒度是**页面文件级**（碰过 emitter 就整体表态）。
逐调用点判需要可靠的作用域分析，代价高且易假红 ⇒ 采文件级；代价是「同文件内**部分**消费点被删」
（如只删复盘那一处、保留另两处）不会报警。**这一层已登记，未闭合。**

## 4 🔴 缺陷 D3 · 「去建卡 / 去映射」返回后页面不刷新

- `pages/m3/dishreview/index.json`：`enablePullDownRefresh: false`（**无下拉刷新**）；
- 旧 `onShow() { if (this.data.locked) this.init(); }` —— **只在 locked 时**重载；
- 而 R264 专门设计了「去建卡」闭环（`goNewCard` 带菜名预填跳 `pages/card/edit`），`goMap` 也 `navigateTo` 走掉。

⇒ **返回后页面全然不刷新**：刚建的卡**不进**关联 picker（`cardOptions` 是旧的）⇒ 用户以为卡没建上、可能重复建；
刚挂上的菜**不进**毛利榜、`unmatched` 也不减少 ⇒ 用户以为关联失败。

**对照**：`pages/card/index.js:122` 同类**只读页**就是 `onShow() { this.load(); }` ⇒ 这是**遗漏**，不是设计选择。

**修法**：`onLoad` 置 `this._shown = false`；`onShow` 在非 locked 路径**返回时重载**（`_shown` 哨兵防首次重复拉）。
判据 = `12-⑬`（+ `12-⑭` 反恒真：旧 onShow 必须判不通过）。
