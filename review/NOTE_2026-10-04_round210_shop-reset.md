# R210（2026-10-04）· 店铺「删不掉」的第二层解法：给「删除」配一条轻得多的出口 —— 清空月度账

> 起因＝李老师一句话：**「删除可以要求，新增店铺又要花钱，对于有一个店的餐饮老板，删除店铺是删除不了的。这个是咱们的本意吗？」**
> 上一轮（R209）我答的是"你手机上跑的是旧包 —— R208 已经把删除放开，软删不占配额、删完还能再建"。
> **这个回答只对了一半**：放开是对的，但**放开 ≠ 合适**。本轮解决的是后半句。

---

## 一、决策（李老师授权"听你的"）

我把上一轮留给你的二选一**两个都做，并且合成一条路**：

| 原方案 | 采纳 | 理由 |
|---|---|---|
| ① 删除前先提示这家店有几个月账套（后果量级） | ✅ | 让用户对着**真实数字**做不可逆决定，而不是一句万能恐吓句 |
| ② 改成「重置这家店的数据」（保留店铺、只清账套） | ✅ | 老板真正想要的出口是「重做一遍账」，不是「店消失」 |

**关键判断**：只有一个店的老板点「删除」，九成想要的是**把账重做一遍**。
删除是认知负担最重的动作，把它做成唯一出口 = 用最重的锤子敲最轻的钉子。
⇒ 补一条破坏力小得多的出口 `op=reset`，并把「删除」的确认框也改成**真查量级再确认**。

最终形态（店铺行右侧三个行内按钮，破坏力从左到右递增）：

```
[耙三样 当前店铺]    改名   清空   删除
                   中性   琥珀    红
```

## 二、实现

### 2.1 后端 `cloudfunctions/manageShop`（新增两个 op，**未新增云函数**）

为什么不新开云函数：新增云函数要牵动四处同步（A15 白名单 / `core/10` 全集 + 契约行 / 隐私收集项 /
契约标「+幂等」⇒ 代码必须有 `findPriorResult`+`writeAudit`）。`op` 只是路由，挂在既有的 `manageShop` 上是同一件事、零契约面扩张。

| op | 性质 | 做什么 |
|---|---|---|
| `stats` | 纯读 | 清点这家店的月度账月数 / 行数（不写库、不写审计、不进幂等） |
| `reset` | 写 | 软删这家店的**月度账三张表**（店铺 / 菜品成本卡 / 原料档案**全保留**） |

- `service.js`：`RESET_COLLECTIONS` + `RESET_MAX_ROWS`（2000，护栏不是额度）+ `decideReset()` 纯函数。
- `validate.js`：`OPS` 由 3 个扩到 5 个（`create/rename/delete/reset/stats`），新增 `NAMELESS_OPS`。
- `index.js`：新增 `scanMonthly()` / `onStats()` / `onReset()`。

### 2.2 🔴 清空范围铁律（本轮最硬的一条约束）

```
RESET_COLLECTIONS = ['shop_monthly_account', 'shop_monthly_income', 'shop_monthly_expense']
```

**绝不含** `shop_cost_card` / `shop_material` / `shop_amortize` / `shop_sandbox` / 店铺本体。
理由：成本卡、原料是老板**一条条录进去的资产**（菜品配方、采购单价）；重做一个月不该赔掉整本菜谱。
而"顺手往数组里多塞两个集合名"在实现上毫无痛感、用户却永久丢数据 ⇒ 必须有机器判据（守卫 C-②）。

写库纪律：
- 必用 `da.listAll`（`list()` 上限 1000 ⇒ 漏掉的行既不会被清、也不会报错，**典型的静默半删**）；
- 软删按行内真实 `_id`（`row._id || row.id`），逐条核 `stats.updated`，**不等即整体 fail**（绝不留"半清干净"中间态）；
- `listAll` 返回 `truncated` ⇒ **一律不放行**（审计护栏：宁可不给这个功能，也不半删）。

### 2.3 前端 `pages/shop/switch`

- 行内三个按钮（`onRenameTap` / `onResetTap` / `onDeleteTap`），宽度收到 88rpx 容纳第三个；
- `fetchImpact(id)` 走 `op=stats` 拿真实月数 → **失败返回 -1，两个调用方都不往下走**（fail-closed）；
- 确认框 content 由 terms 的 `deleteAsk(months)` / `resetAsk(months)` 生成，**把数字写给用户看**；
- 没月度账时点「清空」只弹提示，不弹危险确认窗。

文案示例（`miniprogram/i18n/terms.js`，两份副本 md5 一致）：
- `resetAsk(3)` → 「清掉这家店 3 个月的月度账？店铺名、菜品成本卡、原料档案都留着，只是账本归零，可以马上重录。」
- `deleteAsk(3)` → 「这家店有 3 个月的月度账。删除后店铺不再出现在列表里，这几笔账在前台也看不到了（后台仍保留，不物理销毁）。」

### 🔴 本轮抓到的**守卫自身假绿**（值得单独记一笔）

变异回灌时 M4a / M4b / M4c 三条变异**全绿 rc=0**。第一反应是"我的变异太弱"（符合"先怀疑自己"），
但手动验证发现变异体确实生效、node 也读到了 ⇒ **是守卫错了**：

> 非法 op 的负样本只写了 `{op:'clean', target_shop_id:'s1'}`，**没传 name**。
> 于是即使白名单被放宽放行，下一步「缺 name」仍返回**同一个错误码** `INVALID_PARAM`
> ⇒ `.error === 'INVALID_PARAM'` **恒真**，守卫永远发现不了白名单退化。

修法：负样本一律带上合法 `name`，隔离出「op 校验」这一个变量；并补 B-⑨ 做反向对照
（同样的入参去掉 `target` 是另一回事，证明不是靠缺字段才红）。

**定式**：判某个校验分支时，**必须把其它分支的入参喂成合法值**，否则命中的是下游同码错误 ⇒ 判据恒真。
