## 1. 做了一半的那件事（R418 的欠账）

R418 把金额体检接到 M2 测算页（10 个框），但 M1 月度录入页**没接** —— 而月度录入才是老板
**每月从 Excel 粘贴金额**的主战场，同一条链路（`yuanToFen` fail-soft → 0）同样可达。

本轮接上：`pages/month/input.js::updateRow` 是所有金额格子的**统一入口**
（`onSubAmount` → `updateRow(kind, gidx, ridx, {amountYuan})`），在这里调 `checkAmounts()`：
- 遍历 `incomeGroups + expenseGroups` 的全部行，`classifyAmount(r.amountYuan).readable === false` 计数
- 计数 > 0 ⇒ wxml 顶部显示 `t.amountBadTip`
- 只在数量变化时 `setData`（不每次按键重渲染）

**文案单源**：`amountBadTip` 从 `TERMS.m2` 挪到 `TERMS.ui`（它是跨页 UI 提示，放 m2 组里 M1 引用不合适），
两页都用 `TERMS.ui.amountBadTip`，守卫 ②-18 专门盯这条。

**样式单源**：`.warn-note` 原来只定义在 `pages/sandbox/index.wxss`，M1 用不到 ⇒ 提到 `app.wxss`，
sandbox 本地定义删除。

## 2. 🔴 包体满载：本轮撞上的真墙

门禁第一次跑红在 `P-③`：

```
P-③ 单个未忽略顶层条目 ≤ 顶格 · pages = 1.0017 MB > 1.0 MB
P-① 入包总量 = 1.4718 MB / 预算 1.5 MB   ← 只剩 28 KB
```

用 `git stash` 在 **HEAD 状态**下复测：`pages = 0.9996 MB` —— **本来就只剩 0.4 KB 余量**。
⇒ 不是"本轮写多了"，是**任何改动都会破**。

根因：`app.json` **没有 subpackages**，27 个页面全在主包。

### 处置（李老师 2026-10-21 拍板：临时提阈值，先交付）

`tools/check_pack_size.js`：
- `PER_TOP_CAP_MB` 1.0 → **1.2**（实测 pages 1.0005 MB）
- `TOTAL_BUDGET_MB` 1.5 → **1.7**（实测入包 1.4718 MB）
- 常量注释里写明：**这是权宜，不是解法**；仍 < 微信 2 MB 硬上限。

🔴 **没有偷偷调**：注释留了实测值与拍板来源；同时在 `AUTO_QUEUE` 登记「包体必须分包」为后续条目。
