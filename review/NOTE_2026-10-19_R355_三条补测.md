## 一、矩阵展开高级维度（6/6）

设 `dims = { rent:[3000,5000], labor:[2,3], margin:[45,60], target:[0,10000] }` 后生成：

| 断言 | 实测 |
|---|---|
| 行数 = 2×2×2×2 | 16 |
| 毛利率两档都出现 | 45 / 60 |
| 人数两档都出现 | 2 / 3 |
| **不同人数 ⇒ 不同人工/月** | 9000 / 13500 |
| 无失败行 | invalid 0 · 保本为 null 0 |
| 结论仍正常 | ✅ |

> 「不同人数对应不同人工」这条是本轮重点：R335 把人工改成「人数 × 人均」后，
> 必须确认展开维度时**真的按人数分别算**（而不是所有行都用第一档的人数）。

## 二、活动卡负毛利率分支（2/2）

构造：毛利率压到 40% + 全员参与 + 实收率 40（等于 4 折，让价 60% > 毛利率）。

| 断言 | 实测 |
|---|---|
| 进入 bad 态并说明 | `这个折扣让价已经超过毛利率，卖多少都亏` |
| bad 态不编数 | 毛利率/客流文案均为空 |

> 这条分支平时走不到（只有让价超过毛利率才触发），但它是**唯一会告诉老板"这个活动做不了"**的路径。

## 三、导出与页面一致性（7/7）

方法：在页面上下文临时替换 `wx.cloud.callFunction`，拦下 `exportData` 的请求体（不真下载）。

| 断言 | 实测 |
|---|---|
| 拦截到请求 / 类型正确 | `m2_matrix` |
| 导出列数 = 14 | 14（与页面表头一致） |
| 导出行数 = 页面行数 | 4 = 4 |
| 每行列数 = 表头 | 全 14 |
| **目标利润 0 导出仍是 0（不是「—」）** | `0` |
| 房租列没有被导成「—」 | 0 处 |

> 「0 与 —」的区别很重要：`0` 是"这一档就是保本"，`—` 是"这一档算不出来"。
> 导出里把 0 写成 —，会计会以为数据缺失。

R354 修的两个问题（单位串、映射丢）是这轮之前就存在的，本轮的补测确认没有连带问题。
