## 2. 疏漏清单（按严重度）

### 🔴 P0-1 · **删除店铺：全站没有**（最硬的功能缺口）

- **事实**：`shop/switch` 只有「选店 + 新增」；`shop/setting` 只有改名/备注；云函数侧 **无 `deleteShop`**（`cloudfunctions/` 42 个函数全扫，无 shop 删除路径）。
- **为什么是 P0 不是 P2**：免费档 **只给 1 家店**（额度真相源 `feature_permissions.plan_free.limits.shop`）。
  ⇒ 建错名可以改，但**多建出来的第 2 家店永久占位**，且会直接顶到上限 ⇒ 免费用户一旦误建，**连新建都做不了**，只能靠客服人工救。
- **基础设施其实齐了**：`cx_dataAdapter` 已有 `softDelete`（写 `is_deleted=true`，不物理删），计数 `da.count` 也只数 `is_deleted=false` ⇒ **软删后立刻腾出额度**，逻辑自洽。
- **建议**：`switch` 页每家店右侧 `⋯` → 【重命名】【删除店铺】；删除走二次确认 + 明示「该店账本/菜品卡不再显示，不物理清除」；**当前店是最后一家时禁止删除**（否则用户把自己锁死）。
- **代价**：新增云函数 ⇒ 牵动同步面四处（A15 白名单 / `core/10` 全集+契约行 / 隐私收集项 / 幂等 `findPriorResult`+`writeAudit`），并需部署上云（`cli.bat … --names deleteShop -r`，一次一个）。**需李老师拍板**。

### 🔴 P0-2 · **客服入口缺失（全站 0 处 `open-type="contact"`）**

- **事实**：全仓 `open-type` 只有 1 处 `chooseAvatar`（头像）。求助只有 `wx.openFeedback`（微信官方「意见反馈」页，**不是客服会话**，且是单向提交）。
- **自相矛盾处（更难堪）**：文案 `pay.contactServiceHint`（"已达上限，请联系客服"）在 **3 处**提示里出现
  （`card/index` 硬上限、`paywall.js`、`pay/orders`）⇒ **叫用户去联系客服，但没给他任何可点的地方**。
- **建议**：①「我的」页加 `联系客服`（`<button open-type="contact">`）；② 付费墙 / 硬上限弹窗把 confirm 改成「联系客服」直接进会话。
- **前置**：需在 mp 后台「客服」里绑定客服人员（**李老师操作**），否则按钮点了是空会话。可同时加「复制客服微信」兜底。

### 🟠 P0-3 · **「我的」页找不到订单 / 订阅**

- **事实**：`pay/orders`（看有效期、订单、续费）**只能从三条路进**：到期提醒条（只在快到期时出现）、`month/index`、`card/index`。
  ⇒ **已付费用户在「我的」里完全找不到自己的订阅**，想看"我买到什么时候"只能等快到期弹条。
- **建议**：「我的」页加常驻行 **`我的订阅 / 订单`**（不管有没有到期都在）。

### 🟠 P0-4 · **M2 开店盈亏：算完即丢**

- **事实**：`sandbox/index.js` 中 `export|save|Storage` 命中 **0 次** ⇒ 不存、不导出、无历史，退出/下拉刷新即重填。
- **为什么严重**：选址测算的核心用法就是 **A 铺位 vs B 铺位对比** + 拿给合伙人看，现在既不能存也不能比也不能导。
- **建议（分两级，先便宜的）**：
  - L1（零云端）：本地缓存上次输入（`wx.setStorageSync`）+ 顶部「上次测算 · 载入 / 清空」，可满足"回来接着调"。
  - L2（需新集合）：保存多方案 → 列表 → 并排对比 → 导出。**属新能力，需走规范增量（specs 增量 + 锚点复算）**，不建议与 L1 同批做。

### 🟡 P1-5 · **无 tabBar，深层页"回家"靠连点返回**

- **事实**：22 页无 tabBar；全站**只有** `month/amortize` 有 `goHome`。`card/version`、`material/edit`、`pay/orders`、`month/assetEdit` 等都要连点系统返回。
- **建议（低成本版）**：给 3 级以上页底部加一个 `回首页` ghost 按钮（`version`/`assetEdit`/`orders`/`recon`/`impact`）。
  ❌ 不建议现在上 tabBar：会重排页面结构，牵动 app.json 页面数、提审材料 §4、跳转统计三处同步面，收益/代价比不划算。

### 🟡 P1-6 · **「设置」按钮语义歧义**

- 首页 `设置` → 其实是 `shop/setting`（店铺名 + 备注）。老板会以为是小程序的"系统设置"。
- **建议**：改名 **`店铺名称/备注`**，或把它的活并进「我的」页的店铺卡。

### 🟡 P1-7 · **新建店铺要钻 3 层**

- 路径：首页店铺卡 → `switch` → `新增店铺` → `setting` → 输入 → `保存`。且 `setting` 页标题不区分新建/编辑，保存后无"已创建"反馈落点。
- **建议**：`switch` 页内联一行输入框直接建店（不用跳页）；或 `setting` 收 `?mode=new` 改标题与按钮文案。

### ⚪ P2-8 · **下拉刷新"假刷新"（3 页）**

- 全局 `enablePullDownRefresh: true`，但 `index` / `m3/hub` **未实现** `onPullDownRefresh` ⇒ 用户下拉转圈、松手没反应。
- 反向一条：`material/edit` / `card/edit` **开了刷新且实现了重载** ⇒ 编辑到一半下拉会**丢未保存输入**。
- **建议**：`index`/`hub` 补实现；`material/edit`/`card/edit` 在页面 json 里 `enablePullDownRefresh: false`（`assetEdit` 已这么做 ✅ 照抄即可）。

### ⚪ P2-9 · **导出入口分散**

- 有：M1 结果页、成本卡列表（付费）。无：M2 沙盘、外卖测算、对账。
- 建议：不急着全加，等付费墙口径统一后，按模块各放一个固定位置（都在结果区右下）。

### ⚪ P2-10 · **新用户 0 引导**

- 首页打开就是 4 张卡，M1 要填 40+ 字段，没有任何"第一次怎么用"。
- 建议：「我的」页加 `使用指引`（3–5 行：先建店 → 先录一个月 → 再看菜品卡），成本极低。

## 7 · R194 实施回执（2026-10-03）

### 7.1 途中发现并修复的真缺陷：越权拦截整体失效

- **缺陷**：`cloudfunctions/common/auth.js::assertShopOwner` 用 `fail()` 返回 `{code,msg,data}`
  （**无 `error` 字段**），而全仓 **20 处调用点**统一判 `if (owner.error)` ⇒ 恒 `undefined` ⇒
  **归属校验形同不存在**：任意已登录用户改 `shop_id` 即可读写他人店铺数据（真云可达）。
- **修法**：失败一律返回 `{ error: <code> }`、成功返回 `{ error: null, data: shop }`；
  20 处调用点判据**不变**（它们本来就是对的）。`sync_common --sync` 派生到全部函数目录 `cx_auth.js`。
- **新守卫**：`tools/check_auth_guard_shape.js`（R194，**17 断言**）—— G1 扫描面非退化（单源 + 44 份派生副本）
  / G2 每个 `return` 分支都带 `error` / G3 单源无 `ok()`·`fail()` 残留 / G4 派生副本同形 /
  G5 关键锚点在场（`FORBIDDEN` 分支 + `shop.user_id !== userId`）/ G6 生产调用点判据与形状一致。

### 7.2 包 B：店铺增 / 改名 / 删除

- 新增云函数 `cloudfunctions/manageShop/`（一函数三 op：`create` / `rename` / `delete`），自测 **46/46**。
  要点：`_id ≡ id ≡ shop_id`；删除走 `da.softDelete`（软删、不占额度）；边界「至少保留一家」；
  写库主键一律 `_id` + `stats.updated === 0` fail-loud；三 op 均写 `audit_log`；
  `create` 幂等由 `_id` 确定性派生保证、`rename`/`delete` 走 `findPriorResult` 重放。
- 前端 `pages/shop/switch.{js,wxml,wxss}` 重写：列表行「点名字 = 切店 / 点 ⋯ = 重命名·删除」，
  就地输入（**不跳页、不弹层** —— 弹层 × 键盘是死结）；删当前店时**先切到剩下任一家**，
  否则后续请求会带着已软删的 `shop_id` 集体报错；i18n 双副本（md5 一致）。
- ⚠️ 目标店字段命名为 `target_shop_id`（**不是** `shop_id`）—— `utils/api.js::call()` 会无条件注入**当前店**。
