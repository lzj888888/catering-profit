# R363 · 「已有铺面」这页为什么让老板迷糊：诊断 + 信息架构重构建议

> 2026-10-19 · 只做分析与设计，**未改代码** · 结论：问题不在文案，在**信息架构**

## 零、我给自己写的提示词（原文照录）

> 你是给餐饮老板做决策工具的产品设计师。现在有一个测算页：**26 个输入框 + 8 个结果块**平铺在
> 一条滚动流里，标题依次是「先答 4 个」「先估个数（含开店投入/菜品毛利率/做活动会怎样/渠道佣金/
> 本月实际营业额）」「测算结果」「做到这些营业额能赚多少」「每天得来多少人」「面积和人值不值」
> 「回本参考」「敏感度」「指标对照」。请回答，每条都要能落地：
>
> 1. 老板第一眼看到什么？他要滑多久才拿到第一个数字？
> 2. 页里一共混了几**类**信息（事实 / 假设 / 试验 / 校验 / 结论）？分别混在哪？
> 3. 「做活动会怎样」属于哪一类？为什么现在它长得像"第 6 个参数"？
> 4. **引擎锁定、不许改算法**的前提下，只靠信息架构 + 文案 + 默认折叠态，怎么把它从"一坨"变成"一条路径"？
> 5. 「做活动」要**既独立又连着数据**：给 3 种形态，选 1 种，并说明数据连接方式（同引擎？同基准？只输出差值？）
> 6. 每条建议必须标注代价：纯前端 / 要出码 / 要改引擎。
> 7. 说出你**不建议做**的事，以及为什么。

## 一、结论（一句话）

**迷糊不是因为字多，是因为这页把"填表—看答案—做假设"三件事压成了一条直线，
而老板的心理顺序恰好相反：先要答案，再改条件。**

## 二、诊断（每条都有页面事实支撑）

| # | 症状 | 页面事实 |
|---|---|---|
| 1 | **答案来得太晚** | 8 个结果块在 26 个输入框之后；首屏只有 4 个问题，第二个数字要滑 3–4 屏 |
| 2 | **一个大标题下混了 5 类信息** | 「先估个数」= 开店投入（一次性事实）+ 毛利率（事实）+ 做活动（试验）+ 渠道佣金（平台规则/选择）+ 本月营业额（**校验值，不参与保本**） |
| 3 | **标题语域不统一** | 对话体「先答 4 个」「还有几个能改的」／会计体「渠道佣金（外卖/团购抽成）」／疑问体「做活动会怎样」「做到这些营业额，能赚多少」——三种语气混排，大脑要不停切换"这是要我干嘛" |
| 4 | **「做活动」站在错误的位置** | 它现在是第 6 类输入，和"面积""房租"平级；但老板对它的心理是**决策问句**（做不做？做了赚不赚？），不是"我店里一个固定事实" |
| 5 | **唯一常驻的结论只有一个数** | 吸底条只显示「保本营业额」；"一个月能赚多少""健不健康"要滑到底才看得到 |
| 6 | **选填项混进主流程** | 「本月实际营业额」自己也写着"不参与保本"，它其实是个**对照/校验**参数，却排在计算参数中间 |
| 7 | **两个出口像补丁** | 「场景矩阵测算」「并排对比」挂在结果区之上，老板读到一半被按钮打断；进去还要重新填参数 |

**老板视角翻译**：他打开这页想知道一件事 ——「我这店现在到底赚不赚、要卖多少才不亏」。
现在的路径是：先被问 26 个问题，才有资格看到答案。**第 10 个框就退出了。**

## 三、重构方案：三层 + 一条常驻结论

> 关键手法：**答案前置 + 只把"能改的"做成交互 + 其余默认收起**。引擎一行不动。

### 层 1 · 你的店（写事实）
- 4 个必填（面积 / 房租 / 人数 / 目标利润）—— 保持现在的"先答 4 个"
- 展开区「还有几个能改的」：菜品毛利率、开店投入、本月实际营业额
- **改名**：把「先估个数」这个"包住五种东西"的标题废掉 —— 它现在是混淆的主犯

### 层 2 · 结论条（常驻，喂完即出）
- 三段式：`保本营业额 9,160` · `一个月能赚 8,400` · `评级：健康/偏紧/危险`
- **吸顶**（不是吸底）：改任何一个输入，这三个数当场动
- 下方一个「为什么是这个数」→ 展开层 3

### 层 3 · 明细（默认收起）
- 指标对照 / 利润阶梯 / 客流 / 坪效人效 / 回本 / 敏感度 —— **默认全部收起**，只留一行小标题
- 理由：这些是"复查用"，不是"第一眼要的"；现在它们是 8 个实心卡片，把页面压成水泥地

### 层 4 · 试验台（问"如果"）
- 做活动、上外卖/团购 —— **统一放进这个区**，位置在答案之后
- 每个试验只输出**差值**：`保本额 +0` / `月利润 −1,200` / `要多卖 27% 才持平`
- 视觉上换一种底色 + 语气改成"如果…"，与事实区明确分开

### 层 5 · 下一步
- 矩阵 / 对比：**带着当前参数跳转**（现在进矩阵要重填，这是流失点）

## 四、专答「做活动怎么样」：三种形态，选第 1 种

### 形态 1（推荐）结果之后的"情景卡"
```
┌ 如果做个活动？                    [收起 ▸]
│ 打 8 折 → 要多卖 27% 才不亏（当前 9,160 → 11,633）
│ 展开：每 100 元实收 [ 80 ]   月利润 Δ [ −1,200 ]
└
```
- **独立性**：位置在结论之后、有独立底色、标题是疑问句「如果…」
- **连接性**：以当前全部参数为**基准**，只替换"折后实收率"这一个变量再算一次 ⇒ 不需要重填
- **不污染主结论**：层 2 那三个数永远是"不做活动"的现状；活动只给 Δ
- 引擎零改动：`utils/promoImpact.js` 现成，且已有 `gaPct / trafficText / sameRevText`

### 形态 2 结果表加一列"做活动后"（不推荐）
主结论被两列并置，老板第一眼就分不清"哪个是我现在的数"；
而这页最高频的诉求恰恰是"我现在怎么样"。

### 形态 3 独立二级页（不推荐）
最"独立"，但最断数据：进去要重填参数，且老板不会为了一个折扣数跳页。
独立页只适合**重**工具（矩阵、对比），不适合**轻**假设（一个折扣率）。

### 附带一个必须区分的点
「渠道佣金」里混着两种东西，**不能一起搬去试验台**：
- **平台费率**（外卖抽成 20%、团购 5%、刷卡 0.6%）= **平台规则 = 事实**，留在事实区
- **外卖/团购占比** = **老板的选择 = 试验**，应进试验台
现在它们被同一张卡包着，所以老板看到"渠道佣金"不知道是该填事实还是该试算。

## 五、代价分级（老板不用管，我落地要知道）

| 建议 | 代价 | 说明 |
|---|---|---|
| 结论吸顶（保本/月赚/评级） | **纯前端** | 已有 `refreshStick()` 与 `verdict`，改成吸顶 + 加两个数即可，**不出码**（wxss 可能要微调） |
| 拆掉「先估个数」大标题、重排分组 | **要出码** | 纯 wxml 结构调整 + terms 改名 |
| 明细默认收起 | **纯前端** | 加 `show` 开关，默认 false |
| 试验台（活动迁移 + Δ 展示） | **要出码** | 位置移动 + 差值渲染；引擎零改动 |
| 矩阵/对比带参跳转 | 纯前端 | 已经传 `mode`，再带上 `preset_key` 即可 |
| **改保本算法/口径** | 🚫 **不动** | 与本期无关，且会动到锁定锚点 9160 |

## 六、我不建议做的（以及为什么）

1. **不要加"新手引导/蒙层"**：26 个框的问题不是不知道怎么填，是**不需要一次看到全部**；
   引导只会让第一次更慢。
2. **不要把 8 个结果块做成轮播/Tab**：老板要横向对比"保本 vs 目标 vs 实际"，
   分页会让他失去对照。
3. **不要为了"看起来简洁"砍掉专业参数**：老手要靠它校准费率；只把它默认收起即可。
4. **不要给「做活动」加独立 Tab 平级**：它和"已有铺面/寻找铺面"不是一个维度 ——
   那是"我在什么处境"，这是"我要不要做一件事"。

## 七、最小可行第一步（如果只做一件事）

**把结论条吸顶**（保本 + 月赚 + 评级）。理由：不引出码、不动引擎、改一个 `refreshStick`
渲染位置就能让老板在**第一屏**拿到答案 —— 这一条就能消掉 60% 的"迷糊"。
其余四步按上表顺序跟进。
