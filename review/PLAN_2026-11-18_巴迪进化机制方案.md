### 0.2 要不要装 GitHub 上的记忆 skill？——**现在不装，理由如下**

我确实搜了（不是空谈），候选有 5 个：

| Skill | 卖点 | 我的判断 |
|---|---|---|
| **文档即记忆**（agent-doc-memory） | 记忆做成能读能改能提交的文档，干活前先查、干完更新 | 最贴合我们的工作流，但**和仓库 `review/` + 重启键文档做的事重复** |
| 跨会话记忆捕获（session-memory-capture） | 观测→压缩→分层检索 | 我们已经有 Cloud Memory 自动注入 + conversation_search |
| 记忆管理 Self-Improving Agent | 记住/回忆/复盘/体检四动作 | 和已有 `self-improvement` + `memory-setup` 重叠 |
| WorkBuddy记忆管理大师 | 四层记忆 + 25 条 CLI + 敏感脱敏 | 能力强，但**又造第四个真相源** |
| 跨会话记忆引擎（supermemory） | BM25 召回、偏好/项目分类 | 与 `space-library` / `conversation_search` 功能重叠 |

**不装的真正理由**：我们的痛点是**纪律和可见性**，不是"没有记忆工具"。我们现在已经有 3 层记忆（云端注入 / 用户级 / 工作区）+ 重启键文档 + 一堆 skill。再装第四个，短期好看，长期一定会出现"到底哪份是真相"——这正是本仓反复吃亏的"两份真相"病。

**什么时候我会改主意**：如果有一天实测出现"我明明写过但下次完全想不起来"，且查遍现有 3 层都找不到，那才说明缺的是检索能力，届时我建议装 **文档即记忆** 而不是那几个花哨的。

## 1 我的进化方案：四个零件（3 个今天就能落，1 个已经跑着）

### 零件一：决策台账（新）
**文件**：仓库 `review/DECISION_LOG.md`（append-only）

每条 5 行，不多写：
```
## 2026-11-18 · G1 跨月分摊
- 问题：区间表 biz_date 记末日 ⇒ 跨月整段归次月
- 证据：引擎实跑 查10月=0/查11月=700
- 我主张：分摊+尾差倒挤；反对"相交即全额计入"（会两月都虚高）
- 谁拍板：李老师"听您的"
- 状态：已修 f986219 / 守卫 21 条 / 变异 3/3
```
**解决什么**：防止同一个问题在三个月后被重新讨论一遍——"当初为什么这么定"有据可查，不用翻聊天。

### 零件二：错误模式库（新）
**文件**：仓库 `review/ERROR_PATTERNS.md`（append-only）

每条固定四段：**症状 → 根因 → 触发条件 → 防呆手段**。今天先入 6 条（都是真踩过的）：

| # | 症状 | 根因 | 防呆 |
|---|---|---|---|
| E1 | 探针返回 null/NaN 就下结论 | 字段契约猜错（value_fen vs total_value） | 契约不对先怀疑自己；`抽不到就 exit 2` |
| E2 | U盘/仓库文件复制错位 | robocopy 源参数传错，exit code 还是成功 | 复制后必核**数量+体积** |
| E3 | 整文件行尾被翻写 | Python 读全文→写全文 | 大文件只用 Edit 精改；看 `git diff --numstat` |
| E4 | 网页表单打进错误输入框 | 靠截图目测坐标 | 表单只做"打开+读原因"，输入交给您 |
| E5 | 中间插套件顶掉后面序号 | 新增套件位置错 | 一律**追加到 SUITES 末尾** |
| E6 | 后台任务被杀只剩 .lock | git bundle 放后台 | 长任务前台跑+足量 timeout |

### 零件三：记忆回执（硬规矩，今天起）
每次收尾最后一段**显式写**：
```
记忆：已写入 <具体文件>（写进去的是 <一句话>）
```
这一条直接解决您"最近很少看到提示"的问题——不是多写记忆，是**让您看得见我写了什么**。

### 零件四：闭环（已在跑，继续）
**审计 → 修复 → 守卫 → 变异回灌 → 契约同步 → 门禁**

这轮 G1/G2 已经完整走了一遍。以后凡是"改计算口径"的，一律走这个闭环，不搞"改完就跑门禁绿了算完"。

## 2 针对"反复改升级"的五条纪律（我会自己守）

1. **开工前三扫**（已有 skill `preflight-no-false-start` S9）：扫已有字段 / 已有门控 / 已有方法 / 已有技能，并回答"如果仓库里已经有了，它最可能叫什么名字"。答不上来不许开工。
2. **数字必须生产引擎实跑**，不手算、不照源码推演；探针返回 null 先怀疑契约。
3. **后端能力 ⊇ 前端入口**：任何"后端支持但 picker/按钮不放行"都算真缺口（G2 就是这类，且仓库早记过同类风险却没守卫）。
4. **契约 ≡ 实现四处同步**：代码 / 契约文档 / 重启键套件数 / 新守卫入 git 索引——漏一处门禁自己会红，别等复审方指出。
5. **不静默跳过**：没做的、存疑的、被我推翻的，都写进"未完成/存疑+理由"。
