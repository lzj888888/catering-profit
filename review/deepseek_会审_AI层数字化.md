# 一、可行性裁决

**可行，但只做「规则引擎先行」的 AI 解读层，不做开放对话式大模型。**

理由：底座齐（口径锁、anomalyRules、aiGate、cx_indicatorRef 都在），缺的只是「规则→人话」这一层，工程量小、风险可控。

**最大两个风险：**

1. **合规/出境风险**：aiGate 已建但 0 处真调，一旦接 LLM，经营数据（营收、成本、客单）出境即触发授权四态。任何「默认开」「静默传」都是红线。必须 fail-closed：无授权→纯规则输出，不降级不兜底。
2. **口径漂移风险**：LLM 润色时最容易「顺手补个行业均值/损失金额」。这是编造数字，直接违反单源。必须物理隔离——LLM 只拿「已算好的结论句」改写措辞，**不拿原始数字、不参与计算、不允许新增任何数值**。

# 二、架构方案

**推荐：混合，但 LLM 是可选末环，可整段摘除。**

数据流（单向、fail-closed）：

```
M1/M2/M3 结果（已锁口径的数值对象）
  → 智库规则匹配（纯函数，输入=结构化指标，输出=命中规则ID+定性结论+联动模块）
  → 模板渲染（结论句 + 边界声明，数字全部来自单源对象，占位符填充）
  → [可选] LLM 仅做措辞润色：输入=已渲染文本，输出=同义改写，数值白名单校验，含新数字则丢弃回退原文
  → 输出（定性 → 可控动作 → 工具测算入口）
```

**守口径三原则：**
- 数字只从单源对象取，规则与模板都不算数，只引用。
- LLM 输出做数值白名单比对，出现模板外数字→整段回退模板原文（fail-closed）。
- 每条输出强制附边界声明（「基于本店历史，非行业基准」）。

**MVP 边界：**
- 只读 M1/M2/M3 已有结果，不新增采集。
- 规则库纯配置化（JSON），版本化，可回滚。
- 无 LLM 也能完整跑通；LLM 开关默认关，授权后才开。
- 不做多轮对话、不做自由问答、不做跨店聚合。

# 三、分期路线

**第一期（1–2 周）：**
- 做：规则引擎骨架 + 模板渲染 + 边界声明 + 5–8 条规则 + 结果页入口（挂 M1/M2 结果页）。
- 不做：LLM 接入、对话、RAG、跨店、复购/淡旺季/储值因子、任何新指标采集。

**首批 5–8 条规则（高频 + 现有数据可判 + 不越界）：**

1. **结构性营收不足 vs 原生流量不足**：用客单×毛利率 vs 每客固定成本判定（GPC 锚点，M2 已有）。
2. **毛利率异常**：本店销售毛利率 vs 自身历史中位数（anomalyRules 复用）。
3. **盈亏平衡未达**：M2 反算缺口，定性「差在量还是差在价」。
4. **菜品四象限失衡**：M3 高毛利低销/低毛利高销占比提示（只定性，不报损失额）。
5. **外卖渠道侵蚀**：渠道层扣点后毛利 vs 堂食，定性「渠道是否吃利润」。
6. **成本卡缺失/不全**：BOM 完整度检查，提示测算不可信。
7. **单店 vs 多店**：第 2 店付费墙触发时，给「先验证单店模型」定性，不承诺扩张收益。
8. **储值/现金流**（可选因子，仅提示录入，不判定）。

每条规则字段：触发条件、联动模块、结论模板、边界声明、版本号。

# 四、商业模式咬合

**推荐：AI 解读「定性层」免费，「测算+动作清单」进付费域。**

- 免费：命中规则的定性结论 + 边界声明 + 引导入口（引流，不破坏漏斗）。
- 付费：联动到具体测算（M1 真拦、套餐/外卖/全菜单诊断、M3 毛利榜）才展开动作清单与数字推演。
- 矩阵导出维持免费引流不变。
- LLM 润色属体验增强，**不单独收费、不设付费墙**，避免「为措辞付费」的观感。

**咬合原则：** AI 层只做「指路牌」，不替代任何付费测算；免费定性必须能自然导向一个付费动作，否则不算合格规则。
