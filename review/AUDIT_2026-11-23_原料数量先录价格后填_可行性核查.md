# 「原料数量先录、价格后填」可行性核查（2026-11-23）

> 李老师问：菜品成本卡 / 原料库 支持**数量先录、价格完全不填**吗？会报错吗？（明确不是填 0，是完全不填）
> 方法：读校验与计算链路 + **node 桩跑 `buildCalcLines` 四场景实测**（不是推理）。证据见文末。

---

## 一、结论（先看这个）

| 位置 | 价格完全不填 | 会报错吗 | 结果 |
|---|---|---|---|
| **原料库**（新建/编辑原料） | ✅ 支持 | **不报错** | 存 `purchase_price_fen = 0` |
| **成本卡 · 手工录入行**（自己填单价） | ⚠️ 数量填了、单价空 | **会中止**，但弹的是「**用量**」 | 提示词**错位**（实际是用量填了、价格没填） |
| **成本卡 · 引用原料行**（从原料库选） | ⚠️ 不报错 | 不报错 | 按 `net_unit_cost = 0` **计入**，成本算 0 |
| **成本卡 · 混合**（一行有价一行没价） | ⚠️ 不报错 | 不报错 | 没价那行被**静默丢弃**，成本偏低 |
| **毛利率显示** | — | — | 成本为 0 时**不显示**（不会出现"毛利 100%"假象）✅ |

**一句话**：原料库可以放心先不填价；但进了成本卡，"只填数量不填价"**目前走不通**——要么被一句错位的"用量"提示挡住，要么静默把成本算低。

## 三、三个真问题（按危害排序）

### ① 提示词错位：缺价格却弹「用量」
`card/edit.js:1620 buildCalcLines` 末尾：
```js
if (out.length === 0) { warn(TERMS.card.qty); return null; }   // TERMS.card.qty = '用量'
```
手工行单价空 ⇒ `manualNetUnitWan(...) = 0` ⇒ `if (wan <= 0) continue;` 跳过整行 ⇒ `out` 为空 ⇒ 弹「用量」。
**老板会去改用量，改多久都没用**——真正要填的是单价。这是引导性错误，比不提示更糟。

### ② 引用行价 0 静默按 0 计入（无任何提示）
```js
} else {
  if (!l.material_id) continue;
  const m = this.data.materials.find((x) => x.id === l.material_id);
  if (!m) continue;
  out.push({ quantity: qtyBase, net_unit_cost: m.net_unit_cost, ... });  // ← 不判 > 0
}
```
原料价没填（=0）⇒ 该原料成本贡献 0 ⇒ **整张卡成本偏低、毛利率虚高**，页面零提示。
对照：手工行有 `if (wan <= 0) continue;` 的兜底，**引用行没有**——两条路不一致。

### ③ 混合场景静默丢行
场景 4 实测：一行有价、一行没价 ⇒ 提交给引擎的只有 1 行。**没有任何提示说"有一行没算进去"**。
老板看到的是"成本 ¥X、毛利率 Y%"，但 Y% 是基于残缺成本算的。

### 已有的保护（不算问题，但要说清）
- `marginTextOf(costFen, priceYuan)`：`if (!(p > 0) || !(costFen > 0)) return ''` ⇒ 总成本为 0 时毛利率**留空**，不显示 100%。
- `card/edit.js:1509`（R383）：`lines` 为空时不许试算，防「成本 ¥0.00 · 毛利 100%」假数。
- 列表页有 `unpricedCount` / 「待补价」条目（`card/index.js:275`），但判据是 `bandOf(margin) === none`，即「**售价或总成本缺**」，**不等于**「某行原料价缺」。

## 四、如果要支持「先录数量、后补价」，建议怎么改（按性价比）

| 优先级 | 改动 | 理由 |
|---|---|---|
| **P0** | 修正提示词：`out.length === 0` 时区分「用量没填」vs「价格没填」，后者给「有 N 行还没填单价」 | 现在的「用量」是误导，成本最低、收益最大 |
| **P1** | 引用行补 `net_unit_cost <= 0` 的检测，与手工行对齐（至少给一次提示，别静默按 0 算） | 消除"成本偏低但看起来正常"的静默错误 |
| **P1** | 行级「价格待补」标记（输入框旁小标签）+ 卡片级汇总「N 行未定价」 | 让"先数量后价格"变成**可见的中间态**，而不是隐形的错 |
| **P2** | 保存时若存在未定价行，允许保存但显式提示「成本为估算下限，补价后更准」 | 保住"先录入"的诉求，同时不误导 |
| **P2** | 列表/详情页对"含未定价原料"的卡加灰标（复用 import 的「待补价」视觉语言，`terms.js:2438`） | 口径统一，不新造术语 |

> ⚠️ 涉及口径决策（"允许带未定价保存" vs "必须填全才能存"），属产品判断，**不擅自实装**，等李老师定。
