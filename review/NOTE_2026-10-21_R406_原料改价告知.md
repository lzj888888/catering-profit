## 0 一句话

原料改价保存后，**不再静默返回列表**：先探一次「有几道菜用到它」，再如实告诉老板「成本卡里还是旧价、不会自己跟着变」，并给一个直达既有只读影响面页（`pages/metrics/impact`）的入口。

## 1 为什么不能照豆包原文落码（本轮最重要的判断）

豆包 O5 拟的文案是：

> 改价后弹「所有用该原料的菜成本已自动更新」

**这句在本仓是假承诺。** 证据在云函数自己的头注里：

`cloudfunctions/syncCostCard/index.js:4-5`
```
//   **生成新版本**（version+1），旧版本保留可查。引导前提：改原料价后，旧卡成本不变（快照隔离）；
//   只有手动点本函数才更新，且产生新版本。
```

即：成本卡明细行是**快照**，改 `saveMaterial` 的采购价**不会**回写任何已保存的卡。要让成本跟上，只有两条路：

1. 在成本卡列表页手动「同步至最新价」（单张 `onSync` / 批量 `onBatchSyncRun`，`pages/card/index.js:456-499`）；
2. 重新保存该卡（`saveCostCard` 取当前价重建快照）。

所以照抄原文的后果是：老板看到「已自动更新」⇒ 认为成本对上了 ⇒ 按**没变的旧成本**继续定价 / 算毛利。这属于「让老板算错」，比不提示更贵。按队列优先级规则第 1 条，这类问题排最前。

⇒ 本轮实际落的文案是**说实话**：
- 有影响：`用到这个原料的 N 道菜，成本卡里还是旧价 —— 成本卡不会自己跟着变。要看这次涨价影响多少吗？`
- 探不到数：`用这个原料的菜，成本卡里还是旧价 —— 成本卡不会自己跟着变。要看影响面吗？`
- 按钮：`看影响面`（4 字）/ `先算了`（3 字）—— 平台硬限制 ≤4 字符。

## 2 改了什么

### 2.1 术语文案（i18n 双副本）

`specs/dev-specs/i18n/terms.js` ≡ `miniprogram/i18n/terms.js`（按字节同步，md5 一致、纯 LF）：

| 键 | 用途 |
|---|---|
| `matPriceSaved` | 弹窗标题「原料价已保存」 |
| `matImpactAsk(n)` | 有 N 道菜用到时的话术 |
| `matImpactAskUnknown` | 探不到影响数时的通用话术 |
| `matImpactGo` | 确认按钮「看影响面」 |
| `matImpactSkip` | 取消按钮「先算了」 |

### 2.2 `pages/material/edit.js`

- 新增模块级 `costKeyOf(priceFen, convertFactor, yieldRate)`：把**影响成本卡成本的三要素**拼成可比较的键。
  为什么是三要素而不只是价格：成本卡快照里存的净料单位成本 = 单价 ÷ 换算系数 ÷ 出成率。老板把「1 件 = 20 公斤」改成「= 25 公斤」时单价一分没动，但每克成本已经变了 ⇒ 只比价格会漏提醒。只改别名 / 备注 / 分类（不进成本）时不打扰。
  为什么用「分」整数而不是 `priceYuan` 字符串：`'20'` 与 `'20.00'` 是同一个价，字符串比较会误报「改了」⇒ 变成一路弹窗骚扰。
- `data.origCostKey`：编辑态加载时记基线，且**取表单即将呈现的值**（库里缺字段时表单会回落 100/建议换算，拿裸值做基线会让「什么都没改」被判成改了）。
- `onSave` 编辑态分支拆两路：
  - 三要素没变 ⇒ 原行为（toast 已保存 + 返回）；
  - 三要素变了 ⇒ `tellPriceImpact()`。
- 新增 `tellPriceImpact()`：
  - 先调 `syncCostCard{ material_id, dry_run: true }` 探影响数（**只读、零写库、零新版本、不计写限额**，见 `syncCostCard/index.js:51-53`）；
  - `n === 0` ⇒ 不弹（没有菜用到它，说"不会变"是废话），直接 toast + 返回；
  - `n > 0` ⇒ 弹带数量的话术；探数失败（`n === -1`）⇒ 弹不带数量的通用版；
  - 确认 ⇒ `wx.redirectTo` 到影响面页（**用 redirectTo 不用 navigateTo**：表单已存过，留在栈里会让"返回"退回一个不该再填的页面，与 round156「改完即走」同一条纪律）；
  - 取消 / modal fail ⇒ `navigateBack()`（不能把老板困在「已保存但仍显示为编辑中」的表单上）。

### 2.3 fail-soft 的边界（想清楚才敢这么写）

- 探数失败**不等于 0**：`n = -1` 单独分支。「成本卡不会自己跟着变」这句话与影响数无关、永远成立 ⇒ 宁可多说一句，也不许让老板误以为已自动更新。
- 唯一「不弹」的分支是**确实读到 0 道菜**。
- 保存已成功，`tellPriceImpact()` 外再包一层 `.catch(() => {})`：任何异常都不许冒到外层 catch（外层会把成功渲染成"保存失败"，那是假话）。

## 3 判据与反恒真

3. **真告知**：`tellPriceImpact` 函数体内有 `wx.showModal(`、有 `dry_run`、跳 `/pages/metrics/impact`。
4. **无假承诺**：话术禁词表（`已自动更新` / `已自动跟着变` / `已跟随更新` / `成本已更新` / `自动同步完成`）；且必须含「旧价」（只说"要看影响吗"而不说现状 = 半个告知）。
5. **按钮合规**：两个按钮 ≤4 字符 —— 用变量引用时 `check_modal_button_len` 抓不到字面量，只能自己守。
6. **双副本一致**：terms 两份逐字节相等。

反恒真两层：
