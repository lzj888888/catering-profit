## 一、P0：修掉方向性错误（固定成本扣了两次）

### 改前（错）
```js
invest  = 一次性投入 + 日均固定成本 × 天数
netDiff = 毛利差 − invest
```
固定成本提示写的是「房租＋固定人工」——**做不做活动这笔钱都要付**，在「活动相比不做多赚/赔多少」的增量口径里两边抵消，不该再扣一遍。

实测：原日流水 8000、毛利 60%；8 折后 50%；7 天预计日流水 11000；房租人工 800/天；海报 500：

| | 结果 |
|---|---|
| 改前 | **赔 1200** |
| 改后 | **赚 4400** |
| 差 | 5600 = 800×7 |

### 改后
```js
invest  = 一次性投入            // 只扣这次活动专属花的钱
netDiff = 毛利差 − invest
```
- 删掉「每天固定成本」输入框（`fixedCostPerDay` 从页面 data / TOP 字段 / 传参中全部移除）。
- 「一次性投入」提示改为「宣传、物料、达人探店等**只为这次活动花的钱**，没有填 0；**不含房租和固定人工**」。
- `promoEffect` 不再读 `fixedCostPerDay`（外部硬塞该键也不生效，K-⑯ 反恒真钉住）。

四方一致：我方独立复核 + 功夫 + 豆包 + 4 个权威案例（Top Growth Marketing / CasesCoach / 电商 ROI 框架 / 零售清仓优化），全是增量口径。

## 二、P1：①段防误导 + 基线引导

- ①段大字折扣下加一句：**「这只是价格折扣，不代表划算。要判断做不做，往下填完『是赚还是赔』。」**
  - 既不设毛利率门槛（8 折就是 8 折，豆包二轮已改口站功夫），又不让老板只看大字就做决定。
- 「现在日流水」提示改为：**「填了才算得出赚还是赔。不知道就翻最近 7 天收款记录算平均，或：每天接单数 × 客单价」**
  - 不给默认值（基线错 1000，结论可能从赚变赔）；不给主观三档系数（"忙/闲"没有统一基准）。
- **基线留空时效果区保持 null**，显示「⚠ 填『现在日流水』才能算赚还是赔」——不是 `ok:false` 那种"算错了"的报错。
  - 这是页面桩实跑抓出来的：`back.ok` 在缺流水时仍为真（只算出"涨几成"），原来会拿 `Number('')=0` 进引擎得到一个 `badInput` 对象，显示成"算错了"。已修。
