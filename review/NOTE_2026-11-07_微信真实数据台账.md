## 3 🔴 最重要的发现：渠道拆分不用等任何人

李老师一直说「团购核销、外卖，各平台都有销量」，而 `营收日报表` 证明**老板自己每天就在按渠道记**：

| 渠道 | 9.1–9.5 五天合计 |
|---|---|
| 现金 | 1,033.00 |
| 充值（预存，非收入） | 8,808.00 |
| 扫码 | 13,748.40 |
| **美团团购** | **2,020.00** |
| **抖音团购** | **274.80** |
| **美团外卖** | 189.46 |
| **京东外卖** | 271.33 |
| **淘宝闪购** | 944.82 |
| 茶楼 | 140.00 |
| 会员消费 | 8,345.00 |
| 营业收入 | **23,589.40** |

（营业收入五天 = 4539.5 + 4476 + 5514.5 + 4878 + 4181.4 = **23,589.40**，逐日可复算）

**这意味着**：
1. 要「各渠道赚多少」→ **不需要等平台核销明细**，老板这张表就是答案
2. 要「哪道菜赚多少」→ 用平台商品表（淘宝 / 美团 / 京东订单导出）
3. 要「团购的菜品级」→ 收银《套餐销售明细》里有「美团团购-xxx套餐」（见 §4）

### 但有三处必须先问清楚，不能猜

1. **营业收入 23,589.40 的口径**：9.1 早班「现金121 + 扫码1410 + 茶楼70 + 会员消费1238.5 = 2839.5」，
   但表里写营业收入 **2381**。差额 458.5 —— 说明「会员消费」里有一部分是储值扣款（非新增收入），
   或与扫码有重叠。**这套算法是老板自己的口径，我不能反推成公式。**
2. **充值 8,808 是预存还是收入**：本仓现有规则是预存不算当月收入（权责发生制），但老板表里
   「合计 23,589.40」是否已排除充值，需要确认。
3. **只有 9.1–9.5 五天有数**，9.6 之后连续 26 天全 0 —— 是「没营业」还是「没记」？
   从连续 26 天为 0 看，几乎肯定是**没记**。这本身是个产品洞察：
   **老板手工记账坚持不下来，正是小程序要接管的事。**

## 4 团购的菜品级：收银《套餐销售明细》里有

`pos_combo_detail_20260907-0913.xlsx`（73 行）第 4 行数据：

```
菜品编码 9983003356
套餐     美团团购-【免费停车】火锅4人餐｜耙牛肉+耙牛筋+耙肥肠
单品名称 小料
菜品类型 普通菜   单位 --   菜品大类 锅底
销售数量 8   销售额 25.66   菜品优惠 3.2   菜品收入 22.46
```

**套餐名里直接写着「美团团购」** —— 这是目前唯一能看到「哪笔是团购来的」的表。

但它是**形态 B，被主动拒收**，理由写在代码里：套餐组分**已并入**菜品销售表
（`dining_pos` 那份参数行写着「销售方式：单品+套餐明细」），两表相加会双计。

**所以正确用法不是「导入」，而是「归属」**：
用它的「套餐 → 单品」关系，给菜品表里对应行打上「来自团购」的标记，而不是另算一遍金额。
**这需要一轮专门设计（父-子行关系 `combo_parent`），本轮不做。**
