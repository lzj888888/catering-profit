# 三司会审议题：店算小程序「AI 层 + 餐饮常见问题数字化」可行性与方案

## 背景（真实代码现状，已实地核查，勿按想象答）
- 产品「店算」微信小程序（云开发），三模块：M1 月度实际利润核算（双场景口径锁：库存关=手填消耗参考利润 9160 / 库存开=倒轧 8160）、M2 开店盈亏矩阵（正算/反算/矩阵/多候选对比，永久免费，含营销套餐沙盘）、M3 菜品成本卡 BOM + 菜品四象限 + 外卖渠道层（淘宝闪购/美团/京东）。
- 已有底座：`cx_indicatorRef` 分业态×城市层级参考带（M2/M3 已用）；`anomalyRules` 异常核对清单（版本化、fail-closed、只比本店历史中位数，已接 M1 结果页）；`aiGate.js::canSendToModel` + `grantAiConsent/revokeAiConsent/getAiConsent`（AI 数据出境四态授权闸门，已建但**全仓 0 处真调模型**）；M3 菜品四象限页已上线。
- 多店铺：一个微信号可建多店，第 2 家店付费墙已实现（free_limit=1）；shop.biz_type 业态字段已存在；跨店聚合（chainMerge 钩子已留未接）。
- 付费墙红线：M1 一家店真拦、套餐/外卖/全菜单诊断进付费域、矩阵导出有意免费引流。口径单源、fail-closed、绝不编造行业基准/损失金额。

## 已收敛的前期结论（来自与豆包的长对话，观点汇总见附件要点）
1. **轻量结构化智库**（指标字典 + 条件→结论诊断规则库）现阶段做；完整 RAG/向量智库暂缓（触发条件：付费用户 200+ 或规则不够用）。
2. 「餐饮专家」价值 = 护栏+标尺+行业锚点，vs 通用 AI 甩数据有本质区别。
3. 常见问题数字化题库 18+ 条（营业额不好/扩张/撤店/选址/营销/菜单/现金流/储值/淡旺季/复购…），每条规则带：触发条件+联动模块+边界声明。
4. 原创指标「客利润/单客盈利锚点」（GPC=客单价×销售毛利率）+ 每客固定成本 → 打通 M2 盈亏平衡。
5. 博主观点（剑哥聊餐饮）入库必须：二次原创、口径校验（销售毛利率 vs 成本毛利率、POC1/2/3 对齐）、触发条件绑定数据、冲突舍弃。
6. 复购/淡旺季/储值 = 可选校验因子（不填不影响核心算账）。
7. 输出三层：诊断定性（结构性营收不足 vs 原生流量不足）→ 可控动作 → 工具测算。所有 AI 输出带边界声明，禁止编造数字。
