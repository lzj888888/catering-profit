## 一、诚实评级：为什么「解决方案」是唯一不能拖的一项

延续上轮六维评级（🟢 可靠 / 🟡 待补 / 🔴 缺失）：

| 维度 | 评级 | 说明 |
|---|---|---|
| 数据来源可靠性 | 🟢 | 全用老板自己录的账，不引入外部估值 |
| 结论可核对 | 🟢 | 近 N 月利润明细 + 数据截止可见 |
| 防自欺 | 🟢 | 数据不足不给分、缺项不按 0 算、单档重大食安 |
| 阈值科学性 | 🟡 | 分业态阈值已校准，但「连亏」口径仍打架（见 S1） |
| 通俗度 | 🟡 | 术语已改人话，需真机复验 |
| **可执行性（给动作）** | 🔴 | **引擎一个动作都不输出**；结论到「房租占 18%」就停 |

🔴 这一项和其他五项**不是并列关系**：前五项做得再好，只要不给动作，产品就还是「体检报告」而不是「智库」。
体检报告谁都能出，智库值钱在处方。**所以下一阶段全部资源压在这一项，不是给它加个功能，是补上立身之本。**

## 二、主线：三层递进（有先后，不是三件并列的事）

### S1 · 先让结论可信（地基，必须先做）

动作要挂在结论上；**结论自相矛盾，给的动作就是错的**。两件待清：

1. **#132 连亏口径打架**：连亏项用固定「可扛 4/5 个月」，现金流项用「现金 ÷ 月均净亏」。
   同一页可同时出现「能撑 8 个月」和「连亏 6 个月已超上限」两个相反结论 ⇒ 工具当场失信。
   需先统一到「现金可撑月数 + 失血率」一个口径，再谈动作。
2. **覆盖率 50%「数据不足」**：补录链路双根因已修并部署，但**真机尚未复验**。
   必须先确认「补录 → 保存 → 返回 → 覆盖率上升」这条路真通，否则处方建在空结论上。

> S1 产出：**一个可信、不打架、能随补录更新的结论**。这是 S2 的输入。

### S2 · 把弹药接进枪膛（本阶段主线 = 处方层）

#### ⚠️ 前置卡点：一条被「扩大解释」的旧底线（现场查到，先裁决再动手）

- `cloudfunctions/common/diagnosisEngine.js:18` 把「**输出不给行动指令**」列为三条设计底线之一，
  标注「违反即驳回」，理由「给数字 ≠ 替他做决定」，并引用规范 §12.7。
- **回查 §12.7 原文**（`review/收费与权益_总设计师规范_20261105.md:447`）实际只禁三类：
  算命/运势类措辞、绝对化承诺（「一定能救活」「保证不亏」）、「食材成本率」对外；
  兜底句是「仅供参考，经营决策请结合实情」。**没有任何一条禁止「给带数的改善动作」。**
- ⇒ 「不给行动指令」是当年实现时把「**替他做终局决策**（建议闭店、判生死）」
  与「**给可执行选项 + 依据**（房租占 18%，可谈降租 / 提坪效）」混为一谈的扩大解释。
  智库三元组的「动作」列本来就全是后者，从来不是前者。
- 全仓 `tools/` 检索：**零守卫**守这条，纯注释约束 ⇒ 改它不会连带门禁，但属**产品口径变更**，按规矩先拍板。

**建议裁决（不推翻底线，只划清边界）**：

| 仍然禁止（底线保留） | 允许新增（本次要做的） |
|---|---|
| 「建议闭店 / 该关了」等终局判决 | 基于他自己账的改善动作 + 量化依据 |
| 「一定能救活 / 保证不亏」绝对化承诺 | 「按当前数字，改善到 X 可打平」的条件句 |
| 无依据的通用鸡汤（「注意控制成本」） | 带业态边界、带不适用说明的规则表条目 |
| 生成式 AI 自由发挥 | 预设规则表，可追溯、可复核、可进门禁 |

配合智库 §十一的兜底句「本诊断基于你录入的经营数据与预设经营规则自动匹配，不构成生成式 AI 建议」，
责任边界反而**比现在更清楚**：给的是选项和依据，决定权仍在老板手里。

智库里**已有一份现成的处方库**，不是要从零编：

- `智库规则体系_三元组合并扩充版_20261104.md`：每条规则有「触发条件 / 结论基准 / **动作** / **边界（不适用）**」四列。
  例：房租占比 > 15% → 「谈降租 / 提坪效」；生存月数 < 3 → 「立刻砍固定成本、别做大动作」；连亏 3 月 → 「换菜单/品类/定位」且注明「3 个月内可能是季节因素，再看看」。
- `review/PLAN_2026-10-30_31条诊断规则_分组裁决.md`：31 条规则哪些有数据、哪些该转话术、哪些不做进产品，已裁决完。

**当前缺口 = 引擎一个动作都不输出，页面一句都没渲染。** 是接线问题，不是资料问题 ⇒ 成本可控、感知最强。

#### 什么才算「解决方案」（五条硬标准，缺一条就是正确的废话）

1. **带数**：不说「谈降租」，说「房租占 18%，同业态警戒 15%，降到 15% 每月约省 ¥X」——**用他自己账里的房租和营业额现算**。
   智库的动作是通用句，接进产品必须用他的数落地，否则还是鸡汤。
2. **分级**：动作按生存月数分档（智库 V断-3 已有）：< 3 月「别做大动作、先砍固定成本」／3–6 月「可试 1–2 个动作」／> 6 月「别慌，按优先级慢慢调」。
   同一条「房租高」，快断粮的店和账上 50 万的店，处方**不该一样**。
3. **有边界**：业态不适用要说（火锅/烧烤共点强场景，引流菜别乱涨价缩份）、季节因素要说（连亏 3 月内先观察）。
   智库三元组的「边界」列是现成的，别丢。
4. **可追溯**：动作来自**预设规则表**，每条能指回「依据你填的哪一项 + 那个数」。
   🔴 **不做生成式建议**——李老师一贯要求数字可复现、不采信自述；规则表可复核、可回归、可进门禁，生成式不行。
5. **合规兜底**：诊断底部固定带「本诊断基于你录入的经营数据与预设经营规则自动匹配，不构成生成式 AI 建议。」
   （智库 §十一 明写，全部前端/话术必须带。）

#### 顺带解决的两件事

- **付费墙的价值锚**：免费给「你哪不行 + 最该动的一项」，付费给「分几步走 + 每步省多少钱 + 全部短板处方」。
  现在付费卖「精度与拆解」是虚的；**动作才是老板愿意掏钱的东西**。S2 定型后 #131 才有得切。
- **结论页不分组**：维持上轮判断，按「丢分 × 权重」排序本身就比分组更有指导性；风险信号单独一栏。

### S3 · 从单次诊断到持续陪伴（v1.1+，**明确不进上线**）

- 月度趋势进处方：这个月房租 18%、上月 15% ⇒ 处方应是「谈租约」而非「提坪效」。
- 动作回执：做了没、下月数据有没有改善（需 ≥3 个月账）。
- 这两项是数据飞轮，但没有账龄就是空中楼阁 ⇒ **不进 15 天上线，不摊大饼**。

## 三、取舍：明确「不做」的四条

| 不做 | 理由 |
|---|---|
| 不做生成式 AI 建议 | 合规护栏 + 可复现要求；动作必须来自可回归的规则表 |
| 不新增录入字段 | 处方层纯接线 + 用已有账算数，零新增填写负担 |
| 结论页不做分组展示 | 排序比分组更有指导性；补录页可按钱/店/底三组折叠降低填写疲劳 |
| 不新增第二个弹窗 / 不新增付费墙类型 | 上一轮裁决：啊哈时刻已在免费域，付费点保持现状四类 |

## 五、验收判据（怎么算「做完了」，不靠自述）

1. **反证样本**：构造「现金能撑 8 个月但连亏 6 个月」的账，页面**不得**出现两个相反结论 ⇒ 进 `check_diag_engine` K 组。
2. **处方覆盖率**：11 项指标 × 各档位，**每一档都必须有动作句**，不允许空档 ⇒ 新守卫枚举比对，缺一判红。
3. **带数复核**：动作句里的金额必须能从该月账**独立重算**得到，且随补录变化 ⇒ 页面桩真跑 `buildView` 对拍。
4. **分级反证**：同一短板在「生存月数 < 3」与「> 6」两档下，动作句**必须不同** ⇒ 防「分档只改了文案没改处方」。
5. **合规兜底句在场**：诊断页底部固定渲染，删掉即判红。
6. **真机闭环**：补录 → 保存 → 返回 → 覆盖率上升 → 结论与处方同步刷新，一条链走完（L3）。
