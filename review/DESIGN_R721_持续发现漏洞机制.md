## 0. 一句话结论

**问题不在「审得不够仔细」，在「同一双眼睛审自己写的东西，必然有盲区」。**
所以不靠更努力地审，靠**换视角 + 唱反调 + 让发现跑不掉**：三个独立切面并行审 → 一个专门的挑毛病角色逐条证伪 → 我自己真跑复核 → 全部落进机器台账，由守卫天天盯「不许假装修了、不许没证据、不许挂着没下一步」。

## 4. 机制：六条腿（缺一条就会再漏）

| # | 腿 | 做什么 | 防的是哪一种漏 |
|---|---|---|---|
| 1 | **分层取证** | L0 静态形状 / L1 纯函数 / L2 页面桩 / L3 模拟器截图 / L4 真机，每层写明「能证什么、不能证什么」；**硬指标是「零桩页 = 0」（口径 `tools/scan_zero_stub_pages.js`），不再用「源码里出现 `global.Page` 字面」的比例**——那测的是写法不是覆盖（R1-9 已废该口径） | 全绿假象、只判长得对 |
| 2 | **多视角交叉审** | 并行 3–4 个只读 reviewer，各给一个切面（门禁盲区 / 好用省心 / 数据安全 / 数值口径），**先独立出结论、互不通信** | 同一双眼睛的盲区 |
| 3 | **唱反调** | 再跑一个 adversarial reviewer，唯一任务是证伪准备修的每一条，并审「修法会不会引入新事故」 | 确认偏误、修法本身有洞 |
| 4 | **变异证伪** | 每条新守卫必须配真变异；区分「真红」与「崩溃红」；定期抽查没变异的 116 个守卫做体检 | 恒真橡皮章 |
| 5 | **外部模型复核** | 豆包/DeepSeek 出题或评审，但按 `external-plan-review` 纪律：逐条四分类、读码对齐仓内现状、量化「有多少是我们已有的」 | 自洽闭环、外部方案空转 |
| 6 | **盲区扫描 + 回归固化** | 每轮自动输出「零桩页面 / 无变异守卫 / 纯静态守卫 / 新增 storage key / 新增页面未登记」；**所有发现进机器台账**，由守卫天天盯 | 漏洞悄悄消失、待办永远挂着 |

### 本轮新增的第 6 条腿（已落地）
`tools/check_audit_findings_ledger.js` + `review/evidence/r721_findings.json`：
- 每条发现必须带 `evidence`（file:line）与 `verified_by`（真跑证据或 reviewer）
- `status=fixed` 必须有 `fix_evidence`，**且守卫会去产品源码核对状态不是嘴上说说**
- `status=deferred` 必须有 `priority` + `next_action`（不许挂着没下一步）
- 准备修的条目必须记录挑毛病结论 `challenge`
- 反恒真：删证据 / 假装修了 / 缺下一步，都必须判红
