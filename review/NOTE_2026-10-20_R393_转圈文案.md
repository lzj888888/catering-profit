# R393 · 转圈文案：必须说「正在发生的那件事」

> 日期：2026-10-20 · 触发：R392（提示被截断）的同族追问 ——
> 截断修完了，但**文案说的动作对不对**没人查过。

## 一、怎么发现的

R392 把「>14 字会被 toast 截断」修完后，我顺手把所有 **`wx.showLoading` 的 title** 解析成真实文本（术语键 → 实际字样），一眼看到：

| 文件 | 转圈写着 | 实际在做 |
|---|---|---|
| `pages/card/index.js::onSync` | **正在导出…** | 同步单张成本卡到原料最新价 |
| `pages/card/index.js::onBatchSyncRun` | **正在导出…** | 批量同步 N 张卡 |
| `pages/takeaway/index.js::onConfirmImport` | **确认导入** | 已确认，正在落库 |

## 二、为什么这不是"小文案问题"

两条都很具体：

1. **「正在导出…」等不到文件。** 老板看到"正在导出"，等的是"待会儿有个 Excel 能打开"。同步完成后没有文件 —— 他会以为失败、再点一次（而同步会**再生成一个版本**）。
2. **「确认导入」读起来是"还要再确认一次"。** 而此刻恰恰相反：他已经点了确认，正在落库。语态反了，人就会去点别的地方找那个"确认"。

## 三、改法

新增两条术语（两份副本逐字节同改，`md5` 一致）：

```
card.syncIng      = '正在同步…'
takeaway.importIng = '正在导入…'
```

顺手把 `reviewBatchSaving: '正在保存'` 补上省略号（其余进行时文案都有「…」，它是唯一例外）。

三处调用改指向正确键；**导出那一处 `exp.exportIng` 保持不动**（它本来就对）。

## 四、判据：只守可枚举的形态

语义"文案说得对不对"机器判不了，但**进行时形态**是可枚举的：

> 所有 `wx.showLoading` 的 title，解析出的文本必须**以「…」结尾**。

这一条同时抓住两种错：

- 借来的动作名（`确认导入`）→ 不是进行时；
- 忘加省略号（`正在保存`）→ 形态不完整。

加在 `tools/check_page_terms.js` 的 **S6 段**（该守卫本就负责"页面文案层"，且未被断言数口径跟踪 ⇒ 不动任何声明）。

### 写判据时踩到的两件事

1. **拼接式转圈**：`'正在保存… ' + done + '/' + total`。
   第一版判据把整串当键名解析 ⇒ 取不到文本 ⇒ 假红。
   改法：先截到第一个 `+`，**用固定部分判形态**（变量部分不该影响"是不是进行时"）。
2. **本条判据全程不用正则**：本环境会把反斜杠写坏（落盘即 `\s` → `/s`）。改用 `split('wx.showLoading')` + `indexOf` 切片。
   这是 R387 那次教训的直接复用。

## 八、诚实边界

S6 只守**形态**，不守**语义**。把 `syncIng` 的值写成 `'正在删除…'` 依然能过（它也是进行时）。
语义正确性只能靠人审 —— 本轮的判据价值在于：**"借别人的文案"和"忘写省略号"这两类错，以后机器就能拦住**。
