# ADR · AI 接口要不要现在预留（2026-09-28 决策）

> 决策人：李老师 + WorkBuddy ｜ 状态：**已决**（暂不建抽象层，改锁三条边界）
> 触发问题：「有必要现在预留 AI 接口吗？以后 AI 是趋势，小程序也会变革」

---

## 〇、一句话结论

**不建 AIProvider 抽象层 —— 不是因为 AI 不重要，恰恰因为太重要，而在"连第一个调用方都还不存在"时抽的抽象，一定是错的抽象。**
真正该预留的**不是接口，是边界**。三条边界今天写死、零成本；抽象层等触发条件成立再建，届时会少重构一半。

---

## 一、为什么不现在预留（三条实证理由）

### 理由 1 · provider 根本没定，抽象必错

候选三条路，形态差异大到抽象层一定抽错：

| 方案 | 调用形态 | 合规责任方 | 数据出境 |
|---|---|---|---|
| 微信云开发 AI（混元） | CloudBase 原生 SDK，不出云开发环境 | **平台侧** | 不出境 |
| 火山方舟（豆包） | 云函数 HTTPS 出站 | **我方** | 出微信环境 |
| DeepSeek 等第三方 | 云函数 HTTPS 出站 | 我方 | 出微信环境 |

且**能不能上 L2（真 LLM）取决于小程序主体是企业还是个人**——个人主体永远申不到「深度合成-AI问答」类目（R165 §三已查证）。**在"能不能上"都没定论时抽的接口，八成要推翻重来。**

### 理由 2 · 一个调用方都没有

当前 AI 场景优先级排序（R165 §四结论）：

1. **账单导入（确定性解析，非 AI）** —— 还没开工
2. L1 模板解读（槽位填充，非 LLM） —— 依赖 1 的数据
3. L2 真 LLM 兜底长尾 —— 依赖 2 的覆盖率数据

给第 3 名写接口，而第 1 名还只在 `parse_bill.py` 里跑通过一次 —— **这是给没有住户的楼修电梯。**

### 理由 3 · 本仓的改造成本被严重低估（硬证据）

实测本仓结构：

- `cloudfunctions/` 共 **42 个函数**
- `cloudfunctions/common/*.js` 由 `tools/sync_common.js` **自动同步**为各函数目录下 `cx_*.js`（`cx_indicatorRef.js` 等 11 份 × 42 处）
- 改 `cloudfunctions/` 必须过 **A15 白名单**（`tools/selftest_r85.js:163` 处逐目录登记，绝不放宽成全豁免）
- 还有 `check_schema_sync.js` / `check_indicator_ref.js` 双向校验

⇒ **新增一个 common 文件的真实代价 = 11→12 份同步 × 42 处 + A15 逐条登记 + 同步守卫更新 + 42 个函数重新部署。**

为一个未验证的功能付这笔钱，是纯亏损。而将来真要建时，**同样的动作一次做完即可**，没有额外惩罚 —— 这就是"等待"几乎免费的原因。

## 二、那现在做什么（三条边界，今天写死）

### 边界 1 · 数据机读化 —— **唯一的"过期不候"，必须现在做**

> 理由：**数据是历史沉淀的**。今天存的账单没有结构化，明天的 AI 也读不到它；而接口随时能补，数据不能回溯补录。

已在做的就是对的事，要守住并推广：

- `review/evidence/r163_waimai/parse_bill.py`（零依赖）→ 输出结构化 JSON：`colmap`（列名归位）、`totals`（金额汇总）、`sign_convention`（符号约定）、`rows`
- 已用淘宝闪购 8 月 **156 行逐行零误差**自证（`6418.08 + 167.00 − 2069.70 − 158.71 − 577.02 = 3779.65`）

**落地约束（新增）**：任何新的账单解析/导入，落库时**至少同时存两件套** ——
① `raw`（客户原始列，不加工，留待溯源）② `facts`（机读事实层，已归位到统一口径）。
本钱包最重要的 `sign_convention`（平台补贴是负号还是正号）必须显式记录，**不靠代码猜**。

### 边界 2 · LLM 不碰数字 —— 今天写成铁律

> 这条**定义了未来所有 AI 集成的形状**，且与本仓 T1 红线天然同源（引擎单源）。

```
❌ 禁止：让 LLM 计算/推断/修正任何金额、占比、阈值
✅ 允许：LLM 只把「引擎已算好的 facts」组织成人话（排序、取舍文体、指代消解）
```

推论（现在就知道，将来省事）：
- 任何 AI 调用**入参必须是 facts（数字已算好）**，不是 raw 凭证
- AI 输出**不得回写**任何金额字段，只能写"解读文本字段"
- AI 结果**可丢弃**：删掉 AI 层，产品功能不能降级（这是 L1/L2 分层的验收判据）

### 边界 3 · 文案与计算分离 —— 守住单一出口，句子不许散落在页面里

现状已经是好的：`miniprogram/i18n/terms.js` 是文案单源（且与 `specs/dev-specs/i18n/terms.js` 双副本一致由守卫视）。

**新增约束**：将来任何"解读/建议/结论"类产出，必须走**纯函数单一出口**形态：

```js
buildInterpretation(facts) -> { lines: [...] }   // 内部今天 = 模板槽位；将来 = LLM 结果
```

**禁止**：把句子拼写在 `*.wxml` 里、或在页面 JS 里散落 `if (x > y) 文案 = ...`。
理由：一旦散落，将来换 LLM 要改 N 处且无法保证口径一致；集中在一个纯函数里，将来**只换这一个函数的实现**。

> 注意：**这条不要求现在建那个函数** —— 只要求**将来真做解读时先建它**。这是 0 行代码的预留。

## 三、明确不做（防过度设计清单）

| 不做 | 为什么 |
|---|---|
| AIProvider / adapter 工厂 / model 枚举 | provider 未定，必错；且届时抽比现在抽准 |
| AI 开关配置项、`shop_switch` 里加 `ai_enabled` | 无调用方的开关 = 死配置，还要背维护与同步成本 |
| prompt 模板管理系统 | 同上，且 prompt 形态强依赖所选 provider |
| 提前在 DB schema 加 `ai_summary` 等字段 | 本仓 schema 有 `check_schema_sync.js` 双向校验，空字段会白付同步成本 |

## 四、触发条件（满足才建抽象层）

**全部满足**才动工，缺一不动：

1. **账单导入已上线并跑满 1 个月** — 有真实覆盖率数据（L1 到底覆盖百分之几）
2. **出现 ≥3 类模板覆盖不住的提问**（不是"可能覆盖不住"，是真实日志）
3. **合规路径已确认** — 企业/个体户主体 + 深度合成类目 + 备案号到位
4. ** Provier 已选定** — 微信 AI 成长计划额度是否申领成功（免费 10 亿 token，**2026-12-31 截止**，这是选型的关键变量）

## 五、届时最小落地路径（先写下来，将来照做）

```
前端 ──(facts 已算好)──▶ 云函数 aiGateway（唯一入口）
                          │
                          ├─ 开关降级：shop_switch.ai_enabled=false → 直接返模板结果
                          ├─ 缓存：同 shop_id+month+hash(facts) 命中 → 不再付费调用
                          ├─ provider 选择：CloudBase AI（首选，合规在平台侧）/ 火山兜底
                          └─ 输出：只写 interpretation 文本字段，绝不回写金额
```

要点：
- **单入口**：全局只此一处调 LLM，便于审计、计费、降级、加标识
- **可丢弃**：关掉 `ai_enabled` 产品照常工作（L1 保底）
- **禁止重试**：HTTP 超时不得自动重试，否则双份烧 token（R165 §五隐性成本）
- **必打标识**：AI 生成内容显式 + 隐式标识（2025-09-01 起强制）

## 六、反方意见与回应（防止自己把话说满）

> **反方**：「等趋势起来了再改，会不会来不及 / 成本更高？」

回应：AI 集成的成本大头**从不在调用层那几十行**，而在 ① 数据是否机读、② 业务逻辑是否允许只换一层、③ 合规则否。这三项**都不是"提前建接口"能解决的**。反过来，提前建接口的代价在本仓是被 A15 白名单 + 42 处 cx_ 同步放大的实打实成本。

> **反方**：「用户想要 AI，是不是显得产品落后？」

回应：客户要的是"看懂我的账"，不是"接了大模型"。**账单导入 + 模板解读**一样达成目标，且零延迟、零幻觉、零合规风险。R165 五轮结论已定：**L1 覆盖 ≥90%**。
