# ROUND_INDEX · 轮次编号单源

> **本文件只干一件事**：告诉下一轮「用哪个 R 号」。
> 除了下面那一个数字，**其余全部由守卫现扫**（`tools/check_auto_queue.js` 的 N 段），
> 所以不存在「表格要跟着维护」的负担——**手工要改的只有 `NEXT` 这一行**。

```
NEXT: 677
```

> 🔴 **`NEXT` 的语义是「下一个可用的号」，不是「本轮正在用的号」。**
> 你用掉 609，就立刻把这里写成 610 —— **跟代码改动同一个提交**。
> 守卫 N-③ 会在「NEXT 已经出现在全仓某处」时直接报红，也就是
> **你忘了进位，门禁不让你过**。这个别扭是故意的：它把「用完进位」从自觉变成硬约束。
> （R609 本轮就撞过一次：先写 NEXT=609、又在 AUTO_QUEUE 里记了 R609，守卫当场报红。）

## 为什么要这个文件（R609 的真实事故）

2026-11-05 我（AI）本轮自用了 `R607`，提交完才发现
`review/HANDOFF_2026-11-04_占比口径交接单.md:8` 早已写着「本地 HEAD：`7c255aa`（**R607**）」
—— 11-04 那批（R605/R606/R607）是另一个窗口用的号。

撞车的后果不是"看着乱"，而是**两份互不相干的记录共用一个编号**：
后来人 `grep R607` 会同时命中「占比口径交接」和「gitignore 收口」，
**两边内容无关，却都自称 R607，且都没有任何标记说谁先谁后**。
而全仓 120+ 个 `check_*.js` 没有一个扫编号 ⇒ 撞车全场零告警。

⇒ 根因是「**编号是全局共享资源，却靠人记**」。本文件 + N 段守卫把这条变成机器判。

## 使用规则

1. **开工前**：读本文件 `NEXT`，用它做本轮标识。
2. **干完活**：把 `NEXT` 改成 `+1`，与代码改动**同一个提交**（不要单独提交一个只改数字的提交）。
3. **禁止**：凭记忆挑一个"看起来空着"的号。必须先跑 `node tools/check_auto_queue.js`，
   N 段会直接告诉你这个号有没有被用过。
4. 若发现 §欠账 里的事已补上，改完请顺手更新本表（这一步无法自动，属于人工判断）。
