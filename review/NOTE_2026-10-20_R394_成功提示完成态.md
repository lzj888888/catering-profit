# R394 · 绿勾配动词：老板分不清"还要做"和"做好了"

> 日期：2026-10-20 · 触发：R393（转圈文案）的同族追问 ——
> 转圈说的事对了，那**结果提示**说得对吗？

## 一、怎么发现的

我把所有 `icon: 'success'` 的提示解析成真实文本，逐条看。除了一条是真错配（见下），
更普遍的是**语态错位**：绿色对勾配的是**动词**，不是**完成态**。

```
界面上：  ✅ 保存        ← 到底是"还要保存"还是"保存好了"？
          ✅ 删除
          ✅ 复制
          ✅ 切换店铺
          ✅ 结账并归档
          ✅ 堂食
```

## 二、根因：按钮文案被当提示文案用

`TERMS.buttons.save = '保存'` 是**按钮上**的字（动词，正确）。
但 7 个页面把它直接塞进 `wx.showToast({ icon: 'success' })`：

| 文件 | 原来的写法 |
|---|---|
| `pages/card/edit.js` | `title: TERMS.buttons.save` |
| `pages/material/edit.js` | 同上 |
| `pages/month/assetEdit.js` | 同上 |
| `pages/month/input.js` | 同上 |
| `pages/month/inventory.js` | `TERMS.inventoryPage.save` |
| `pages/recon/index.js` | `TERMS.buttons.save` |
| `pages/takeaway/index.js` | 同上 |

同类还有 8 处，借的是 **菜单项/页面标题/用途名**：

- `TERMS.card.deleteCard`（"删除"）→ 删除成功提示
- `TERMS.card.copyCard`（"复制"）→ 复制成功提示
- `TERMS.card.matDelete`（"删除"）→ 物料删除成功
- `TERMS.assetDeleteLabel`（"堂食"/"外卖" —— 这是**用途名**）→ 删除成功提示
- `TERMS.amortizePage.terminateNow`（"提前报废"）→ 报废成功
- `TERMS.nav.archiveNow`（"结账并归档"）、`archivePrev`（"归档上月"）→ 归档成功
- `TERMS.exp.switchTitle`（"切换店铺" —— 这是**页面标题**）→ 切换成功

**注意：这些键不能改值**——它们同时是按钮文案/菜单项/页面标题，改了会把界面本身改坏。
所以只能在**调用处**换成完成态术语。

## 三、改法

在两副本的 `TERMS.ui` 里加一组完成态（单源、跨页复用）：

```
savedDone: '已保存'      deletedDone: '已删除'    copiedDone: '已复制'
archivedDone: '已归档'   switchedDone: '已切换'   scrappedDone: '已报废'
```

15 处调用逐个替换（每处先断言**唯一命中**再改，避免误伤同名写法）。

## 四、判据：完成态标志只有三个

语义仍靠人审，但"完成态"是可枚举的：

> `icon: 'success'` 的提示文本，必须含 **已 / 完成 / 成功** 之一。

加在 `check_page_terms.js` 的 **S7 段**（与 S6 同属"页面文案形态"，该守卫不在断言数口径内）。

### 两个必须防的"恒真"

1. **动态表达式太多 ⇒ 判据被写窄成恒真**。
   `'已保存 ' + done + '/' + total`、`resetDone(n)` 这类解析不到 ⇒ 跳过。
   但要有下界：**解析到 ≥ 20 条**，否则判红（本轮实测 29 条）。
2. **删掉术语键会被误判成"动态"放过**。
   第一版把 `取不到文本` 也归入 skipped ⇒ 变异 M3（删键）当场漏过。
   改成：**静态引用但取不到文本 ⇒ 直接判红**（这正是本守卫最初要抓的"WXML 对 undefined 静默渲染成空"）。

## 七、诚实边界

S7 只守**有没有完成态标志**，不守"完成态说得对不对"：
把值写成 `'已完成报废'` 放在"保存"场景仍能过。语义正确靠人审与 NOTE 记录。

本轮价值在于：**"按钮文案当提示用"这一类复用错误，以后机器就能拦住**——
它比"文案不好看"严重，因为绿勾是一个**明确的承诺**。
