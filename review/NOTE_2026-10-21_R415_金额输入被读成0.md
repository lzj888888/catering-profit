# NOTE · R415 预研：金额栏「填了，但系统读成 0 元」

- 时间：2026-10-21
- 出处：队列 #25（本轮只预研 + 备落地件，未改生产码）
- 一句话：老板把「12,000」粘进房租栏，引擎收到的是 **0 分**，保本额少算 **40%**，全程零提示。

## 1. 链路（每一环单独看都"没错"）

```
输入框（type="digit"，贴什么进什么）
  → pages/**.js 组装：{ amount_fen: api.yuanToFen(输入字符串) }
  → utils/api.js::yuanToFen：!isFinite(n) || n < 0 ⇒ return 0      ← fail-soft，刻意设计
  → 云端 validate：fen 必须是非负整数分 —— 0 合法 ⇒ 通过
  → 引擎照算
```

问题不在任何一环，在**拼起来**：fail-soft 把「读不出来」压成了「就是 0」，而 0 在金额域里是**合法值**，
于是错误在跨进云端之前就已经被洗白了，后面所有校验都在验一个"合法但错"的数。

## 2. 实测（`_m3/_r415_probe/probe.js`，直接 require 生产实现）

`api.yuanToFen` 的行为面：

| 老板可能输入的形态 | 读成分 | 读成元 |
|---|---|---|
| `12000` | 1200000 | 12000.00 |
| `12,000`（微信/Excel 粘贴） | **0** | **0.00** |
| `12 000`（中间多了空格） | **0** | **0.00** |
| `-500`（误带负号） | **0** | **0.00** |
| `1.2.3`（多敲一个小数点） | **0** | **0.00** |
| `１２０００`（打字法全角） | **0** | **0.00** |
| `1e3` | 100000 | 1000.00（"能算"，但不是老板的意思）|

引擎后果（毛利率 65% / 人工 15000 / 水电 3000，只改房租这一栏怎么被读）：

| 房租栏 | 引擎收到 | 固定合计 | 保本额 |
|---|---|---|---|
| `12000` | 12000 元 | 30000 元 | **46153.85 元** |
| `12,000` | 0 元 | 18000 元 | **27692.31 元** |

⇒ 保本额差 **18461.54 元/月（−40.0%）**。老板看着 2.7 万就"保本"，实际要卖 4.6 万。

## 3. 为什么不"顺手帮他清洗成 12000"

自动去掉逗号看着贴心，但它会掩盖一半的真实问题，且**猜错就是替老板编数**：

- `1,5` 是「15」还是「1.5」？中文习惯两种都有人写。
- `１２` 是全角数字，还是打字法没切、本来想敲别的？
- `-500` 去掉负号＝500，但老板真正想表达的可能是"这笔是退款/冲减"。

本仓已有的同类裁决是同一条线（R406 改价影响、R414 占比超 100%）：
**如实暴露 > 假装修正**。所以这一层只做**分辨**，不做修正。

## 4. 落地件（已在 `_m3/_r415_stage/`，未入库）

`utils_amountInput.js::readYuan(raw)` 返回三态：

| kind | 含义 | 页面该怎么处理 |
|---|---|---|
| `empty` | 真的没填 | 保持现状（是否必填由页面语义决定，如 M2 允许空表单看参考区间）|
| `ok` | 能读成金额 | 走 `yuanToFen`，行为不变 |
| `bad` | 填了，但读不成金额 | **不提交**，`showModal` 指出是哪一栏、原样回显他填的内容 |

刻意保持的两个性质：
1. **合法域与 `api.yuanToFen` 逐点等价**（`0.145 / 0.285 / 1.005` 这些半步点都对齐）——避免两处口径分叉。
2. **不用正则**（纯 `charCodeAt` 判定）：本仓 `tools/**` 写盘会破坏反斜杠，同款风格更稳，也顺带禁掉"全角数字被 `\d` 意外放行"这类坑。

自测 29 条全绿（`_m3/_r415_stage/selftest.js`）：kind 判定 17 · 与 `yuanToFen` 等价 9 · 反恒真 3。
