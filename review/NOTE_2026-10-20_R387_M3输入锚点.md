# R387 · M3 `inputs_ref` 契约（哪张卡的哪一版）

> 2026-10-20 · 承接 `PLAN_2026-10-20_AI路线与边界.md` §6 第 2 条。
> 契约先定、再改码——这条队列项本身就是"别拍脑袋"。

## 一、契约

```json
"inputs_ref": { "kind": "cost_card", "card_code": "cc_xxx", "version": 3 }
```

三条规则：

1. **只放业务键**，不放 `_id` / `card_row_id`。
   理由：库内主键**跨环境不稳定**（dev 重建库就变），引用一次就失效；而 `(card_code, version)`
   是业务键，重建库也认得。放主键还会诱使前端把主键存起来当外键用。
2. **`kind` 必填**：以后 M1 月度（`kind:'month'`）、M2 方案（`kind:'sandbox'`）复用同一形状，
   消费方不需要按接口分支猜。
3. **三处出参必须同形**：`saveCostCard`（保存回执）、`getCostCard`（列表）、`getCardVersions`（历史）。

## 二、为什么第三处是被测试逼出来的

原计划只改两处（保存 + 列表）。跑门禁时 `getCardVersions` 自测红了：

```
❌ [doc0] cardToOut ≡ getCostCard.cardToOutput（逐字段 22 项）  (不一致: inputs_ref)
```

`getCardVersions/service.js` 有一份**独立副本** `cardToOut`，selftest 逐字段比对两边 —— 它比我先发现漏改。
⇒ 这不是麻烦，是**多副本纪律**在替我兜底：少改一处，"版本历史页"就拿不到 ref，
而 AI 引用历史版本时恰恰最需要它。

## 四、踩到的环境坑（记下来省下次）

本环境的命令通道会把**反斜杠转成斜杠**：写 `\\s` 进 heredoc，落盘后变成 `//s`，JS 语法直接崩。
⇒ 在 `tools/**` 里写正则，**不要用 `\s` `\{` 这类转义**，改用
「定位字面量 → 取前后片段 → `indexOf` 判断」的写法（本轮的 ⑤ 段就是这么写的）。
