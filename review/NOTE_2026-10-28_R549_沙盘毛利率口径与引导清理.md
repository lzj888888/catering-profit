## 2 为什么第 3 件是真 bug（先把账算清）

引擎口径（`index.js` 装配层 → `calcSandbox`）：

```
保本额 = 固定成本 ÷（毛利率 − 渠道费率 − 其他杂支）
渠道费率 = 外卖占比×(外卖抽成+包装) + 团购占比×(折扣+抽成−折扣×抽成) + 刷卡费率
```

⇒ **毛利率本身必须不含平台抽成**。但页面从没告诉过老板这件事，而老板常见的做法是
「到手多少就填多少」（堂食 55% 被外卖/团购扣到 35%，就填 35）⇒ 下面 ④ 又扣一遍 = **重复扣**。

实测（固定成本 3 万/月；外卖占 30%、抽成 21%+包装 3%；团购占 10%、折扣 30%、团购抽成 5%；
刷卡 0.6%；其他杂支 2% ⇒ 渠道合计 11.15%）：

| 情形 | 算法 | 保本额 |
|---|---|---|
| 填综合毛利率 35%，**改前** | 30000 ÷（0.35 − 0.1115 − 0.02） | **13.7 万** |
| 填 35% 且不再扣渠道（改后 net 口径） | 30000 ÷（0.35 − 0.02） | **9.1 万** |
| 填纯堂食 55%，dish 口径 | 30000 ÷（0.55 − 0.1115 − 0.02） | 7.2 万 |

⇒ 改前**虚高 51%**，且全程零报错（数字看着正常，只是偏大）。

## 3 两款互斥口径（李老师定案）

```
这个毛利率是怎么算的？
 ○ 只算菜品       ← 默认。外卖/团购的抽成和折扣还没扣，下面 ④ 会替你扣
 ○ 已扣平台抽成   ← 到手毛利。下面 ④ 不再重复扣，只用来算外卖占多少
```

- **默认「只算菜品」**：保持既有行为，老用户与存量草稿零回归。
- 选「已扣平台抽成」时：
  - 装配层**不再把 `takeawayComm / grouponComm / cardFee` 推进 `var_items`**（只挡这三项，
    `otherPct` 损耗杂支照常扣 —— 它与平台无关）。
  - ④ 卡里的**五个费率项收起**，「外卖占流水 / 团购占流水」保留（生意结构，两种口径都要），
    并显示 `channelNetNote` 说明为什么收起。
- **分步口径必须给出结果**（李老师原话"最后出的一个综合毛利率"）：
  显示 `综合毛利率 ≈ netMarginPct%（= 菜品 − 渠道合计）`，渠道关掉时 net = 菜品。
  不给出来的话，老板还得自己拿 55% 减 11.15%，也就看不懂两种口径到底差在哪。
- **智能提醒**：填的值比本业态参考带下界还低 8 点以上 ⇒ 提示"是不是已经把抽成扣掉了"。
  阈值留 8 点余量：只低几个点的店是真实存在的，不该天天弹。参考带取 `bandsRaw` 的 `grossMargin`。
- **口径必须进草稿**：不存的话退出重进回默认 dish ⇒ 选过 net 的店被悄悄扣两遍（R443 半份草稿同族）。

## 6 🔴 体积预算 re-baseline（**需要李老师知情**）

`check_pack_size` 的 `TOTAL_BUDGET_MB` 从 **1.7 → 1.9**。

**为什么**：R547b / R548 / R549 **连续三轮**都靠删「为什么」注释换 KB —— 那正好在伤本仓最贵的资产
（注释里存的是"为什么这么定、踩过什么坑"）。这不该是守卫的日常。
且口径本身不贴平台规则：**微信的 2 MB 是每个包的上限**，而这项统计的是**主包 + 分包合计**
（当前主包 ≈0.69 / subpkg ≈1.01，各自离 2 MB 都很远）。

**先例**：1.5 → 1.7 是 2026-10-21（R419）自己定过的 re-baseline，注释里写着"1.7 仍 < 微信 2 MB 硬上限"。

🔴 **下一步定式**：若再撑满，**应改判「每包 ≤ 1.9」而不是继续抬这个合计值** —— 合计口径本身就不贴平台规则。
（若李老师不认可，改回 1.7 即可，代价是继续压注释。）

## 7 踩坑：Python 直写把文件截断成 0 字节（**第二次，同一个坑**）

```python
io.open(p,'wb').write(io.open(p,'rb').read().replace(b'\r\n', b'\n'))   # ❌ 先截断再读
```

`io.open(p,'wb')` **打开即截断**，右边再读就是空 ⇒ `index.js` 变 0 字节、本轮编辑全丢，只能
`git checkout` 后手工重做 9 处。

✅ 定式（本轮起一律照做）：
```python
b = io.open(p,'rb').read()          # 先读
...                                  # 再算
tmp = p + '.tmp'; io.open(tmp,'wb').write(b2); os.replace(tmp, p)   # 最后原子替换
```
