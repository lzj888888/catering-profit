## 一、一句话结论

**跳转侧把原料名 `encodeURIComponent` 编过一次，目标页没有 `decodeURIComponent` 解回来** ⇒
页面顶部把 `%E7%82%B8%E9%B8%A1%E8%85%BF`（「炸鸡腿」的 URL 编码）原样渲染出来。

「很多英文以及百分号」就是这串编码 —— 李老师的描述其实**极其精准**。

## 四、修法

`pages/metrics/impact.js` 新增安全解码器，`material_name` 改走它：

```js
function decodeParam(s) {
  let out = String(s == null ? '' : s);
  for (let i = 0; i < 2; i += 1) {          // 上限 2 次：兼容「框架又替我们编了一次」的双重编码
    if (out.indexOf('%') < 0) break;
    let next;
    try { next = decodeURIComponent(out); } catch (e) { break; }  // 含裸 % 的名字（如「含盐 5%」）会抛错
    if (next === out) break;
    out = next;
  }
  return out;
}
```

三个设计点都有理由：
1. **上限 2 次循环** —— 微信路由对 query 的处理在不同版本/写法下可能多编一次，只解一次会残留 `%25E7…`；循环到稳定为止最稳。
2. **catch 后原样返回** —— 原料名里带裸 `%`（「含盐 5%」这种）会让 `decodeURIComponent` 抛 `URIError`；**宁可显示原样，也不能崩页面**。
3. **`String(s == null ? '' : s)`** —— 参数缺失时给空串，不产出 `"null"` / `"undefined"` 这类英文串（那又会变成新的"英文显示"事故）。

**纯前端修复 ⇒ 不需要部署云函数**，出一张新预览码即可生效。

## 七、附带扫描：函数型术语键"被当字符串渲染"的同族风险

既然撞上了"不该显示的东西显示出来了"，顺手扫了**同族形态**：
术语里有 **31 个函数型键**（`impactBelowBand` / `matSpecHintOf` / `exp.required` …）。
若在 WXML 里写 `{{t.xxxOf}}`（不带括号），小程序会**静默渲染函数源码**——
那会是"一大串英文 + 百分号"的另一种形态。

**扫描 109 个文件 / 94 处键名命中 ⇒ 真问题 0 处**（10 条疑似全是同名不同物、定义处、注释）。
⇒ 该形态**当前无实例**，属**防复发**而非修缺陷。

> ⚠️ 判据要点（将来要做守卫时别踩）：
> 必须排除 ① 定义处（键名后紧跟 `:`）② 同名不同物（`utils/validate.js::required` 是导出函数、
> `amortize.js::endNote` 是页面局部变量）③ 注释 ④ 长标识符子串（`endNote` ⊂ `endNoteLast`）。
> **裸扫键名必误报**。
