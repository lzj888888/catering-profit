# R773 · 每月还账（月供）进现金流出 + 采信"红线第一、评分辅助"

> 触发：李老师三点要求 —— ①「月供」要用餐饮的词；② 有些数据老板填不准，没填怎么处理；③ **红线是第一生死线，其他打分是辅助证明**。
> 本轮只做月供这条主线 + 顺带修两处过期提示；储值红线（R7）留下一轮。

## 一、先纠一个我自己的错误

上一轮我提的「储值可兑付月数 = 储值余额 ÷ (储值余额 × 月核销率)」**在数学上恒等于 1/月核销率**，跟余额无关——那个指标算不出任何东西。
正确口径应是**储值余额 ÷ 账面现金**（退得起吗），两个数老板都能填。本轮先把字段采上来，红线下一轮加。

## 二、「月供」改成餐饮老板的话

- 不再叫月供。上屏是：**「每月要还多少钱」**
- 提示：「贷款、信用卡分期、网贷这类，每月固定要还的加起来。没有就填 0（填 0 和空着不一样）」
- **只有选了「有借钱」（有一点/压力很大）才出现** —— 没借钱的人一个字都不用多填（`wx:if="{{debtIdx > 0}}"`）

## 三、空着 ≠ 填 0（这是本轮的核心设计）

| 填法 | 语义 | 系统怎么处理 |
|---|---|---|
| 空着 | 没填 | **这项不判**，结论照给，不因此判"数据不足" |
| 填 0 | 明确没有 | 参与判断（如储值 0 ⇒ 没做过储值，不触发兑付风险） |
| 填正数 | 有 | 参与计算 |

**为什么必须区分**：仓库贯穿一条红线"缺项 ≠ 0"（`num(null)` 不许当 0）。把"没填"当"没有"会谎报成"查过没问题"，那是这套模型里最危险的谎。

## 四、算法：经营亏损 ≠ 现金流出（新增 `outflowOf`）

损益表里**没有「还贷款本金」这一项**（只有利息），所以：

```
现金流出口径：outflow = 经营亏损 + 月供本金     ← 给「能撑几个月」用
失血率口径：  bleed = 经营亏损 ÷ 营收           ← 给 R2 判断用，不含本金
```

两个口径必须分开，因为错误方向相反：
- 只看经营亏损 ⇒ **高估**可撑月数（8 万现金 / 月亏 1 万 / 月供 1.25 万：旧算 8 个月，真实 3.6 个月）
- 把本金算进失血率 ⇒ 只是还贷重的盈利店被**误判成"经营恶化"**

改动四处，全部走同一个 `outflowOf(i)`：`cash` 项、R1、R2（现金部分）、R5。

### 实跑验证（5 个场景）

| 场景 | 旧口径 | 新口径 |
|---|---|---|
| 现金 8 万 / 月亏 1 万 / 不填月供 | 8.0 个月 | 8.0 个月（退化，兼容） |
| 同上 + 每月还账 1.25 万 | 8.0 个月 | **3.6 个月** ✅ |
| 同上 + 月供填 0 | — | 8.0 个月（与不填等价）✅ |
| 净赚 3 万 / 月供 1 万 | — | 「还完每月的账，现金还在增加」✅ |
| 净赚 0.5 万 / 月供 1 万 | — | 16.0 个月（净流出 0.5 万）✅ |
| 净赚 1 万 / 月供 1 万（打平） | — | 「当前不亏损、也不结余，现金不增不减」✅ |
