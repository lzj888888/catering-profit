### 1. 致命一改（四段式）
#### 现状
当前M3成本卡沿用专业财务逻辑，执行**全字段必填**规则，外露出净率、BOM、损耗等专业术语，所有原料（含低价值辅料、调料）的用量、换算参数必须全部填报；缺值要么按0元计算虚高毛利，要么直接弹窗阻断建卡流程。
#### 问题
90%的门店老板、店长不懂专业成本核算，也没时间逐菜填10余项参数，要么因填错/填不全导致成本数据完全失真，要么直接弃用成本卡，后续所有成本引擎、告警、联动功能全部成摆设，是操作性差的根源。
#### 改法
只改**「建卡准入校验+成本计算容错」这一处核心规则**：① 仅要求填报3个口语化核心字段（主料毛料进价、每份菜净料用量、菜品售价），其余参数自动按品类匹配预置默认值，专业术语全部后台隐藏；② 容错逻辑改为fail-closed：缺核心字段/用量为空/0/负时，禁止标记正式卡、成本显示「--」而非0元，非核心字段缺省自动套默认值并标记「估算卡」，补填后自动转正式卡。模板、文案、状态标记均为该规则的配套落地动作，核心改动仅1处。
#### 预期效果
单菜建卡时间从15-30分钟压缩至30秒内，无财务基础的门店人员也能建出准确率≥85%的可用成本卡，成本卡覆盖率从行业普遍20%拉升至90%以上，所有后续功能具备落地基础，操作性提升量级最大。

### 2. 优先级路线图
排序依据：**老板真实ROI从高到低、落地成本从低到高**，P0为生死必备、P1为控本增值、P2为细分场景补全；标注规则：【复用】=现有计算引擎零改动，【新增】=必须新增机制
#### ■ P0（生死级，ROI≥90分，落地成本≤30人天，上线10天可全量铺开，解决“没人用”的核心问题）
1. 交互口语化+内部能力隐藏：前端隐藏mode A/B、M1↔M3对账、外卖双模式、版本快照等内部/专业入口，所有文案换成门店易懂的口语化表述
   → 【复用】纯前端显隐、文案调整，引擎零改动
2. 品类默认模板预置：按家常菜、烧烤、奶茶等主流品类，预置通用出净率、标准BOM、常规损耗率默认值
   → 【复用】仅后台新增配置项，参数直接透传给现有引擎，无计算逻辑改动
3. 建卡容错规则重构：仅保留3个核心必填项，非核心字段自动套模板；用量异常/缺核心字段禁转正式卡、成本显「--」，默认值生成的卡标记「估算卡」，补全后自动转正
   → 【复用】仅调整前端校验、入参补全规则，引擎计算逻辑无改动
4. 批量建卡流水线：一键导入收银菜单全部在售菜品，自动匹配品类模板，按绿（正式卡）/橙（估算卡）/红（缺核心信息）分状态管理，仅引导补主料核心信息
   → 【复用】复用收银菜单现有接口，仅新增模板匹配逻辑，批量调用现有引擎计算
5. 净料单位成本引擎：基于毛料进价+出净率/损耗自动换算净料单位成本，替代原有毛料直算的粗算逻辑
   → 【新增】（若现有引擎已支持自定义换算参数则为零改动，行业通用基础引擎默认不支持，开发量≤3人天）

#### ■ P1（增值级，ROI≥70分，落地成本30-80人天，上线后单店月度可减损5%-15%，解决“主动控本、算全场景利润”问题）
1. 成本漂移追踪告警：每日同步最新采购进价，自动重算所有菜品成本，涨幅≥5%且单菜成本涨≥0.3元时触发告警，按毛利影响金额从高到低排序
   → 【新增】新增定时同步、批量重算、阈值判断、影响排序逻辑，现有引擎仅支持单次单菜计算
2. 原料变动影响面分析：原料进价调整时，自动关联所有用到该原料的菜品，展示成本/毛利变化幅度、对应周期销量的总毛利影响额
   → 【复用】BOM关联关系为现有已有数据，仅需拉取变动数据、批量调用现有引擎重算，无新逻辑
3. 外卖/团购到手真实核算：自动同步各平台佣金、满减、配送费、团购折扣规则，计算单菜/整单真实到手价、真实毛利率
   → 基础计算【复用】（平台费用作为附加成本项透传即可）；平台接口对接、费用映射规则【新增】
4. 跨场景破线联动提醒：原料涨价导致外卖/团购菜品毛利率低于预设阈值时，自动提醒调整售价/活动力度
   → 【新增】新增跨场景毛利阈值判断、多端联动告警逻辑，现有引擎无跨场景联动能力

#### ■ P2（细分级，ROI≥40分，落地成本≥80人天，仅连锁/精细化运营客户需要，不影响中小客户核心使用）
1. 连锁总部-门店字段级覆盖架构：总部统一制定标准卡、统一预置模板，门店可在权限范围内覆盖本地采购价、出净率等参数，shop_id仅做权限管控、不做物理数据隔离
   → 【新增】现有单店数据架构不支持，需重构数据模型、新增字段级权限、覆盖优先级逻辑
2. 销量导入复盘：关联收银/外卖销量数据，输出周期成本复盘、菜品结构毛利分析、高耗/滞销菜品识别报表
   → 【复用】销量为现有模块已有数据，仅新增报表关联逻辑，核心成本计算完全复用现有引擎
3. 后台版本快照能力：成本卡修改自动留存历史版本，支持回溯、对比差异，仅总部财务/运维有权限查看
   → 【新增】需新增快照存储、版本生成逻辑，现有单版本存储不支持

#### 一句话落地顺序
先上线P0的交互、模板、建卡规则和批量导入功能快速铺覆盖率，再切换净料成本引擎夯实数据准确性，接着落地P1的告警、影响面分析、外卖核算和跨场景提醒帮老板直接省钱，最后面向连锁客户迭代P2的多层级架构、复盘和快照能力。
