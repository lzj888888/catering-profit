# R477 · M1「两口径差异」归因修正（库存模式下参考口径完全没扣食材）

- 日期：2026-10-25 02:xx
- 触发：李老师真机反馈两问 —— ①「**口径差异为什么要等于食材成本？**」②「钱还能撑多久」是否有价值
- 结论一句话：**那不是"口径差异"，是一个真 bug** —— 库存模式下"经营参考利润"的食材项恒取 0，
  所以差异里那一项其实就是**整个食材成本**。已修，差异现在**只剩当月摊销**，且改动被三副本等价守卫钉死。

---

## 一、根因（实测，不是推断）

M1 双利润引擎有三份手写副本（本仓不许跨云函数共享代码）：
`calcMonthlyProfit` / `saveLedger` / `getLedger` 的 `service.js`。

改动前的公式：

```
经营参考利润 = 收入 − 费用 − directConsumeFen − 一次性投入
```

而 `directConsumeFen` = 「老板直接填的当月食材消耗」。**库存开关一开，这个输入框在前端就不显示了**，
于是它恒为 0 ⇒ 参考利润 **完全没扣食材**。

实测（改前，S2 场景把 direct 去掉）：参考利润 = **3,116,000 分 = 31,160 元**，
而真实利润 = 8,160 元。**差 23,000 元，正好是整份食材成本 23,000**。
这就是老板看到的"差异等于食材成本"。

🔴 性质：这不是"两个精度层次"的差异，是**其中一个数算错了**。老板拿它当真会直接误判盈亏。

### 第 5 条为什么不采纳（有实测证据，勿按原话改回去）

外审要求「显式填 0 = 老板明确声明这月没消耗，要尊重，不回落」。听起来对，**本仓行不通**：

```
subpkg/biz/month/inventory.js:240   direct_consume_fen: this.data.directConsumeFen || 0
```

库存页保存时**写死 `|| 0`** ⇒ 库存模式下**恒传 0**。这个 0 是**前端占位**，不承载老板意图 ——
库存模式下那栏 UI 根本不显示，老板**没有地方**去"声明这个月没消耗"。
若硬按"显式 0 要尊重"处理 ⇒ 参考利润仍是完全没扣食材的 31,160 元，**bug 原样保留**。

⇒ 判据定为：**库存开 且 直接填的消耗 ≤ 0 ⇒ 回落倒轧**。
- 库存开 + 填了**正数** ⇒ 用填的值（**S2 锚点即此形态，口径锁不变**）
- 库存开 + 0 / 未填 ⇒ 回落倒轧
- 库存关 ⇒ 恒用填的值（没有倒轧数据可用）

⚠️ 若将来库存模式也开放这个输入框，"显式 0" 才重新具有语义，届时须回来改这里。
