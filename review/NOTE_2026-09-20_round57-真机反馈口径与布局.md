## 1. 已落（有证据）

### 1.1 🔴 三处「网络不可用」= 我自己上一轮部署踩的坑（根因已修 + 已重新部署）
- **现象**：设置页保存、录入页「按库存盘点倒算」「装修设备按月分摊」点击后一律提示「网络不可用，请检查网路连接」。
- **根因（人为，非代码缺陷）**：round55 我用 `cli cloud functions deploy --names saveShopSetting` 部署时**漏了 `-r`**（远程装依赖）。
  本地无 `node_modules`，不带 `-r` 的上传会用本地文件覆盖云端目录 ⇒ 把云端已装好的 `wx-server-sdk` 清掉
  ⇒ 云函数容器启动失败 ⇒ `wx.cloud.callFunction` 直接 **reject** ⇒ `utils/api.js` 的 catch 分支显示「网络不可用」。
- **为什么只有它坏**：42 个函数里本轮只重部署了这一个；`getLedger`/`getShopContext` 等读函数正常，所以页面能渲染、只写操作全挂。
- **修法**：`cli cloud functions deploy --names saveShopSetting -r` 重跑（撞一次 `Updating` 并发锁，等 75s 后重跑成功；
  输出 `success=true / 15 files / 19.8 KB`。⚠️ 包大小与不带 `-r` 时**完全一致**，因为 `-r` 是云端安装依赖、不进本地包
  ——**不能拿 filesCount/packSize 判断依赖装没装**）。
- **教训（已写 MEMORY.md）**：本仓部署云函数**必须带 `-r`**；函数 `Active` + `timeout=20` **都不代表函数能跑起来**。

### 1.2 🔴 收入口径写错了 —— 李老师质疑正确，已按规范改回权责发生制
- **原文案**：`收入按当月实际到账金额填写，平台抽成前的流水不要填。`
- **它错在哪**：规范 `specs/dev-specs/core/开发规范v1.0_ModuleA_收入费用核算.md` A.0-1 写死
  **权责发生制**（收入按业务发生日确认：外卖=订单日 / 团购=核销日；现金看到账日），A.1 又明确外卖取
  「商品总价 + 打包费 + 商家活动补贴」（原文标注 **非顾客实付、非到账**）。
  原文案是**收付实现制**，与规范冲突；更严重的是它与 A.2「佣金记营销费用」**自相矛盾** ——
  收入填到账净额（已被平台扣过佣）、费用里再记一次佣金 ⇒ **佣金被扣两次**。
- **已改为**：`收入按当月实际发生的营业额填：出了餐就算，不管钱有没有到账。平台还没结算的照记，不要挪到下月。`
- **外卖口径改为**：按平台账单「商品总价 + 打包费 + 商家活动补贴」三项相加填；平台佣金与配送费不在这里扣，记「营销费用」。
- **堂食口径补**：企业挂账、签单也按出餐当月计入（同样是权责发生制）。
- **未改的部分（说明）**：规范 A.3 里仍有多处「平台实际到账合计」——那是**现金流 / 待结算估算**口径
  （A.0-6 明确「待结算不进利润」），与收入确认口径是两码事，**不冲突，故未动**。
