### 纯外卖店的判据要求「两个条件同时满足」

```js
if (!quadrant.ok && !quadrant.reason && dineIn.length === 0 && tkDishCnt > 0) { ... }
```

- `dineIn.length === 0`：堂食一道菜都没有
- `tkDishCnt > 0`：外卖确实有已建卡的菜
- **只满足一个都可能误伤**：堂食为空但外卖也没有 ⇒ 真是菜太少，该保留原文案

守卫 I-① 专门钉住这两半：把 `&&` 改成 `||`、或删掉任一半，都会判红（已变异验证）。

## 三、R660 为什么没动（如实说明）

R660 的原话是「分类收进『更多设置』。首屏只留 菜名→配料→售价→毛利率」，这是李老师拍过的产品决定。

本轮的做法是**在缺口出现的地方给出口**，而不是改建卡流程：
- 老板在四象限看到「现在是全店一起比，会失真」，下面就能点「去给菜填类目」
- 点进去是成本卡列表，逐张补

**代价**：老板仍要在建卡页展开「更多设置」才能填。这条路径还是三步（点入口 → 选卡 → 展开更多设置）。要压到一步，必须把类目提到首屏或让列表页直接支持"补类目"——那要李老师拍 R660。
