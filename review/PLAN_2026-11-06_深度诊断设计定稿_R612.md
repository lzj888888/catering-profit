## 3. 定稿方案

### 3.1 位置（修正后）

```
结果页
  ├─ 利润卡（第一屏）
  │    └─ 【新增】一行"这家店还能撑多久 ›"  ← 入口就在利润数字下面，不用滑
  ├─ ... 其余卡片不变 ...
  └─ 页底：只保留导出/诊断包（不放诊断入口）

点进去 → 深度诊断页（独立页 subpkg/biz/diag/index，新建）
```

**为什么是利润卡下方**：老板看结果只关心一个数（这个月赚没赚）。看完那个数的一瞬间，是"我还撑得住吗"这个念头最强的时候。入口放这里，是顺着他自己的思路，不是让他去页底找功能。

**不加首页模块卡、不加 tab**：诊断输入 100% 来自 M1，独立成模块会造出"没录账也能诊断"的错觉；tabBar 三入口已定，不破坏。

### 3.2 页面结构（先结论，后补录）

```
深度诊断页
├─ ① 当前判断（第一屏，不需要填任何东西就有）
│     · 一句事实陈述（如"按你录的数，这家店每月净流出 3,200 元"）
│     · 等级：健康 / 需关注 / 预警 / 高危 / 数据不足
│     · 数据覆盖 78% · 已判 9/11 项
│     · 最严重的 1 条风险信号（措辞用事实，不用判决）
│     · 短板 Top3（失分×权重降序）
│
├─ ② 想更准？就差这几项（单点引导，默认只露 1~2 个）
│     · 按"补这项能改变什么"排序，例如：
│       "补上账面现金 → 能算出你还能撑几个月"        [填]
│       "补上续租涨幅 → 能判断租约到期是不是坎"      [填]
│     · 点一项才展开一项，填完立即重算、立即回显变化
│     · 其余项目收在「其他可选补充」里，不主动打扰
│
└─ ③ 免责兜底（常驻）
```

**关键交互纪律**：
- 进来**不需要填任何东西**就有结论（有多少数据算多少，覆盖率 <70% 就老实说"数据不足 + 还差哪几项"）
- 每填一项**立刻重算并显示变化**（"等级：需关注 → 预警"），这是"问卷"和"诊断"的分水岭
- 缺项**永远不按 0 分算**（引擎既有底线，不改）

### 3.3 四组内容归组（保留李老师要的覆盖面）

| 组 | 内容 | 来源 |
|---|---|---|
| 财务与现金 | 净利率 / 连亏月数 / 月刚性支出 / 账面现金 | 前 3 项**自动**，只有现金手填 |
| 经营与口碑 | 本月客流 / 老客 / 会员销售 / 去年同期客流 / 评分 / 差评趋势 | 前 3 项 M1 自动，后 3 项已采 |
| 市场与合同 | 商圈五档 / 剩余租期 / **续租涨幅（新增）** | 手填 |
| 风险信号 | **食安三场景（新增）** / 借贷三档 | 手填 |

四组只作为**归组与「其他可选补充」的目录**，不作为默认展开的表单。

### 3.4 客流三项的处置

从录入页移除，改到**结果页「经营客流」卡里就地补录**（结果页已有 `onCash` 现金就地输入的同类先例）。

- 数据归属不变：仍写 `shop_monthly_account.traffic_count / old_customer_count / member_sales_fen`，按月存（否则算不了同比与趋势）
- 录入页保留一句轻提示："客流与会员在结果页补，不影响本月利润"
- 这样老板录账时只管钱，看结果时顺手补观测值 —— 各自归位

### 3.5 免费 / 付费分层

| 层 | 给什么 | 依据 |
|---|---|---|
| **免费（免费简诊）** | 等级 + 分数 + **最严重那 1 条风险信号** + 数据覆盖率 | 豆包第 5 条：核心判断不能藏，藏了会被当成敲诈 |
| **付费（深度诊断）** | 11 项逐项得分与扣分依据 + 全部命中信号 + 短板 Top3 拆解 + 精准测算（补全字段后的结果）+ 报告导出 | 卖的是**精度与拆解**，不是卖"能不能活下去"这个答案 |

另：付费做**单次/月度解锁**，不推年卡（低频场景，年卡抬高决策门槛）。
