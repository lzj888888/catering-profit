## 二、跑了才知道的两个真 bug

### 🔴 1. 固定费用拆项「从未显示过」（单位串了）

```js
fixedBreakOf(p.fixed_items, d.fixed_ex_amort_fen)   // 传进去是「分」
if (Math.abs(sumFen / 100 - eng) > 1) return null;  // 却拿「元」比「分」
```

`21750 元` 对 `2,175,000 分` ⇒ 永远差 100 倍 ⇒ 永远 `null` ⇒ **R342 上线后这块就没出现过一次**。

- 修法：函数入参统一为**分**，两侧直接比整数（容差 100 分 = 1 元）
- 为什么静态判据没抓到：R342 的判据钉的是 `sumFen / 100` 这个**字面量**，
  而错就错在这个 `/100` 上 —— **判据把 bug 当成了正确形态**。
- 修后实测：`["房租=5000","人工=15000","水电气=1750"]`

### 🔴 2. 活动卡三个数字渲染成空串（t 映射被覆盖）

`promoDropText / promoBeText / promoTrafficText` 三行映射在 R344/R350 的补丁里**被覆盖丢失**，
terms 里的键其实都在，只是没映射进页面数据 ⇒ 页面零报错，三个位置是空白。

- 修法：补回三行；同时删掉已不存在于 terms 的 `promoTrafficNote` 死映射
- 新增判据：**`T.xxx` 引用集 ⊆ `t` 映射赋值集**（只判「terms 有没有这个键」查不出来）
- 修后实测：`60.6% | 10.5% 的客人（多来的，不是总共）`

## 五、这一轮暴露的元问题

**静态守卫守不住「单位」和「映射」这两类。**
它们都能编译、能跑、零报错，只在**运行时数据**里露出来：
- 单位串了 ⇒ 功能整块静默消失（不是算错，是不显示）
- 映射丢了 ⇒ 文案静默变空串

⇒ 以后凡「新增展示块」，至少补一条**读 data 的行为断言**，别只补源码判据。
