## 2 为什么这一刀砍在幂等

### 2.1 缺口：**形态判据测不了行为**

`tools/check_idempotency.js`（R73 建）的 I1~I7 **全部是形态判据** —— 它读源码文本，判的是：

- I1 契约表能否解析出 `+幂等` 函数
- I2 那些函数**有没有**幂等预检
- I3 预检**顺序**是否早于首个业务写
- I4 造键是否用单源 `shopKey()`
- I5/I6/I7 登记与豁免是否成立

**它测不了的那一条**（契约喂投包 §181 的原话）：
> 「同一 id 重复请求**直接返回首次结果**，不重复写入」

即「**同一 `client_request_id` 连发两次，是否真只产出一条**」—— 这条只能**真跑**。

### 2.2 后果链（为什么值得补）

`cloudfunctions/common/idempotency.js` 是**全仓唯一**的幂等实现，被 **15 个云函数**共用。它一旦漂移（键格式 / `where` 条件 / 返回值形态）：

```
键格式漂移 → 查重键 ≠ 登记键 → 幂等形同虚设
   → saveAsset 重复产资产 → saveLedger 读台账算摊销 → 摊销翻倍 → M1 利润算错
```

而 I1~I7 **全绿**（源码形态没变）。

⇒ 与 R453（摊销引擎"只守形态、不守数值"）、R298 M1（守卫只守"分支在不在"）**同族**。本批补的这一段，就是把「**守形态**」扩到「**守行为**」。
