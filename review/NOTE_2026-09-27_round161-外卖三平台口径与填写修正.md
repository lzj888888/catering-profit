## 二、淘宝闪购 8 月账单：逐行验证过的等式（这是地基）

单位元。以下 4 条在**全部 156 行**上验证，**零不符**：

```
E1  Q 平台服务费 = R 技术服务费 + AJ 配送服务费
    -735.73 = (-158.71) + (-577.02)

E2  J 结算金额 = O 商品金额 + P 打包费 + Q 平台服务费
                 + BI 商家活动补贴 + BJ 商家代金券补贴 + BK 商家智能补贴
                 + BL 商家配送费活动补贴 + BM 商家配送费券补贴
    3779.65 = 6418.08 + 167.00 + (-735.73) + (-791.68) + (-831.02) + 0 + (-447.00) + 0

E3  平台定义：营业收入 = 优惠前总额 − 补贴及支出
              补贴及支出 = 商家活动成本 + 佣金 + 配送服务费 + 其他支出
    6585.08 − (2069.70 + 158.71 + 577.02 + 0.00) = 3779.65   ⇒ 本店 8 月「其他支出」= 0.00

E4  AJ 配送服务费 ≈ (AM 距离收费 + AO 价格收费) × AQ 配送费折扣系数
    推算 -576.70 vs 实际 -577.02（差 0.32；20 行有 ≤0.01 的逐行舍入尾差）
    ⚠️ 直接用 AM+AO 反推配送费会多算约 246.83 元
```

**月度汇总（8 月）**：优惠前总额 `6585.08` ／ 商家承担补贴 `-2069.70` ／ 佣金 `-158.71` ／ 配送服务费 `-577.02` ／ 其他支出 `0.00` → **商家到手 3779.65**。
平台承担补贴六列（活动 228.81 + 代金券 359.32 + 配送费活动 146.10 + 支付立减 2.76 + 外部 1.10 + 代理商代金券 6.00）= **744.09**，**不进商家到手**——这是人工核对时最容易误加的一笔。
（附注：上一轮读表曾报 743.99，与逐列相加差 0.10 ⇒ **存疑待复核**，不影响任何结论。）

**单量结构**：156 行 = 外卖订单 150 + 退单 6（整单退 3 / 部分退 3）；即时单 141 / 预定单 9；业务类型 **超抢手 83 / 外卖 73**；配送方式全为蜂鸟配送；抽佣费率 5% 151 行、0% 5 行。结算日期 27 天，**缺 2026-08-16**。

平台**自己印在图上的公式**：

```
美团   营业额 = 有效订单 × 实付单均价 + 活动补贴 − 顾客配送费
       支出   = 商家活动成本 + 佣金 + 配送服务费 + 其他支出 + 公益捐款
       收入   = 营业额 − 支出
淘宝闪购 营业收入 = 优惠前总额 − 补贴及支出
         补贴及支出 = 商家活动成本 + 佣金 + 配送服务费 + 其他支出
```

**两个关键读数差（本次最值钱的两句话）**

1. 美团的「**活动补贴 384**」与「**商家活动成本 198**」**不是一回事**：384 是商家 + 平台的总补贴，198 才是商家承担（差 186 = 平台承担）。客户照着概览页抄，就会多扣。
2. 美团的「营业额 837」= 优惠前总额；以 837 − 198 − 33 − 83 = **523**，而平台显示的「收入」是 **442** ⇒ **差 81**，正是「其他支出 + 公益捐款」（我按上表反算 = 80，量级吻合）。⇒ **「其他杂项扣减」必须显式留位，不能当暗项。**

## 四、我方现状（§A.11 锁定版）

- 分项：每平台 **3 框** — 商品总价 / 打包费 / 商家活动补贴；小计 = 三项相加。
- 快速：每平台 **1 框** = 商品总价 + 打包费 + 商家活动补贴。
- 配平软校验：`应有商家应收款 ≈ 外卖收入合计 − 商家活动补贴 − 佣金 − 配送服务费 − 配送补贴`，阈值 **50 元**；差额≈打包费、差额≈配送费另有专提示。
- 费用侧营销项：外卖平台佣金 / 外卖配送服务费 / 外卖活动补贴 / 外卖配送补贴 / 外卖推广费。

**结论：配平式是对的。** 展开即 `(商品总价+打包费+商家补贴) − 商家补贴 − 佣金 − 配送费 = 商品总价+打包费 − 佣金 − 配送费`，与平台的 `优惠前总额 − 佣金 − 配送服务费 − 其他支出` **同构**（当"其他支出"= 0 时完全等价，本店 8 月正是 0）。**问题不在等式，在"客户能不能把数抄对"。**

## 六、豆包 2 轮复核：采纳 / 不采纳 / 存疑

### 第 1 轮（问题：三平台数据哪些必填、并 M1 还是单独专段、M3 最少输入、该加哪些校验）

**我采纳的**
- **精细模式 4 必填**：优惠前商品总价 / 打包费收入 / **商家承担活动补贴** / **有效订单数**；可选框：平台佣金、商家承担配送服务费、推广费、平台补贴（仅参考不参与利润）。
- 系统自动算（不让老板算）：优惠前总营收 = 商品总价 + 打包费；商家到手全额 = 优惠前总营收 − 商家补贴 − 佣金 − 配送服务费；渠道总支出 = 商家补贴 + 佣金 + 配送服务费 + 推广费；单均优惠前总价 / 单均商家到手 / 到手率 = 到手 ÷ 优惠前总营收。
- **快速模式 2 必填**（本月该平台商家到手总额 + 有效订单数），不拆分补贴佣金配送。
- **M1 视图层加「外卖专段（多平台卡片）」，底层合并进 M1 双利润引擎**；明确**不推荐**做成完全独立的外卖模块（会造成两套利润表）。—— 与我方「单一装配口」纪律一致。
- **M3 完整测算**（单均毛利 / 保本单量）要额外补 **2 项平台账单永远不给的输入**：外卖菜品加权平均净料成本（优先从 M3 成本卡按销量加权自动拉）、单份外卖打包耗材成本（餐盒/袋子/贴纸）。
  保本式：`单均边际贡献 = 单均到手 − 单均食材成本 − 单均打包耗材成本`，`外卖保本单量 = 外卖分摊固定成本 ÷ 单均边际贡献`。
- **校验分硬/软**：硬 —— 商家补贴 ≤ 商品总价+打包费（防填反）、有效订单 ≥ 0 且整数；软 —— **到手率 < 40% / > 85% 双向预警**、单均原价合理性（单均 < 5 元防手滑）、**同店同月同平台重复录入禁止**。

**参考阈值（它给的真实值）**：美团到手率 523/837 ≈ 62.5%，京东 4224/7422 ≈ 56.9% ⇒ 40% / 85% 的带子与我们数据不矛盾。

**第 2 轮（我拿实测去纠正它，并点名要文案）——它给的成品文案（可直接抄）**

- 字段显示名：**「商家承担全部补贴（合计）」**
- 输入框下固定口径小字：
  > 填写规则：平台账单里【商家活动补贴 + 商家代金券补贴 + 商家配送费活动补贴】三项相加的合计金额；不要只抄"商家活动补贴"单列，漏填代金券、配送补贴。
- 外卖专段**顶部边界说明**（防双记，固定）：
  > 外卖专段内的「商家承担全部补贴（合计）」已经包含：商家活动补贴、商家代金券补贴、商家配送费活动补贴；不要再在 M1 费用页面重复录入「外卖活动补贴」「外卖配送补贴」，同一笔补贴不能二次计入费用，否则成本重复叠加，利润失真。
