## 2 我填的数据跑出来什么（实测，非推算）

场景：小面店 / 二线三线 / 快餐 —— 加盟 3 万(3年) + 装修 8 万(3年) + 设备 5 万(5年)；
月租 6000 / 人工 12000 / 水电 1500 / 杂费 500；外卖佣金 8%；毛利率 62%；目标月利润 1 万。

### 2.1 正算（forward）

| 输出 | 实测值 | 手验成立 |
|---|---|---|
| 建店总投入 | 160,000.00 元 | ✓ |
| 月摊销 | 3,888.89 元 | = 30000/36 + 80000/36 + 50000/60 ✓ |
| 固定合计 | 23,888.89 元 | = 20,000 + 3,888.89 ✓ |
| 综合变动成本率 | 46% | = (100−62) + 8 ✓ |
| 边际贡献率 | 0.54 | ✓ |
| **保本月营业额** | **44,238.69 元** | = 23888.89 ÷ 0.54 ✓ |
| 保本日均 | 1,474.62 元 | ÷30 ✓ |
| **目标月营收** | **62,757.20 元** | = (23888.89+10000) ÷ 0.54 ✓ |
| 回本周期 | 16 月 | = 160000 ÷ 10000 ✓ |

### 2.2 反推（reverse）· 房租改由租金率导出

`bands_preview` 实测 rent 行 = `{lo:5, hi:10, redline:15}` ⇒ 派生 `target_rent_rate = 10`。

| 输出 | 实测值 | 手验成立 |
|---|---|---|
| **目标月营收 R** | **63,383.84 元** | 固定'=14000+3888.89；变动 38+8+10=56%；(17888.89+10000)÷0.44 ✓ |
| 房租上限 | 6,338.38 元 | = R × 10% ✓ |
| 月客流 | 2,535.35 人 | = R ÷ 25 元 ✓ |
| 日均客流 | 84.51 人 | ÷30 ✓ |
| 翻台率（**输出**） | 2.11 | = 2535.35 ÷ (40×30) ✓ |
| 面积上限 | `null` | 坪效=0 ⇒ 不编造 ✓ |

**正反一致性**：反推房租上限 6,338.38 vs 正算输入房租 6,000 ⇒ 偏差 5.6%（**预期内**，两者口径本就不同；
反推是"按行规上限倒推"，正算是"按实际租金正推"）。

### 2.3 边界与失败模式（全部 fail-closed，无一静默出数）

| 用例 | 实测 |
|---|---|
| `rev_price_fen=0`（客单价没填） | ✅ 拒：必须是 > 0 的整数分 |
| `seats=0`（面积没填 ⇒ 估不出座位） | ✅ 拒：必须是 > 0 的整数 |
| `open_days=0` | ✅ 拒：必须是 1~31 的整数 |
| 反推仍带 `rent`（重复计租） | ✅ 拒：反推模式下房租由目标租金率导出 |
| `target_rent_rate=0`（行规还没取到） | ✅ 拒：必须是 (0,100] 的 number |
| 毛利率 8% + 佣金 8% ⇒ 综合 100% | ✅ 红警：R / 保本 / 派生量**全部 null**（不编造） |

⚠️ 此处我**先写错了一个期望**：首版用"毛利率 20%"期望红警 —— 实际 80+8=88% < 100%，不红警是**正确行为**。
改期望而不是改代码迎合（同 R234「守卫红先怀疑自己」）。

## 3 实测抓到的两个真缺口

### 缺口 A（P0）· `turnNum`（翻台率）= **纯死输入**

- 全仓出现仅 3 处：`data.turnNum` 声明 · `onTurn()` handler · wxml 一个 `<input>`。
- 🔴 **引擎根本不收 `turn` 参数**（`validate.js` / `service.js` 零命中）。
- ⇒ 用户在 L3「专业参数」里填了翻台率 → 触发 `scheduleCalc` → **对任何结果零影响**。
- 这比"填了算错"更坏：**用户以为自己填的数有用**。
- 佐证李老师原话完全成立：「翻台率……这些本身是咱们计算出来的」——
  引擎**本来就在输出** `turn_rate`（实测 2.11），只是没人把它和输入框对上。

### 缺口 B（P0）· `pixelEffYuan`（坪效）仍在输入区

- L3 里原封不动（`terms.js: pixelEffLabel2='坪效'`），违反 R223 §3.2 定案。
- 其唯一下游 `area_cap_sqm` **恒为 null**（坪效不让问 ⇒ 传 0）⇒ wxml 那行 `wx:if` 永不显示 = **伪功能**。

### 🔴 缺口 C（P1，最值得记）· 守卫判的是「我改过什么」，不是「需求要什么」

v1.4 我新立的 `check_m2_biz_inputs.js` 当时 **28/0 全绿**，却对 A、B 两个缺口**完全无感**。
根因在 `BAN_INPUTS = ['revRentRate', 'revPixelEff']` ——
只列了**我自己删掉的那两个 `rev*` 字段**，而 L3 里历史存量的专业指标**一个都没进扫描面**。

> 黑名单只能拦"已知的历史错误"。判据写成"我清过的地方干净了"，
> 就等于**给自己发合格证**，而不是守住需求。
