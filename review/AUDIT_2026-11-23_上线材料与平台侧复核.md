## 1 修复的真实缺陷：隐私政策「不收集」段与第 9 项自相矛盾

**证据（修复前）**：
- `specs/dev-specs/上线材料_隐私政策_v1.md:39` 第 9 项登记「参考照片（相册选择或当场拍照）」，`chooseMedia` 取本地临时路径。
- 同文件 `:46`「不收集」段写「❌ 相册（头像走微信官方 `chooseAvatar` 能力，**不读相册**）」。
- 同文件 `:109` 附录写「`getPhoneNumber` / `getLocation` / `chooseImage` / **相册相关 API 均未出现**」——而 `chooseMedia` 确已在代码中出现。

**风险**：审核员对照隐私指引与代码描述会看到明确互斥，属"隐私政策不实/自相矛盾"，可直接驳回；且这不同于数值漂移，**原有 C7 守卫抓不到**——C7（`tools/check_privacy_collection.js:227-238`）只解析「无 `API` 调用」/「均未出现」后跟反引号 API 名的句式，而矛盾写在中文描述里。

**修法**：
1. `:46` 改为「❌ 相册**批量/后台读取**……**唯一例外**：用户主动点「拍张照」时按上表第 9 项选一张或当场拍照」。
2. `:109` 改为「`getPhoneNumber` / `getLocation` / `chooseImage` 等均未出现」+ 单独一行说明「相册类唯一例外：`chooseMedia`……该流程内无 `uploadFile`」。
3. `check_privacy_collection.js` 新增 **C10 组 4 条断言**：C10-① 段可定位（fail-closed）/ C10-② 提及相册拍照必须带例外限定 / C10-③ 反恒真（旧句式必须被拦）/ C10-④ 附录不得再写绝对否定。

结果：`check_privacy_collection.js` **31 通过 / 0 失败**（原 27）；`check_privacy_placeholders.js` 9/9 未受影响（6 处占位符口径未动）。
