## §1 三步做了什么

| 步 | 改哪 | 关键 |
|---|---|---|
| ① 识别 | `service.js::detectDishShape` | 加 `DISH_SHAPES.S = 'dsi1_standard'`，**放在最前面判** |
| ② 分发 | `index.js` | `shape === S` 走独立 handler |
| ③ 落库 | 新增 `handleDSI1Import` | 按 `(platform, bizDate)` 分组写，`_id` 确定性 |

### 为什么识别要放最前

DSI-1 同样是「商品名称 + 销量 + 销售额」三列齐全 —— **形态 C 的判据更松**（还允许「菜品名称」别名）。
若放在 C 后面，AI 整理好的标准表会被当成"外卖商品销量表"解析，**渠道列直接丢失**（C 没有渠道概念）。
而 DSI-1 的判据最严（前 7 列逐字 + 顺序一致）⇒ 放最前不会误吞任何现有形态。

验证过：DSI-1 → `dsi1_standard`、形态 C 表 → `waimai_goods`、形态 A 表 → `dish_sales`，三者互不干扰。

## §2 两个"为什么不用现成的"

### 为什么不能复用 `handleFormCImport`

C 分支的入参只有一个 `platform`。而**一份 DSI-1 可以同时含堂食 + 美团 + 淘宝闪购**（老板一个月的账就一张表）。

若复用它：全部行会被写成同一个 platform，且 `saleDocId(shop, platform, bizDate, seq)` 的
platform 与 seq 都固定 ⇒ **同一天不同平台的行互相覆盖，且不报错**。

### 为什么不再套 `checkGradeA`

那道闸是为「平台原始导出表」设计的（列名不固定、单位混乱、可能有合计行）。
DSI-1 是**已经标准化过的表** —— `dsi1.parse` 已逐列校验完（日期/渠道/数字/名称）。

再套一层只会把"格式问题"报成"数据问题"，反而更难懂。
⇒ 门禁口径改为：解析不过就直接把 dsi1 的**人话错误**（带行号）透给用户。

## §3 最易错的一步被抽成了纯函数

`groupByPlatformDate(rows)` 放在 `dsi1.js` 里导出，handler 只负责调它 + 写库。

**为什么必须抽出来**：这段逻辑没法在 handler 里单测（要 mock 整个云环境），
而它恰好是「错了也不报错、只是数据互相覆盖」的那类失效。

实测（同一份表，2 天 3 平台）：

```
正确：双维分组 ⇒ 5 组（09-07 三组 + 09-08 两组），每个 _id 都带 platform
错误：按日期单维 ⇒ 2 组，平台维度被压平 ⇒ 后写的冲掉先写的
```

断言 D2-①~⑤ 就盯这个，其中 D2-⑤ 是**反证**：单维 2 组 vs 双维 5 组，证明 platform 维度不能省。

## §4 落库字段

复用现有口径，只多一个来源标记：

```js
source: 'dsi1'      // 与普通 excel 导入('excel')区分开
```

这正是 R581 里我提的"来源维度"——**先落第一笔**。将来如果 AI 采的数据混进来，
至少能分辨"这批是 AI 按标准格式整理的"，出问题可以只清那一批。

`_id = saleDocId(shop, platform, bizDate, seq)` 确定性 ⇒ **同一份表重导是覆盖不是翻倍**。

## §7 又一个"判据把数量钉死"的坑（R584 实测）

加了 DSI-1 的落库点后，`check_m333_parse::6-⑦` 当场判红：

> ❌ 6-⑦ 落库面：**三处** external_sales_daily 写入全部带字段 —— 写入点 4 个 / 缺字段 0 个

**注意 detail：缺字段 0 个。** 也就是说新增的那处**完全合规**，红的原因只是"数量不再是 3"。

这是本仓第 N 次遇到同一类问题（此前有"判据钉单行字面量"、"判据钉函数签名"）：
**判据把"性质"写成了"数量"。**

正确处置（本轮已改）：

```js
// 改前：writeBlocks.length === 3            ← 加一处合规写入就假红
// 改后：writeBlocks.length >= 3 && badBlocks.length === 0
//       数量只做下界保护，真正的分辨力在 badBlocks（逐块查三字段）
```

⇒ **纪律：断言要判"每一处都满足 X"，不要判"恰好有 N 处"。**
`=== N` 只在 N 是**业务不变式**时才用（比如"核心 4 组"），实现细节的数量一律用 `>=` + 逐项校验。
