## 2 M1：「每100g」缺份量换算（本轮唯一的口径变更）

### 2.1 核准：错的到底是什么

`cloudfunctions/common/specDerive.js` 里 per100g 预设是 `coef` 五项全 1：

```js
{ spec_key: 'per100g', name: '每100g', coef: { main:1, aux:1, season:1, semi:1, pack:1 }, unit_label: '100g' }
```

`calcBom/index.js` 用这份 coef 跑 `deriveSpec` ⇒ 规格成本 ≡ **整份成本**。
而页面上这一格的售价是「**元/100g**」（`edit.wxml`：`（元/{{t.specPer100gUnit}}）`）。
⇒ 收入按 100g、成本按整份，两者不同单位。

可复现的一对数（本轮写进 `tools/selftest_m3_per100g.js` B 组，用工卡 975 分 + 500g 一份）：

| | 100g 成本 | 每100g 售价 11.05 元 | 毛利率 |
|---|---|---|---|
| 改前（整份成本） | 9.75 元 | 11.05 元 | **11.76%** |
| 改后（975×100/500） | 1.95 元 | 11.05 元 | **82.35%** |

差值 70.59 个百分点 —— 不是精度毛刺，是**同一个数字的两套单位**。
更贵的是建议价：`reverse_price_fen` 也按整份成本反推 ⇒ 老板照它定价，等于把 5 份的料钱摊到 1 份来收。

### 2.2 修法（口径决策）

- **克重是用户事实，不是引擎常量**：新增 `portion_g`（「这一份多少克」），随规格一起**快照落库**
  （`specs_json`），改克重 = 新版本；老版本回看仍按当时的克重算。
- **换算公式**：`100g 成本 = 整份成本 × 100 ÷ 克重`。实现仍走 `deriveSpec`（喂一个**五项同值**的均匀系数），
  所以成本 / 毛利率 / 建议价全部由**同一个 `calcCostCard`** 算 —— 不在页面或 Controller 里另写一份毛利公式。
- **不填就不给数（fail-closed）**：`need_portion: true` + 全 0 出参 + 页面红字提示。
  改前的"按整份算"**不是兜底，是错数**；而"0 元成本 ⇒ 100% 毛利"同样会被当真 ⇒ 宁可空着。
- **预设里绝不带默认克重**：守 `check_spec_per100g_identity` P5（一旦有人写 `portion_g: 250`，
  每张卡都会按这个猜的值静默算成本）。

### 2.3 契约变更（向后兼容）

| 通道 | 新增字段 | 缺省时行为 |
|---|---|---|
| `calcBom` 入参 | `spec_portions: { per100g: 克重 }` | 缺 ⇒ `need_portion:true`（不出数） |
| `calcBom` 出参 | `spec_results[].need_portion`（布尔） | 老调用方忽略即可 |
| `saveCostCard` / `specs_json` | `specs[].portion_g`（数字，0 = 未填） | 存量卡无此字段 ⇒ 0 |

## 3 M2：停用 ≠ 删除

`collectSpecs()` 原来是 `.filter((r) => r.enabled)` ⇒ 停用的规格**根本不提交**，
而 `saveCostCard` 是**整份覆盖** `specs_json` ⇒ 停用一次就永久消失（下次进编辑页没这一行）。
服务端 `sanitizeSpecs` 一直保留着 `enabled` 位（`enabled !== false`），**只是前端没送**。
现在：全部行都提交，带 `enabled`；停用行没填价就只带键。

## 4 M4：反算与正算不是同一条式子（复核时又挖出两处）

原分子：`Cf + Cp + M + s + d + 顾客配送费 − 打包费`，分母 `(1 − c)`。

按 `calcTakeawayOrder` 的到手口径重推：

```
M = P* + 打包费 + 顾客配送费 − s − 佣金(P*) − d − 配送补贴 − 推广费 − Cf − Cp
⇒ P*(1−c) = Cf + Cp + M + s + d + 配送补贴 + 推广费 − 打包费 − 顾客配送费
```

三处与原实现不同：

1. **漏推广费 / 配送补贴**（审计原文指出的那条）—— 二者在到手口径里都是实打实的现金流出。
2. **顾客配送费符号反了**（本轮新发现）—— 它是**实收**（`payment = 商品总价 + 打包费 + 配送费(顾客承担)`），
   反解时要**减**。原式 `+` 会让反算价虚高 2×dc。**存量用例 dc 恒为 0 ⇒ 长期不可见**
   （这正是"用例只覆盖一半"的典型，见 T-i）。
3. **`commission_mode='fixed'` 完全没算**（本轮新发现）—— 固定佣金与挂牌价无关 ⇒ 不该除分母，
   应直接加回。原实现一律 `÷(1−c)` 且 fixed 模式下 `c` 恒 0 ⇒ 每个订单少收一个固定佣金。

判据不靠"记得补"：新增 **T-i 回带闭合** —— 反算出的价喂回 `calcTakeawayOrder`，到手利润必须 ≡ 目标利润（±1 分）。
改前该用例直接红 400 分，改后 800→800。**这个判据是唯一能同时抓住上述三处错的形式**（grep 分子里有没有 `promo` 抓不到符号错）。

## 5 M5：读不到卡 ⇒ 空白表单（最伤的一条）

`load()` 里是 `if (c) { 回填 }`，**没有 else**。读不到卡（已删 / 串号 / 网络失败被 catch 吞成 `cardList=[]`）时：

- `loading` 变 false、表单**空白但可编辑可保存**；
- 老板以为"这张卡没数据"重新录一遍 ⇒ 保存带 `card_code` ⇒ **追加新版本，把有内容的卡盖成空白版**；
- 若卡其实已删 ⇒ 凭 `card_code` 新建版本链 = 凭空造卡；
- 全程零提示。

三条腿一起断：显式错误页（`loadMissing`）+ 整块表单与两个保存按钮不渲染（`wx:else`）+ `onSave` 首行硬拦。

## 6 M6：N+1 查询

`getCostCard` 在 `for (const card of targets)` 里 `await loadLines(...)` ⇒ N 张卡 N 次串行查询。
改为**一次** `listAll('shop_cost_card_line', { shop_id })` + 内存按 `cost_card_row_id` 分组。

三点必须同时成立（否则"优化"会变成新缺陷）：

1. 每张卡仍只拿自己的行 —— 分组键 `cost_card_row_id`（行的物理外键）；
2. 行顺序不变（按库返回顺序 append，不排序）；
3. 取全用 `listAll`（短页判据），且 `truncated` 并入出参 —— 否则"卡齐了、行少了"而页面显示正常。

判据是**行为对拍**（`getCostCard/selftest.js` G-1~G-7）：同一份数据，"逐卡 where 查"与"批量分组"逐卡全等
（含条数、顺序、孤儿行丢弃、空输入）。

## 7 M7：快照提示的比对基准

```js
const isOld = snapMonth && snapMonth !== this.data.curMonth;   // 改前
```

`curMonth` 只在 `init()` 里取一次「今天几月」，之后再没更新；而 `month`（统计月）可被 picker 改。
⇒ 看任何**历史月**，`snapMonth`（卡的创建月 = 统计月）必然 ≠ `curMonth` ⇒ **全表误挂**「该卡成本为 X 月快照」。
提示语的含义是"比你在看的这个月旧"，基准就该是 `month`。

（附带修复：这条提示所在的 `fmtRanked` 被 `check_dishreview_engine` 12-④ 用「700 字窗口」判定，
本轮加的注释把 `dishKey:` 顶出窗口 ⇒ 判据**假红**。已把该判据改成「剥注释 + 花括号配对取函数体」，
窗口长度不再影响判定 —— 这是"窗口判据"的天敌，已在守卫头注写明。）

## 8 M8：三项数值校验

`checkAmounts()` 原来只查金额栏。三项直接进引擎的数值栏一个都不查，且提交时全是 `Number(x) || 0`：

- `lossRate` 读成 0 ⇒ 成本偏低（损耗被当成没有）；
- `targetMargin` 读成 0 ⇒ 建议价归零，界面照常显示；
- `batchOutput` 读成 0 ⇒ 引擎 `out = 1` 兜底 ⇒ **整批料钱当成一道菜的成本**（虚高 N 倍）。

前两项并入金额体检（同一套 `classifyAmount`）；第三项单独一条横幅 `batchOutputBadTip`（讲"必填没填"，
与"金额读不成"分开讲，免得老板改错格）。改模式 / 改出货量 / 选模板都会触发体检。

## 10 已知边界（诚实登记）

1. **per100g 填了价但没填克重**：允许保存（规格定义仍是有效信息），只是不出成本/毛利/建议价。
   没有硬拦的理由：拦了老板就存不下草稿；但**绝不能**替他猜一个克重（猜错比空着更贵）。
2. **`commission_min_fen` 保底佣金**：反算按纯比例求解，命中「比例佣金 < 保底」那一段时反算价**偏低一档**。
   分段点是 `P = min/c`，要解需引入分段函数；登记不做（比错价小得多，且方向保守）。
3. **入包体积只剩 0.4 KB**：本批在页面里加了注释与文案就到线了。下一批动页面文案前，
   先想 `packOptions.ignore` 或压缩注释，别去调 `check_pack_size` 的预算（那是守卫，不是配额）。
4. **M3（复制卡）只去掉了死拼接**：复制路径的字段集仍靠"照抄"，`portion_g` / `specs` 是随 `specs` 整块过去的
   （`specs: src.specs || []`），未逐字段白名单。若将来加字段，仍要过一遍 `check_m3_card_roundtrip`。
