## 二 巡检方法（可复用）

云端代码**读不到**（`cli` 无 `invoke`；`download` 会覆盖本地，禁用）⇒ 只能用间接判据：

```
每个函数 f：
  t_local  = max( git log -1 --format=%ct -- cloudfunctions/f/**/*.js )
  t_deploy = max( mtime(_m3/deploy_logs/deploy_f_*.log) )
  t_local > t_deploy + 60  ⇒ 云端可能落后
```

### 两个已踩的坑（判据自身）

| 坑 | 现象 | 修法 |
|---|---|---|
| **逐个文件调 `git log`** | 44 函数 × ~15 文件 = 660 次派生 ⇒ 脚本被 SIGTERM 杀 | **一次** `git log --format=%ct --name-only -- cloudfunctions/` 全量解析成 `{fn: 最后提交时间}` |
| **提交时间 ≠ 内容变更** | 本轮先部署后提交 ⇒ 4 个**已部署**函数也被判"落后"（提交晚于部署，但内容在部署前就在工作树里） | 判据只作**初筛**，定性须回看「改动批次是否晚于部署批次」 |

### 辅助判据

- `cli cloud functions list` ⇒ 云端函数全集（**44 个**）
- `cli cloud functions info --names <空格分隔>` ⇒ `status` / `timeout` / `runtime` 三列（**唯一**机器判据）

### 3.2 🔴 P1 —— 两个函数 `timeout` 仍是平台默认 **3**

`info` 全量实测（单位秒）：

| 函数 | timeout | 说明 |
|---|---|---|
| `importSalesBill` | **3** | 走 `cloud.downloadFile` + xlsx 解析 + 落库 ⇒ **3 秒必超时**，账单导入在真机用不了 |
