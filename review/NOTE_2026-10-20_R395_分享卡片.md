## 3. 口径决定（为什么这么写）

1. **只传原始「分」，不在分享路径上重算。** 页面展示串是 `fenToYuan(2)` 出来的「9,160.00」，
   从它反解回分会带格式误差，也不该在分享路径上再跑一次业务逻辑 ⇒ 页面在 `load()` 里留
   `shareFacts`，分享时只读它。
2. **没账本 / 没算出来 ⇒ 退回通用句，绝不编 0。** 编 0 会说「最后剩下 0 元」——
   与 R298「无账本月三态判据恒真」同族：把"不知道"说成"是 0"。
3. **M3 只统计「已定价」的卡。** 未定价 `margin=null`；算进分母会说「12 道里 5 道毛利低」，
   而其中几道根本没定价 —— 假结论。档位线取 `utils/marginBand.js::MID`，页面与 utils 都不再写 40。
4. **M2 失败/红灯分支必须清 `shareFacts`。** 只清 `result` 不清取数 ⇒「保本数已经没了，
   分享出去还在说旧保本线」，正是 R359 记过的「派生状态漏清 → 把旧数当新数」。
5. **页面不自己拼 `title` / `path`。** 守卫 ②-d/②-e 明令：一旦页面自己拼，单源立刻失效。
6. **禁词**：标题只陈述本店算出的数，不出现 盈利 / 赚钱 / 投资 / 回本周期 / 收益率（`TERMS.forbidden`）。
