## 1 · round71（补记）：分项→快速→分项 不丢值

**李老师原话**：点分项填数字 → 点快速录音出现堂食总收入 → 再点分项渠道录入，「提示总额已暂放第一行，让自己再分配」
——「这种来回点击本身就是解决看数字有没有错误，现在看还需要人工二次填写」。

**根因**：`onPickDineMode` 切到快速时 `g.rows` 被**整体覆盖**成单行总额 ⇒ 分项各渠道值被销毁；
切回分项时 `rows.length <= 1` ⇒ 重铺预设 + 总额塞首行。

**修法**：数据层加 `dineDetailRows` 快照；切快速前快照、切回分项**非空即原样恢复**（不重铺、不弹提示）；
仅从未填过分项才走旧逻辑。`load`/`onShow`/`onHide` 同步快照。

**守卫**：batch8b **G9**（4 条）。

## 2 · round72：渠道「全集常在」+ 装配单一入口

### 李老师原话
> 分渠道录入，下面那些字段很多不见了，比如 挂账 团购 还有其他的，核查一下，
> 同时避免以后改东西，改完一处又的修复另外一处。

### 2.1 根因（两条）

**① 直接症状**：渠道行是「后端存过什么就渲染什么」。
`rebuildFromItems()` 把 `sub_items` 原样当行数组 ⇒ 老板**没填过**的预设渠道
（个人/单位挂账消费、团购/代金券核销、银行卡/POS 刷卡…）**压根不出现**。
只有「从未填过分项」的 seed 分支才铺 7 行 —— 所以现场看到的是「字段少了几个」，
而 terms.js 里 7 条**一条没少**（先核对了单一数据源，确认不是词条被删）。

**② 病根（李老师点名的那句）**：产出堂食行的路径有 **5 条**且各拼一遍：
`initGroups` / `rebuildFromItems` / `addRow` / `delRow` / `onPickDineMode`。
这天然就是「改一处、漏三处」的结构。

### 2.2 修法：唯一装配口

新增 `utils/dineChannels.js` → `normalizeDineRows(rows, items, notes)`，三条语义：

| 语义 | 说明 |
|---|---|
| 预设渠道**全集常在** | 清单里有的渠道一定出现（没填 = 空行），顺序按 terms；金额**按名回填**（不按下标），后端只回传部分行也不错位 |
| 自定义渠道**留末尾** | 「+ 添加渠道」加的行保留，`fixed:false` 可编辑、可删除 |
| **幂等** | `normalize(normalize(x)) === normalize(x)`，可重复调用不越补越多 |

页面 `decorateDineRows()` 转调它 ⇒ **5 条路径一次收口**。
🔒 渠道清单**只**来自 `miniprogram/i18n/terms.js` → `ledger.income[dine_in].items`；
页面/wxml **零硬编码**（G10h 变异实证能抓到）。

### 2.3 三处配套（不配套就会引入新 bug）

1. **新增行带 `custom:true`** —— 否则空行被装配当「空行丢弃」⇒ 点「添加渠道」没反应（回灌 M6 实证）。
2. **保存只提交填了金额的行** —— 判据看**金额不看名字**：快速模式单行是「无名、有额」，必须保留；
   否则每存一次往后端塞一堆空 `sub_item`。
3. **预设行不给删除键**（`wx:if="{{!r.fixed}}"`）—— 装配必然把预设补回，给了 × 只会让人以为「删不掉」；
   自定义行仍可删。

### 2.4 守卫 G10（20 条）与一条方法论

⚠️ **守卫直接 `require` 真模块 + 真 terms 跑用例**，不在守卫里复制实现 ——
复制一份逻辑会跟着一起错，守卫就成了摆设（「断言不得恒真」）。

覆盖：装配模块导出 / 清单 ≥7 且含挂账+团购 / **后端只回传 3 条仍补齐全集** / 金额按名不错位 /
顺序不打乱 / 自定义留末尾且可编辑 / 预设 `fixed=true` / 空行丢弃 / custom 空行放行 / **幂等** /
**round-trip 后全集+数值俱在** / 静态 4 条（转调唯一入口 · require 存在 · 无硬编码 · 保存过滤 · 删除键）。

### 2.5 变异回灌 6/6（并因此修掉 **2 条假绿**）

| 变异 | 结果 |
|---|---|
| M1 装配不再铺预设全集（= 李老师现场 bug） | ✅ 抓到（❌=6，脚本崩亦算抓到） |
| M2 页面绕过唯一入口自行拼装 | ✅ 抓到（G10g） |
| M3 页面写死渠道名 | ✅ 抓到（G10h） |
| M4 保存不过滤空行 | ✅ 抓到 —— **首轮漏网**，见下 |
| M5 删除键退回「行数>1 就显示」 | ✅ 抓到（G10j） |
| M6 新增空行不带 custom | ✅ 抓到 —— **首轮漏网**，见下 |

**首轮两条漏网 = 真收获（回灌的价值就在这）**：

- **M4**：`G10i` 原先只认「有 `.filter(`」⇒ 改成 `.filter((r) => true)` 照样命中（恒真）。
  加严为**把匹配锁在箭头函数体内**：`\.filter\(\(r\) =>[^)]*amountYuan`
  ⚠️ 关键在 `[^)]*` 而非 `[\s\S]{0,n}` —— 后者会**吃到后面 `.map()` 里的 `amountYuan`** 而假绿（已用正/变异两串对照验证）。
- **M6**：只有运行时用例（G10d）测不到 `addRow` 的**静态写法** ⇒ 补 `G10k` 守 `concat([{ subItem: '', amountYuan: '', custom: true }])`。

### 2.6 ⚠️ 回灌脚本自身两个坑（已修，写下来免得再犯）

1. **`restore()` 顺手删了 `.mutbak`** ⇒ 第 2 条变异起「没被还原」而**逐条累积**，表现为
   **「还原后 fail=3」（应为 0）**，且 M2–M5 的失败数异常递增（G10g/G10h 一直红）。
   本次因此**污染了工作树**（`input.js` 残留 `HARD_CODED` / 自行 map / `filter(r=>true)`；`input.wxml` 残留旧条件），
   已用 `_restore_r72.js` + 按行精确删除清干净并逐条校验。
   **修法**：备份只在开头做一次；每条变异前 `reset_to_base()`；结尾统一 `cleanup()`。
2. **用「N 通过 / M 失败」里的 M 判是否抓到** ⇒ 变异若让 selftest **崩溃**（语法错），压根不打印汇总行，
   M 取不到 = `-1`，会被**误判成「漏网」**（本次 M1 即如此，其实 6 条 ❌ 都已打出）。
   **修法**：抓到 = 「有 ❌ 行 **或** 退出码非 0」。

> 附带教训：`input.js` 是 **CRLF** 行尾 —— Python/JS 里做字符串替换时锚点带 `\n` 会 miss（须用 `\r\n` 或按行处理）。
