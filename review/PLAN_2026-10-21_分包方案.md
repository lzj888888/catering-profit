## 2. 怎么分：按「老板的使用路径」分两个包

不分一个包的理由：老板只算月账时不该被迫下载 M2 选址那 316 KB。
分两个的依据是**两条天然不同的使用路径**：

| 使用路径 | 频率 | 包含 |
|---|---|---|
| **核算线**（记账、算成本、看毛利） | 每月/每天 | 月度账、菜品卡、原料、外卖 |
| **工具线**（选址试算、店铺、对账、支付） | 偶尔 | M2 测算、店铺设置、对账、订单 |

> 因为分包内容也算入包）。它降的是**主包（单个顶层条目）**——而这正是会撞的那堵墙

## 3. 🔴 真正的成本：**555 处路径引用**

这是本方案最重要的数字，也是为什么**不能手改**：

| 面 | 处数 | 说明 |
|---|---|---|
| 守卫（`tools/*.js`） | **450 处**（45 个唯一路径），分布在 **76 个文件** | 大量守卫写死了 `pages/xxx` 路径做扫描面断言 |
| 页面代码（`.js` / `.wxml`） | **105 处** | 跳转 `url:` / `navigateTo` / `redirectTo` |
| **合计** | **555 处** | 手工改必错 |

### 还有一个隐蔽陷阱：**相对 require 深度**

```js
// 现在：pages/month/input.js
require('../../utils/api.js')        // 上 2 级到根

// 移动后：subpkg/biz/month/input.js
require('../../../utils/api.js')     // 必须上 3 级
```

每个被移动文件的**所有**相对 require 都要 +1 级。`check_requires.js` 会抓漏，但它是事后报红，不是预防。

## 4. 做法：写迁移脚本，不手工改

`tools/migrate_to_subpkg.py`（一次性工具，跑完归档，**不进 SUITES**）：

输入 = 一个模块名（如 `month`）+ 目标 root（如 `subpkg/biz`），执行：

1. `git mv pages/<mod> subpkg/<root>/<mod>`（用 git mv 保留历史）
2. **重算该目录下所有文件**的相对 require：按文件新深度重新拼 `../` 级数（不是简单字符串替换）
3. 全仓替换路径引用：`pages/<mod>/` → `subpkg/<root>/<mod>/`（守卫 + 页面 + `app.json`）
4. 更新 `app.json`：从 `pages` 移除、加入对应 `subpackages[].pages`
5. 打印改动统计，由人确认后再跑门禁

**为什么脚本比手改可靠**：555 处 + 相对深度，人手一定漏；脚本是**同一条规则**应用全局，漏了就是规则错，容易被门禁抓到。

## 5. 预加载策略（避免老板点进去等）

`app.json` 配 `preloadRule`：

- **首页加载完** → 预下载 `subpkg/biz`（核算线是主路径，老板进来大概率要记账）
- **`m3/hub` 加载完** → 预下载 `subpkg/tools`（选址入口在 hub）

这样"第一次点进去"不会看到 loading 转圈。

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| 漏改某处路径 ⇒ 运行时跳转 404（**门禁可能抓不到**，因为守卫扫的是文本） | 每步**额外**跑一次"路径存在性探针"：全仓扫 `pages/` 与 `subpkg/` 引用，逐条核对目标文件真实存在 |
| 相对 require 深度算错 | 脚本按新深度**重算**，不靠替换；`check_requires` 兜底 |
| tabBar 页误移 | 脚本硬编码 tabBar 白名单（`index`/`m3/hub`/`mine`），命中即拒 |
| 守卫写死路径导致大面积假红 | 预期会有；**先跑一次看红在哪**，再判断是"该改路径"还是"守卫扫描面该放宽" |
| 真机表现与模拟器不同（分包下载时机） | 真机验证一次（这也是队列 #7 的一部分） |

## 8. 验收标准

1. 门禁 **202/202** 绿（含新增的路径探针）。
2. `check_pack_size`：主包 ≤ **0.8 MB**、最大分包 ≤ 1 MB。
3. `app.json` 的 `pages` 只剩 3 个 tabBar 页；两个 `subpackages` 配置正确。
4. 全仓无 `pages/(month|card|material|takeaway|sandbox|shop|recon|pay|metrics)/` 残留引用。
5. 真机：从首页 → 记账 → 返回 → 选址，全程无 404、无长时间白屏。

## 9. 本方案**不做**的

- ❌ 不动 `utils/`（360 KB 主包大头）——它是公共依赖，拆进分包反而重复。
  （若将来主包仍紧，可论"把 M2 专用的 bizPreset 拆出"——但那是另一件事，需先确认无跨页共用。）
- ❌ 不做"独立分包"（`independent: true`）——它不能 require 主包 utils，会导致代码重复，反而变大。
- ❌ 不顺手改任何业务逻辑。**纯搬迁 + 路径修正**，行为零变化。
