const TAKEOUT_FOLD_KEY = 'takeout_fold_';        // 常量在文件头
takeoutFoldKey() {                                 // key = 常量 + shopId + '_' + month
  const app = getApp();
  const shopId = (app && app.globalData && app.globalData.shop_id) || '';

saveTakeoutFold(expanded) {

## 2 建议方案 A：提示词收纳（箭头折叠）

### 2.1 判定规则：多长才折？

**不按"字数"一刀切，按「是否抢占首屏 + 是否必读」分三类：**

| 类 | 判据 | 处理 | 例 |
|---|---|---|---|
| **① 一句话就够**（≤18 字） | 保留原位不动 | **不动** | 「改完自动重算，不用点按钮」(13) |
| **② 结论短句 + 详情**（19~60 字，且有"结论/细则"可分离） | 拆成 **首行结论句**（留在原位）+ **详情**（折进 `▸`） | **折叠** | `incomeHint`(47)：留「出了餐就算，不管钱到没到账」；折"平台还没结算的照记" |
| **③ 纯细则/口径**（>60 字，无独立结论句） | **整块折进箭头**，标题写「XX 怎么填？」 | **折叠** | `dine_in`(181) / `subsidyNote`(119) / `boundaryNote`(107) |

🔴 **红线：折叠 ≠ 删文案。** 全部原文保留、只是"点开才见"，绝不改写语义（本仓有「术语单源」和文案守卫）。

### 2.2 交互形态：用 `▸` 还是 `?`

**建议：`▸/▾` 箭头为主，`?` 只在"整段口径"这种入口用。**

理由：
- 本仓已有 `▸/▾` 的两处实现，**改动能复用既有 class 与守卫**（`ad-gates G1` 按 `.scope` 查字号 ≥28rpx）。
- `?` 是**新符号**，需要新增样式与守卫；且本仓禁 emoji、`?` 需要画图标块。
- **触控红线**：箭头行点击区必须 **≥88rpx**（本仓硬红线）。`?` 若做成小圆点很容易踩线。

⇒ **采用**：段首/区块首用**整行可点**的 `▸ 详细口径`（整行 88rpx 高，好点）；
**不用**孤立的 `?` 小图标。

### 2.3 落点清单（按优先级）

| 优先 | 页面 | 现状 | 动作 |
|---|---|---|---|
| **P0** | `pages/month/input` 月录入页 | **62 条长文案 / 8.3 屏** | 全页 3 类分流；`dine_in`(181) 等超长项**必折** |
| **P0** | `pages/month/input` · 外卖段 | 24 条 / 3.5 屏 | 已有折叠框架，把 `subsidyNote`/`boundaryNote`/`scopeGuide`/`periodNote` 收进去 |
| **P1** | `pages/sandbox/index` M2 沙盘 | 22 处 hint | 已有 L2/L3/假设三层折叠 ⇒ **只需把长 hint 挂进去** |
| **P1** | `pages/month/amortize` | 4 处，含 `scopeHint`(134) | `scopeHint` 折进已有折叠块 |
| **P2** | `pages/card/edit` | `lineKindHint`(49) | 折 |
| **P2** | `pages/material/batch` | 6 处 `tip` | 多为短句（`matBatchCols` 42） ⇒ 酌情 |
| **不动** | `pages/index`、`mine`、`shop/switch` | 2 处以内、均短 | **保持现状** |

### 2.4 默认展开 or 默认收起？

**建议：全部默认收起，但首行必须是一句"能独立读懂"的结论句。**

反例（不可接受）：收起来只剩「填写口径」四个字 ⇒ 用户不知道点开有什么。
正例：**「外卖怎么填？· 一个数就够 ▸」** —— 标题本身就是信息。

⚠️ **记忆化**：展开过后记住（复用 `takeoutFoldKey` 模式），下次进来自动展开
—— 老用户不必每次点。

## 3 建议方案 B：3 个功能模块的引导（我的判断）

### 3.1 先看用户的四个选项

| 选项 | 我的评估 |
|---|---|
| ① 进模块**弹页**，可跳过/不再显示 | ❌ **不推荐**（见 3.2） |
| ② 三个模块**共用一个**弹页 | ❌ 同上，且共用页要么内容泛、要么太长 |
| ③ **长期可折叠隐藏**的功能说明（箭头） | ✅ **推荐** |
| ④ 把**填表说明也做进去** | ✅ **部分推荐**：引导页放"4 步总览"，填表口径留在各页折叠块（**不要混在一起**） |

### 3.2 为什么不做自动弹窗 —— 三条硬理由

1. 🔴 **会每次都弹。** 全仓**没有任何 `firstRun` 标记**（§1.5 实测），
   要"只弹一次"必须先做持久化。做持久化本身不难（有 §1.4 模式），
   但**弹窗必须有"不再显示"**，否则第二次打开就烦人 —— 而"不再显示"一旦点了，
   新用户可能永远看不到引导（**跳过的代价比不弹更大**）。
2. 🔴 **弹窗会打断"填表"这个主任务。** 李老师的北极星是「**填起来不费力气**」。
   用户点进模块是**带着目的来的**（我要录这个月的账），弹一层说明 = 先拦一下。
   本仓已有教训：`pages/index/index.wxml` 注释明确写过按钮不许叫「记一笔」（会被理解成记流水 ⇒ 觉得被骗）
   —— **同一族的"预期错位"问题**。
3. 🔴 **符合已有取舍。** 本仓对「弹层 × 键盘」已有明文死结结论（表单必须独立页、不用弹层），
   说明本仓**倾向减少弹层**而非增加。

### 3.3 推荐做法：**「入口处一行折叠条」+ 复用已有使用指引**

```
首页
├─ hero 卡（本月利润）
├─ ① 月度盈利核算        ›      ← 卡本身不动
├─ ② 开店盈亏平衡点测算   ›
├─ ③ 菜品成本毛利核算     ›
├─ ┌────────────────────────┐
   │ ▸ 第一次用？看这里（4 步）│   ← 新增：整行可点，≥88rpx
   └────────────────────────┘
   （点开 → 复用 exp.guideBody 那 4 步）
```

**三个要点：**

1. **做在首页、不做进模块。** 用户从首页出发时就该看到；进到模块里说明"你要干什么"已经晚了。
2. **不动已有 3 张卡。** 卡片已经有 `subtitle`（如「每月到底能剩多少，一算就清楚」）
   —— 那**就是**最好的功能说明。再加一层反而重复。
3. **复用而非新建。** `exp.guideBody`（4 步）已经写好且已上云，
   **只是入口埋得太深**（我的 → 使用指引）。正解是**把它搬到首页**，而不是再写一份。
   ⇒ 零新文案、零新页面、零新集合。

### 3.4 「不再显示」怎么做（如果李老师坚持要自动弹）

若最终仍要自动弹，**必须**满足：

- 标记键：`guide_seen_{openid}`（或本地 `guide_seen_v1`），**本地即可**（换设备重看一次不算错）。
- **默认不弹**：只在「有店铺 + 本月无账本」时弹（= 真新用户），**不是**无脑首屏弹。
- **弹层含「不再显示」**，且该按钮**必须 `wx.setStorageSync` 落盘**（否则点了下次还弹 = 假开关，
  与 `check_flow_entry_and_fold.js` 里记录的「假折叠」是同族缺陷）。
- 每个弹层入口**都要能被守卫验证**（本仓标准：新增交互必须有机器判据）。
