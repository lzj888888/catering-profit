## 0 结论（先看这五条）

1. **个体户能开，且比个人主体更宽**：开通只要求「已认证 + 主体为个体工商户 + 主体信息完备」。**「类目含工具」是个人主体的门槛，不是个体户的硬条件**（元宝核对指出，我原先说错了）；但「服务类目要覆盖所售虚拟商品类型」仍需满足，我们工具类是覆盖的。
2. **iOS 能卖，且必须卖**。我们代码里「iOS 端一律不给购买入口」的策略**已过时**，应改为「满足四条件走 IAP，不满足才降级」。不做的代价是丢掉 iOS 全部付费流量。
3. **费率是限时价，不是长期价**：Android 当前 1%，**标准 10%**；iOS 当前 12%（腾讯 5% 已减免），**标准 17%**。定价必须按「最坏情况 10% / 17%」做敏感性，不能拿 1% 当常态。
4. **iOS 退款我们做不了主**：不能主动退，只能 3 秒内应答 Apple 的退款问询；「7 天未使用全额退」这句在 iOS 上**不能原样承诺**，必须分端表述。
5. **发货只认推送，不认前端 success**：`xpay_goods_deliver_notify` 是唯一的发货依据；前端 `wx.requestVirtualPayment` 的 success 只代表「支付已调起」。

## 1 官方硬事实（逐条可复核）

### 1.1 开通（企业/个体户档）
| 条件 | 原文 |
|---|---|
| 主体 | 已认证小程序；类型为企业 / 事业单位 / **个体工商户**；主体信息完备 |
| 入口 | MP 后台左侧【虚拟支付】→ 开通 → 签协议 → 提交执照/提现账户/支付管理员 |
| 审核 | 一般 1–7 个工作日；支付管理员为法人可跳过账户验证 |
| 结果 | 拿到 **二级商户号（OfferID）** + 现网 AppKey + 沙箱 AppKey |

### 1.2 终端与 iOS
- 适用 **Android / iOS / 鸿蒙 / Windows**；iOS 需微信客户端 **8.0.68+**。
- iOS 额外条件：① 已开通虚拟支付 ② 配置**小程序简称**（Apple 展示名）③ 在「基本配置」**开通苹果 IAP**。
- iOS 用户下单条件：iPhone/iPad 且 **iOS 15+**；微信 **8.0.68+**；**单笔 ≥1 元**；**仅中国大陆 App Store 账户**。
- **Apple 支付仅现网、无沙箱**（沙箱只有 Android/开发版开发者工具内可用）。

### 1.3 费率与结算（2026-11-22 抓取）
| 终端 | 当前生效 | 标准 | 结算 |
|---|---|---|---|
| Android / 鸿蒙 / Windows | **1%**（限时） | **10%** | T+3（冻结 3 日后分账） |
| iOS | **12%**（=Apple 佣金，腾讯 5% 限时免） | **17%**（Apple 12% + 腾讯 5%） | 自然月结束后 45–60 天 |
| 自动续费订阅 | 首笔 1%、第二笔起 10%（元宝补充，需以协议为准） | — | — |

> 🔴 我们不卖自动续费，走「主动支付」1%（限时）。但**定价必须按 10%/17% 算一遍**：25.9 元年卡在 17% 下到手 21.5，19.9 单次诊断到手 16.5。
> 桌面豆包补正：**1% 仅限主动支付**；自动续费订阅首笔 1%、第二笔起恢复 10%，且订阅是**独立链路**（微信≥8.0.71、基础库≥3.16.1），
> iOS 无法自动扣费、退订只能在 App Store 设置里操作。我们全 one_time 不建订阅，这条是「别误接」的提醒，不是漏项。
> 退款：支付 180 天内平台退手续费，超 180 天不退。发票：次月 5 号后可申请上月腾讯技术服务费发票。

### 1.4 退款
| 终端 | 谁能退 | 方式 |
|---|---|---|
| Android 等 | **开发者主动退** | 调官方 `refund_order` 接口 / MP 后台 |
| iOS | **开发者不能主动退** | 用户在 App Store 申请 → Apple 问询开发者（**3 秒内**回 0 建议退/1 拒绝，连续 3 次不应答=「不确定」交 Apple 判）→ 退款成功推 `xpay_refund_notify` |
| 共同 | 退款成功后平台推 `xpay_refund_notify`，服务端**回收权益 + 更新订单** | |

### 1.5 回调事件族（不是普通支付回调）
`xpay_goods_deliver_notify`（**发货，核心**）、`xpay_coin_pay_notify`、`xpay_refund_notify`、`xpay_complaint_notify`（投诉）、`xpay_subscribe_signing_result_notify`、`xpay_subscribe_pay_fail_notify`、`xpay_subscribe_ios_refund_query_notify`（**3 秒问询**）。

### 1.6 限额
- 10 万元/月（全终端合计）**只写在《虚拟支付：个人》**，是个人主体专属条款。
- 个体户档文档**未列**月限额 —— 但**不等于没有**（可能另有风控/提现额度），不能拿它做宣传。

## 4 接入方案

### 4.1 商品模型（先建道具，再谈代码）
后台「虚拟支付 → 道具管理」建 4 个道具，发布到现网：

| 道具 | productId 建议 | 价格（分） | 对应业务 |
|---|---|---|---|
| 真实利润·月 | `plan_basic_month` | 2590 | 31 天权益 |
| 真实利润·季 | `plan_basic_quarter` | 6900 | 90 天 |
| 真实利润·年 | `plan_basic_year` | 19900 | 365 天 |
| 深度诊断·单次 | `plan_diag_single` | 1990 | 1 次额度 |

> 道具价格是**唯一价格来源**：`goodsPrice` 必须与后台一致，否则报 `-15013 道具价格错误`。
> 道具发布后约 **10 分钟**生效（`-15014`），上线前预留缓冲。
> 全部 one_time，**不建订阅**（结构性规避自动续费投诉）。

### 4.2 下单
```
前端：选档 → 调 payCreateOrder（服务端）
服务端：读订单/道具 → 生成 outTradeNo（8-32 字符，一次性）
        → signData = {offerId, buyQuantity:1, env:0, currencyType:'CNY',
                      productId, goodsPrice, outTradeNo, attach: plan_id}
        → paySig（AppKey 签名）+ signature（用户态签名）
前端：wx.requestVirtualPayment({mode:'short_series_goods', signData, paySig, signature})
```
🔴 五条硬约束（1–3 桌面豆包复核确认，4–5 为其新增）：
1. **`outTradeNo` 每单只能用一次**，重复报 `-15002`。支付失败重试必须**换新单号**，业务订单与支付单号是 1:N（业务单表加 `pay_attempts` 数组或子表）。
2. `signData` / `paySig` / `signature` **必须服务端生成**，前端只透传；`attach` 放 `plan_id`，但**发货时仍以订单表为准**，不信任 attach。
3. 前端 success **不代表发货成功**，只代表支付调起成功；UI 必须显示「支付处理中，权益到账后刷新」。
4. **`outTradeNo` 限 8–32 字符，且不能以 `_` 下划线开头**（豆包复核新增）；生成函数必须本地校验，不能只靠微信报错。
5. **`goodsPrice` 仅道具直购模式必填校验**；`-15013` = 道具价格与后台不一致，`-15002` = 单号重复（豆包已核实码值）。

### 4.3 发货（唯一可信入口）
```
xpay_goods_deliver_notify
 → 验签（官方签名机制，勿自研）
 → 按 OutTradeNo 反查 shop_payment_flow（不是按 transaction_id 预检后插新单）
 → 校验：订单存在 / 状态 pending / 金额与道具价一致 / plan_id 与订单一致
 → 幂等：同一 OutTradeNo 已发货 ⇒ 直接返回成功
   🔴 微信回调失败最多重试 15 次（豆包复核新增）：发货/收权两端都必须幂等，
      不能只靠「订单状态 pending」挡一次——重复推送、乱序推送都要能安全返回成功
 → 发货：grants='diag_credit' ⇒ shop_diagnosis_credit +1（不碰 expire_at）
         其余 ⇒ 乐观锁更新 shop_entitlement.expire_at
 → 回写订单 paid + 发货时间
```
> 这正好把上一轮审计的 P0-1/P0-2/P0-3 一次性改对：**反查订单 + 校验金额 + grants 分流 + 乐观锁**。

### 4.4 退款
- **Android**：调 `refund_order` → 成功 → 收 `xpay_refund_notify` → 收权（`adminRefundMark` 的 `revokePlan` 复用）。
  🔴 `refund_order` **限 JSAPI 现网单**（豆包复核新增）：沙箱单退不了，测试方案必须按此设计。
- **iOS**：不提供「申请退款」按钮，文案改为「请到 App Store → 购买记录申请」；收到 `xpay_refund_notify` 后同样收权。
- **iOS 退款问询**（`xpay_subscribe_ios_refund_query_notify`）：3 秒内必须应答。
  - 独立轻量函数，**预留实例 ≥1**（不能靠按需冷启动）；
  - 只做「查订单状态」一次快查（订单状态提前写缓存/内存），**不做复杂计算、不调 AI**；
  - 内部硬超时 1.5–2.5 秒，超时**直接返回 0（建议退）**——宁可少赚，不触发「连续 3 次未应答」；
  - 规则：未发货/7 天内未使用 ⇒ 0；已发货且超 7 天 ⇒ 1；其余按 refundPolicy 结论映射。
  - 监控：P99 延迟与应答率单独告警。

### 4.5 多端
- `platform` 取 `android / ios / windows / hongmeng`：
  - iOS：先校验 iOS15+、微信 8.0.68+，不满足**不展示购买入口**（降级为说明）。
  - Windows/鸿蒙：与 Android 同通路（`wx.requestVirtualPayment`）。
- 🔴 iOS 端**不得出现任何引导站外支付**的文案（「联系客服购买/加微信转账」全部禁止），只能走 IAP 或纯说明。

### 4.6 测试
- Android/开发版：沙箱（`env:1`），但真机预览会被 `PAYMENT_ILLEGAL_IN_SANDBOX` 拦，只能在开发者工具内调。
- **iOS 无沙箱**：只能现网真机 + 真实扣款（最低 1 元）。测试道具建议单独建 1 元档，测完下架。

## 7 一句话

**规则上我们没有障碍**：个体户可开、iOS 可卖、工具类可卖会员与解锁；**真正的障碍是三条限时口径（1%/12%/T+3）会变，以及 iOS 退款与 3 秒问询这两处工程硬约束**。接入方案已按「道具直购 + 推送发货 + 分端退款」定稿，与上一轮审计的 P0 修复完全兼容——可以合并成一次改造。
