## 1. 改前的真实状态

`TERMS.m2.channelOver100` 原文写着「外卖 + 团购占比不可超过 100%，请调整」，全仓引用只有两处：
① 定义处 ② `pages/sandbox/index.js` 把它绑进 `t`。**wxml 从未渲染、js 从未判定** ⇒ 死文案。

后果（不是"提示缺失"这么轻）：
老板填「外卖 60% + 团购 60%」，`recomputeChannel` 照算：

```
佣金 = 60% ×（平台抽成 + 打包） + 60% ×（团购抽成 + 折扣）
```

这等于**按 120% 的流水扣佣** ⇒ 加权挂钩费率虚高 ⇒ 保本额虚高 ⇒ 老板以为要多卖很多才不亏。
全程零报错、零提示。与 R396 `anomalyRules` 同族：**能力/文案写了但零生产调用**。

## 3. 三个口径决定

1. **只判定、不钳制。** 超限时页面**照原样算**并提示"请调整"。
   为什么不静默钳到 100%：钳制会掩盖输入错误 —— 老板看不出自己填错了，看到的仍是一个看起来很合理的保本额
   （钳完的数同样是错的，因为真实占比关系未知）。**如实暴露 > 假装修正。**
2. **恰好 100（60 + 40）不算超。** 全程走满仍自洽，没有第 101 份流水。用 `1e-9` 容差吸收 `0.1 + 0.2` 的浮点残差。
3. **垃圾入参（负数/NaN/空串/乱字符）按 0、不报超限。** 这不是"占比超限"问题，报超限会把老板引向错误的修改方向
   （他该改的是"填了个负号"）。空值走 0 也保持 `recomputeChannel` 既有语义（`Number(x) || 0`）一致。
4. **关渠道时（`off`）不提示。** 此时占比不参与计算，提示只会误导。

## 4. 🔴 关键坑（R413 预研时 node 实测）

**不能在 wxml 里裸算**：输入框 `e.detail.value` 是**字符串**，`'60' + '40'` = `'6040'` ⇒ `> 100` 判 true
⇒ **「恰好 100」被误判成超限**。必须走 js 纯函数（`Number()` 归一 + 容差）。

## 5. 🔴 本轮元发现：判据自身也会「锚错地方 ⇒ 恒假」

接线完成后守卫仍红 3 条（②-3/②-4/②-5 报「未写入 over100」「未见纯函数调用」），但补丁自检明明是绿的。

根因：`bodyOf(src, name)` 用 `indexOf(name + '(')` 找**第一次出现**。而 `pages/sandbox/index.js:683`
有一处 `this.recomputeChannel();` **调用**，排在 822 行的**定义**之前 ⇒ 取到的是一段不相干的块。

⇒ 与 R299 记的「三种恒真形态」**同源、方向相反**：锚错地方不只造成恒真，也会造成**恒假**（永远红）。
修法：`bodyOf` 改为跳过成员调用（前一个非空白字符是 `.` 即跳过），并要求 `(` 到 `{` 之间无 `;`。

⚠️ 这条教训的价值在于：**它是在"接线后第一次跑绿"时才暴露的** —— 之前守卫"行为面全绿、接线面全红"，
红得"符合预期"，所以没人怀疑判据本身。

## 7. 诚实边界

- **只守 M2 渠道卡**（`pages/sandbox/index.js::recomputeChannel`）。矩阵页（`matrix.js`）若也有渠道占比入参，
  未接这条规则 —— 那是另一处，需要时按同一纯函数复用。
- **提示不等于拦截**：超限时仍然让老板算（因为"超 100%"有时是他故意的试算）。若产品上要改成**禁止计算**，
  那是产品决策（李老师定），本轮不做。
- 守卫的 `bodyOf` 现在只认 "方法简写 / 函数声明" 两种形态；若未来把 `recomputeChannel` 改成 `const f = () => {}`，
  取体会失败 ⇒ ②-2 会红（fail-closed），不会静默绿。
