## 0 一句话结论

M3 现有规范已经把「**理论 BOM + 快照 + 只 INSERT 不 UPDATE**」这条地基打得非常硬，
**套餐和外卖不该另起一套引擎**，而应分别落在两块已有的地基上：

| 李老师要的 | 我的判断 | 落法 |
|---|---|---|
| 套餐成本（勾选几个菜 → 套餐成本） | **本质是"引用型成本卡"**，不是新物种 | `shop_cost_card` 加 `card_type=3`；明细行加 `line_type=2`（引用子卡）。**复用**版本/快照/软删/配额五套机制 |
| 外卖按每一单算 | **= 套餐的"组合能力" + 一层渠道费用层** | 先做套餐的"组合"，外卖单均 = 组合 + 平台扣点/配送/补贴 + 包材。**一次投入，两处收益** |
| 不同业态 | **不要新建第二份业态数值** | 复用 M2 的 `BANDS` 单源（四业态）。M3 只做三件事：毛利参考带 / 灰字参考 / 包材档位参考 |
| 原材料变动 | **已有"同步最新价⇒生成新版本"**，缺的是"**影响面预警**" | 新增只读的"涨价影响面"：改价后列出受影响卡 + 新成本 + 毛利率变化，**绝不自动改卡** |

一句话：**M3 从"单品核算"升为"组合核算 + 渠道核算"，但引擎仍只有一套、快照纪律一条不改。**

## 1 行业数据（外部检索，带来源）

### 1.1 业态毛利率 —— 与仓内 M2 参考带**高度吻合**（关键一致性证据）

| 业态 | 外部区间 | 来源 | 仓内 M2 `BANDS.grossMargin` |
|---|---|---|---|
| 快餐 / 简餐 | 55%~70% | [S7] | `fastfood` **[58, 68]** ✅ |
| 中式正餐 | 50%~65% | [S7] | `dining` **[55, 65]** ✅ |
| 火锅 / 烧烤 | 50%~65% | [S7] | `hotpot` **[52, 67]** ✅ |
| 饮品 / 咖啡 | 60%~80% | [S7] | `cafe` **[62, 72]** ✅ |

- 行业平均：食材成本占收入 **30%~40%**，净利率 **5%~15%**；食材成本率通行标准 **28%~35%**（对应目标毛利率 65%~72%）。
- 中国饭店协会《2025中国餐饮行业成本白皮书》：**2024 年全国餐饮平均食材成本率 34.2%**（较 2022 +2.8pp）。[S5]

> **结论**：仓内 M2 那套四业态参考带**不需要重建**，M3 直接用（单源）。这同时满足本仓「禁止第二份真相源」铁律。

### 1.2 净料 / 出品率（M3 出成率的现实分布，可用于灰字参考）

- 公式：`净料率 = 净料重量 ÷ 原重量`；`净料成本 = 原料价格 ÷ 净料率`。[S6]
- 常见出品率：**熟五花肉 60%、熟排骨 65%、熟肥肠 45%**；冰冻虾仁解冻 **80%**；干货涨发 木耳 **500%**、干海参 **650%**。[S6]
- 蔬菜类实际出成率 **70%~85%**；调料损耗占食材成本 **3%~5%**。[S5]
- **燃料费**：通过历史测算，约占销售额 **3.8%~4.9%**，实操常按**每道菜 1~2 元**估。[S6]

> 对 M3 的意义：现有规范的「出成率默认 100 / 损耗率默认 0」会让**几乎所有菜品的理论成本偏低**。
> 不是要改默认值（改了会动 9.75 锚点），而是**在录入处给灰字参考**（见 §3.3）。

### 1.3 外卖成本结构（按单拆账，老板视角）

**一笔 30 元外卖单的典型构成** [S8]：

| 项 | 金额 | 占订单价 |
|---|---|---|
| 食材成本 | 9~15 元 | 30%~50% |
| 包装成本（餐盒/餐具/袋/纸） | 1.5~3 元 | 5%~10% |
| 配送成本 | 3~6 元 | 10%~20% |
| 平台抽成 | 4.5~7.5 元 | 15%~25% |

**平台费率真相（分平台）**：

- 美团官方口径：技术服务费（= 真佣金）**6%~8%**；履约服务费按**距离/价格/时段阶梯独立计价**。[S1]
- 饿了么：技术服务费约 **8%**，设**保底**（如每单 **1.3 元**）；履约服务费浮动。[S3]
- 京东外卖：固定佣金 **5%**（新入驻曾全年 0 佣金）。[S3]
- 县域实测：美团约 **17%**、饿了么约 **15%**（综合费率，含配送等）；纯餐饮平均客单价 **35~36 元**，平均每单约 **6.3 元**。[S2]
- 商户实际负担：**20% 以上，有时 30% 以上**（含平台大额券的商家分摊）。[S3]
- 补贴分摊实例：「满 38 减 18」⇒ **商家承担 12 元 / 平台承担 6 元**。[S3]

**🔴 最有价值的一个锚点 —— 商家实收率（同一套餐三平台实测）** [S4]：

| 平台 | 顾客支付 | 商家实收 | **实收率** |
|---|---|---|---|
| 美团 | 31.76 元 | 23.76 元 | **74.81%** |
| 饿了么 | 26.74 元 | 17.94 元 | **< 70%** |
| 京东外卖 | 16.96 元 | 18.26 元 | >100%（平台亏损补贴） |

- 低价单更惨：15 元外卖单，扣佣金 2.25~3.75 + 配送商家担 1.5~3 + 活动补贴分摊 2~4 + 包材 0.5~1
  ⇒ **商家到手只有 7~10 元**；而 **15 元以下订单占外卖总量约 40%**。[S14]

**包装成本的"客单价定律"**（这条直接决定外卖模式怎么设计）[S9][S10]：

| 客单价 | 包装成本占比 |
|---|---|
| ≥ 70 元 | **< 5%** |
| 20~30 元 | **20%~25%** |
| 4~5 元单品 | 20%~25% |

- 单件采购价参考：普通塑料餐盒 **0.3~0.5 元**、环保纸盒 **0.5~0.8 元**、一次性筷勺 **0.1~0.2 元**、包装袋 **0.05~0.1 元**；
  加保温层或定制 LOGO ⇒ 单套可 **≥1.5 元**。[S10]
- 商家感知差：餐盒**零售 2 元 / 商家采购 0.65~0.7 元**（所以"包装费"本身可以是一笔微利）。[S9]

### 1.4 套餐结构（行业成型做法）

**三级架构 + 黄金比例** [S12][S13]：

| 档位 | 定价 | 目标毛利率 | 建议占比 | 作用 |
|---|---|---|---|---|
| 引流款 | 28~35 元 | 50%~55%（≤30% 极端引流） | **30%** | 冲销量/排名/评价，"不赚但别亏" |
| 利润款 | 38~50 元（双人 48~68） | **60%~65%** | **60%** | 真正利润来源 |
| 形象款 | 58~88 元（高端 398~699） | 65%~75% | **10%** | 价格锚点，抬客单价 |

- 外卖定价三步法：`成本 = 食材 + 包装 + 平台抽成(15%~20%)` ⇒ `售价 = 成本 ÷ (1 − 目标毛利)`。[S11]
- 组合逻辑：**高毛利品 + 引流品**打包（如 9.9 元酸辣粉 + 15 元高毛利拼盘 = 24 元单人餐）。[S11]
- ⚠️ 避坑（行业共识）：**别为了好看塞太多配菜** —— 成本上去了，顾客还会觉得"都是配菜，主料太少"。[S12]

### 1.5 中小餐饮老板的真实痛点（决定"好用"的定义）

1. **不知道一份外卖到底赚不赚**：只知道"平台到账多少"，不知道扣了什么、扣了多少。
2. **改价后没人回头核算**：食材涨价 → 菜品毛利已破线 → 菜单价还是去年定的。
3. **套餐是拍脑袋定的**：靠"看着差不多"，说不清"这个套餐比我单点卖少赚多少"。
4. **堂食和外卖一套价**：堂食毛利率 60% 的菜，外卖扣完点只剩 35%，却按同一个价卖。
5. **理论成本和真实成本对不上**：出成率、损耗、燃料从没进过成本 —— 这就是 M3 与 M1 差异的来源。

### 2.3 🔴 三条必须先讲清的**口径边界**（否则一定算错钱）

**① 平台账单的「打包费」是收入；餐盒采购是成本 —— 两者不是同一件事。**
M1 已按 A.1 把「商品总价 + **打包费** + 商家活动补贴」计入外卖**收入**。
而餐盒/餐具/袋是**成本**。二者**不得相抵**：相抵 ⇒ 收入少记 + 成本少记，且"包装是否赚钱"这个真相被抹掉。

**② 外卖有「到手口径」与「总额法口径」两套，数字不同、都对。**
- 到手口径（现金视角）：`实收 = 顾客支付 − 平台各项`，最贴老板直觉 → 答"这单赚几块"。
- 总额法口径（会计视角）：`收入 = 商品总价 + 打包费 + 补贴`，`费用 = 佣金 + 配送 + 补贴 + 推广` → 与 M1 月度账**对得上**。
- 同一单，两种口径的"毛利"**必然不同**（补贴在总额法里既进收入又进费用）。**页面必须显式标注用的是哪套。**

**③ M3 的数是理论值，永远不能加进 M1 月度账。**
M3 现有规范已有常驻提示（M3.1）。新增的"外卖单均利润"**也是试算**，必须沿用同一条提示，
且**不得**在 M1 侧被当作"外卖渠道利润"加总 —— 那是 M1 自己的事。

## 3 四条主线的设计

### 3.1 套餐成本（勾选几个菜 → 套餐成本）

**核心判断：套餐 = 引用型成本卡。** 明细行不是原料，而是**其他成本卡**。

#### 3.1.1 数据模型（最小改动）

```
shop_cost_card  增 1 个字段
  card_type   TINYINT   -- 1=单品(默认) 2=批量预制 3=套餐

shop_cost_card_line  增 1 个字段（**复用现表，不新建集合**）
  line_type   TINYINT   -- 1=原料(默认) 2=子成本卡
  -- line_type=2 时，以下字段改语义（表达"引用哪张卡的哪个版本"）：
  sub_card_id      STRING   -- 被引用卡的逻辑卡号 card_id
  sub_version      INT      -- 锁定版本号（**锁版本，不跟最新**）
  material_name    → 存子卡名称快照
  net_unit_cost    → 存"该子卡单份成本"快照（沿用现有「万分」表示：分×100）
  quantity         → 份数
```

> **为什么锁版本而不是跟最新**：套餐若"跟最新"，子卡一改价，历史套餐成本会**回溯变化** ——
> 直接违反 M3 最硬的那条红线（快照不变）。锁版本 = 套餐和单品一样"记得当时多少钱"。
> 需要跟新价时，走**「同步套餐至最新价」= 生成套餐新版本**，与现有功能 8/9 同构。

#### 3.1.2 计算

```
套餐食材成本 = Σ(子卡单份成本快照 × 份数)                      ← 复用现有明细累加
套餐总成本   = (套餐食材成本 + 套餐辅料/包材分摊) ÷ (1 − 制作损耗率/100)   ← 与单品同式
套餐毛利(定价) = 套餐售价 − 套餐总成本
套餐毛利率     = 套餐毛利 ÷ 套餐售价
```

#### 3.1.3 "好用"的三个关键信息（这是别人家产品往往没做的）

1. **顾客省了多少**：`Σ 子菜单点挂号价 − 套餐售价`（顾客视角的价值感，直接可写进外卖菜单文案）。
2. **我少赚了多少**：`套餐毛利 − Σ 子菜单点毛利`（老板视角）。**为负 ⇒ 红字提示"这个套餐在拉低你的毛利"**。
3. **套餐 vs 单点的结构对比**：列出每个子菜贡献的成本占比，一眼看出"哪个菜在吃利润"。

> 第 2 条是本模块最有商业价值的一条：它把"套餐是不是引流款"从感觉变成数字。

#### 3.1.4 复用与不变量（**零重写**）

| 机制 | 是否复用 | 说明 |
|---|---|---|
| 版本快照 / 只 INSERT 不 UPDATE | ✅ 完全复用 | 套餐改 = 生成新版本 |
| 软删除 30 天 | ✅ 完全复用 | |
| 循环引用拦截 | ✅ 复用并**扩展** | 套餐引子卡；子卡引套餐 ⇒ 必须拦（现有 `detectCycle` 扩一层） |
| BOM 层级 | ⚠️ 需拍板 | 现有"最多 2 层"。套餐是否算第 3 层？（见 §4 决策点 D3） |
| 免费配额 3 张 | ⚠️ 需拍板 | 套餐是否计入 3 张？（见 §4 决策点 D4） |
| 引擎 | ⚠️ **多副本** | `calcBom` / `saveCostCard` / `syncCostCard` / `getCostCard` / `getCardVersions` 各有一份 `service.js` ⇒ 改引擎必须**五副本同步 + md5 校验**（本仓既有铁律） |

### 3.2 外卖成本（按每一单算）

**核心判断：外卖单均 = 组合能力（套餐那套）+ 一层渠道费用层。** 所以 §3.1 是 §3.2 的基座。

#### 3.2.1 计算对象是「一单」，不是「一道菜」

一单 = `[{卡片/套餐, 份数}] + [包材项] + 平台参数`。输出的是**这一单的账**：

```
① 顾客支付 P            = Σ(商品标价 × 份数) + 打包费 + 配送费(顾客付)
② 平台扣项 = 佣金(率 c × 商品总价，可设保底 min) + 配送服务费 d + 配送补贴
              + 商家活动补贴分摊 s + 推广费分摊
③ 商家实收 R            = P − 商家承担补贴 − 佣金 − 配送服务费 − 配送补贴
④ 菜品成本 C_food       = Σ(卡片单份成本 × 份数)
⑤ 包材成本 C_pack       = Σ(包材采购单价 × 数量)
⑥ 单均理论利润           = R − C_food − C_pack
⑦ 到手率                 = R ÷ P          ← 行业实测 70%~75% [S4]，可直接当"填得对不对"的校验
```

#### 3.2.2 🔴 最该做的一个功能：**外卖挂牌价反算**

老板最痛的场景："这道菜堂食卖 28，外卖该挂多少才不会亏？"

```
目标：达到目标到手利润 M
挂牌价 P* = (C_food + C_pack + M + s + d − 打包费收入) ÷ (1 − c)
```

- 输入：菜品/套餐、目标到手利润（或目标到手毛利率）、平台费率 c、配送费 d、补贴 s。
- 输出：**外卖建议挂牌价**、该价位下的到手率、以及"比堂食价高/低多少"。
- 附校验：到手率落在 70%~75% 外 ⇒ 提示"参数可能填错"（用行业实测当**软提示**，同 A.11.4 的软提示纪律，**不阻断**）。

#### 3.2.3 口径必须显式二选一（见 §2.3 ②）

页面顶部用**开关**（不是自动判断）：`[到手口径]` / `[总额法口径]`，默认到手口径。
结果区必须显示当前口径名 + 一句人话解释。**两套数字不得混在一个总数里。**

#### 3.2.4 与既有外卖能力的衔接（不重复造）

M1 侧已具备（`utils/takeaway.js`）：4 平台预设、快速/分项模式、粘贴提取、配平校验（软提示）、

⇒ 若要留痕，单独存 `shop_takeaway_plan`（**不进任何利润计算**），列为 v1.1。

## 5 红线与风险

1. **引擎五副本**：`calcBom` / `saveCostCard` / `syncCostCard` / `getCostCard` / `getCardVersions` 各有一份 `service.js`。
   任何公式改动**必须五副本同步**，并加一条守卫断言"五副本引擎段 md5 一致"（现有节奏下建议直接挂进门禁）。
2. **9.75 / 4.48 / 12.35 / 12.08 / 24.38 五个既有锚点一个都不能漂**。新增套餐/外卖的验收锚点必须**另外新增**，不得改动旧锚点。
3. **禁止第二份真相源**：业态数值（M2 `BANDS`）、平台名与费率（`terms.js`）、色阶阈值 —— M3 一律引用，不复制。
4. **禁止把 M3 试算值并入 M1**：任何"外卖单均利润"都不得出现在月度盈利计算里。
5. **打包费（收入）≠ 包材成本（成本）**：两条腿都要走，不得相抵（见 §2.3 ①）。
6. **R128 不预填**：所有参考值只进 placeholder / 灰字，绝不进 `yuan` 字段。
7. **术语三处同步**：新增可见文案 = 双副本 `terms.js` + `input.js` 的 `t`，否则 wxml 取空串（既有纪律）。

## 7 验收锚点草案（新增，不动旧锚点）

沿用 S3 的构造风格（整数好手算、结果唯一）：

**套餐（A-a）**：宫保鸡丁（成本 9.75，售价 28）+ 米饭（成本 1.20，售价 3）+ 例汤（成本 1.80，售价 6）
⇒ 套餐食材成本 **12.75**；若套餐售价 **25**：
- 顾客省 **= 37 − 25 = 12 元**
- 套餐毛利 **12.25**、毛利率 **49.00%**
- 对比单点毛利（18.25 + 1.80 + 4.20 = **24.25**）⇒ **少赚 12.00 元**（红字提示"拉低毛利"）

**套餐锁版本（A-b）**：套餐保存后，把宫保鸡丁原料改价 ⇒ 套餐成本**仍 12.75**（快照不变）；
点"同步至最新价" ⇒ 生成套餐新版本，成本变为新值，旧版本可查。

**外卖单均（B-a）**：一单 = 宫保鸡丁套餐 × 1 + 包材 1.60 元
顾客支付 25（商品）+ 2（打包费）= 27；佣金率 6%（美团官方口径 [S1]，保底 1.3 元）、配送服务费 4.5、商家补贴分摊 3
⇒ 商家实收 `= 27 − 3 − max(25×6%, 1.3) − 4.5 = 27 − 3 − 1.5 − 4.5 = 18.00`
⇒ 单均利润 `= 18.00 − 12.75 − 1.60 = 3.65`；到手率 `= 18 ÷ 27 = 66.7%`
（⚠️ 66.7% 低于行业 70%~75% ⇒ 正好用来验证"软提示"能触发）

> 🔴 **基数铁律（我复算时被自己绊了一下，故单列）**：佣金（技术服务费）的计费基数是
> **商品总价**，**不含打包费**。若误把"顾客支付额（含打包费）"当基数，上例佣金会从 1.50 变 1.62，
> **单均利润差 12 分/单** —— 单量一大就是系统性偏差。这条必须写进规范正文并在页面口径说明里点名。

**外卖挂牌价反算（B-b）**：目标到手利润 **8 元**、佣金 6%、配送 4.5、补贴 3、打包费收入 2
⇒ `P* = (12.75 + 1.60 + 8 + 3 + 4.5 − 2) ÷ (1 − 6%) = 27.85 ÷ 0.94 = 29.63 元`

**涨价影响面（C-a）**：宫保鸡丁原料鸡胸肉 15 → 20 元/斤
⇒ 影响面列表出现"宫保鸡丁：成本 9.75 → 12.08、毛利率 65.18% → 56.86%"，且**卡不变**（需手动同步）
