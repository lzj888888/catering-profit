## 二 P1 · 无店铺态（`no_shop`）前端零处理 + 两个 tabBar 页不加载上下文（R214 §三 P1-2 / P1-3）

### 2.1 根因

| 既有守卫 | 它守什么 | 为何漏 |
|---|---|---|

| `check_idempotency`（R73） | 幂等与审计 | 同上 |

**新守卫判据 = 分类穷尽（不是"应当有鉴权"的白名单断言 —— 后者在 admin/回调/定时三类上必假红）**：

| 段 | 判据 | 实测 |
|---|---|---|
| **S 扫描面**（fail-closed） | 函数目录数 ≥40 / 契约文档存在且行数 ≥100 / A 类数 ≥25 / 锚点函数在场 | 5 条 |
| **A 三分穷尽** | 每个 `cloudfunctions/<fn>/index.js` 必落进 A（用户鉴权）/ B（admin 鉴权）/ C（免鉴权）之一 | A=29 / B=9 / C=6 |
| **B 登记双向防腐** | C 类逐条登记 + 每项 `why` ≥12 字 + 陈旧键红 + **已带鉴权却仍登记 ⇒ 红** | 4 条 |
| **C 定时/探针自保** | `mustSelfGuard:true`（现 2 项：`payExpireNotify` / `smokeTest`）必须**真判来源** + **解析器自证正负样本** | 4 条 |
| **D 自失效护栏** | 断言数 ≥15 + 扫描面文件数 ≥40（防"扫空 ⇒ 0 ≤ 预算 ⇒ 恒绿"，R182 教训） | 2 条 |

**关键判据形态**（`REJECT_RE = /if\s*\([^)]*OPENID[^)]*\)[\s\S]{0,120}?\breturn\b/`）：
必须要求 OPENID 出现在 **`if` 条件里且紧接一段 `return`**。⚠️ 首跑用宽松版 `OPENID[\s\S]{0,160}?return` ⇒ **C-④ 自证样本当场转红揭穿**：`const out = { openid: ctx.OPENID }; return out;`（只读不判）会被误判成"已拒绝"。已收紧并明写边界（`const u = !!ctx.OPENID; if (u) return` 这类**间接写法不算** —— 宁漏不假红）。
