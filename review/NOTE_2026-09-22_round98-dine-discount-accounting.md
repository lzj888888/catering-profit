## 1. 一句话结论

**所有收入一律按实际成交金额（折后）记，折扣让利不单列** —— 零结构改动，只改口径文案 + 规格留痕 + 2 条断言。

## 2. 为什么是「记实收」而不是「加折扣字段」（回源核实后）

### 2.1 先纠正一个事实：这不是「实现漏了字段」

全仓搜「折扣」= **0 命中**（`miniprogram/pages/month` + `utils` + `cloudfunctions` + `specs/dev-specs`）
⇒ 口径**从未定义**（空白 ≠ 缺陷）。堂食渠道行 7 个（现金 / 微信 / 支付宝 / 银行卡 / 储值卡 / 挂账 / 团购代金券核销），
**无「折扣 / 让利 / 原价」任何字样**。

### 2.2 可复用判据：让利有没有「独立的、老板拿得到的金额载体」

| 让利类型 | 载体 | 规范现状 |
|---|---|---|
| 平台外卖活动补贴 | 平台账单**独立列** | 已定总额法（收入含补贴 + 费用侧「外卖活动补贴」⇒ 净影响 0） |
| 团购券核销 | 平台账单**成交价** | `A.1` 已定「按团购价=成交价（非原价168、非到账）」= **折后** |
| 自发代金券 | **券面额**（张数 × 面额可数） | `A.1` 已定「按面额记收入，成本 MVP 简化不追溯」 |
| **店内会员折扣 / 满减**（本项） | **无** | 收银端即时少收，老板手上只留实收 ⇒ **只能记实收** |

⇒ **填实收不是新立口径，是把团购已定的折后口径推广到全堂食**（收敛而非分裂）。

### 2.3 为什么不能照抄外卖总额法

外卖有账单三列（商品总价 / 打包费 / 补贴）当数据源；堂食折扣**无账单无载体**，
硬套 ⇒ 「**无数据源配平**」= 与**已证伪的 T2** 同族（无源的等式必然稳定误报）。

### 2.4 为什么不按原价记（跨模块核对结论：不打架，但按原价会毁掉判据）

- `cloudfunctions/calcMonthlyProfit/service.js`：收入 = `Σ incomeItems`（**实收**）；
  `grossProfitFen = 收入 − materialCostFen`；`毛利率 = grossProfit / 收入`
  ⇒ 若堂食填原价，**分母仍是实收、分子含折前价 ⇒ 毛利率虚高**
  （折后 800 / 原价 1000 / 食材 400 ⇒ **50% vs 60%，虚高 10 个点**），
  而该指标正是「要不要继续开店」的判据。
- `cloudfunctions/calcBom/service.js`：`单品毛利 = 建议挂牌售价 − 原材料成本` ⇒ 用**牌价**，
  属**定价分析层**（有意为之），与 M1「实际经营结果」**目的不同、不冲突**；
  但若 M1 也改用原价，M1 会变成既非实收也非定价的**四不像**。
- 特例（已定口径，勿混入）：**代金券核销按面额、储值卡按核销金额** —— 二者属**支付方式**而非折扣，
  各有独立金额载体（券面额 / 卡内余额），与收银端即时少收的会员折扣**不同族**。
