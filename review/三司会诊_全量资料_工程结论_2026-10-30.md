### A2 一句话定位确认

【确定】保留原定位内核，**换掉对外表述**：
> 用你店里真实的账，先算清这个月真赚了多少，再告诉你下个月先动哪一手。

- 内部仍叫"经营决策大脑"没问题；**对外一律不出现**"AI 生成 / AI 诊断报告 / 智能决策"（合规 P0）。
- 对外统一词：**「经营体检 · 规则诊断」** + 页脚"本结论由规则引擎按您录入的数据判定，非人工智能生成"。

### A5 冲突点与工程裁决（本节是李老师只需要看的 4 个选择）

**C1 · M3 免费额度：8 / 5 / 20 三说并存**
- 事实：代码 20（唯一生效值）；文档 5 与 20 自相矛盾；任务书 8。
- 【建议】**维持 20，但抽成配置项**（`feature_permissions.plan_free.limits.cost_card`）+ 加一个 `free_card_limit` 灰度开关，允许 8/12/20 三档在线切换。
- 理由：改额度是改一行数，**现在拍死毫无收益，反而失去 A/B 能力**。真正要拍的是"免费用户能否看到 1 条结论"（见 A4-③），那才是漏斗的闸门。
- 若李老师坚持 8：需同步改 `collections.js:214` + `01_架构总览` 两处 + `check_collection_perms` 锚点，**约 40 分钟**，可做但建议推迟到有数据后。

**C2 · 罗盘是新建引擎，按新引擎排期**
- 【确定】工时**不进公式**（采纳豆包，理由：工时不可校验，一旦进公式排序不可复现，直接违背"数字可复现"口碑）。
- 【确定】连带系数走"品类默认档 + 三档自评 ±0.1"，但**必须入参落库并写进 `rule_trace`**，否则同数据两次算出不同客利贡献，事后无法解释。
- 【建议】默认档数值（火锅/烧烤 0.75–0.85、快餐/家常 0.45–0.55）目前**无出处**，需豆包补一句 IP 经验背书或改成"首月用中值 0.80/0.50，第二月起允许自评覆盖"。

**C3 · 四象限必须自店分位**
- 【确定】禁止 30:60:10（无来源，已否决）。
- 【确定】用**本店**销量中位数 × 毛利额中位数分四档（明星 / 走量薄利 / 高利低销 / 双低），每档 1 条动作，页面标注"**仅本店相对位置，非行业标准**"。
- 【建议】这是 AI 规则 #5 的前置引擎，先做引擎再谈规则，顺序不可反。

**C4 · 付费边界与北极星的对撞**
- 【建议】保留 `PAID_FEATURES` 现状（外卖/复盘锁），但新增一个"免费摘要"通道：免费用户在 M1 结果页看到**1 条**结论 + 1 个测算入口；点开第 2 条触发付费弹窗（与"保存超限/导出"同一弹窗，不新增第二个弹窗）。
- 理由：北极星是录入完成率，不是付费转化。**没有啊哈就没有录入，没有录入就没有付费**——这是唯一的因果链。

### C3 北极星指标：首月录入完成率 — 定义与落地

**漏斗（5 步，全部复用现有 `audit_log` 动作名，不新增采集面）**

```
S0 授权登录          action=user_login
S1 建店完成          action=shop_create
S2 首笔收入录入      action=ledger_save  (且 income_total_fen>0)
S3 首月账保存        action=ledger_save  (month 完整)
S4 结果页二次打开    action=result_view  (≥2 次，跨天)
S5 次月复录          action=ledger_save  (month = 上月+1)
```

- **不新增隐私面**：以上动作名 `audit_log` 已在写（铁律 9 操作必留痕），只做聚合查询，不采新字段。

## D. 工程实现建议（CloudBase 落地细节）

### D1 集合设计：新增 2 张，共 31 张

| 集合 | 用途 | 关键字段 | 权限 |
|---|---|---|---|
| `diagnosis_log` | 规则判定留痕（`rule_trace` 落库） | `trace_id, shop_id, month, engine_version, rules_version, pack_version, level, hits:[{code, level, params, evidence:[{field, value, source, period}]}], created_at` | 仅管理端可读写 |
| `funnel_event` | 北极星漏斗旁路事件 | `user_id, shop_id, step, at, meta` | 仅管理端可读写 |

**必须同步三处**（否则守卫会红，这是既有纪律）：
1. `cloudfunctions/initDb/collections.js` → `COLLECTIONS` 注册 + 索引
2. `specs/dev-specs/core/15_集合权限矩阵.md` → 29 → **31 张**（第 30/31 行）
3. `tools/check_collection_perms.js` 锚点数字

**索引**：`diagnosis_log` 建 `idx_diag_shop_month`（`shop_id + month`）；`funnel_event` 建 `idx_funnel_user_step`（`user_id + step`）。都遵循 `collections.js` 现有命名范式。

### D2 三层结构怎么落（关键：**不改引擎**）

现状 `utils/interpretation.js` 出参是 `{version, level, items:[{code, level, params}]}` —— 判断已对，**不要动它**。加一层纯函数做"附层"：

```js
// utils/diagnosisDoc.js —— 纯函数，零 IO，零模型
// 输入：interpretation 的一条 item（原样）+ 事实来源
// 输出：三层
{
  verdict:   { code: 'BELOW_BREAKEVEN', level: 'red', title_key: 'diag.below_be' },
  evidence:  [ { field: 'revenue_fen', value: 850000, source: 'calcMonthlyProfit', period: '2026-09' },
               { field: 'breakeven_fen', value: 920000, source: 'breakeven',        period: '2026-09' } ],
  narrative: { text_key: 'diag.below_be.body', params: { gap: 700 }, boundary_key: 'diag.boundary.volume' }
}
```

四条硬规则：
1. **`verdict.code` 必须复用现有机器码**，不新造一套（否则两套码，术语单源断裂）。
2. **`evidence` 每条必须有 `field + value + source + period`** —— 守卫 `check_diagnosis_trace.js` 机判：任何 item 的 `evidence.length === 0` ⇒ 红。这是"数字可复现"的机械保证。
3. **`narrative` 只放 key，不放中文** —— 文案走 `miniprogram/i18n/terms.js` 术语单源（已有 `check_page_terms` 守护）。理由：R464 实测，硬编码文案改名后判断会静默失效。
4. **不新增前端调用**：`diagnosis` 挂在 `calcMonthlyProfit` / `getLedger` 出参上，随首屏一次返回。多一次云函数调用 = 多 300–800ms，首屏不允许。

### D3 云函数与 trace 落库

- **写入时机**：`calcMonthlyProfit` 算完后**同步组装** `diagnosis` 返回前端，**异步** `await` 之后写 `diagnosis_log`（放在 `Promise` 里不阻塞返回；失败只 `console.error`，**不影响主流程**）。
- **幂等键**：`shop_id + month + rules_version + engine_version`。同键重复跑 ⇒ `update` 覆盖最新一次，不新增行（避免每次打开都涨一条）。
- **不采信前端**：`diagnosis` 全由云端算，前端传的任何 `diagnosis`/`profit`/`total_cost` **一律丢弃**（`01_架构总览` 铁律 6，已有实现，别破坏）。
- **容量**：单店单月最多 1 行（幂等去重），1 万店 × 24 月 = 24 万行，远低于 2 万行/查询红线（`dataAdapter` 的 `LIST_TOTAL_CAP`），无截断风险。**但**：`diagnosis_log` 查询必须带 `shop_id`，禁止全表扫。

### D4 金额分存储与防绕过（现状已对，只需别破坏）

| 检查项 | 现状 | 后续动作 |
|---|---|---|
| 金额整数分 | `common/money.js` 单源 + `check_money_precision`（30 断言） | 罗盘引擎所有金额**只经 `money.js`**，禁 `parseFloat` |
| 前端传值丢弃 | `calcMonthlyProfit` 已有 | 罗盘同上，**新增字段也要加进丢弃白名单** |
| 付费判定 | `entitlement.js` 只读 `expire_at` | 新能力必须登记 `PAID_FEATURES` 才收费；**未登记 = 免费**（开放默认，防漏登记锁死用户） |
| 额度计数 | 云函数侧 `count()`，`is_deleted=false` | 罗盘/复盘不涉及额度，**但 M3 20 张计数不得改由前端传** |

### D5 回滚策略（四层，与 `06_工程治理与运维规范` 对齐）

| 层 | 手段 | 触发条件 | 回滚耗时 |
