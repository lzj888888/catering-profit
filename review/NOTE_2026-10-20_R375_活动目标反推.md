# R375 · 活动卡接回目标反推（「做活动还想月赚 X，要做到多少」）

> 2026-10-20 · 承接 R367（目标反推）与 R370（活动卡收缩为保本门槛）。本轮把两者接上。

## 一、为什么值得做

R370 之后，活动卡能回答两个问题：
- 让价后毛利率变成多少；
- 打平**要多卖多少**。

但老板真正会问的是第三个：**"我做这个活动，还想月赚 1 万，得做到多少营业额？"**
R367 已经在主结论卡上做了这件事（毛利率 / 人工上限反推），活动卡却停在"门槛"，口径没接上。

## 二、口径（这轮唯一的难点）

活动期一条**原价流水** R 的利润是：`利润 = R × 原价口径边际贡献 − 固定费用`。
所以：

```
所需原价流水 = (固定费用 + 目标利润) ÷ marginalOnGross
```

`marginalOnGross` 必须取**原价口径**（每 1 元原价流水留下多少）：

```
cut      = W × (1 − d)
numer    = G0 − cut                 ← 原价口径边际贡献
denom    = 1 − cut                  ← 实收率
numerNet = numer − a × denom        ← 扣掉活动成本后，仍是**原价**口径
```

⚠️ **不能用 `gaPct`**：`ga = numerNet / denom` 是**实收**口径（分母是实收），
拿它配"原价流水"会把门槛算小。实测 8 折、G0=63%：

| 分母 | 目标 1 万所需原价流水 |
|---|---|
| `gaPct = 53.8%`（实收，❌） | **25,093** |
| `marginalOnGross = 0.43`（原价，✅） | **31,395** |

差 25% —— 这正是 R370 修过的同族坑（两个口径混用），所以这轮把它钉进判据。

## 三、改了什么

- `utils/promoImpact.js` 多返回一个 `marginalOnGross`（小数，0.43），**不新增 `*100`**
  ⇒ 不动金额登记表（R374 刚因"按序号登记"踩过一次）。
- `pages/sandbox/index.js::promoOf` 增 `goalText`：
  `做活动还想月赚 {p}：原价流水要做到 {a}（不做活动是 {b}）`
- `pages/sandbox/index.wxml` 在「同样做到 R 少赚 D」下面渲染这一行；**没填目标利润就不出现**。

## 四、验证

### 数值（node 直算，不依赖模拟器）

```
8 折 / G0=63% / 全部参与
  marginalOnGross = 0.43 · gaPct = 53.8% · 保本 8,140（与 R370 一致）
  目标 1 万 → 原价流水 31,395；不做活动 21,429
加 5% 活动成本
  marginalOnGross = 0.39 → 34,615
```

### 判据（`check_m2_matrix` ⑧，170 → 176）

三条静态 + 三条行为：
1. 页面必须取 `out.marginalOnGross`（不许用 gaPct）；
2. wxml 必须**真正渲染** `{{promoRes.goalText}}`；
3. 行为腿：`marginalOnGross = 0.43`、目标 1 万 → 31,395、**反恒真**（两个口径不能给出同一结果）。

### 变异 2/2（`review/evidence/r375_mut.py`）

```
[抓到了] M1 分母换成 gaPct        → 点名「用 gaPct 会把门槛算小」
[抓到了] M2 删掉渲染（改 gaText） → 点名「只出现在 wx:if 条件里不算渲染」
[通过]   M3 还原后复跑            → 176/176
```

🔴 **M2 第一版漏过了**：我的判据只 grep `promoRes.goalText`，而同一块的
