## 2. A 组 · 对账页抑制文案误导（🔴 用户可见）

### 2.1 缺陷

`utils/reconDerive.js::reconcile()` 的 reason 判定顺序是：

```
coverage_missing → coverage_low → menu_no_price → actual_no_data
```

⇒ 能走到 `menu_no_price`（菜品卡没填售价）/ `actual_no_data`（本月没录收入）这两种，
**说明覆盖率是够的（≥60%）**。而 `pages/recon/index.js` 修前是这样的：

```js
if (rec.reason === 'coverage_missing') suppressText = TERMS.card.reconSuppressNoCount;
else if (rec.reason === 'coverage_low') suppressText = TERMS.card.reconSuppressCoverage;
else if (actual.reason === 'need_detail_income') suppressText = TERMS.card.reconSuppressDetail;
else suppressText = TERMS.card.reconSuppressCoverage;   // ← menu_no_price / actual_no_data 兜底
```

**后果**：覆盖率 100% 的用户会被页面上那句「覆盖率不足（<60%），差值可能失真，暂不显示。」
引去**补「在售菜品数」**，而真问题是**没填售价 / 没录收入** —— 诊断方向被文案带反。
（同族于本仓「探测器坏了与命中 0 长得一样」：说的和真正发生的不是一回事。）

### 2.2 修法

1. **单源**：`utils/reconDerive.js` 新增纯函数 `suppressKeyOf(rec, actualReason)` → 返回 `TERMS.card` 下的**键名**。
   - 刻意 **不** require TERMS：本函数只回答「用哪个键」，取值由调用方 `TERMS.card[key]` 做
     ⇒ 保持纯函数、可被 selftest 直接 require **实跑**。
2. **文案**：terms **双副本**新增 3 键
   - `reconSuppressNoPrice`：指向「售价」
   - `reconSuppressNoIncome`：指向「收入」
   - `reconSuppressGeneric`：**不含任何具体 reason 措辞**的通用兜底（不得再借用覆盖率文案）
3. **页面**：删掉内联分派，改 `TERMS.card[suppressKeyOf(rec, actual.reason)] || TERMS.card.reconSuppressGeneric`。

### 2.3 判据（`tools/selftest_m3_recon.js` · 16 → **27** 条）

新增 `R298X-①~⑪`：单源可 require 实跑 / 6 组入参映射 / **③ 覆盖率文案只属于 coverage_low（实跑）** /
专属键互异 / 键真存在且非空 / ⑥⑦⑧ 文案语义相符（不串味）/ ⑨⑩ 页面零 reason 字面量 /
⑪ 用例表下界。

> 🔴 **自纠一条**：③ 的初版写成 `KEY_CASES.filter(...)` —— 那只在检查**测试自己的表**，
> 对生产码是**恒真断言**（把单源改坏它照样绿）。**变异证明 A1 当场把它证出来**（A1 红在 ②、③ 没红）。
> 已改为**实跑** `suppressKeyOf`：对 4 种非 `coverage_low` 入参断言一律取不到覆盖率文案。

## 3. B 组 · switch key 跨函数同源判据只覆盖子集（🔴 漂移已真实发生）

### 3.1 缺陷

`cloudfunctions/saveShopSetting/service.js` 头注自称「与 getShopContext **同款**开关键，**防漂移**」；
`.../index.js:16` 也写「与 getShopContext 一致，防漂移」。
而 `cloudfunctions/getShopContext/selftest.js §3` 的实际判据**只有两键**：

```js
check('inventory 键读≡写', SWITCH_KEYS.inventory === writeSide.SWITCH_KEYS.inventory);
check('amortize 键读≡写', SWITCH_KEYS.amortize === writeSide.SWITCH_KEYS.amortize);
```

⇒ **注释声称"一致"，机器只守 2/5**。盲区里的真实状态：

| 键 | 写侧 `saveShopSetting` | 读侧 `getShopContext` |
|---|---|---|
| `inventory_switch` | ✅ | ✅ |
| `amortize_switch` | ✅ | ✅ |
| `m3_takeaway_params` | ✅ | ✅ |
| `m3_menu_dish_count` | ✅ | ✅ |
| `m3_buffet_food_cost_total` | ✅ | ❌ **缺** |

**并且**放宽扫描面后又抓到第 6 个键：

- `cloudfunctions/importSalesBill/index.js:280` → `upsertSwitch(db, shopId, 'm3_review_last', ...)`
- 该键经 `specs/.../开发规范v1.2_…md:250` **明确登记**为新增 `switch_key`
- 但它**不在任何 `SWITCH_KEYS` 里**，且全仓**暂无读方**（摘要落库、无人读回）

⇒ 结论：`SWITCH_KEYS` 只是「**saveShopSetting 会写的那些键**」，**不是全仓词表**。

### 3.2 修法（**零生产代码改动**）

判据升级为 **4 条腿**（`cloudfunctions/getShopContext/selftest.js §3` · 30 → **38** 条）：

| 腿 | 判据 |
|---|---|
| **J1** | 读侧每个**同名键**的值 ≡ 写侧（**全键集**，不再只挑两键） |
| **J2/J2b/J2c** | 读侧**缺**的键必须**显式登记 + why ≥12 字**；登记表**双向防腐**（读侧已补回 / 写侧无此键 ⇒ 红） |
| **J3/J3b** | 建立 **repo-wide 词表** `REPO_SWITCH_KEYS`（6 键，每条带 `writer`/`reader`）；词表 ⊇ 写侧键值（fail-closed） |
| **J3c/J3d/J3e** | **两条扫描腿**：① 直连形态 `switch_key ===/: 'X'`；② **命名约定** `'m3_*'` / `'*_switch'` ⇒ 必须 ∈ 词表 ∪ 非键白名单 |
| **J4** | 每个注册键必须真被引用（防「注册了却没人用」的死键） |

**为什么必须有第 ② 条扫描腿**：J3c 的正则抓不到两种真实写法 ——
把键存成变量再比较（`const k = 'm3_x'`），或把键当**位置参数**传给辅助函数
（`upsertSwitch(db, shopId, 'm3_review_last', …)`）。**变异证明 B3 当场把 J3c 的绕过证出来过**
⇒ 补 J3d 后 B3 转红。

**非键白名单**（看着像键、其实不是，防误杀）：`shop_switch`（集合名）/ `m3_cards`（导出 scope）/
`m3_combo` `m3_takeaway` `m3_dishreview`（付费能力键，`common/entitlement.js::PAID_FEATURES`）。

**为什么"读侧缺 `buffetFoodCostTotal`"登记为合法不对称、而不是补齐**：
读侧 `SWITCH_KEYS` 的语义是「**我读哪些键**」，`getShopContext` 并不读它
（消费方是 `getDishReview` 直读 `shop_switch`）。硬补进去等于**谎称它读**。
⇒ 正解是「把不对称**声明出来**」（`READ_ABSENT` + why），并靠 J2c 防腐：
将来前端若要回显自助线消耗，必须补读侧、删登记 —— **守卫会强制提醒**。

## 4. C 组 · 三页死钩子（下拉刷新写好但永不触发）

### 4.1 缺陷

仓内 **20 页**定义了 `onPullDownRefresh`，其中 **3 页**的 `.json` `enablePullDownRefresh` 是 `false`：

| 页 | json 开关 | 钩子 |
|---|---|---|
| `pages/card/edit.js`（成本卡编辑 · **表单页**） | `false` | `onPullDownRefresh() { this.load().then(() => wx.stopPullDownRefresh()); },` |
| `pages/takeaway/index.js`（外卖试算 · **含参数表单**） | `false` | 同上（**逐字相同**） |
| `pages/metrics/impact.js`（原料影响面 · 只读） | `false` | 同上（**逐字相同**） |

三处**逐字相同** ⇒ 明显的复制粘贴样板。钩子**永不触发**，而页面照常渲染、零报错、控制台干净
⇒ 纯观感/功能静默失效，人工走查极易放过。

### 4.2 修法：**统一删除三处死钩子**（零行为变更）

**为什么不选"把开关打开"**：`card/edit` 与 `takeaway` 都是**表单页** ——
给表单页开下拉刷新＝**刷新即冲掉未保存输入**，是数据丢失隐患。
方向只能二选一，那就选**零行为变更、不需要产品拍板**的那条：
删掉钩子（删一个永不触发的钩子＝什么都没发生），三页 json 保持 `false`。

> 📌 **如实登记一个未采纳的备选**：`pages/metrics/impact` 是**只读**列表页，给它开下拉刷新
> 本身是安全的、也符合作者意图（钩子是他写的）。本轮**不**单独为它开，理由：
> ① 那是一次 UI 行为变更，属产品决策，C 线冻结期不宜顺手改；
> ② 上游 `pages/material/index` 本身有下拉刷新，用户改完价先刷上游再进本页即可。
> 若后续要开，**必须同时**把钩子加回来 + 打开开关（⑥ 会强制两者一致）。

### 4.3 判据（`tools/check_pages.js` ⑥，新增）

**不变量：定义了 `onPullDownRefresh` ⇒ 该页 `.json` 必须 `enablePullDownRefresh: true`。**
- 方向刻意选「钩子 ⇒ 开关必须开」：反过来（开关开而钩子缺）微信正常跑、不产生"看不到效果"的错觉，故不判红。
- 附扫描面下界（全仓"钩子+开关"齐备页 ≥10；现 17）。
- `tools/check_pages.js` **不在** R107 受守集合内 ⇒ 无需改断言数声明。

## 9. 本轮新踩的坑（写进项目记忆）

| # | 坑 | 现象 | 正解 |
|---|---|---|---|
| 1 | **R68 顶层块切分**（`tools/check_selftest_shape.js`）要求顶层语句的**行尾必须是 `;` 或 `}`** | 我写了三处**多行链式调用**（`.filter(...)` 换行接 `.map(...)`、`fs.readFileSync(...)` 换行接 `.replace(...)`）⇒ 行尾是 `)` ⇒ R68 报「第 N 行无法定界」并 **fail-closed**（该文件形状结论不下）⇒ 门禁 174/175，唯一红点名我自己改的两个 selftest | **写成单行**（或拆成两条独立语句）。⚠️ 守则明写「**别改判据**，补分号即可」——多行链式无处分号，所以只能改写 |
| 2 | **`grep "❌"` 会把「✅ 行内的 ❌ 字面量」也算命中** | 首轮门禁摘要里 `✅ D6 输出内零 ❌` 被 grep 捞出来，看着像失败项 | 判据永远是 **`总览：N/N` + `FAIL` 清单**，`grep ❌` 与 shell `rc` 都不可单独采信 |

| 4 | **沙箱探针定性先于一切** | 本轮先跑 5 项 spawn 探针矩阵，`git/cmd/where/python/node` **全 `ok`** ⇒ 走**原生 `node verify_all.js`**，**无需**刷 gitcache（若跳过这步而条件反射去建缓存，会白花一整轮） | 探针 30 秒，定性后再决定路径 |
