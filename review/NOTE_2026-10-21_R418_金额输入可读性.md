# NOTE · R418 金额栏「填了但读不成金额」不再静默读成 0（队列 #25）

- 时间：2026-10-21
- 依据：`review/AUTO_QUEUE.md` #25；实测探针 `_m3/_r415_probe/probe.js`
- 结论：粘贴「12,000」不再无声无息地变成 0 元 —— 页面会明确提示，老板能自己改。

## 1. 问题（不是"提示不够"，是算错了还不说）

界面「元」进引擎的唯一入口是 `utils/api.js::yuanToFen`，它对非法输入 **fail-soft 返回 0**。
这个行为被 `check_money_precision` B 组**刻意钉住**（很多地方依赖它不抛错）⇒ **不能改它**。

于是这条链路真实可达：

```
老板粘贴「12,000」→ yuanToFen → 0 分 → 0 是合法金额 → 云端校验无从拒 → 保本额照常出数
```

实测（毛利率 65% / 人工 1.5 万 / 水电 3 千，见 `probe.js`）：

| 房租输入 | 进引擎 | 固定合计 | 保本额 |
|---|---|---|---|
| `12000` | 12000 元 | 3.0 万 | **46154 元/月** |
| `12,000` | **0 元** | 1.8 万 | **27692 元/月** |

**少 40%，全程零报错。** 老板会以为自己只要卖 2.7 万就保本。

## 3. 五个口径决定

1. **不改 `yuanToFen`。** 它的 fail-soft 是被守卫钉住的契约（B 组），改了会牵连一大片。
2. **不自动清洗。** 看到 `12,000` 就自动去掉逗号？不做 —— `1,5` 可能是欧洲写法（15 还是 1.5？），
   猜错比不猜更糟。与 #24「不钳制、如实暴露」同一原则。
3. **只暴露、不改数。** 计算仍按 0 走（引擎口径不变），老板看到提示后自己改。
4. **`0` 是合法金额，不能当"读错"。** `''`（没填）也不算读错 —— 只有"填了但读不成"才提示。
5. **元→分必须用规范形态** `Math.round(Number((x * 100).toFixed(10)))`。
   第一版写的是 `Math.round(v * 100)` ⇒ `check_money_precision` C-④ 当场判红（只认这一种形态）。
   顺带修对了精度：`1.005 元` 旧写法得 100 分，新写法得 **101 分**。

## 4. 🔴 判据的设计要点（防"抄对了"冒充"覆盖全"）

`②-6` 没有把 10 个字段名硬抄一遍 —— 那样只证明"我抄对了"，不证明"覆盖全了"。

做法：**从生产代码实扫** `XxxYuan: e.detail.value` 得到真实字段集，
要求它 **⊆** `checkAmountInputs` 里声明的清单。
⇒ 将来新加一个金额框却忘了加进体检 ⇒ **当场红**，且报错直接指出"未覆盖：xxxYuan"。

## 6. 诚实边界

- **只覆盖 `pages/sandbox`**（M2 测算页的 10 个金额框）。M1 月度录入页、M3 成本卡录入页的金额框**未接**这条体检
  —— 它们走各自页面，需按同一纯函数复用（`utils/amountInput.js` 已是通用件，接线成本很低）。
- **提示是汇总式**（"有金额栏读不成数字…"），**不是逐框标红**。逐框标红要改 10 个 `input` 的 class，
  这轮没做（取舍：先让老板知道"有问题"，再谈"哪个框"）。
- **不拦计算**：读不成数字时仍然算出结果（按 0）。要不要在"有非法金额"时**拒绝出数**，属产品决策（李老师定）。
- `1,5` 这类歧义串**不会被判为可读**（安全侧），但也**不会被自动修正** —— 提示老板自己确认。
