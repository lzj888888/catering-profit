# DEV 测试环境归属裁决（豆包交叉验证 + 我方裁正 · 2026-11-16）

> 李老师问：用执照注册的新小程序，DEV 测试是留在旧个人账号、还是挪到新执照账号里做？
> 明确要求"去和豆包沟通确定"。本文件是三方（我方取证 / 官方文档 / 豆包）对齐后的**最终裁决**。

---

## 一、裁决：**选 A —— DEV 测试留在旧个人账号，新执照账号只建 prod 正式环境**

两条路（复盘）：

| | **A（采纳）** | B（不选） |
|---|---|---|
| DEV 在哪 | 旧个人账号的现有 dev 环境 | 新执照账号里再建一个 dev 环境 |
| 新账号 | 只建 1 个 prod | 建 dev + prod 两个 |
| 账号数 | 两个账号、两个 AppID | 一个账号、一个 AppID |

**我上一轮其实推荐过 B**——理由是"代码本来按同账号 dev/prod 双槽位设计"。这个理由不充分：
代码有两个槽位**不等于**必须用同一个账号的两个环境。槽位只是"配置开关"，指向哪个账号的哪个环境都行。**所以 B 的技术便利性不是决定因素，我收回对 B 的倾向。**

## 二、三方证据对齐

### 2.1 豆包（已直连调用，全文见 `review/evidence/_r748_doubao_env_answer.md`）
选 A，三条理由：
1. **资产合规隔离**：正式经营数据与云资源全归个体户主体，测试脏数据/调试痕迹留在个人账号 —— 符合外包交付权责隔离，正式账号无冗余测试资源，后续合规核验/转让/注销更清爽。
2. **零迁移成本**：现有测试链路、测试数据、定时触发器、真机调试权限全在旧 dev，无需重建迁移。
3. **风险天然隔离**：两账号两 AppID 物理隔离，配合 `initDb` 的 dev-only 门禁，杜绝同账号下切错环境/测试脚本误删正式数据。

### 2.2 官方文档（已 WebFetch 核实）
- 微信侧一个小程序可建 **2 个免费环境**，环境间数据库/存储/云函数**完全隔离**。
- ⚠️ 免费环境"**开发免费、正式使用需付费**" —— ⇒ 若走 B，新账号的两个免费环境里跑正式版，可能踩付费限制；A 方案里 prod 是新建账号的唯一环境，同样要付费，**这一点两方案都躲不掉，需按量计费**。
- `云开发环境不支持跨账号迁移`（⇒ 数据不搬，各留各的，符合 A）。

### 2.3 我方裁正豆包的一处不准
豆包第 4 点说 A 的坑是"跨账号云调用默认拦截，需在旧控制台授权新 AppID"。
**这个坑在本项目不成立**：我们的迁移是"**改新 AppID + 新环境 ID → 把代码部署到新账号**"，
运行时代码只连自己账号的环境，**从不发生"新账号代码去调旧账号环境"的跨账号云调用**。
⇒ 不需要配跨账号授权。豆包这条是通用经验套到本项目上的误判，已剔除。

### 2.4 我方补的一条独立理由（豆包没提）
**A 是唯一能保住"随时回滚"的路径**：本项目的测试真机码、1728 次提交的开发基线、
所有审计套件，都围绕旧账号的 dev 环境运转。留着它 = 新账号上线出任何问题，
都能立刻切回旧账号继续验证/开发，不至于"正式账号一出事，连个能跑的测试环境都没有"。

## 三、最终流程（A 方案 · 上线前）

```
【并行起跑】
您：① 全新邮箱注册小程序 → 主体选个体工商户 → 30 元快捷认证 → 拿新 AppID
    ② 提交备案（类目选「工具」）→ 短信 24h 内核验 → 等管局 1~20 工作日
我：③ 继续用【旧个人 dev 环境】做开发/审计/真机验证（不中断）
   ④ 准备 MIGRATION_RUNBOOK + 迁移守卫 + 验 ensureCollections

【备案等待期】
您：⑤ 新账号开通云开发 → 建唯一 prod 环境 → 把 AppID + 环境 ID 发我
我：⑥ 改 project.config.json 的 appid + env.js 的 ENV_MAP
    ⑦ 部署 60 个云函数到新 prod；跑 ensureCollections 建 33 集合 + 索引；灌种子
    ⑧ 上传 4 个触发器（先暂停）；真机码在新账号跑一轮核心链路回归

【备案通过】
我：⑨ 打 Tag（发布版本）
您：⑩ 提审 → 通过后开启 4 个触发器 → 发布正式版
   ⑪ 若选分阶段发布：首版必须全量（官方规则），后续版本可 10%→50%→100%
```

**关键：③ 与 ⑤⑥⑦⑧ 全程并行** —— 测试不中断，迁移不返工。这就是 A 方案"零迁移成本"的实证。

## 四、秒级回滚（豆包方案与我方架构合并）
| 层 | 做法 |
|---|---|
| **云函数**（算钱逻辑全在这，绝大多数 bug） | 版本快照 + 流量比例；出错一键把 100% 流量切回稳定版，**秒级、全端无感** |
| **小程序前端** | 后台终止分阶段发布 → 回退上一全量版本；安卓 `wx.getUpdateManager` 主动检测更新，iOS 已打开的用户需杀进程重进（可用云函数返回版本不兼容标识强提示） |
| **最终兜底** | 切回旧个人账号 dev（A 方案独有）—— 正式账号彻底不可用时仍有可跑环境 |
