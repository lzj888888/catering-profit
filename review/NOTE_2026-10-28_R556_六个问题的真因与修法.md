# R556 · 李老师六问：逐条真因 + 修法

日期：2026-10-28

---

## 1️⃣ 「生成矩阵」点击报「填写有误」→ 🔴 **真 bug（前后端契约不一致）**

**真因**：矩阵页「转让费」默认**不摊销**，前端于是发 `years: 0`（`matrix.js` 注释写明：
"引擎是 `if (years > 0) amort += ...`，所以 years:0 不参与摊销但仍计入 build_total"）。
引擎 `service.js:64` **确实支持** 0；但 `validate.js:94` 写的是 `years < 1` ⇒ 直接拒成
`INVALID_PARAM` ⇒ 前端 toast「填写有误，请检查后重试」。

**为什么一直没暴露**：单页（已有店铺）没有"转让费不摊"这个选项，只有矩阵页有；
而搭上 R550 的种子把首页转让费带过来之后，**一填转让费就必报**。

**第一版修法不对（被守卫拦下）**：我直接放开 `years: 0`，结果
`check_matrix_validate` A-⑤ 与 `check_m2_entry_parity` A-⑧ **同时转红** ——
它们明确要求「年限 0（清空）⇒ 必须拒」，理由是**会静默产数**（老板清空了年限，系统却按"不摊"算出一个数）。

**这两个诉求都合理，冲突在于同一个 0 有两种语义**：

| 0 的来源 | 含义 | 处置 |
|---|---|---|
| 老板把年限输入框清空 | **未填** | 🔴 必须拒（防静默产数） |
| 矩阵页"转让费不摊" | **故意的** | 合法（引擎本就支持） |

**正确修法**：加**显式标记** `no_amort: true` —— 只有带这个标记才允许 `years: 0`。
- `validate`：`years < 1 && !(no_amort && years === 0)` ⇒ 拒
- `matrix.buildItems()`：不摊时 `{key, fen, years: 0, no_amort: true}`
- 这样单页清空年限（无标记）仍被拒 ⇒ **两个守卫继续成立**

**加固**：`calcSandbox/selftest` 新增 **L14/L15/L16**（98 → **101** 条）：
- L14：`years:0 + no_amort` 放行、`build_total` 仍含该笔钱、摊销为 0
- L15：`years:21` 仍拒（防"放宽 0"被写成"不校验"）
- L16：`years:0` **没标** `no_amort` ⇒ **仍拒**（防"清空年限静默产数"这条老规矩被顺手破坏）

⚠️ **需要部署 `calcSandbox`** 才在真机生效。

## 2️⃣ 「开始测算」点不动、不点也自动出数 → **他说得对，它本来就冗余**

改任意数字 700ms 后会自动重算（`scheduleCalc`），所以按钮点下去只是"再算一遍同样的数"，
视觉上就是没反应。

**修法**：不删（网络失败时可手动重试），但**降级成次要按钮 ghost + 改名「重新测算」**。
⚠️ 没在按钮旁加平铺说明 —— 会破坏 `check_hint_fold` 的「短提示 ≤18 字」分层线（实测 23→25 判红）。

## 4️⃣ 「本月实际营业额」填了，人效/坪效体现到哪 → **在算，但被折叠藏了**

四项派生（每天来客 / 翻台 / 坪效 / 人效）确实会跟着算，但它们属于 R442 那批"更多分析"
（李老师自己定的：通篇太长，默认收起）⇒ 填完看不到，以为没算。

**修法**：把指路写进**已有折叠正文**（`expectRevNote`）：
> 已有铺面填真实流水：用来算每天来客 / 翻台 / 坪效 / 人效，对照保本线（结果在下面「更多分析」里）

**关于"放进「你的经营指标对照」是否适合"** —— **不适合**，理由是硬的：
那张表每行都有**行业参考区间 + 评级**（优秀/合理/偏高/过高），而坪效/人效**没有行业分位数**
（R223 §3.2 红线：不得编造分位数）。硬塞进去会出现"有值无区间"的怪行，或者逼我们去编区间。
⇒ 留在「更多分析 · 效率」里、只出数值不评级，是当前最诚实的放法。

## 5️⃣ 矩阵「读取我填的数据 / 清除重填」像没接上 → **一半是语义误解，一半是真没效果**

- **「读取」**：进页时**已经自动读了种子**（R550 设计），所以进页面就发现数据已经填好，
  再点按钮看不出变化 —— 它不是没接上，是"进页已自动做了一次"。按钮的真实用途是：
  手改乱了、或从别处回来，想重新同步一次。
- **「清除重填」**：🔴 **真没效果**。原实现是"把档位重置成按他的店算出的基准值"，
  而进页时档位本来就等于基准 ⇒ **按下去什么都没变**。

**修法**：改成**真清空** —— 档位回系统默认、装修/设备/加盟/转让/面积/人工/管理费全清、
旧结果撤掉；点之前弹二次确认，并写明"想找回你填的，点「读取我填的数据」"。
两个按钮因此成为一对：**清空 ⇄ 读回**。

## 6️⃣ 「矩阵里体现人员工资了吗？盈亏平衡的关键指标都要体现，你认同吗？」

**认同方向，但不是"都要占一列"。**

现状核对：
| 项 | 矩阵里在哪 |
|---|---|
| 房租 | reverse 有「月租金」列（含元/㎡）；forward 房租只 1 档不占列（值在副标题） |
| 人工 | forward 有「月人工费」列；**reverse 在 R555 被换成「回本月数」**（原默认列只有 6 个位置） |
| 毛利率 | 有「到手毛利率」列 |
| 水电气 / 其他 | **表格里没有**，但在表格**上方**的「固定费用构成」块里逐项列出 |

⇒ 他的感受是对的：**关键项散在两处，表格里看不全**。

**修法（本轮）**：把「固定费用构成」块的标题改成
> 固定费用怎么构成（**保本营收 = 这些合计 ÷ 毛利率**）

让"这些数"和"保本营收"的关系一眼可见 —— 这一块本来就是保本公式的分子，四项齐全。

**没做的**：没有硬加「水电气」列。原因：14 列已满（R349 要求导出与页面列数一致），
再加列要么挤爆、要么动导出契约；而"固定费用构成"块已经逐项列出且就在表格上方。
⚠️ 若李老师仍希望水电进气列，可行的做法是**用「每月固定支出」合计列**替换「月人工费」，
把明细留在这块里 —— 待他拍板。
