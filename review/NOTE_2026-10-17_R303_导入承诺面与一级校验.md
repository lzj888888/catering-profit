### 2.3 一级校验（新建 `utils/importSanity.js`，纯函数）

**零外部依赖** —— 只用导入表自身就能自证的错：

| code | 触发 | 为什么要 |
|---|---|---|
| `noDays` | 没解析出任何日期 | 这张表没东西 |
| `crossMonth` | 表里出现 >1 个月份 | 复盘**按月**看，跨月表会把数据分到两个月，读起来像"某月少了" |
| `zeroTotal` | 有销量但销售额合计 = 0 | 明显不对（不是"这个月没卖"这种合法的 0） |
| `oddAvgPrice` | 均价（金额 ÷ 销量）落 [1, 500] 元之外 | **高度疑似"销量列与金额列被写反"**；只报均价数值，**不猜**是哪列反了 |

🔴 **故意不做「只覆盖 N 天不是整月」**（一开始想做的第一条）：导入是**按日**落库的，**导一段本就合法**；
"这个月只有 N 天有数据"这件事该在**复盘时**讲，而 R301 已用 `range.days` + 期间标注讲清了
（那里才有"目标月"这个概念）。**在导入侧判它会"把合法操作报成错误"（假红），只会训练老板忽略提示。**

🔴 **纪律**：只给结论、**不改数、不阻断**（与 A.11.2 配平校验同一条：最坏结果只能是"多一句提示"）；
**没有问题就回空串 ⇒ 不渲染** —— 也**不假报"一切正常"**（一级校验只看"表内自洽"，看不了"表对不对"）。

**二级校验（与 M1 该平台外卖营收对拍）**：按 R300 §6.2，它是**可选加强项**（需读 M1，与"M3 独立"的前提冲突）
