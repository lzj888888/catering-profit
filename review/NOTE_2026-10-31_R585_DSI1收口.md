## §1 这一轮解决的是「看得见」

R584 结束时云函数能回 `preview`，但导入页只认形态 C/D 的结构（`p.totals`），
DSI-1 的 preview 里**没有 `totals`**（结构是 `rowCount/dayFrom/.../byChannel`）
⇒ 落进账单 `else` 分支会 `p.totals.amountFen` 抛 TypeError，被 catch 吞成一句 toast
⇒ 老板只看到「导入失败」，连"失败在哪"都不知道。

所以本轮第一件事是把 DSI-1 的分支**放在 `isC` 之前**判。顺序不是风格问题：
`isDsi` 必须在 `else`（账单）之前，否则 TypeError；而 `isC` 与 `isDsi` 互斥，先后无碍。

## §2 预览卡为什么必须「分渠道」

一份 DSI-1 可以同时含堂食 + 美团 + 淘宝闪购（老板一个月的账就是一张表）。
若只显示一个「合计」：

- 老板会把这个数当成**某一个平台**的钱；
- 同店三平台实测，扣点率差 **5.67 个百分点**（11.17% vs 16.84%，R577-B），
  合在一起的数对哪个平台都不成立。

所以预览按渠道逐行列出（堂食在前、外卖按金额降序），排序在 JS 里做完，wxml 不排。

**不提供平台 picker**：平台已由表里的「平台」列写死。给 picker 反而会被覆盖成单值。

## §3 三条「已替你处理」的说明

都是老板最容易当 bug 报的点，空串则不渲染（沿用 `importSanityText` 的"不假报没问题"约定）：

| 说明 | 触发条件 | 不写会怎样 |
|---|---|---|
| 有 N 行按斤/按重卖，已按整份记 | `summary.nonInt.length > 0` | 老板以为销量被改了 |
| 含 N 行退款，已按负数抵扣 | `summary.refunds.length > 0` | 老板以为退款被算成销量 |
| 这张表不含打包费，和月度账对不上是正常的 | 恒显示（`noteNoPackFee`） | 老板当成"你们漏算了" |

第三条是契约 §S1-③ 那条「S1 汇总 ≠ S2 营业额」的产品侧兑现 —— 文档写了不够，
**得在界面上说**，否则等于没写。

## §6 升版规则（补上 R582 自己提的缺口）

R582 我方意见第 ③ 条说：「格式一旦发布就是对外承诺，改列名会让依赖它的 AI 静默失配」，
当时只写了版本号、没写"什么情况允许升版"。本轮补进契约 §5：

| 改动 | 升版？ |
|---|---|
| 加**可选**列 | 不升 |
| 加**必填**列 / 改列名 / 改顺序 | **必须升** |
| 改枚举值 | **必须升** |
| 改口径（`销售额` 从原价改实收） | **必须升 + 旧数据标注**（最危险：格式没变、数变了分量） |
| 只改说明/加样例 | 不升 |

升版必做三件事：旧文件**保留不删**、顶部写明差异、解析器**两版并存至少一个周期**。

## §13 🔴 新坑：git 跟踪文件集合变了，门禁会假红（缓存只刷 node 不刷 git）

现象：新增第 226 套件后，门禁稳定报

```
❌ [suite-coverage] exit=1     ← S7「豁免清单无僵尸：已不在面 B：…/verify_examples.py」
❌ [suite-assert-counts] exit=1 ← 它的 A0 又跑了一遍 coverage，同样红
```

**但单跑 `node tools/check_suite_coverage.js` 是 10/0 全绿。** 单跑与门禁的唯一区别是 preload。

### 根因

沙箱下 node 派生子进程被拦 ⇒ 所有 git 输出都来自 `gitcache.json`。
而两条刷新路径**都不覆盖 git 条目**：

| 脚本 | 刷什么 | 漏什么 |
|---|---|---|
| `mk_force.py` | 只重跑 `node.exe` / `python.exe` 开头的 key | **从不刷 git 条目** |
| `mk_cache2.py` | 什么都刷 | 但第 31 行 `cache = {}` **整体重建** ⇒ 清掉 177 条 node 缓存，代价太大 |

⇒ `git ls-files` 缓存里没有新 add 的文件 ⇒ `faceB` 里没有它 ⇒ 已登记的豁免被判成**僵尸**。
反向同理：新判据不在扫描面 ⇒ "零漏网"**假绿**（这个更危险）。

### 处置

新增 `review/evidence/r179_gate_sandbox/refresh_git_entries.py`：**只更新 6 条 git 条目，node/python 缓存一条不动**。
跑完 `git ls-files` 等 6 条就被真实重跑刷新（177 → 177，数量不变、值更新）。

> 纪律补一格：**「改过 tools/** 先刷缓存」只覆盖了代码变更，没覆盖"git 跟踪的文件集合变更"。**
> 新增/删除/重命名文件后，要额外跑一次 `refresh_git_entries.py`。

看起来像"数据坏了"，实际只是键名不对。已在脚本里加注释钉死。
