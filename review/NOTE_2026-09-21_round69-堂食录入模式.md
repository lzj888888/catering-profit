## 2. 已落（有证据）

### 2.1 堂食渠道 5 → 7

| 现状 | 改后 |
|---|---|
| 现金 | 现金收款 |
| 微信支付宝 | 微信扫码收款 / 支付宝收款（**拆分**） |
| — | 银行卡 / POS刷卡（**新增**） |
| 储值消费 | 储值卡消费 |
| 团购券核销 | 团购 / 代金券核销 |
| 企业挂账消费 | 个人/单位挂账消费 |

两处口径标注挂在细项下方（李老师点名的两处困惑）：
- 储值卡消费 → 「储值充值不算收入，只有顾客用余额买单才算」
- 团购/代金券核销 → 「钱结算在美团/抖音平台、不是当日到账，但按核销当月计入」

`incomeScope.dine_in` 同步补：挂账**回款**也不算营收（那是把应收款收回）。

### 2.2 互斥模式开关（方案 A）

- 开关视觉复用 round55 的 `cm-opt`（✓ + 墨蓝描边 + 浅蓝底三重可辨）。
- **快速录入**：一个「堂食总收入」框。
- **分项渠道录入**：7 个渠道 + 底部「合计」由 `syncDineSum()` 相加自动算出，**是只读 text 不是 input**（方案 A 的落点）。
- **切换语义（都不丢数据）**：
  - fast → detail：铺开 7 渠道，把已填总额**暂放第一行**并 toast「请按实际拆分到各渠道」（系统不知道拆分比例，只能交给人）。
  - detail → fast：把合计写回单行（无损）。
- 模式**只存本地**，不动 `getLedger`/`saveLedger` 契约。

### 2.3 布局：回到一行三列（渠道名 / 金额 / 删除）

李老师反馈「字段 金额 修改或删除 要在一行才好看」。回一行的同时保住金额框宽度，靠：
**预设渠道名是固定标签不可编辑**（`decorateDineRows` 给行打 `fixed` 标记），省出的宽度全给金额框（240rpx 带边框）；
只有「+ 添加渠道」的自定义行才可编辑。

### 2.4 🔴 删除键「视觉小 / 热区够」—— 硬约束的破解

ad-gates **G2 只查 `min-height` 声明值，不查 `width`**（读 `tools/selftest_ad_gates.js:39` 确认）。
所以两者可以兼得：
- `width: 88rpx → 56rpx`、**去掉红底方块**（`background: none`）⇒ 视觉上只剩一个 × 字符；
- `min-height: 88rpx` **保持不变** ⇒ 点击热区仍合规，门禁不过红。

⚠️ 反过来若真把 `min-height` 调小，门禁 77/77 会转红 —— 已在 wxss 注释里写死这个理由。
