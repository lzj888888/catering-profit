# R374 · M3 成本卡：吸底动作条（保存不再藏在第三屏）

> 2026-10-20 · 承接 R372（编辑页从 3.15 屏压到 2.76 屏）。本轮解决的是**动作可达性**，不是密度。

## 一、问题

R372 实测：成本卡编辑页整页 **1367px**，而「保存菜品核算」按钮在**页面最底部**。
改一个菜名、调一个用量，都要滚三屏才能保存；老板在第二屏时**不知道自己算得对不对**（成本/毛利只在结果区）。

## 二、为什么不做「实时成本」

第一版想做「边填边变的成本 / 毛利率」。核过代码后否掉：

- 成本**只能**由 `calcBom` 返回（引擎单源），页面里没有任何本地成本算法；
- 想在页面里"实时"，只有两条路：**再抄一份成本算法**（会成为第 4 份手写引擎，仓里已有硬守卫盯三副本），
  或**每次输入都调一次云函数**（打字即计费，且返回乱序会把旧结果盖到新输入上）。
- 两条都不划算 ⇒ 采纳第三条：**吸底条只展示「上一次试算」，并如实这么写**。

> 这与 R359/R370 是同一个教训：**不能拿旧数当新数**。宁可写「上次试算」，不写「当前成本」。

## 三、做了什么

```
┌──────────────────────────────────────────────┐
│ 上次试算  ¥12.40   毛利率 67.37%    [ 保存 ] │   ← 固定在底部
└──────────────────────────────────────────────┘
```

- 左半区（可点）＝ 重新试算：`bindtap="reverseCalc"`；
- 未试算时显示「还没算成本 · 试算成本」，不给空数字；
- 右半区＝保存：`onSave`，宽 220rpx、高 88rpx；
- 页面底部留 200rpx（`env(safe-area-inset-bottom)` 之上），不遮最后一行与页内保存按钮。

### 毛利率怎么算的（与后端同式）

`saveCostCard/service.js:105`：
```js
grossMarginPct = Math.round((priceFen - unitCostFen) / priceFen * 10000) / 100;
```
页面新增 `marginTextOf(costFen, priceYuan)`，逐字同式（含 `toFixed(10)` 的分转换），
**只做两个已知数之间的百分比**，不碰成本本身。

### 售价改动时会重算毛利率

`onPrice` 里同步刷新 `stickyMargin`（成本不变、比例变）。实测：

```
marginTextOf(1240, '38.00') = 67.37%   ← (3800−1240)/3800 = 0.67368
marginTextOf(1240, '0')     = ''       ← 无售价不给数
marginTextOf(0, '38')       = ''       ← 无成本不给数
```
