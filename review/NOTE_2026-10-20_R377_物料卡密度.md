# R377 · M3 物料卡密度（4 行竖排 → 2 行）

> 2026-10-20 · 承接 R372（成本卡编辑页 3.15 屏 → 2.76 屏）。本轮对象是**原料档案列表**。

## 一、问题

一张原料卡原来是 **4 行竖排**（品牌 / 单位·价格 / 换算 / 净料成本），每行都是全局 `.cell`
（`padding: 24rpx 0`、字号 30rpx）⇒ 单行 ≈ 44px，四行 176px，加标题与操作行整卡 ≈ 285px。
结果：一屏只能看 2 张卡，而原料库动辄几十条。

## 二、怎么压的（信息一条没删）

```
改前                          改后
┌──────────────────────┐      ┌──────────────────────┐
│ 鸡腿肉        置顶 荤菜│      │ 鸡腿肉        置顶 荤菜│
│ 品牌      —           │      │ 净料成本 ¥0.0150  采购 件·¥120.00 │
│ 单位/价格  件 · ¥120  │      │ 1 件 = 20000 个 · 出成率 100%      │
│ 换算   1件=20000个…   │      │                    涨价影响  ⋯      │
│ 净料成本  ¥0.0150     │      └──────────────────────┘
│          涨价影响  ⋯  │
└──────────────────────┘      整卡 166px（−42%）
   整卡 ≈ 285px
```

三条改动：
1. **净料成本 + 采购价合并成一行**（老板比价看的就是这两个数，本来就该并排）；
2. **品牌为空就不渲染**（原来恒渲染一个「—」白占一行）；
3. **换算只在有值时出现**（round149 的语义不变）。

## 三、两个只有实测才会发现的问题

1. **标签长度决定折不折行**：原来标签是「单位 / 价格」（6 字），这一行在 342px 宽的卡片里
   必然折成两行（实测 51px vs 31px）。换成两字「采购」后仍不够。
2. **分隔点「·」是压垮它的最后一根稻草**：`.dot` 两侧各 16rpx 边距，白占 26px。
   去掉 dot 之后同一行立刻变单行（48px → 28px），整卡 190 → 166px。

⇒ 结论：**在窄容器里做"一行多值"，要按"像素预算"算，不能按"看起来不长"算**。
这两次都是量出来的，不是看出来的。

## 五、没做

- **枢纽页（m3/hub）没动**：它是 4 张大卡（每张有名字/描述/计数/阴影），不属于"列表密度"问题；
  压它反而会削弱"入口感"。
- **不改字号下限**：`.mat-kv` 已降到 28rpx（AD-G1 下界），再小就违反无障碍红线。
