## 二、根因（为什么用户会卡住）

`pages/takeaway/index.js::onConfirmImport` 成功分支原本只有：

```js
wx.showToast({ title: TK.importSuccess, icon: 'success' });
this.setData({ /* 清空预览态 */ });
```

两处断层：

1. **零下游引导** —— toast 没有按钮，用户拿不到"下一步"；
2. **跨模块跳跃** —— 导入入口在「**外卖**」tab，展示位在「**配方 → 单品毛利复盘**」，
   两处不在同一模块，**用户不可能自己猜到**（李老师的实测就是证据）。

叠加第三处：导入入口的提示语只写「支持淘宝闪购 / 美团外卖的 xlsx 账单」，
**没说堂食的《菜品销售统计》也从这里导**（全仓仅此一个导入入口 —— 已核实 `importSalesBill` 的唯一调用点）。

## 三、改动（最小面：不动引擎、不动云函数、不增节点）

| 文件 | 改动 | 说明 |
|---|---|---|
| `miniprogram/i18n/terms.js`（源） | `importPickHint` 22 → **33 字**；新增 `importSuccessGo` / `importGoReview` / `importGoLater` | 入口补「堂食也从这里导」 |
| `specs/dev-specs/i18n/terms.js`（副本） | 同上（md5 一致） | 双副本纪律 |
| `pages/takeaway/index.js` | `t:{}` 登记 3 键；成功分支 `showToast` → `showModal` + `navigateTo` | 唯一功能改动 |

🔴 **三处设计取舍（都是为了让边界为零）**：

1. **用 `showModal` 而非「页内引导卡」** —— 后者要在 wxml 增节点，会动 `check_hint_fold` 的
   分层线（takeaway 页 `keepPlain=1`）；`showModal` 只改 JS，**wxml 一字未动**。
2. **`importPickHint` 改的是文案、不是节点** —— 22 字 → 33 字，**仍 ≥18 字 ⇒ 仍在折叠块内**，
   分层线不受影响（实测 `check_hint_fold` 190 通过 / 0 失败）。
3. **modal 正文刻意不带条数** —— 幂等重放分支是 `return ok(prior)`，`prior` **不含 `written`**
   ⇒ 若写成「已写入 {n} 条」，重复导入会渲染「已写入 **0** 条」= 把"重导"说成"没导进去"。

### 4.1 顺手修一处守卫能力缺口（本轮新代码**当场触发**）

`tools/check_modal_button_len.js` 新增**页面局部别名**支持（`PAGE_ALIAS`）：

| 阶段 | 事实 |
|---|---|
| 现象 | 该页术语走 `TK.xxx`（= `TERMS.ledger.takeaway.xxx`，**页面既有风格**），而解析器只认 `TERMS.` 前缀 ⇒ **B-② 判红**「无法解析 `TK.importGoReview`」 |

| 处置 | **不是**改业务代码写全路径去迎合守卫（会破坏该页风格一致性、且下一个人还会踩），而是**让解析器认识该别名** —— 守卫自己的注释就写着「写法变了 ⇒ 转红提醒更新别名表」 |
| 配套 | 加 **C-⑥ 防腐化**（押 takeaway 页内 `TK` 仍绑定 `TERMS.ledger.takeaway`；逐条遍历 `PAGE_ALIAS` ⇒ 将来加别名不必再改断言） |
| 效果 | 按钮引用 **42 条全部解析**（此前 2 条为 unknown）⇒ 长度红线**真正覆盖**到本页 |
