# R357 · 分批中途失败：已算出的不再丢，并说清哪一段没算

> 日期：2026-10-19 · 前序 `NOTE_2026-10-19_R356_大样本导出.md` 第八节「没做的」第一条

## 一、先说结论

R356 把 960 行拆成 6~7 批（150 行/批），解决了 1MB 响应上限。但**失败语义没改**：

> 任一批抛错 ⇒ 冒到外层 `catch` ⇒ `loading=false` + 一句笼统 toast
> ⇒ **整张表空白**，已算好的前几批全部丢弃。

老板看到的画面是「什么都没有 + 一句话」，分不清是
**「全部算不出来」**还是**「算到一半断了」**，也不知道该不该重试。

| 场景 | R356 及以前 | R357 |
|---|---|---|
| 第 1 批就失败 | 空白 + 笼统错误 | 空白 + 具体错误（**保持原语义**） |
| 第 4 批失败（共 7 批） | 空白 + 笼统错误，前 3 批白算 | **显示前 3 批** + 「第 451-600 档没算出来（共 960 档），下表只显示已算出的 450 档」 |

## 二、改法

### ① 逐批 try/catch（`pages/sandbox/matrix.js`）
```js
let failedAt = -1;
let failedMsg = '';
for (let off = 0; off < cleanArr.length; off += CHUNK) {
  const part = cleanArr.slice(off, off + CHUNK);
  try {
    const d = await api.call('calcSandbox', { action: 'matrix', clean_array: part });
    /* 累积 rows / rejected（rejected.index 补批次偏移） */
  } catch (e) {
    failedAt = off;          // 记住断在第几批
    failedMsg = (e && e.msg) || '';
    break;                   // 不继续打云端：后面每批大概率同样失败
  }
}
// 第一批就失败 ⇒ 没有可展示的内容，保持原语义：报错退出
if (failedAt === 0 || (!allRows.length && failedAt > 0)) { ... return; }
```

**为什么 `break` 而不是 `continue`**：中途失败通常是网络/配额/云函数异常这类**全局性**原因，
继续跑剩下的批只会重复失败、拖长等待。断在第一批失败的批，把已知结果交出去，比全丢掉有用。

**为什么行序仍然对得上**：`allRows` 只从 0 号批开始连续累积，失败即停 ⇒ `allRows[i]` 恒对应
`meta[i]`，下游 `toRow/pivot/insight` 一行没改。

### ② 页面说清（`matrix.wxml` / `.wxss`）
明细表上方新增 `.partial-note`（28rpx 琥珀告警块，与既有告警口径一致）：
```
第 {a}-{b} 档没算出来（共 {n} 档），下表只显示已算出的 {m} 档
```
文案进 terms 双副本 `matrix.matrixPartial`（`miniprogram/i18n/terms.js` ≡ `specs/dev-specs/i18n/terms.js`，逐字节一致）。

> 为什么不把 `failedMsg` 也拼进去：中途失败最常见的映射结果是
> `api.js` 的「网络不可用，请检查网络连接」——那正是 R356 判定为**方向相反**的提示。
> 这里只陈述事实（哪一段没有），不替老板猜原因。

## 三、判据（`tools/check_m2_matrix.js`，168 → **171** 条）

三条腿分别守「有内层 try」「真 emit」「真渲染」，且**都要能抓红**：

| # | 断言 | 失效形态 | 变异 |
|---|---|---|---|
| 1 | 内层 `catch` 里置失败标记 + `break`，且该标记为真时才取 `matrixPartial` | 退回外层 catch ⇒ 整表空白 | M1 ✅ 抓红 |
| 2 | `result: {...}` **对象字面量里真的产出 `partialText` 这个键** | 只算不 emit ⇒ 页面静默少数据 | M2 ✅ 抓红 |
| 3 | `.wxml` **去注释后**有 `result.partialText` + `.partial-note` | 页面不渲染 | M3 ✅ 抓红 |

### 两条判据纪律（本轮实证）

**① 「读到了 ≠ 送出去了」（R298Y 同族第九例）**
初版判据写的是 `/partialText/.test(mjs) && /matrixPartial/.test(mjs)` —— 只要词出现在文件里就算过。
把 `result: { ..., rejected, partialText }` 里的 `partialText` **删掉**、其它不动：
计算还在、词还在、`setData` 也在，但页面永远拿不到 ⇒ **缺陷照旧，判据照绿**。
⇒ 改为**单独一条腿**去解析 `result:` 后面的对象字面量，判它的**产出键集合**。

**② 判据不能钉字面量（R297 同族）**
初版第一条腿写死 `/failedAt\s*=\s*off/`。变异 M4 把变量整体改名 `failedAt → failOff`（**语义完全不变**）⇒ 判据转红 ⇒ 属于误伤。
⇒ 改为**从 `catch` 块里捕获变量名**（`/([A-Za-z_$][\w$]*)\s*=[\s\S]{0,120}?break/`），再用这个名字去查下游用法。

### 变异结果（`review/evidence/r357_mut.py`，4/4 符合预期）

```
[基线]   171 通过 / 0 失败
[抓到了] M1 去掉内层 try            → 170/1 · 命中「分批没有内层 try」
[抓到了] M2 只算不 emit             → 170/1 · 命中「没送进 result」
[抓到了] M3 页面不渲染              → 170/1 · 命中「没渲染 partialText」
[通过]   M4 只改名 failedAt→failOff → 171/0（语义不变，不得误伤）
[还原后] 171 通过 / 0 失败
```

> 变异脚本挂 `SIGTERM/SIGINT` 还原，且跑完 `git status` 无残留（R299 教训：被打断会留脏）。
