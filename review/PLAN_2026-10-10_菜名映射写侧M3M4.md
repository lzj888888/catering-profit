## 二 🔴 键的决定（先定死，否则写进去读不到）

读侧实测（`cloudfunctions/getDishReview/index.js:76-88`）：

```js
mapIndex.set(p + '|' + ref, cc);                     // p = platform（trim，可空）
lookupCardCode = (dishKey, platform) =>
  mapIndex.get(p + '|' + k) || mapIndex.get('|' + k) || '';   // ← 有「无平台」兜底
```

| 决定 | 理由 |
|---|---|
| ① `external_ref_id` 存 **原始 `dish_key`**（导入菜名，**不归一**） | 读侧查的就是 `agg` 的 key = `s.dish_key` 原样。若写侧先 `normalizeDishName`，「★发鱿鱼」会写成「发鱿鱼」⇒ **永远查不到** |
| ② `platform` **可空，默认空** | 读侧有 `mapIndex.get('|' + k)` 兜底 ⇒ 空平台一条覆盖**所有平台**。同一道菜在淘宝/京东都叫「【招牌】耙牛肉(小份)」，关系是菜本身的属性，**与平台无关** |
| ③ 两端都 **trim 后**比较 | 读侧 trim 了（`index.js:77-79`），写侧必须同样 trim |

⇒ **写侧与读侧的键口径必须机器对齐**（由新守卫守住，见 §五）。

## 五 新增守卫 `tools/check_dish_mapping_write.js`

骨架按四组（S 扫描面 / A 正向 / B 反向 / C 自检）+ **自失效护栏**：

- **S**：文件存在、目录数下界、锚点在场（防"扫空 ⇒ 0 ≤ 预算 ⇒ 恒绿"）
- **A**：键三决定（§二 ①②③）逐条；鉴权/付费墙/限流/幂等/审计在场；`_id` 主键
- **B**（反向）：写侧**不得**先归一 `dish_key`；不得 `doc(业务键)`；不得缺付费墙
- **C**：判定函数对合成样本能红能绿

🔴 最关键的一条：**「写侧键 ≡ 读侧键」双向** —— 只守写侧，读侧改了键写侧不知道 ⇒ 死输入。
