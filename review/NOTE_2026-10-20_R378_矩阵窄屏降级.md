# R378 · M2 矩阵窄屏降级（冻结首列 + 横滑提示）

> 2026-10-20 · 承接 R362（矩阵竖排）与 R377（物料卡密度）。这轮解决的是**宽表在窄屏上"能滚但看不懂"**。

## 一、问题

矩阵表 **14 列 × 200rpx = 2800rpx ≈ 1400px**，而手机内容区约 350px：

- 一屏只能看到 **2 列半**（房租 / 人工 / 人工金额…）；
- 横滑之后**行名（房租档位）跟着滚走** ⇒ 老板看到一排数字，但不知道在说哪一行；
- 没有任何提示"这张表可以横滑"，第一眼像"只有两列"。

## 二、方案（为什么不是"缩列宽"或"卡片化"）

| 备选 | 结论 | 理由 |
|---|---|---|
| 缩列宽到 150rpx | ❌ | round276 已实证：150rpx 时表头「月租金档位（元）」排不下 ⇒ **竖排**（R362 同族） |
| 小屏切卡片式 | ❌ | 14 个指标 × 12 行 = 168 个键值对，卡片化后要滚十几屏；而且**矩阵的价值就是横向对比**，拆成卡片就没了 |
| **冻结首列 + 明说可横滑** | ✅ | 保住"横向对比"，只补上"我在看哪一行" |

实现只改 CSS + 一句提示，**零逻辑改动**：

```css
.td:first-child { position: sticky; left: 0; z-index: 2; background: #fff;
  box-shadow: 6rpx 0 10rpx -6rpx rgba(30,58,95,.18); }
```

- 表头首列 `z-index: 3`，压在滚动单元格之上（否则表头会被数据行盖住）；
- 用**投影**代替描边：横滑时能看出首列是"叠在上面"的，而不是表格断了一截；
- 只有 `windowWidth < 400` 才渲染「← 左右滑动看全表」（桌面/平板不打扰）。

## 四、没做 / 边界

- **没做"表头行冻结"**（纵向）：表放在横向 `scroll-view` 里，纵向 sticky 在该容器内不生效；
  要做得把表拆成"表头 + 表体两个横向滚动容器"并同步滚动位置——复杂度和风险都远高于收益（12 行不滚屏）。
- **横滑联动没有行为验证**：当前自动化工具**没有 scroll-view 横向滚动 API**（只有 `pageScrollTo`），
  所以只做了「计算样式 + 截图」两件事。**真机走查时请顺手横滑一下**，确认首列不动。
- 列宽仍是 200rpx，没有为窄屏改窄——理由见表。
