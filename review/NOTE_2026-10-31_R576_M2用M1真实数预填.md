## §1 最关键的一条：和 R128 的边界

这不是"顺手加个预填"，它踩在两条互相冲突的纪律上：

| | R128（`check_m2_ref_not_prefill`） | #100（本轮） |
|---|---|---|
| 填什么 | **行业参考值**（BANDS 中值反算） | **用户自己在 M1 填过的真实数** |
| 为什么不许 / 可以 | 行业平均不是你的租约，填进去等于替你自证合理，**比不给还坏** | 房租多少是他自己的租约，预填只是省一次抄写 |
| 机器判据 | `applyRefAmount` 函数体零 `yuan` + input value 白名单 | **刻意不碰 `applyRefAmount`**（C-② 断言） |

⇒ **边界是"数据来源"，不是"字段名"**。这句话写进了页面注释和 terms 注释，防止下一个人把行业参考也顺手填进来。

## §2 实现（四条边界，全部有断言）

`subpkg/tools/sandbox/index.js::loadM1Baseline()`

| # | 边界 | 为什么是硬约束 |
|---|---|---|
| ① | **只填空字段** | 用户改过 9999，进页面被改回 12000 —— 他看不出发生了什么（静默改数） |
| ② | **缺项不填** | M1 没填人工 ⇒ 人工=0 ⇒ 保本点算低 ⇒ 结论**变乐观**，全程零报错 |
| ③ | **`account_id` 非空才认** | `getLedger` 对**没建档的月返回一份默认空账**，只判"有返回值"就恒真 |
| ④ | **失败静默** | M2 不依赖 M1，取数失败不许打断沙盘主流程 |

取 **上一月**（`ui.prevMonth(ui.nowMonth())`）而不是本月：本月常没填完，拿它预填等于把半份数据当基准。

水电特殊处理：M1 只记**一个合计**（指标 `utility`），拆不成水/电/气 ⇒ 四项输入全空时切到「水电合计」态

## §5 🔴 本轮事故（必须记）：`open(path,'wb')` 会先截断，把 `verify_all.js` 写成了 0 字节

经过：登记脚本里 `open(VA,'wb').write(out)` 中 `out` 是 `str` ⇒ `TypeError`。
**但 `'wb'` 模式在 `open()` 那一刻就已经把文件截断成 0 字节**，`write` 才失败 ⇒ 文件没了。

- 发现：紧接着 `grep -c "串联：222 个套件"` 返回 **0**、`ls -la` 显示 **0 字节**。
- 处置：`git checkout -- verify_all.js` 立即恢复（164730 字节、语法复验 OK），再重跑登记。
- **根因**：把"构造"和"落盘"写在同一个表达式里，中间异常就会留下半成品（这里是空文件）。
- **纪律**：Python 写文件一律 **先构造完整 bytes，再开文件**：
  ```python
  data = out.encode('utf-8')     # 先算好，失败不会碰文件
  open(p, 'wb').write(data)
  ```
  更稳的是写临时文件 + `os.replace`（原子替换）。
- 附带验证：门禁 `check_js_syntax` 只验语法、不验"文件是否被清空"；这次靠**grep 计数**才发现
  ⇒ 改关键文件后，**回读字节数是必要动作**（`ls -la` / `wc -c`）。
