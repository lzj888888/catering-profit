## 一 《小面测算.xlsx》机器复核结果（逐格，非目视）

| 项 | 实测 |
|---|---|
| 工作表 | 1 张（`小面成本测算`），A1:O145，无隐藏表、无合并单元格、无图表 |
| 公式 | **0 条** —— 2175 个非空格全部是静态数值 |
| 条件格式 / 自定义数字格式 | 0 条 / 无 |
| 组织维度 | 面积 3 档(20/30/40㎡) × 月租金 8 档(3000~10000) × 人工 2 档(2/3人) × 目标 3 档(保本/赚1万/赚1.5万) = 144 行 |

**反推还原的计算逻辑（144/144 行命中）**

```
月人工     = 人工人数 × 4500
月固定成本 = 月租金 + 月人工
边际贡献率 = 1 − 45%(食材) − 5%(水电燃气) − 5%(管理费) − 2%(杂支损耗) = 43%
月营业额   = (月固定成本 + 目标净利润) ÷ 43%      ← 反推核心
月碗数     = 月营业额 ÷ 12 元客单价 ；日碗数 = 月碗数 ÷ 30（向上取整）
```

**三个硬伤（机器证据）**

1. 🔴 **面积对结果零影响**：三个面积区块除 A 列外，其余 14 列 × 48 行**逐格完全相同**（差异单元格数 = 48，全部在 A 列）。
2. 🔴 **参数全写死在数值里**：4500 元/人·月、12 元/碗、45%/5%/5%/2%、30 天 → 无独立假设区，换业态要整表重做。
3. 🔴 **全表 0 条公式**：改任何一个数都不会联动重算。

**复算一致性**：`输出_店算_小店决策对比表_小面样例.xlsx` 第 4 张表把 48 个组合全量复算，
**「差额」列 48/48 全为 0** ⇒ 口径可完整复现（首行 27907/78 碗，末行 89535/249 碗，与原表一致）。

## 三 融合方案 v1（骨架）

### 3.1 两个互斥 Tab（**都落在既有 `mode` 语义上，不是新建模块**）

| Tab | 输入 | 输出 | 对应本仓 |
|---|---|---|---|
| **A｜已有铺面**「我想月赚 X，现在这个房租要卖多少？」 | 业态、面积、月租金、员工数、盈利目标 | 目标月/日营业额、保本月/日营业额、固定成本拆解、可行性评估 | 既有 `mode='reverse'`（v1.1 已交付） |
| **B｜寻找铺面**「我大概能卖这么多，最高扛多高房租？」 | 业态、面积、预估日均营业额、员工数、盈利目标 | **最高可承受月租金** + "超过即难达成"提示 | 🔴 **引擎已算出** `rent_cap_fen`（v1.1 §3.3），只是没做展示 ⇒ 近乎零成本 |
| 正推（跳转）「我只能做到 X，实际赚多少？」 | 预估营业额 | 实得净利润 | 既有 `mode='forward'` |

### 3.2 三层输入（渐进式披露）

- **L1 小白（默认）**：业态、面积、月租金（或预估日营业额）、员工数、盈利目标。**其余全部读业态参数包**；折叠可见底层假设。
- **L2 进阶**：可改 客单价、单人月人工单价、菜品毛利率 —— 均带同业态参考区间提示。
- **L3 专业**：全部费率、营业天数、坪效、翻台等开放编辑。
- 🔴 **L1/L2 严禁把 坪效 / 目标租金率 / 翻台率 作为输入项**；它们降级为**输出**，仅 L3 可编辑。

### 3.3 业态参数包（单源）

每个业态**整套独立**配置：菜品毛利率、水电燃气、管理费、杂支损耗、人工单价、月营业天数、客单价。
样例工作簿「业态参数包」表已按 4 业态（小面快餐 / 火锅 / 新式奶茶 / 烧烤）落值并标了来源与待校准项。

### 3.4 对比表（客户交付物）

- 主表：**行 = 月租金档 × 列 = 盈利目标档，单元格主输出 = 日营业额（元/天）**；人员配置做维度/切换。
- 可选开关（默认关）：日碗数/份数、翻台 —— 仅单品业态建议打开。
- 面积放在表头做全局输入，不进矩阵行列。
- 导出：**图片 / Excel**（⚠️ 见 §五-e 付费墙问题）。
- 样例成品：`输出_店算_小店决策对比表_小面样例.xlsx`（4 表：客户版决策对比表 / 多业态对照 / 复现校验 / 业态参数包）。

## 四 我的增量判断（豆包看不到的仓内约束与机会）

### a) 🔴 关键技术判断：**引擎可以一行不改**

本仓 M2 的 `fixed_items` = 房租/人工/水电气/管理费/其他固定（**金额**），`var_items` = 佣金/刷卡/其他（**占比**）。
而《小面测算》把 水电 5%、管理 5%、杂支 2% 全部当**随营业额变动的率**。

> ⇒ 小白模式下把 `utility` / `manage` / `杂支` 从 `fixed_items`（金额）**挪到** `var_items`（费率），
> 方程与正算**同形** —— 与 R219「反推 = 剔 `rent` + 加 `租金率`」**完全同构**，**引擎零改动**。

⚠️ 但**口径会变**：费率化会把这两项摊到营收上 ⇒ **保本线被压低**（原表 43% 贡献率 vs 本仓若用金额口径）。
必须在 UI 明示"本次测算假设这两项随营业额变动"，且 L3 可改回金额口径。**此为本方案最大的口径决策点**（§六-3）。

### b) 🔴 口径缺口：本仓**没有"杂支损耗"科目**

`fixed_items` 白名单（`common/indicatorRef.js`）无此项；`var_items` 的 `other` 语义是"其他挂钩费用"。
⇒ 要落地参数包，需**规范增量**明确：给 `var_items` 新增一个损耗类 key，或声明归入 `other` 并写清语义。**不能默认存在**。

### c) 🔴 豆包说的"同业态同面积流水区间"本仓**没有数据**

本仓 `indicatorRef.js::bands` 是**成本占比参考带**（毛利率/人工/房租/推广/能耗/管理），
**不是流水带、也没有坪效带**。豆包要用它做"目标是否离谱"的硬校验 —— 数据不存在。
⇒ 只能先做**软提示**（如"该目标高于同业态同面积普遍水平"），**不得编造分位数**。要做硬校验须先补单源数据。

### d) 豆包口径与本仓单源**冲突一处**

豆包称「火锅水电燃气 8~12%」，本仓 `[D1]` 参考带为 **hotpot energy [4,6]**。两者差近一倍。
⇒ 记入待核清单（§六-6），样例工作簿里**按仓内单源取值**并显式标注冲突，不擅自采信外部口径。

### e) 豆包漏掉的仓内约束：**"导出"是付费域**

本仓 M1「导出月度报表」已在付费墙内（`check_paywall_coverage` = 13 项）。豆包直接建议"支持导出图片/Excel"，
未考虑免费/付费边界。⇒ **免费档能不能导出对比表，必须拍板**（§六-1），否则付费墙会被这个新入口绕过。

### f) 豆包说"回本周期移出 M2" —— 本仓成本更高

本仓 M2 **已有** `build_items`（加盟费/装修/设备/其他 + 摊销年限），摊销**已进固定成本** ⇒ 回本所需数据**已具备**。
"移出 M2 建独立模块" = 新增页面 + 新增入口 + 破 `app.json` 页面清单三关，收益未必大于成本。
⇒ 建议改为 **M2 内不默认展示、给折叠/跳转**（§六-2）。

### g) 术语红线：豆包写了"食材成本率"，**本仓禁止对外出现**

本仓 round111 铁律：对外一律「**菜品毛利率**」，`食材成本率 = 100 − 菜品毛利率` 只是引擎内部中间量。
⇒ L2 的可改项必须写成「菜品毛利率」；三层模式的命名也要与 **M1.4「专业模式（真实利润）」** 统一，禁止出现第三套"专业"。

### h) 面积：从"硬伤"改口径为"本就不该参与"

面积不参与保本公式**不是缺陷而是正确口径**（原表恰好证明了这一点）；
本仓 v1.1 **已有** `pixel_eff_fen`（坪效）入参与 `area_cap_sqm` 出参 ⇒ 面积的正当用途**已实现**，无需新增。
