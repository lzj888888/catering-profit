## 三 🔴 本轮最重要的发现：M3 免费配额 = **只提示不拦截**（P0）

### 实扫证据（全部有行号，可复现）

| # | 事实 | 证据 |
|---|---|---|
| ① | 额度值**硬编码** | `cloudfunctions/checkQuota/service.js:17` `const FREE_LIMIT = { shop: 1, cost_card: 3 };` |
| ② | `subscription_plan` **从未被用于读额度**（只读价格）| 全仓 12 处命中全在 `payCreateOrder`/`payCallback`/`payRenew`/`adminManualOrder` |
| ③ | **写侧零拦截** | `cloudfunctions/saveCostCard/index.js` 全文无 `FREE_LIMIT`/`checkQuota`/`activeCount`/`count(` |
| ④ | 全仓 `checkQuota` **仅被前端调用一次** | `pages/card/index.js:62`；**云函数侧零调用** |
| ⑤ | 守卫把**违规当单源** | `tools/check_quota_limits.js:35` `SRC_REL` 指向含硬编码的那份；全篇只校验**「文档 ≡ 代码」**，从不校验**「代码 ≡ 规范」** |
| ⑥ | 自测把错值**钉成断言**（假绿）| `cloudfunctions/checkQuota/selftest.js:14` `check('FREE_LIMIT.shop=1 / cost_card=3', …)` |
| ⑦ | 守卫自述**与事实相反** | `tools/check_free_shop_limit.js:7-9` 称 checkQuota 是"真正执行付费墙拦截的那一个" |

### 与既有登记的关系（**不冒功**）

该问题**已登记**于 `specs/dev-specs/core/13_上线前查缺补漏_决策与待办总览.md:256-278`
（「① 以 `checkQuota` 常量为准 ⇒ 只改基线措辞 / ② 走配置化 ⇒ 改 4 处」，**明确"待李老师二选一"**）。

**我补的新证据（既有登记与 R117 守卫都未覆盖的两维）**：
- **③ 写侧零拦截** —— 这才是"付费墙失效"的直接原因（不是"数值不一致"）；
- **④ 只被前端调用** —— 证明 R117 头注"真正执行拦截"是**事实错误**。

### 定案（按 D12 授权）

**走路线 ②「配置化」**：额度配置落 `feature_permissions`（`plan_id='plan_free'` + `limits`），
`checkQuota` 改为**入参注入**、**禁字面量兜底**（缺配置 ⇒ `QUOTA_CONFIG_MISSING` 响亮失败），
`saveCostCard` **新增写侧拦截**，R102 加**反向断言**（额度字面量再现于 service.js 即转红），R117 修头注事实错误。
⇒ 共 **12 项改造清单**，见规范 M3.22 §三。

> **为什么不放 `subscription_plan`**：它是**付费套餐价格表**（4 档种子全是付费档），且 `payCreateOrder` 按 `plan_id` 读它下单
> ⇒ 塞一个"免费档"会让免费档变成**可下单的付费档**。故 v1.0 规范 M3.7 那句「读 `subscription_plan`」在当前数据模型下
> **不可执行**，本规范以**勘误替代**更正为读 `feature_permissions`（**v1.0 文件本体一字不动**）。
