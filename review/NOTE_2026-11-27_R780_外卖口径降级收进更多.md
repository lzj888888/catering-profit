# NOTE 2026-11-27 · R780 外卖页口径降级：不常用的收进「更多」

> 触发：李老师「总额法和到手这个概念餐饮老板完全不理解……不常用的可以收到更多，还有我说的一起排就是你看到的这些。你操作吧。」

## 一、先回答李老师的问题：点口径，数据会变吗？

**不变。** 实跑确认：`calcTakeawayOrder` 一次算出 `cash` 和 `accrual` 两套数，`mode` 原来只决定结果区显示哪一块——输入一样、菜一样、佣金一样，不是算两遍也不是两个答案。

两套的区别是**同一单的两种记账视角**：
- 到手口径：平台扣完、成本减掉，实际落袋多少 → 定价用
- 总额法：订单总额记收入、成本费用分开记 → 和月度账对账用（有平台补贴时两个数才会拉开）

## 二、改前的问题：三组选择权重视 Same，挤成一串

页面上半部连着三组选择：

1. 顶层 tab「外卖每单赚多少 | 销量导入」—— 两个**功能**
2. 口径 tab「到手口径 | 总额法口径」—— 换一副**眼镜**看同一单
3. 佣金 radio「按比例 | 固定金额」—— 一个**输入参数**

老板分不清哪个是换算法、哪个是换输入。而且 R724j 的注释早就写过「首屏 4 个块连成一片色块墙，老板一眼跳过」——同一个病又犯了。

## 三、改法（纯展示层级，不碰计算公式）

| 项 | 改前 | 改后 |
|---|---|---|
| 顶部口径切换 | 两个 tab + 一段会计术语解释 | **删除** |
| 结果标题 | `resultTitle` | **「这单赚多少」** |
| 到手结果 | 要 `mode === 'cash'` 才显示 | **默认显示**（只看 `result`） |
| 总额法结果 | 平级的第二个 block | **收进结果区下方「更多：换个算法看」折叠**，默认收起 |
| 折叠说明 | — | 「做账/对账时才用，平时不用管」 |
| 佣金 radio | 保留 | 保留（它是输入参数，只是不再有 tab 感） |

### 文案全换成人话

| 原 | 现 |
|---|---|
| 到手口径 | **这单赚多少** |
| 总额法口径 | **按总额记账** |
| 现金视角：老板实际到手多少，减掉菜品和包材成本就是赚的 | **平台扣完、成本减掉，这单实际落袋多少。** |
| 会计视角：按订单总额记收入… | **和月度账对得上才用：订单总额记收入，成本费用分开记；有平台补贴时两个数会不一样。** |
| 填了实收，总额法不出数… | **填了「商家实收」后这格算不了：按总额记账要的是顾客原价付了多少，而你填的是平台扣完打给你的钱。想看就把实收留空。** |

「会计术语不再上屏」这条由守卫 R780-⑤ 钉住。

## 四、关键设计：折叠只切显示，不切算法

- `mode` 保留恒为 `'cash'`，不再给用户切（下游 view 与老守卫仍读它，避免波及）。
- 新增 `moreOpen: false`，`onToggleMore()` **只改 `moreOpen`**，绝不碰 `mode`、不重算。
- 两套数仍由 `calcTakeawayOrder` 一次算完，折叠只是显示层的开关。
