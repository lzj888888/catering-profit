## 二、缺陷定位（3 个，其中 1 个李老师没报但必现）

### 缺陷 ① 新增路径 `init.lines` 未初始化 ⇒ TypeError ⇒ 「系统异常」

`pages/card/edit.js`：

```js
const init = { materials, loading: false };
if (this.data.isEdit) { ... init.lines = ... }   // ← 只有「编辑」分支才给 lines 赋值
if (init.lines.length === 0) ...                 // ← 非编辑（新增）路径 init.lines === undefined
```

`isEdit = ('').length > 0 = false` ⇒ 新增时 `init.lines` **从未被赋值** ⇒ `undefined.length`
抛 `TypeError` ⇒ 被外层 `catch` 吞掉 ⇒ `api.toastError(e)` ⇒ `e.msg` 为 undefined
⇒ 兜底取 `msgOf('SYSTEM_ERROR')` = **「系统异常，请稍后重试」**。

**纯前端、必现、与云端配置无关。** 李老师没单独报它，是因为他没走到过这一层（见缺陷 ③：
新增按钮在列表页就被 `checkQuota` 拦住了）。

### 缺陷 ② `wx:key="idx"` 重复 ⇒ 明细行「输入即丢 / 点一下就被删」

`pages/card/edit.wxml` 用 `wx:key="idx"`，而 `edit.js` 的 idx **不唯一**：

```js
// onLoad 预填：每一行的 idx 都被写死成 0
init.lines = (c.lines || []).map((l) => ({ idx: 0, ... }));
// ⇒ 打开一个有 3 个原料的菜品，lines = [{idx:0},{idx:0},{idx:0}] ⇒ key 全重复

// delLine：只 filter、不重排 idx
const lines = this.data.lines.filter((l, i) => i !== idx);
// ⇒ 3 行删中间 1 行 ⇒ idx 变 0,2；再 addLine（idx = length = 2）⇒ 0,2,2 又撞键
```

微信对重复 key 会告警 `Do not set same key` 并**节点复用错乱**：一次 `setData` 后输入框被
错误复用/回写 ⇒ 表现为「输入不进去、一点就没」。李老师说的「**打开菜品时**」正是触发条件 ——
新增页（本应只有空行）因缺陷 ① 进不去，而打开已有菜品必定预填多行 ⇒ 必现。

### 缺陷 ③ 云端 `feature_permissions.plan_free` 缺失 ⇒ `checkQuota` fail-closed

`pages/card/index.js:goAdd()` 在跳转前先调 `checkQuota({ scope:'cost_card' })`：

```js
const q = await api.call('checkQuota', { scope: 'cost_card' });
```

而 `cloudfunctions/checkQuota/index.js` 读配置：`where({plan_id:'plan_free'})` ⇒ 取不到 `limits`
⇒ `fail(SYSTEM_ERROR, '配额配置缺失（plan_id=plan_free）')`。

`plan_free` 这行是本轮（`789ceee`）新引入的**种子数据**，而 `initDb` 旧实现把
`feature_permissions` 的播种挂在「`subscription_plan` 整表为空」这个**总闸**下 ⇒
已建库的 dev 环境**永远不会再插入新种子行** ⇒ 云端缺这行。
（round122 已修播种粒度 + 已部署，但**补种动作尚未在云端执行**。）

**可区分性证据**（解释现象 1 与 2 为何同时出现）：
`goEdit()`（点列表项打开已有菜品）**不调 checkQuota**，`goAdd()`（新增）**调**。
⇒ 打开已有菜品能进去（于是踩到缺陷 ②），新增进不去（卡在缺陷 ③）。

### 附带发现 ④ 后端具体 msg 被前端映射吞掉

`utils/api.js`：`const msg = terms.msgOf(r.code)` —— 后端 `fail(code, msg)` 携带的
`'配额配置缺失（plan_id=plan_free）'` 被**整条覆盖**成「系统异常」；且 `r.error` 为空
⇒ 连既有的 `console.error` 都不触发 ⇒ 真机排障信息归零。

## 三、修复

| 文件 | 改动 |
|---|---|
| `pages/card/edit.js` | 新增 `emptyLine()` / `renumber()`；预填改 `renumber(map(...))`；空行兜底改 `if (!init.lines \|\| init.lines.length === 0)`；`addLine`/`delLine` 末了统一 `renumber`（保证 `idx === 数组下标`） |
| `utils/api.js` | 当 `r.msg` 与 i18n 文案不同时打 `console.warn` **记录后端原始 msg**（不改 UI 文案口径，仍走 `msgOf`） |

**设计要点**：`idx` 字段**只服务 `wx:key`**，业务侧仍以**数组下标**为准（wxml 的
`data-idx="{{index}}"`）⇒ 修复不引入第二套索引真相源。`renumber` 返回新对象，不就地改入参
（保 `setData` diff 语义）。

**未改**：`cloudfunctions/**`（属写码方域，且缺陷 ③ 的根因是**配置未就绪**，不是代码缺陷）；
`specs/dev-specs/**`（本轮无口径变更）。
