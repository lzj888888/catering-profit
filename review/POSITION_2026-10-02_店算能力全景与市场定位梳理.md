# 店算 · 能力全景与市场定位梳理（2026-10-02）

> **一句话结论**：店算已经是一个**算得准、口径硬**的核算引擎（双利润 / 双口径 / 成本卡版本模型 / 行业参考带 / 开店推演都齐了），
> 但它现在**不是**一个好用的产品 —— 因为**所有数据都得老板自己敲进去**。
> 收银软件靠"点单即数据"自动喂饱自己，店算靠手工录入，这是两者之间**唯一但致命**的差距；
> 好消息是差距可以用三条低成本通道补齐（上月复制 / 粘贴面板扩张 / Excel 批量导入），不必等开放平台资质。

> 本文事实部分全部来自本仓代码与规范实读（`dev` @ `98d5611`，门禁 125/125），外部行情来自 2026-10-02 联网检索，均标注来源。
> 🔴 **文中"建议"部分均为待拍板项**，未开工；按项目纪律「先审后合」，不自行写码。

## 一 能力全景：现在到底能干什么

### 1.1 四个模块的实际边界

| 模块 | 能算什么 | 数据从哪来 | 收费 |
|---|---|---|---|
| **M1 月度盈利** | 经营参考利润 / 真实利润（双利润）+ 差异归因；库存倒轧 `期初+采购-期末`；一次性投入与分期摊销；**行业参考带对照** | **纯手工录入**（36 个预设细项，默认只显示 1 行空行） | M1 免费 1 家店（月份不限）；**导出付费**；专业模式（真实利润）付费键已登记但**代码零判据** |
| **M2 开店盈亏 / 选址** | 城市层级 × 业态 → 保本月/日均、目标月/日均、回本周期、红警、6 项指标对照 | 手工，**默认二三线 + 中式正餐 + 毛利率 65%**，填营业额后给每项**参考金额占位符** | **永久全免费、不限套数、永不弹付费墙** |
| **M3 菜品毛利** | BOM 两层成本（净料单价 = 采购每克 ÷ 出成率）；单品/套餐；多规格试算（半份/小份/**每100g**）；目标毛利率反算售价；版本历史与成本趋势；原料涨价影响面 | 手工建卡；有 **20 道菜模板 + 65 条原料词库**（只预填名称行，**价格全留空**） | 免费 **20 张可算卡**（原料档案永久免费）；套餐 / 外卖 / 批量导出付费 |
| **外卖 / 对账** | 单均测算（到手 vs 总额法双口径）；**账单导入**（xlsx）；M1↔M3 率对率对账 + 4 条归因 | 手工 + **唯一的文件导入通道** | 外卖单均付费键已登记（前端有墙、云端无判据） |

**引擎侧（这是真本事，别妄自菲薄）**：核心计算全在云端，前端不算公式 ——
`calcMonthlyProfit`（双利润）/ `calcBom`（BOM 两层 + 快照）/`calcAmortize`（摊销尾差）/`calcSandbox`（保本推演）/ `detectCycle`（BOM 防环 DFS）/ `specDerive`（规格系数）。
另有 12 个后台管理函数、6 个支付函数、2 个导入导出。

### 1.2 已经做对的四件事（相对同行是优势）

1. **口径是为餐饮老板量身定的，不是会计科目**：到手口径 vs 总额法、外卖补贴归属、佣金基数不含打包费、权责发生制 —— 这些是收银软件**不会替你做**的判断。
2. **成本卡是版本模型（只 INSERT）**：改价留痕、可回退、有成本趋势图 —— 多数收银软件的"成本卡"改了就覆盖。
3. **行业参考带是内嵌的**：M1 结果页 + M2 沙盘都有分业态 × 分城市层级的参考带，页面零硬编码（`indicatorRef.js` 单源）。
4. **M2 是免费引流且体验最好**：进页面先算一次、先给结论，再让你填 —— 这是全仓唯一"零输入先有输出"的页面。

## 二 对照收银软件：市场与竞争

### 2.1 行情（2026-10-02 联网检索，两家来源口径不同，取区间）

| 品牌 | 价格区间 | 定位 |
|---|---|---|
| 美团收银 | 基础免费，增值 300–800/年；主流版 999–2500/年/店 | 外卖生态无缝对接（本店正在用） |
| 银豹 | 300–600/年；买断 2000–3000/店 | 多业态兼容、可买断 |
| 客如云 | 800–1500/年（另一来源 3000–4000/年/店） | 正餐/火锅/烧烤，后厨与桌台强 |
| 天财商龙 | 买断 1800–2500；连锁年费 5000+ | 中大型连锁、供应链与财务核算 |
| 唯顿 / 乔拓云 | 699 终身买断 / 699 元起每年 | 小微单店性价比 |

### 2.2 关键判断：**不是同一个层，别硬刚**

| | 收银软件（美团/客如云/银豹/天财商龙） | 店算 |
|---|---|---|
| 管的层 | **交易层**：点单、收银、库存、会员、供应链、报表 | **核算层 + 决策层**：这个月到底赚没赚、这道菜到底赚多少、这家店能不能开 |
| 数据从哪来 | **自动**（点单即销量、采购即成本） | **手工 / 导入**（这是最大差距） |
| 强项 | 每天离不了、店员会用、硬件生态 | 口径专业、会算"收银软件算不出来的账"、能推演未来 |
| 弱项 | 成本毛利模块普遍浅（多为"标准成本卡 + 毛利率预警"，依赖你把进销存录全） | 不接管日常经营，老板得**额外**录一遍数 |
| 结论 | **替代不了，也不该替代** | **吃它吃剩下的那一层** |

> 收银软件里也有"成本毛利核算"模块（如 Kimpos：菜品成本卡 + 采购价波动联动毛利 + 低毛利预警；用友系：业财一体、标准食谱卡算实际成本）。
> 但它们的共同前提是**你把进销存跑起来**（录采购单、盘点、领用）—— 小微店根本跑不动，于是那个模块永远没人用。
> **这正是店算的机会**：不要求你做进销存，只要"采购价 + 用量"两件事就能算出成本。

### 2.3 三类真实竞品与胜负手

| 竞品 | 它强在哪 | 店算怎么赢 |
|---|---|---|
| **收银软件的成本模块** | 数据自动流、和采购联动 | 赢在**零前置**（不用做进销存）+ **口径专业**（双利润/双口径）+ **能推演**（开店能不能开） |
| **Excel 模板**（李老师自己就在做免费引流） | 老板熟、零学习成本、随便改 | 赢在**算完还有解释**：行业带对照、归因、版本趋势、反算定价 —— 模板给不了结论 |
| **业财一体财务软件**（用友畅捷通等） | 合规、发票、凭证、多门店 | 赢在**轻**：它们面向会计，店算面向老板；价格与学习成本差一个量级 |

### 2.4 客户是谁（要挑清楚，不然体验做不对）

- ✅ **精准客户**：1–3 家店的小微餐饮老板，外卖占比高，**正在用美团收银但看不懂钱去哪了**，愿意每月花 20 分钟记账。
- ⚠️ **会用但不理想**：已有专职会计 / 已跑通进销存的店（它们该上业财一体）。
- ❌ **不该接**：连锁（我们没多账套、没团队协同）、只想要"记流水"的（那是记账 App 的活）。

> 🔴 一句话定位建议（供拍板）：**"不是收银，是收银之后的那本账"** —— 你负责收钱，我负责告诉你这个月赚没赚、哪道菜在亏、下家店能不能开。

## 六 让客户更快 · 五条优化建议（按性价比排序，**均需拍板**）

> 排序原则：先补"最痛且最便宜"的，不碰"最炫但最贵"的。
> 成本一律写**改动面**（可验证），不写人天 —— 没实测的数字不进汇报。

### ① M1「上月一键复制」+ 预设细项默认展开 —— **性价比最高**
- **解决**：每月从零填 40+ 字段（负担点 1+2）。
- **做法**：录入页加「复制上月」按钮（读上月 ledger 覆盖空值，金额留空让用户改）+ 首次进页面按业态展开常用细项。
- **改动面**：前端 1 页（`pages/month/input`）+ 复用现有 `getLedger`；**不新增集合、不动引擎**（门禁影响小）。
- **风险**：低。唯一要防的是"复制后忘了改" ⇒ 加"已复制上月，请核对"横幅 + 存草稿标记。

### ② 粘贴面板从"外卖三框"扩张到收入/费用全框
- **解决**：老板手边其实有 Excel/账单，现在只能一个一个敲。
- **做法**：把 `input.wxml:424-435` 那套"粘贴一列自动提数字求和"复用给所有金额框。
- **改动面**：前端复用，零后端；**改动最小**。

### ③ 原料 / 菜品卡 Excel 批量导入（模板下载 → 填 → 导入）
- **解决**：30 道菜 = 30 次建卡（负担点 4），这是**拉新后留存的第一杀手**。
- **做法**：出一份标准模板（原料：名称/单位/采购价/换算/出成率/分类；菜品：菜名/原料名/用量/单位）→ 用户填 → 走**已有的** `wx.chooseMessageFile` 通道上传（阶段① 已验证可用）→ 云端解析 → 预览 → 确认落库（照抄阶段① 的"预览 + 甲级门禁 + 确认才写"三段式）。
- **改动面**：新增 1 个云函数（+ 三处同步面：A15 白名单 / `core/10` 契约 / 隐私声明）；**复用已验证的导入通道**，风险可控。
- **依赖**：需一份模板规范（可先做，不依赖销量样例）。

### ④ 渐进式披露：M1 先给"三个数的粗结论"
- **解决**：新用户进 M1 看见 40 个空框就跑。
- **做法**：新增"快速算"入口 —— 只填**营业额 / 食材成本 / 房租人工**三个数，立刻出"这个月大概赚/亏多少 + 行业位置"，再引导进完整录入。
- **改动面**：前端 1 个轻量入口 + 复用 `calcMonthlyProfit`（引擎零改动）。
- **注意**：粗结论必须标"估算"，别和真实利润口径混淆（我们的红线是口径不能糊）。

### ⑤ 拍照 OCR —— **建议继续不做，但要留门**
- 现状：ADR 已裁决不做（AI-D10）。检索显示同行（菜小秘等）**有** OCR 采购单识别，这是行业趋势。
- 判断：**现在做不划算**（识别错一个数 = 成���全错，而我们卖的就是"算得准"）；
  真要做，正确姿势是"OCR 只填草稿 + 人工确认"，且放在 ③ 之后。
- 结论：**维持不做**，本次不动。

### 另外两条"便宜但要补"的
- **术语解释入口**：出成率 / 净料率 / 权责发生制 三处加一行 hint（抄 `matUnitHint` 现成样式）—— 半天以内的前端活，收益明显。
- **导出补 PDF/图片**：老板真正会转发的是"我这个月赚了多少"的图 —— 但**先确认这是不是转化点**（付费墙锚点），再排期。
