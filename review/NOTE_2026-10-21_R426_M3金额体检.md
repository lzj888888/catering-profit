# R426 · 队列 #32：M3 两页（成本卡 / 原料）金额栏接体检

## 1 为什么这两页比 M1 更危险

M1 录入页的「元 → 分」还走 `api.yuanToFen`（fail-soft 返回 0）；**M3 这两页根本没走它**：

| 页面 | 原写法 | 「12,000」会变成 |
|---|---|---|
| `subpkg/biz/card/edit.js::onSave` | `Math.round(Number(((Number(priceYuan) \|\| 0) * 100).toFixed(10)))` | `Number('12,000')` = **NaN** ⇒ 分 = NaN ⇒ 上云 null/0 |
| `subpkg/biz/material/edit.js::onSave` | 同上（`purchase_price_fen`） | 同上 |

而 **0 是合法金额** ⇒ 云端校验无从拒 ⇒ 成本卡按 0 元落库、原料按 0 元/斤落库，毛利率显示照常。
原料按 0 元落库的后果是**全店**用到它的菜成本一起归零 —— 比 M1 单行金额错得更狠。

## 2 做法（与 R419/R425 同口径：只判定、只暴露、不改数）

- 复用同一个纯函数 `utils/amountInput.js::classifyAmount`（不新造第二个口径）。
- `card/edit.js::checkAmounts()` 覆盖：售价 / 辅料成本 / 活动价 / 团购价 / 团购活动价 /
  规格售价（`specRows[].priceYuan`）/ 手工行单价（`lines[].unit_price_yuan`，仅 `input_type=2`）。
- `material/edit.js::checkAmounts()` 覆盖采购单价。
- 六处输入 handler + `onSpecPrice` 各补一次调用；`onSave` **硬拦**（横幅只提醒，不拦照样能存 0 元卡）。
- 文案复用已有的 `TERMS.ui.amountBadTip`（不新增可见文案 ⇒ 无需 i18n 三处同步）；按钮用 `TERMS.buttons.gotIt`（3 字）。

## 3 守卫（`tools/check_amount_input.js` 37→56 条）

新增 ②-23~②-38 + ③-8~③-10。关键点：

- **字段集从生产代码实扫**（`XxxYuan: e.detail.value`），要求每个命中 handler 都调了体检。
  后缀判据会把 `aliasesYuan` 误抓 —— 它是**别名列表**（逗号是合法分隔符），按语义进 `NON_MONEY_FIELDS` 排除。
- 规格售价是另一条写法（`priceYuan: v`），实扫抓不到 ⇒ 单独守 `onSpecPrice`。
- 保存拦截守「`checkAmounts()` 之后必须 `return` 且 `showModal` 在前」，否则"提示归提示、照样存"。

### 3.1 本轮自己踩的判据坑（写下来防复发）

`handlerAt()` 最初只取「最近的 2 空格缩进行」。而赋值常发生在 `this.setData({ ... })` /
`Object.assign({ ... })` 里 ⇒ 取到 `this.setData` / `lines[idx] = Object.assign` 这种非标识符，
覆盖率腿**假红**两条。修法：向上继续找，直到取到纯标识符为止（不是改代码迎合判据）。
