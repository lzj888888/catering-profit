# R606 · M1 外卖收入录入「框填不进」排查与整改

> 日期：2026-11-02 ｜ 模块：subpkg/biz/month（M1 录入页）｜ 整改状态：已闭环，待真机复核

## 一、用户现象（原话锚点）

> 用户：「M1模块 外卖收入那里 有个 填入总数 ，一开始填不进去，点开折叠后，可以填 单数和金额 下面的输入框 依旧输入不进去」

拆解为三段可验证症状：
1. 外卖段默认（折叠/未充分展开）状态下「填不进去」；
2. 展开折叠后，**首行**的「单数 + 金额」能填；
3. **下方的输入框（后续行的框）依旧输入不进去**。

## 二、排查链路（按 miniprogram-page-stub / miniprogram-page-review 三层路由）

| 层 | 手段 | 结论 |
|----|------|------|
| L2 逻辑层 | 页面桩 `new Function` 内存加载 `input.js`，真跑 6 个外卖 handler（net.onSubAmount / net.onFastQty / gross.onTwDetail×3 / gross.onRecYuan） | **6/6 PASS** ⇒ 写入逻辑正确，`setData` 回写无误 |
| CSS | 通读 `input.wxss` | 无 overlay、`pointer-events:none`、异常 `z-index` ⇒ **排除遮挡** |
| L3 结构 | 比对 `miniprogram-page-review` 模式2「输入框输入即丢」 | 命中：`wx:key="index"` 是头号成因 |

## 三、根因（确定性）

`subpkg/biz/month/input.wxml` 中**所有带 `<input>` 的行级 `wx:for`** 都用 `wx:key="index"`：

- 行 121 堂食分项 `g.rows`
- 行 203 外卖净额（net）`g.rows` ← **用户报的这段**
- 行 381 其他收入 `g.rows`
- 行 446 费用 `g.rows`

机制：外卖净额模式按平台有多行（美团/饿了么/抖音…）。每敲一个键 → `updateRow` → `setData` 重渲染整段。
`wx:key="index"` 让原生 `<input>` 按**下标**复用 DOM 节点；重渲染后节点身份错位 ⇒
**第一行的框能填，下方行的框（后续下标）输入即丢 / 焦点丢失 / 填不进** —— 与用户三段症状完全吻合。

（gross 模式用 `wx:key="platform"`、折叠态用 `wx:key="name"`，本身稳定，故未被报告。）

## 四、整改（已落地）

1. **注入稳定唯一键 `rid`**（`input.js`）：
   - 模块级 `const _ridPrefix = 'k' + Date.now().toString(36) + '_'` + 自增 `let _ridSeq`；
   - `ensureRid(r)`：仅在 `rid` 缺失时写入；`updateRow` 的 `Object.assign` 会保留它 ⇒ 跨次键入稳定；
   - 会话前缀保证：会话内唯一、跨会话（含已落库行回填）不重号。
2. **装配口统一补键**：
   - `decorateRows` 非堂食分支：`markFixedRows(rows, g.items).map(ensureRid)`；
   - `decorateDineRows`：预设渠道用 `p:<渠道名>`（天然稳定唯一），自定义行用会话序号。
3. **WXML 四处 `wx:key="index"` → `wx:key="rid"`**（121 / 203 / 381 / 446）。
   - 仅静态文案 `fillGuide`（行 23）保留 `index`（无 `<input>`，无风险）。

> 为什么不动 `normalizeDineRows` 本体：`decorateDineRows` 是页面层「唯一装配口」，键只服务于渲染 diff，
> 不进计算、不进保存契约（保存走 `cleanItems` 只取已知字段），故加在页面层最安全，共享 util 行为零改动。
