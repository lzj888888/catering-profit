# R358 · 重算失败时，旧表必须清掉（否则旧数字被当成新结果）

> 日期：2026-10-19 · 由 R357 行为套件新增断言 D 抓出 · 脚本 `tools/check_m2_partial_behavior.js`

## 一、先说结论

矩阵页「生成」失败时，`result` 一直**没被碰过**。第一次算成功之后，老板改了租金/目标档位再点生成：

| 情况 | 屏幕上 | 老板的理解 |
|---|---|---|
| 第 1 批就失败 | **上一次那张表原样留着** + 一句「网络不可用」 | 「这就是我刚改完的测算结果」 |

数字全是旧的、档位是他刚改的 —— 属于**静默错账**，而且方向是「看着挺好」那一种。

## 二、怎么发现的

R357 的行为套件原本只覆盖「一次会话内第一次跑」。补断言 D 时先**假定**它是对的，
结果当场判红：

```
❌ D1 重算第 1 批失败 ⇒ 旧表必须清掉  → 仍留着上一次的 {"count":750,"partialText":""}
```

⚠️ 静态判据抓不到这条：`result` 的写入语句、字段、渲染全都在，**只是失败分支没有清它**。

## 三、改法（`pages/sandbox/matrix.js`）

```js
if (failedAt === 0 || (!allRows.length && failedAt > 0)) {
  this.setData({ loading: false, result: null });   // ← 新增 result: null
  api.toastError({ msg: failedMsg });
  return;
}
```

外层 `catch` 同样要清，但**不能无条件清**：`setData(result)` 之后还会跑 `buildCash()` /
`fixedBreakOf()`，它们若抛错，此时结果是**本次有效的新结果**，清掉等于把好数据一起扔了。
⇒ 用一个 `shown` 标记区分：

```js
let shown = false;
try {
  ...
  this.setData({ ..., result: {...} });
  shown = true;            // 新结果已上屏
  this.buildCash();        // 其后任何一步抛错，都不该清掉这份结果
  ...
} catch (e) {
  this.setData({ loading: false, result: shown ? this.data.result : null });
  api.toastError(e);
}
```

**为什么是「清空」而不是「保留 + 加一句『这是上次的』」**：
后者要新增一块提示区（改 wxml ⇒ 要出码），而且老板对「上次的」这种小字通常不看；
清空 + toast 说明原因，是**不会误读**的最小改动。重新点一次生成即可。

## 四、判据（行为套件 11 → 15 条）

| # | 断言 | 变异 |
|---|---|---|
| D0 | 前置：先成功算过 750 行 | — |
| D1 | 重算第 1 批失败 ⇒ `result === null` | 去掉 `result: null` ⇒ 红（正是本轮实证） |
| D2 | 重算失败 ⇒ 仍有 toast 说明原因 | — |
| E1 | 重算中途失败 ⇒ 显示**新的**部分结果（150 行），不是上一次的 750 行 | 写回旧 result ⇒ 红 |

E1 是为了防「清空逻辑矫枉过正」：中途失败时必须给**新**的部分结果，不能退回旧表、也不能空表。

## 六、没做的（如实）

- 输入校验失败（毛利率填 150 / 超 1000 行）时**仍保留旧表**：那类提示指向具体哪一档错了，
  语义上不属于「跑了一遍但失败」，本轮未动；若要一并清空，需另立判据。
- 没有「一键重试」；老板要自己再点一次生成。
