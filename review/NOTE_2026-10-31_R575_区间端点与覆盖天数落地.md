## §1 改了什么（四处，均可复算）

### 1.1 解析层：把"这是一段"抽出来（`importSalesBill/service.js`）

- 新增 `extractPeriod(sheetRows)` → `{from, to}`：从表头参数行抽**首末两个日期**，
  写反自动交换，取不到返回空串（**不猜**）。
- `extractBizDate()` 改为**复用** `extractPeriod().to` —— 日期解析只此一份，防两处正则漂移；
  **返回语义不变**（`biz_date` 与 `_id` 都靠它，改了会让同表重导覆盖不到旧文档）。
- 新增 `classifyGranularity(from, to)` → `'daily' | 'interval' | 'unknown'`（三值封闭集）。

真表实测（`review/evidence/r574_dish_ingest/matrix.json` 的形态 A 候选）：

```
bizDate= 2026-09-13 | from= 2026-09-07 to= 2026-09-13 | gran= interval | rows= 36
```

### 1.2 落库层：三处写入全部带上（`importSalesBill/index.js`）

| 写入点 | 数据来源 | 写入值 |
|---|---|---|
| 外卖账单（`BILL_` 前缀） | 逐日 | `daily` / 两端 = 该行 `bizDate` |
| 堂食《菜品销售统计》 | 区间汇总 | 取 `parsed.granularity`（实测 `interval`） |
| 外卖商品销量（形态 C/D） | 逐日分组 | `daily` / 两端 = 该组 `bizDate` |

**为什么三处都要写、且都要显式写**：读侧靠"字段缺不缺"区分「明确是逐日」与「历史数据不知道」。
少写一处 ⇒ 那条通道的"这是一段"永远丢失，而解析层断言照样全绿（"解析对了"≠"写下去了"）。

### 1.3 读侧：算真实覆盖天数（`getDishReview/service.js::coverageStats`）

纯函数、零 db。口径：

- `days` = 按 `biz_date` 去重的**有数据日期数** —— **保持旧语义**（与 `countDataDays` 逐值相等，
  有断言 15-⑦ 钉住），不动既有展示与断言。
- `coveredDays` = **真实覆盖天数**：`interval` 行按**区间并集**算，`daily` 行记 1 天，
  两者重叠**不重复计**；`unknown`（含无字段的旧数据）按单日计。
- `hasInterval` / `hasUnknown` = 两个**如实标记**（"含汇总表" / "含旧版导入"）。

五场景实测（`node` 直接调生产函数）：

| 场景 | days | coveredDays | hasInterval | hasUnknown |
|---|---|---|---|---|
| ① 堂食 7 天汇总（36 行同 biz_date） | **1** | **7** | true | false |
| ② 外卖逐日 7 行 | 7 | 7 | false | false |
| ③ 混合（①+②） | 7 | 7 | **true** | false |
| ④ 旧数据（无字段） | 1 | 1 | false | **true** |
| ⑤ 两段不重叠区间（3 天 + 4 天） | 2 | 7 | true | false |

③ 是要害：**两栏都报 7**，但一个是"7 天逐日"、一个是"7 天记在 1 天"。

### 1.4 界面：把粒度讲成人话（`pages/m3/dishreview/index.js` + terms 双副本）

| 条件（云端 flag 决定，**前端不猜**） | 文案 |
|---|---|
| `has_interval` | 本榜统计 2026-10，覆盖 **N** 天（含汇总表，非逐日） |
| `has_unknown` | 本榜统计 2026-10，共 N 天有数据（含旧版导入，天数可能偏少） |
| 常规 | 本榜统计 2026-10，共 N 天有数据（**原样不变**） |

`terms.js` 双副本 `md5` 全等（`0c6137c0e13f441683ce11d17cb07c08`）。

## §4 本轮踩到的两个坑（都值得记）

### 4.1 🔴 Python 文本模式写文件 ⇒ 整个文件变 CRLF ⇒ 提交看着"改了 919 行"

`open(p,'w',encoding='utf-8')` 在 Windows 下会把 `\n` 写成 `\r\n`。变异脚本用它还原文件后：
`cloudfunctions/importSalesBill/index.js` 变成 **474 行全 CRLF**，`git diff --stat` 报
**474 插入 / 445 删除** —— 实际只改了 29 行。同轮 `utils/gradeGate.js` 也中招（88 行）。

**识别**：`git diff --stat` 的行数远超实际改动 ⇒ 立刻查
`b.count(b'\r\n')` 与 `git show HEAD:<file>` 的对比；HEAD 是 LF 而工作树是 CRLF = 自己污染了。
**修法**：二进制 `b.replace(b'\r\n', b'\n')`。
**纪律**：Python 写文本**一律** `open(p,'wb')` 或 `newline=''`。

### 4.2 判据钉字面量：我给 `range` 加字段并换行 ⇒ 14-② 判红，而我并没有改语义

原判据正则要求单行 `range: { from: rangeFrom, to: rangeTo, days: rangeDays }`。
正确处置不是"把代码写回单行迎合判据"，而是**把判据改成判语义**：
同一对象里含三个键即可（允许换行、**允许额外键**），且必须在**剥注释后**的源码里判。
