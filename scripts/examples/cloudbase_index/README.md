# 云开发控制台 · 数据库索引 批量操作脚本（实测 2026-09-17）

> 配套文档：`references/recipes.md` 配方 14 / 14.1；坑点：`references/pitfalls.md` P20/P27~P32。
> 实战战绩：一次跑通 **25 集合 40 条索引**（24m35s，`ok=13 exists=27 fail=0`），随后三层独立核对全绿。

## 为什么是 GUI

免密钥路径已逐条证伪：SDK 无 `createIndex`、开发者工具 CLI 无 `invoke`、
网页控制台 302→`/cloudrun`、云调用无免 token 触发路径、**控制台窗口无 DevTools**（`Ctrl+Shift+I` 新增窗口 0 个）
⇒ 键鼠驱动控制台是**唯一**可行路径。

## 脚本

| 文件 | 用途 |
|---|---|
| `gen_tasks.py` | 从**单源 dump**（`[[集合, 索引名, keys, unique]]`）派生任务 JSON，**避免手抄**索引名/字段 |
| `do_indexes3.py` | **建库主力**：填表 → 提交；建前重读列表、同名即跳过；连续 2 次失败即中止 |
| `verify_indexes2.py` | **名称核对**：逐集合列出实读到的索引名，与期望做容错比对（独立于建库脚本） |
| `verify_fields.py` | **组成核对**：逐行绑定「索引名称 / 索引属性 / 索引字段」，核字段顺序 + 升/降序 + 唯一性 |
| `probe_attr.py` / `probe_attr2.py` | 一次性探针：确认某格 OCR 在哪些 crop/scale/预处理下能读出真值（P32 用） |

## 用法

```bash
# 0) 先让窗口就位：微信开发者工具 → 工具栏 ∞ → 云开发控制台（不是 ≡）
#    并把「数据库 → 集合管理」停在可见状态；脚本会自己搜集合、点「索引管理」页签

PY="C:/Users/lzj/.workbuddy/binaries/python/envs/default/Scripts/python.exe"

# 1) 派生任务清单（需要先 dump 出单源的索引定义：gen_tasks.py 里改 DUMP 常量）
"$PY" gen_tasks.py

# 2) 批量建（长跑必须后台！前台 120s 会被 SIGTERM）
"$PY" do_indexes3.py                    # 断点友好：已存在的会自动跳过

# 3) 两层独立核对
"$PY" verify_indexes2.py                # 名称
"$PY" verify_fields.py                  # 组成（可带集合名：verify_fields.py a,b,c）
```

## 硬约束（照抄会踩）

1. **坐标绑定当前版本控制台**（实测窗口 `rect=(60,0,1860,1034)`，截图 1:1 ⇒ 屏幕 = png + (60,0)）。换版本先重标。
2. 「唯一」判据是**像素级**（绿点 png x≈698 唯一 / ≈791 非唯一，分界 745），**不经 OCR**；绿簇取中心要用
   **x 众数 ±45 + 最小像素数门槛**（`min/max` 会被 2 个游离像素拉偏 83px ⇒ 连点 4 次全空、截图 md5 相同）。
3. 加行**恒点第 1 行**的 `⊕`（末行是 `⊗` 删行）；弹窗纵向有 3 类高度状态（+65 / +39 / 第 1 行=标签 y+4）。
4. 弹窗是**模态**：开工前后各关一次；粘贴前**先 `Ctrl+A` + `Delete`**。
5. **进程被杀 ≠ 动作没做成** ⇒ 收工后必须**回读现场**核对，不能拿退出码当结论。
6. OCR 存在**稳定系统性误读**（`sort`→`so戊`，12 种读法全错）⇒ 判据要显式白名单 + 放大图佐证（P32）。
