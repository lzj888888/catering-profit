# 能力搭配 Playbook —— 把原语串成「一次干完」的闭环

> 本技能真正的价值**不在单条命令，而在编排**。
> 截屏 / 键鼠 / OCR / 探针 / 锚点 / 哨兵 六类原语，按固定回路组合，就能像人一样
> **看 → 想 → 动 → 验**，而且每一步都**可取证、可回滚**。
> 单看 `recipes.md` 是"零件"，本文是"装配图"。

---

## 0. 统一前置（所有配方/脚本都从这三行起）

```python
import sys, time
sys.path.insert(0, r'C:/Users/lzj/.workbuddy/skills/win-desktop-control/scripts')
from win_gui import *
T = r'C:\Users\lzj\AppData\Local\Temp'      # 用 Windows %TEMP%，别用 Git Bash 的 /tmp
```

- **为什么要这三行**：
  - `from win_gui import *` —— 一行拿到**全套原语**，用**模块模式**而不是一条条 CLI。CLI 每次都要重新进程启动 + DPI 初始化，
    一个"会话"里发 8 条命令 = 8 次冷启；一段脚本 = **1 次初始化**。这是最直接的效率来源。
  - `T` 必须是 **Windows 真实路径** —— Git Bash 的 `/tmp` 是虚拟挂载，`PIL`/`subprocess` 之外的**桌面应用打不开**，截图/保存会莫名其妙失败。
- **配方范式 = 「统一前置 + 只改坐标/标题」**：`recipes.md` 里每条配方都是这个形状，
  意味着**学会一条就学会了全部**，复用时只需换 `title=` 和 `x,y`。这是"可搬运知识"的关键设计。

## 1. 标准闭环（七步，缺一步就会翻车）

| 步 | 目的 | 动作（模块函数） | 已知翻车点 |
|---|---|---|---|
| ① 找 | 拿到窗口句柄 | `find_window(title=…)`，拿不准先 `list` | 标题常不含项目名（硬教训 8） |
| ② 前置 | 抢焦点 | `focus(h)` | `SetForegroundWindow` 静默失败 → 内部已兜底 `AttachThreadInput` |
| ③ **留证(前)** | 操作前快照 | `screenshot_window(h, T+r'\step0.png')` | 安全护栏要求"每一步留证" |
| ④ 定位 | 算出可点的坐标 | OCR `find` / **锚点法** / `crop`+`zoom` 目视 | 颜色判据随主题失效（硬教训 13） |
| ⑤ **判活** | 别对着死窗乱点 | `probe_alive(h, x, y)` | probe 也会被骗（P25）→ 补"点完 UI 无变化"判据 |
| ⑥ 动 | 一次点完 | `click / key / type / paste_file` | 菜单必须**同一段脚本**点完（硬教训 7）；提权进程 → 交人（硬教训 6） |
| ⑦ **验+留证(后)** | 结果快照 | `screenshot_window(h, T+r'\step1.png')` | 读图确认，别假设成功 |

> **③④⑤ 是本技能区别于"自动点击器"的地方**：动手之前先把"坐标怎么来、窗口活没活"两件事解决掉，
> 而不是试错式连点 —— 连点会把**半死窗口**推成**真死**（硬教训 15）。

## 2. 能力搭配决策树（遇到什么 → 用哪个原语）

| 现象 | 用什么 | 出处 |
|---|---|---|
| 不知道窗口在不在 / 标题是什么 | `list` / `find --title` | SKILL 速查 |
| **模型读不了截图** | `ocr_screen.py read/shot`（转成文字 + 坐标） | 配方 11 |
| OCR 认不出彩色/浅色按钮上的字 | **锚点法**：OCR 两个已知按钮 → 等距推第三个 | 配方 12 |
| 主题深浅切换后颜色判据整体失效 | 锚点法（**别**用 `find_color_center` 硬判） | 硬教训 13 |
| 只要"看着对不对" | 截图 + 模型 Read 读图 | 配方 8 |
| 窗口疑似卡死 | `probe`（多帧 md5 + 悬停高亮），**别**信 `IsHungAppWindow` | 配方 4 |
| probe 说"活着"但点了没反应 | 判为**半死** → 状态栏进度文案 + 立刻停手交人 | P25 / 硬教训 15 |
| 菜单 / 右键菜单 | **必须同一段脚本**里点完（脚本一结束菜单就没了） | 硬教训 7 |
| 长中文进输入框 | 剪贴板 + `Ctrl+V`（`paste_file`），绝不逐字敲 | 配方 5 / 硬教训 1 |
| 一闪而过的 Toast / 提示框 | `ocr_screen.py watch` 连拍 + 逐帧 OCR | 配方 11 ⑤ |
| 原生"另存为"框 | `save_dialog_fill(全路径)` | 配方 3 |
| **要证明某个构建/忽略配置真生效** | **哨兵法**（造只可能被该规则挡住的探针） | 配方 13 / SKILL 方法学 |
| 目标是管理员权限进程 | **只能交人**（能截图 ≠ 能点击） | 硬教训 6 |

## 3. 与既有知识怎么嫁接（这套技能 × 本项目纪律 = 更省事）

本技能不只是一双手，它天然**长在既有方法学上**。把下面的"旧纪律"接进闭环，效率翻倍：

| 既有纪律（旧知识） | 嫁接点（新用法） | 收益 |
|---|---|---|
| **直接证据 > 推理**（review 只认实跑/实测） | ①②③⑤⑦ 天然产出截图与 probe 报告 | 结论可被独立复核，不用"我觉得点到了" |
| **留证入 `review/evidence/<主题>_<日期>/`** | 闭环③⑦ 的 `step0/step1.png` 直接归档 | 证据链自洽，复审方零成本复现 |
| **可回滚 + 复验**（改完必须复跑回基线） | 哨兵法"备份 → 还原 → 复跑"；`git diff` 为空 | 破坏性验证也不留副作用 |
| **差异/体积/计数先对齐口径再判** | `crop`+`zoom` 后目视读数；OCR 坐标换算回原图口径 | 避免"94 处假差异"式误判 |
| **探针先于盲点** | 动手前先 ⑤ `probe`，而不是试错连点 | 不把半死窗口推成真死 |
| **双提交 / 门禁 EXIT=0** | 技能侧同样 `git commit && git push`、打 tag | 云端有版本、可回溯 |

**一句话**：旧知识解决"**结论可不可信**"，本技能解决"**怎么拿到第一手现象**"；
两者接起来 —— **现象用本技能取、结论用旧纪律判** —— 就是本项目里"复审 + 驱动"分工能跑通的原因。

## 4. 效率速查（省时间的几个既定选择）

1. **一个"会话"写成一段脚本**，不要拆成多条 CLI（省 N 次冷启）；菜单/右键必须同段（硬教训 7）。
2. **起手 `selfcheck`** —— 安全软件（360/毒霸）曾让注入整体失效数天（硬教训 12），先自检再动手。
3. **要一张图最快**：`shot --screen --out`（配方 8），比 `find`+`focus`+`screenshot_window` 少两步。
4. **OCR 提识别率**：定点 `--crop` 小块 + `--scale 2~4`（配方 11 ④），比全屏硬 OCR 准得多。
5. **坐标怎么来的要写死在配方里**：能复用的坐标/偏移（如"预览按钮 = 真机调试 −108"）直接记进 `recipes.md`，下次零推导。
6. **不可逆动作前一定留证 + 停下**：上传/发送/提交订单属红线，截图给人确认（安全护栏）。

## 5. 何时**不该**用本技能
- 目标进程以管理员运行（硬教训 6）—— 交人。
- 敏感界面（密码/支付/网银）—— 停止注入，交人。
- 半死窗口（P25）—— 别硬怼，交人。
- 能用官方 CLI/API 完成的事（如 DevTools `cli.bat preview`）—— **先试 API，再退化为 GUI 驱动**；GUI 是最后手段，不是第一手段。
