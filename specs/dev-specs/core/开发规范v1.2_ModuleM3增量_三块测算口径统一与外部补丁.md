## 1 🔴 M3 三块测算统一口径卡（本文件核心）

> 这一章是"重梳理"的落点：**一张表讲清三块分别算什么、公式是什么、分母是谁、谁不许进分母**。
> 三块**共用同一个引擎**（`calcCostCard`），差别只在**入参怎么填**（v1.1 §2 的设计原则）。

### 1.1 一张总表

| 维度 | **① 单品**（含半成品） | **② 套餐** | **③ 外卖单均** |
|---|---|---|---|
| **计算对象** | 一份菜（模式 A）/ 一批预制（模式 B） | 一组子菜（引用型卡） | **一"单"**（多菜/套餐 + 包材） |
| **引擎入口** | `calcCostCard({mode:'A'\|'B'})` | **同一个** `calcCostCard({mode:'A'})` | **不进引擎**（渠道费用是纯算术层） |
| **成本** | `(Σ用量×净料单位成本 + 辅料) ÷ (1−损耗率)`；模式 B 再 `÷ 产出份数` | `Σ(子卡 unit_cost_fen × 份数)` 当原料行喂引擎（`net_unit_cost = 成本分×100`） | `Cf = Σ(卡 unit_cost_fen × 份数)`；`Cp = Σ(包材单价 × 数量)` |
| **收入** | 挂牌售价 / 活动特价（二选一展示） | 套餐售价 | 口径一 `P`（现金视角）/ 口径二（会计视角），**两套并列** |
| **毛利** | `售价 − unit_cost` | `套餐售价 − 套餐成本` | `R − Cf − Cp`，`R = P − s − 佣金 − d − 配送补贴` |
| **毛利率分母** | **售价**（零价行/赠品**不进分母**） | **套餐售价** | ⚠️ **不是毛利率** ⇒ 用**到手率 `R ÷ P`** |
| **反算售价** | `成本 ÷ (1 − 目标毛利率)` | 同左 | 挂牌价反算 `P* = (Cf+Cp+M+s+d−打包费收入) ÷ (1−c)` |
| **必显信息** | 成本 / 毛利 / 毛利率（+ 色阶） | ＋**顾客省多少** / **我少赚多少** / **成本结构** | ＋**到手率**（<70% 软提示）/ 佣金基数说明 |
| **落库** | ✅ 只 INSERT 不 UPDATE（版本链） | ✅ 同左（`card_type=3`） | ❌ **不落库**（仅平台参数存 `shop_switch`） |
| **实测锚点** | `9.75` / `4.48` / `12.35` / `24.38` | `1275` → 售 25 ⇒ 毛利 `1225` / 毛利率 `49%` | 佣金 `150` / 实收 `1800` / 利润 `365` / 到手率 `66.67%` |

### 1.2 三块的共同点（**这三条是三块能"只做一次"的根本**）

1. **同一个成本函数**：`（明细 + 辅料）÷ (1 − 损耗率)`。模式差异只体现为"要不要再 ÷ 产出份数"。
2. **同一个精度纪律**：中间量以「万分之一元」整数累积，**只在最后一步** round 到分（§2）。
3. **同一个反算公式**：`成本 ÷ (1 − 目标毛利率)`。**单品、套餐、外卖三处的反算都归约到它**。

### 1.3 三块的不同点（**必须分别讲清，不许合并**）

| 差异 | 说明 |
|---|---|
| **分母不同** | 单品 = 售价；套餐 = 套餐售价；**外卖 = `P`（且指标叫"到手率"，不叫毛利率）** |
| **是否落库** | 单品/套餐落库（版本链）；**外卖不落库** |
| **成本构成** | 外卖多一层"包材成本"，且**佣金由收入侧扣**（不进成本）|

### 1.4 🔴 三块的共同红线（违反任一即判错）

1. **佣金基数 = 商品总价**（不含打包费）。实测误用含打包费 ⇒ **差 12 分/单**。**该句必须出现在外卖页面的口径说明里**。
2. **打包费（收入）≠ 包材成本（成本）** —— **两条腿都走，不得相抵**。
3. **赠品 / 零价行**：成本进分子，**售价不进分母**（否则毛利率虚高，实测虚高 3.79pp）。
4. **参考值只进 placeholder / 灰字**（R128）—— 含出成率、损耗率、包材占比、半份折扣率。
5. **引擎 5 份副本一行不改** —— 规格/套餐用**入参变换**，外卖用**后置渠道层**。
6. **M3 试算值不得进 M1**（R135）。

## 2 金额尺度澄清（D19 · 此前措辞不清，本文件钉死）

仓库**同时存在两个金额尺度**，各有其位，**不得混用**：

| 尺度 | 单位 | 用在哪 | 证据 |
|---|---|---|---|
| **分（INT）** | 0.01 元 | **一切落库值**与**一切展示值**：`unit_cost_fen` / `gross_profit_fen` / `auxFen` / `priceFen` | `calcBom/service.js:113` `Math.round(rawTotalYuan * 100)` |
| **万分之一元（INT）** | 0.0001 元 | **唯一**用于 `net_unit_cost` 中间量（4 位小数精度） | `calcBom/service.js:47-50` `Math.round(yuan * 10000)` |

**唯一换算点**：`lineNetCostYuan(quantity, netUnitWan) = quantity × (netUnitWan / 10000)`（`calcBom/service.js:53`）。
⇒ 任何**新增**代码若需要"半成品成本当原料行用"（套餐正是如此），**必须**把"分"乘 100 转成"万分之一元"再喂引擎
（v1.1 M3.16 已如此规定：`net_unit_cost ← 子卡单份成本(分) × 100`）。

> **一句话**：**落库看分，中间看万分。** 二者只在 `lineNetCostYuan` 一处交汇。

## M3.30 原料档案补三字段（D20）

### 为什么（不是锦上添花，是补一处既有不自洽）

v1.0 **M3.7 #10** 承诺列表可"按分类、标签筛选"，但 **M3.2 的原料档案字段表里没有分类**（只有**菜品**有分类）。
⇒ 要么删掉该功能，要么补字段。**补字段**（5 条类目成本极低，且"原料按类目找"是采购/盘点的基础动作）。

### 字段（`shop_material` 新增 3 个，均可选）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `category` | VARCHAR | `''` | 枚举：`meat` 肉类 / `veg` 蔬菜 / `dry` 干货 / `season` 调料 / `pack` 包材 / `other` 其他 |
| `aliases` | VARCHAR | `'[]'` | JSON 数组字符串，如 `'["鲜味生抽","生抽"]'`。**仅用于检索** |
| `remark` | VARCHAR | `''` | 备注 |

### 🔴 三条硬约束

1. **`category` 是独立枚举，绝不与 M1 的 `ITEM_TAGS` 混用、不建映射**。
   两者视角不同：`category` = **采购/仓储视角**（这料是什么）；`ITEM_TAGS` = **利润归属视角**（这钱算哪一类成本）。
   合并会让"利润归属体系"被采购分类污染（R129 同族：**可见名当机器键 ⇒ 改名静默失效**）。
2. **`aliases` 只用于检索建议，绝不自动匹配替换**（M3.20 L325 既有纪律；"辣椒"被自动换成"干辣椒"= 成本**静默变错**）。
3. **不新增索引**。原料量级小（60~200 条/店），按 `shop_id`（既有 `idx_mat_shop`）拉回后**前端过滤**即可。

### 落地
- 前端：原料档案页（**该页当前尚不存在**，见 §9 批次 P0）＋ 搜索框支持"名称 or 别名"合并检索。
- 存量数据：**缺字段按 `''` / `'[]'` 兜底**（fail-soft），**不改写**存量行。

## M3.31 「每100g」计价规格（D21）

### 为什么

v1.1 M3.15 的规格族是"**份**"（大小份/半份/例份）。而**麻辣烫、卤味、凉菜按重量卖**，单位是"100g"。
现有 `coef` 机制（按 `line_kind` 缩放用量）**无法表达**"计价单位不是份"。

### 落法（零引擎改动）

并入 v1.1 M3.15 的 `specs_json`：

```json
[ { "spec_key": "per100g", "name": "每100g",
    "coef": { "main": 1, "aux": 1, "season": 1, "semi": 1, "pack": 1 },
    "price_fen": 680, "unit_label": "100g" } ]
```

- `coef` **全 1** ⇒ 成本 = 该卡的标准成本（**恒等性由构造成立**，与 v1.1 A-d 锚点同源）。
- 差异**只在展示层**：页面显示"¥6.80 / 100g"，并给一句"按 100g 计价，实际按称重结算"。
- 🔴 **不得**为它引入第三种核算模式（现有模式 A/B 已是两种，再加 = 第二份真相源）。

### 复用锚点
复用 v1.1 **A-d 恒等锚点**（系数全 1 ⇒ `unit_cost_fen` 仍 975、`material_total_fen` 仍 876），**不新增锚点**。

## M3.32 外卖补丁：补贴拆行 + 固定佣金（D22）

### 一、补贴拆两行（吸收外部"用户券补贴"）

v1.1 M3.17 的 ② 项只有 `s`（商家活动补贴）。**平台账单里"用户券"与"商家满减"是分列的**，拆开才能对账。

| 字段 | 含义 | 谁承担 |
|---|---|---|
| `s_user` | 用户券（平台券 / 新人券 / 平台红包） | **待定**（§8 K1）|
| `s_merchant` | 商家满减 / 商家券 | **商家**（确定）|

🔴 **承担方未选的项 ⇒ 该行不计入任何计算**（fail-closed）。理由：承担方不同 ⇒ 它**是不是成本**结论相反。
若两者承担方都是商家，则算术上等价于原来的单 `s`；**拆分的意义在归因与对账，不在改数**。

### 二、佣金 `commission_mode`

| 模式 | 取值 | 说明 |
|---|---|---|
| `rate`（默认）| `commission_rate`（%，0~100）+ 可选 `commission_min_fen`（保底） | 现 v1.1 行为不变 |
| `fixed` | `commission_fixed_fen` | **直接取金额**；🔴 **fixed 模式下保底 min 不生效**（避免两条规则打架） |

🔴 **两种模式下 `commission_base` 恒为「商品总价」不变**（铁律不动）。

### 三、额外包材"直接录一笔"

`Cp` 允许一条**临时包材行**（无 `material_id`，当场填金额）。
🔴 红线 7 不动：**打包费（收入）与包材成本（成本）两条腿都走、不得相抵**。

## M3.33 菜品毛利复盘：Excel 导入销量（D23 · 重设计）

> **本节只定"能力与口径"，不定存储**（存储落法待 §8 K3）。

### 为什么值得做（这才是外部真正的贡献）

v1.1 M3.21 已查证：**M1 没有菜品级销量** ⇒ 主动降级为"率对率"（诚实，但少了一个付费理由）。
外部点破：**销量的来源不必是 M1**，可以是**用户自己导出的销售表**。
⇒ 复盘从"做不了"变成"能做"，且**不用等 M1 改口径**。

### 与 M3.21 的分工（**两者并存，不互替**）

| 能力 | 输入 | 输出 | 定位 |
|---|---|---|---|
| **M3.21 率对率对账**（v1.1 已有）| M1 月度整笔（**无销量**）| 差值(pp) + 折算金额，覆盖率 <60% 抑制 | 月度体检（**粗**）|
| **M3.33 复盘**（本节新增）| **导入销售明细**（有销量）| 单品毛利排行榜 + 毛利率标红 | 单品体检（**细**）|

### 口径

```
单品总物料成本 = 销售份数 × 该卡 unit_cost_fen（锁定的标准成本）
单品毛利       = 单品营收 − 单品总物料成本
单品毛利率     = 单品毛利 ÷ 单品营收
```

### 🔴 五条硬约束

1. **销量支持两个来源**：堂食收银导出 + **外卖平台导出**（两个来源分开呈现）。
   理由：外卖销量**不在收银里**，只导收银会**系统性漏掉外卖那一半** —— 而外卖恰是佣金吃掉毛利最多的地方。
2. **菜品名映射必须显式确认**：导入名 ↔ 成本卡名的映射**保存复用**，🔴 **未确认的行不许静默归零**（round116「静默 0 行」同族病）⇒ 未匹配行**单列**并提示。
3. **不回写**：复盘结果**不回写 M3 成本卡**、**不自动写入 M1**（沿用红线 6）。
4. **毛利率阈值由用户自定义**（默认值**仅作占位**，来源单一 ⇒ 不做成"警戒线"，R128 同族）。
5. **成本用"卡内锁定值"**，不是"原料现价" ⇒ 与快照语义一致（若卡用了旧价，页面**须提示"该卡成本为 X 月快照"**）。

### 落库（**待裁决，本文件不擅定**）
见 §8 **K3**：候选方案 = ①仅加 1 张 `shop_dish_review`（明细存 JSON）②完全用 `shop_switch` + 导出文件（零新建集合）。
