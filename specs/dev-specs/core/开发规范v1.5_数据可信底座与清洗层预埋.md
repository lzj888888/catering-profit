## 3 `external_raw_staging`（清洗前脏数据落点 · TR-D1）

> **动机**：清洗规则会变。**只存清洗后的结果 ⇒ 规则一改，历史数据无法重洗**，
> 而"重新对一次账"恰恰是这个产品最核心的信任来源。

| 字段 | 类型 | 说明 |
|---|---|---|
| `_id` | string | 批次内唯一 |
| `shop_id` | string | 门店 |
| `batch_id` | string | 导入批次（同一次导入同一值） |
| `platform` | string | 平台（美团 / 饿了么 / 淘宝闪购） |
| `period_start` / `period_end` | string | 账单期间（YYYY-MM-DD） |
| `raw_columns` | object | **原始列名 → 原始值**，一字不加工 |
| `sign_convention` | string | 🔴 **符号约定显式记录**（平台补贴是负号还是正号），不靠代码猜 |
| `row_key` | string | 🔴 **明细行唯一键** = `结算id + 订单号 + 交易类型 + 交易描述`（**不能用订单号**：同一订单号会重复出现在外卖/广告/保险行） |
| `source_file` | string | 来源文件名（⚠️ **文件名不可信** —— 名为"微信支付账单"的实测是美团账单；**判平台按列不按名**） |
| `created_at` | number | Unix ms |

**辅助索引**：`(shop_id, batch_id)`、`(shop_id, platform, period_start)`

⛔ **纪律**：本表**只增不改**；清洗结果写入业务表，**本表永不回填**。

## 4 可信底座（TR-D2 / D6 / D7）

### 4.1 成本卡版本快照 `hash`

**锁三条，不锁算法**：

1. **输入集合固定**：参与哈希的字段 = 当前快照 5 字段 + 成本行全集 + `card_code` + 版本序号，**逐字段列名写死在实现里**。
2. **输出长度固定**：同一算法下恒定长度；字段顺序**按列名排序**后再算（防顺序漂移导致同一内容两个哈希）。
3. **可复算**：任一历史版本都能用同一函数重算并比对 —— 这是唯一验收判据。

> ⚠️ 加 `hash` 字段时，`tools/check_snapshot_fields.js` 的**读侧字段全集**必须同步（该守卫管"两处读侧字段集合 ≡"，
> 只加一处会当场转红）。

### 4.2 `audit_log`（变更留痕）

| 字段 | 类型 | 说明 |
|---|---|---|
| `shop_id` | string | 门店 |
| `object_type` | string | 业务对象（如 `cost_card` / `material` / `mapping`） |
| `object_id` | string | 对象标识 |
| `field` | string | 被改字段名 |
| `from` / `to` | string | 改前 / 改后（**字符串化**，不存复杂结构） |
| `actor` | string | 操作者 |
| `reason` | string | 原因（可空） |
| `created_at` | number | Unix ms |

⛔ **不记**金额推理过程、不记中间量、不记 AI 输出。

## 5 `facts` / `sourceId` 固定结构（TR-D3）

> **为什么现在就锁**：接口随时能补，**结构一改所有下游解读全部重写**。这是"过期不候"里仅次于原始数据的一件。

```jsonc
{
  "schema": "facts/v1",
  "shop_id": "…",
  "period": "YYYY-MM",
  "generated_at": 1234567890123,
  "metrics": [
    {
      "key": "takeaway_net_income",   // 指标键（术语单源 i18n/terms.js 的对端，不是文案）
      "value": 377965,                // 🔴 单位=分（整数），永不用浮点表示金额
      "unit": "fen",
      "sourceId": "src_0001",         // 指向 sources[] 的下标引用
      "basis": "accrual"              // 权责发生制（E1）；另一取值 cash = 收付实现制
    }
  ],
  "sources": [
    {
      "id": "src_0001",
      "type": "bill_row" | "manual" | "oauth",
      "platform": "meituan" | "eleme" | "taobao" | null,
      "ref": "…"                      // 行键 / 批次号 / 外部流水号
    }
  ]
}
```

**四条硬约束**：

1. 🔴 **金额一律整数分**（`unit: "fen"`），禁止浮点。
2. 🔴 **`sourceId` 必须能在 `sources[]` 里解析出对象**；解析不出 ⇒ **丢弃该条 metric**（不猜、不补）。
3. 🔴 **禁止构造新指标**：`metrics[].key` 必须是引擎已产出的指标，**缺字段直接丢弃该条**。
4. **换 LLM 不改此结构** —— 结构变 = `schema` 版本号变，视为新契约。

## 6 清洗层校验项（TR-D4 / D5）

### 6.1 跨期错位

账单**账期 3 天** ⇒ 月末订单可能落到次月账单。**归月一律按账单日期**，且须校验：
账单期间与所归月份不一致的行**标记**而非静默丢弃（提示老板"这几笔属跨期"）。

### 6.2 套餐子单品数量 vs 套餐销量一致性

套餐销量 × 子单品配比 ⇒ 应等于子单品总用量。不等 ⇒ 告警（常见于退款、改单、赠品）。

### 6.3 老历史数据空值兼容（🔴 豆包点名风险）

**强制用例**：对存量记录（补贴字段为空 / 缺字段）：

- **不得**自动生成额外的补贴行或费用行；
- **不得**因缺字段而报错中断；
- 缺省行为**显式写在代码里**（给缺省值 + 注释），不是靠 `undefined` 自然传播。

> 判据：投喂写码时，此项必须落成**独立门禁用例**（留空 ⇒ 零新增行）。
