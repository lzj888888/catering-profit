## 二 统一设计原则：**一次入参变换，引擎零改动**

反推不是新算法 —— 它是**同一个保本/目标营收方程的换一种读法**：

```
正算：固定成本 F 已知        → 求 保本 / 目标营业额
反推：R 是未知量，但「房租 = R × 目标租金率」把房租变成了「随营业额变动的项」
      ⇒ 把「目标租金率」当成一项**挂钩费率**（与外卖佣金同性质）喂进 var_items
      ⇒ 房租自动从固定成本里消失，方程与正算**逐字节同形**
```

⇒ 实现 = `fixed_items` **剔除 `rent`** ＋ `var_items` **追加** `{key:'rentRate', pct:目标租金率}`，
   再调用**既有** `calcSandbox`，取 `target_monthly_fen`（= R）。

**恒等性由构造成立**（既有正算路径一行未改）⇒ 不需要副本同步、不需要 md5 守卫、锚点零漂风险。

> 🔴 **本条的纪律含义**：新增能力**优先穷举「入参变换」**；只有变换表达不了时才考虑改引擎，
>   且改引擎必须先出增量规范 + 旧锚点回归。

## 三 反推分支（**第一期**实现）

### 3.1 模式与入参

`calcSandbox` 新增入参 `mode`：`'forward'`（默认，**缺省即正算 ⇒ 向后兼容**）/ `'reverse'`。

`mode='reverse'` 时**追加**下列入参（正算路径**不读**它们）：

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| `rev_price_fen` | int 分 | **> 0** | 客单价 |
| `seats` | int | **> 0** | 座位数 |
| `open_days` | int | **∈ [1,31]** | 每月营业天数 |
| `target_rent_rate` | number % | **∈ (0,100]** | 目标租金率（= 房租 ÷ 营收） |
| `pixel_eff_fen` | int 分 | ≥ 0，**选填** | 坪效（元/㎡·月）；0 / 缺省 ⇒ **不算**面积上限（**不编造**） |

🔴 **硬约束（fail-closed，校验层拦截）**：`mode='reverse'` 时 `fixed_items` **不得含 `key='rent'`**。
违反 ⇒ `INVALID_PARAM`，错误信息明示「反推模式下房租由目标租金率导出，请勿在固定支出中重复填写房租」。

### 3.2 计算公式（口径 Y）

```
F_ex_rent     = Σ fixed_items.fen（**不含 rent**）+ 月摊销
v_total       = (100 − 菜品毛利率) + Σ var_items.pct + 目标租金率
边际贡献率     = 1 − v_total ÷ 100                              ← ≤ 0 ⇒ 红警，不计算 R
R（目标月营收）= (F_ex_rent + 目标月利润) ÷ 边际贡献率
```

派生量（**在 R 之上算；中间高精度，只输出时取整**）：

```
目标日均营收 = R ÷ open_days                                  → 取整到分
房租上限     = R × 目标租金率 ÷ 100                           → 取整到分
月客流       = R ÷ 客单价                                      → 保留 2 位小数
日均客流     = 月客流 ÷ open_days                              → 保留 2 位小数
翻台         = 月客流 ÷ (座位数 × open_days)                    → 保留 2 位小数
面积上限     = 房租上限 ÷ 坪效                                  → 保留 1 位小数；坪效 ≤ 0 ⇒ null
```

🔴 **取整方向（钉死，消除豆包算例末位 0.01 的歧义）**：**先算后取整** —— 派生量一律用**未取整的中间值**
参与后续运算，**只在输出时**按各自位数取整；金额类取整到**分**，比率 / 人数 / 台数保留**小数**，
**不进位成整数**（"74.07 人"截成 74 会掩盖边界）。

### 3.3 输出

`mode='reverse'` 时返回体**在正算出参基础上**追加 `reverse` 块（正算出参语义**不变**，但其中
`fixed_total_fen` 等已按"剔除房租"口径计算，UI 须明示）：

```json
"reverse": {
  "mode": "reverse",
  "target_monthly_fen": 10000000,
  "target_daily_fen": 333333,
  "rent_cap_fen": 1200000,
  "monthly_traffic": 2222.22,
  "daily_traffic": 74.07,
  "turn_rate": 3.7,
  "area_cap_sqm": 300,
  "rent_rate_pct": 12,
  "rev_price_fen": 4500,
  "seats": 20,
  "open_days": 30,
  "red_alert": false,
  "warn_keys": []
}
```

### 3.4 前端（`pages/sandbox`）

- 顶部**双 Tab**：「正向测算」/「目标反推」；**两套输入区状态独立缓存、切换互不覆盖**。
- 反推 Tab 输入框：客单价 / 座位数 / 每月营业天数 / 目标租金率 / 坪效（选填）
  ＋ 复用 固定支出（**无房租行**）/ 变动费率 / 毛利率 / 目标月利润。
- 🔴 **`fixed_items` 的房租行在反推 Tab 下必须隐藏**（**不是置灰** —— 隐藏才不会被误填）；
  并强提示一行：「反推模式下房租由目标租金率自动导出，无需另填」。
- 🔴 **前端仍不做任何公式**（§M2.7 铁律不变）：Tab 切换只是**换一套入参**再调云函数，数字全由云端返回。
- 🔴 **新增 `<input>` ⇒ 必须同步登记 `tools/check_m2_ref_not_prefill.js::OK_VALUE` 白名单**
  （该守卫枚举**所有** `<input>` 的 `value` 绑定，**未登记即判红**）。

### 3.5 边界与提示

- `边际贡献率 ≤ 0` ⇒ `red_alert=true`，**所有反推派生量返回 `null`**（不编造；同正算纪律）。
- `客单价 = 0` / `座位数 = 0` / `open_days ∉ [1,31]` / `目标租金率 ∉ (0,100]` ⇒ 校验层**直接拒**
  （这是**入参非法**，不是红警）。
- **软提示（不拦截）**：`翻台 > 8` ⇒ `warn_keys` 含 `turnOverHigh`（前端渲染「翻台偏高，请复核座位数或营业天数」）。
  > 🔴 **自定值声明**：阈值 **8** 为我方自定（无权威源），**不参与任何计算**，仅决定是否显示提示句；
  > 误设**不会算错钱**。回退 = 改一个常量。

### 4.1 Schema 变更（相对锁定版 §Schema）

| 字段 | 类型 | 说明 |
|---|---|---|
| `sandbox_id` | STRING | **逻辑沙盘 ID**（同一沙盘的多个版本共享）🆕 |
| `version` | INT | 版本号，从 1 递增 🆕 |

🔴 **版本化只增（对齐本仓成本卡先例）**：

- **每次保存 = 新建一条**（**不 UPDATE**）；同 `sandbox_id` 的**旧版本软删除**（`is_deleted=true` + `delete_at`）。
- 🔴 **`sandbox_id` 是必需的「分组键」**：缺了它，同一沙盘存 5 次 = 5 条**看起来无关**的记录
  ⇒ 列表页显示成 5 个沙盘。（这正是外部建议漏掉的那一条，属本仓既有经验：成本卡表用「业务键 + 版本」解决。）
- `version` = 同 `sandbox_id` 内 `max(version) + 1`。
- 列表查询**必须有显式上限**（单源 `common/dataAdapter.js::LIST_LIMIT`）。

### 4.2 `param_json` 形状（单源 = 云函数出参 `clean`）

```json
{
  "mode": "forward|reverse",
  "city_tier": "...", "biz_type": "...",
  "build_items": [], "fixed_items": [], "var_items": [],
  "gross_margin_pct": 65, "target_profit_fen": 1500000, "expected_revenue_fen": 0,
  "rev_price_fen": 4500, "seats": 20, "open_days": 30,

```

🔴 **权威源**：加载沙盘时**一律**用 `param_json` 调 `calcSandbox` **实时重算**；
`result_snapshot_json` 只用于列表 / 对比卡片的**快速渲染**，**绝不参与计算**。

## 五 结果快照口径（钉死）

| 项 | 定案 | 理由 |
|---|---|---|
| 快照写库时机 | **仅**用户点【保存沙盘】那一刻 | 不自动实时写、不边输入边写 |
| 快照内容 | `calcSandbox` **完整出参**（含 `indicators_*` 与 `reverse`） | 列表 / 对比需一次性渲染 |
| `engine_version` | 随快照**同写** | 引擎升级 ⇒ 快照可被判废 |
| 版本不匹配 | 加载时比对；不一致 ⇒ 用 `param_json` **重算并覆盖旧快照** + 提示「引擎已更新，已重新推演」 | 自动失效，无需人工维护失效标记 |
| 前端草稿 | **不进库** | 库内快照与库内 `param_json` 永远一一绑定（不出现"快照无源"） |

`engine_version` 单源 = `cloudfunctions/common/indicatorRef.js::ENGINE_VERSION`（**新增常量**，随引擎口径变更递增）。
