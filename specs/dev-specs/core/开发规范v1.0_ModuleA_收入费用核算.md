## A.0 记账总铁律（贯穿全模块，写码必须遵守）

1. **权责发生制**：收入按业务发生日确认（外卖=订单日 / 团购=核销日），现金看到账日，二者可跨月。
2. **毛利铁律**：毛利 = 收入 − 营业成本（**仅扣食材耗材**）；净利 = 毛利 − 运营费 − 人工 − 营销 − 其他。**房租 / 人工绝不算进营业成本**。
3. **记账口径**：默认版本 B 实操版（费用合并），连锁可切版本 A 财务版。
4. **精度**：金额统一 Decimal，禁 JS Number 原生运算。
5. **归档**：`is_archive=true` 后禁 update 主记录金额，错账只新增调整记录。
6. **待结算不进利润**：外卖 / 团购待结算是**现金流 / 应收指标**，仅影响现金口径（A.4），**绝不进入月度盈利（毛利 / 净利）计算**。月度盈利只看权责发生制的收入与费用。

## A.2 费用结构（营销推广费含外卖/团购分列专项）

版本 B 实操版顶层：营业成本 / 门店运营费 / 人工 / 营销推广 / 其他支出（合并展示）。

**营销推广费下分项（名称与平台账单一致，团购佣金与外卖佣金必须分列）：**

| 费用项 | 说明 | 参考费率 / 来源 |
|---|---|---|
| 团购平台佣金 | 美团到店 / 抖音团购扣点 | 美团到店 **5%~10%**；抖音 **2.5% 技术服务费 + 0.6% 支付费**（综合~3.1%）；达人佣金商家自设 **5%~25%**（可选） |
| 外卖平台佣金（技术服务费） | 平台抽点 | 外卖综合 15%~25% |
| 外卖配送服务费 | 平台抽的配送费 | 账单"配送服务费" |
| 外卖活动补贴（商家承担） | 满减/红包商家出 | 账单"商家活动补贴" |
| 外卖配送补贴（商家承担） | 距离/夜间加价商家补 | 账单"商家配送补贴" |
| 外卖推广费（点金/竞价） | 展位/竞价 | 账单"推广费" |
| 线上广告推广 | 抖音/美团到店投流 | — |
| 宣传物料印刷 | — | — |
| 其他营销费 | — | — |
| *汇总行（可选）* | 平台佣金合计 = 团购佣金 + 外卖佣金 | 明细仍分列填 |

> **刷卡 / 扫码手续费**：MVP **不单列**（0.38%~0.6% 金额小、多数收银系统已扣净额到账）；归"其他运营费 / 支付手续费"预留项，精细版 v1.1 可展开。
>
> ⚠️ **可退款项不计入费用（口径闸门，2026-09-12 补）**：**押金 / 保证金 / 定金**属**可退款项**（到期/解约应返还），**不计入营业成本、也不计入月度运营费 / 其他支出**——它们没有"消耗"，计入会**虚增当月费用、拉低当月利润**（退款那月再反向虚增一次）。若需登记，作**一次性投入或资产单列**（如"其他应收 / 资产"），**不进月度损益**。⚠️ 费用项支持**老板自定义增删**（见 `01_架构总览` D2）——这类可退款项即便被自定义费用项收录，**口径上仍须排除**。

## A.3 台账与平台对账（MVP 极简：老板只填 1 个到账数；待结算系统粗估仅供参考）

### 核心原则：MVP 不为中小老板做精确流水账
- 目标用户是**中小餐饮老板**，最关心**本月利润（必须准）**，现金流大致准即可，待结算只是参考。
- 原"外卖 / 团购待结算四字段台账（期初 / 新增应收 / 回款 / 期末）"对目标用户属**过度设计**，MVP **整体删除**。
- 精确四字段台账 + 按平台分列（外卖 / 团购）+ 导入结算明细自动匹配 → 移到 **v1.1 高级开关"精确平台对账"**（面向连锁 / 有财务的老板）。
- > **范围变更说明**：此前 14:03 确认的"D-团购待结算分列"是针对四字段台账的；台账删除后，分列降为 v1.1 高级开关选项，MVP 不区分外卖 / 团购到账。

### MVP 字段（老板手动，仅 1 个平台相关字段）
- **本月平台实际到账合计**（外卖 + 团购合并，1 个数）：老板看银行流水或平台"已结算"汇总，填总数即可。
  - 不拆外卖 / 团购、不填期初 / 期末、不做任何流水账。

### 系统自动估算（仅供参考，不参与利润）
- 🔒 **平台待结算估算** = 本月平台收入合计 − 本月平台实际到账合计
  - ⚠️ **粗估值**：含跨月差异（上月单本月到账、本月单下月到账）及平台已扣费用，仅作"平台大概还欠我多少"的参考，**不做精确对账、不进利润计算**。

### 挂账台账（唯一需手动的账，事件式轻录入，保留）
- 挂账无平台数据，必须手动，但做成**事件触发**而非月度流水：
  - 顾客挂账消费时 → 录一条"挂账增加"记录（金额 + 对象 + 日期）。
  - 顾客还款时 → 标记"已收回"（金额 + 日期）。
- 系统字段（同结构）：挂账期初（= 上月期末滚转）/ 本期新增 / 本期收回 / 🔒 期末。
- 首月种子值：期初挂账余额（用户读一次或默认 0）。

## A.4 现金口径公式（收付实现制）

```
当月现金流入 = 堂食现金微信刷卡 + 私域外卖实收 + 当月储值充值
              + 当月收回往期挂账 + 平台实际到账合计（外卖+团购，MVP 填1个总数）
当月现金流出 = 当月食材实际采购付款 + 所有费用实际现金支付 + 储值退款 + 缴纳税款
当月现金结余 = 流入 − 流出
```
> 注：平台现金流入用 MVP 的"**平台实际到账合计**"（老板看银行流水填的 1 个数），不是本月平台收入（账期 T+3 / T+1 导致跨月）。v1.1 精确版可拆外卖 / 团购到账。

## A.5 核销时点铁律（团购，新增）

- 收入按**核销日**确认（非买券日、非到账日）。
- 顾客上月买券、本月核销 → 收入算本月；本月买券、下月核销 → 收入算下月。
- 平台打款日只影响现金流，不影响收入确认。

---

## A.6 总额法（外卖）vs 净额法（团购）说明（非矛盾）

- **外卖**：账单显式拆出"商家活动补贴" → 总额法（补贴计入收入，同时作费用）。
- **团购**：账单只给净成交价（原价168是划线参考价、无交易意义） → 净额法（商家自促费只作费用）。
- **结论**：两套平台账单结构不同导致两套准则，**会计上均正确，非冲突**。按平台账单实际能取到的数填即可。

## A.7 录入方式（MVP 手动基线，导入为 v1.1 便利）

- **MVP 基线 = 手动填**（更诚实、更好建）：
  - 老板每月导一次平台账单 → 照着填**收入 + 费用**（算利润，必须准）。
  - 看银行流水 → 填**平台实际到账合计**（算现金流，1 个数）。
  - 不做 Excel 解析、不接 API，2 分钟填完，符合小老板习惯。
- **v1.1 便利 = 导入平台账单自动填**：
  - 上传美团 / 饿了么 / 抖音月度账单 Excel → 系统自动解析归类（收入 / 各费用 / 结算金额），自动填入上述相同字段。
  - 平台 API 自动同步（美团 `connectivity-adapter` / 饿了么 `alibaba.wdk.eleme.bill.get`）需商家授权 + 审核，对接成本高，放 v1.1+，MVP 不做。
- **方式 B 净额兜底**：用户只肯填结算金额 → 收入按净额、费用字段隐藏，页面提示"毛利率偏低、看不到费用明细"。整店锁定一种口径，切换提示"月度对比会失真"。
