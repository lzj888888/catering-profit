# 开发规范 v1.1 · ModuleM1 增量 —— 常规科目预置与上月一键复制

> 时点：2026-10-02（round189）· 分支 `dev`
> **与本轮问题的关系**：李老师提出「房租 / 水费 / 电费 / 燃气费这些**每月都有、金额占比大**的项，**首月必须手动加**」。
> 本增量把这件事从"老板自己找细项加"改成"系统铺好行、老板只填数"，并补上每月复制。
> 关联：`开发规范v1.0_ModuleM1_月度盈利核算.md`（锁定版，**一字不动**）。

## 〇 一句话设计原则

**`getLedger` 本来就支持任意 `month` ⇒「上月复制」是一次纯前端的入参变换，云端与引擎零改动。**
（对应增量规范铁律 3：先穷举入参变换，再考虑改引擎 —— 引擎不动 ⇒ 无副本同步、无契约变更、锚点零漂风险。）

## 一 定案表（代拍板项，每条可回退）

| # | 决策 | 理由 | 代价 | 回退方法 |
|---|---|---|---|---|
| D1 | 常规科目只做**费用侧**（房租/水/电/燃气 + 工资绩效），收入侧不铺 | 用户点名的是费用项；收入侧每月波动大、且堂食有「快速/分项」双模式，铺行易串味 | 收入侧仍需手动加 | 往 `recurringFixed/Variable` 里加收入项名即可（无需改逻辑） |
| D2 | 常规科目**只铺行、金额一律留空** | 与 M2「参考金额只作 placeholder、不自动填值」同一条纪律：**系统绝不替老板编数** | 首月仍需敲数 | 改 `ensureRecurring()` 里的 `amountYuan: ''` |
| D3 | 分「固定项 / 波动项」两类，复制后区别标记 | 房租月月不变 ⇒ 沿用即可；水/电/燃气会变 ⇒ 必须提醒核对，防"复制完忘了改" | 多一个分类配置 | 改 `TERMS.ledger.recurringFixed / recurringVariable` |
| D4 | 复制**只带 income/expense 细项** | 库存期初已有 round103 自动结转（重复带入会打架）；摊销/一次性投入跨月复制 = 重复算钱 | 资产 / 摊销仍需在各自分页单独录入 | 在 `copyPrev()` 里加字段复制（**不推荐**） |
| D5 | 本月已填过时**二次确认**才覆盖 | 防误触覆盖已填内容 | 多一次弹窗 | 删掉 `copyPrev()` 里的 `hasAnyFilled()` 分支 |
| D6 | 「复制上月」按钮仅在**上月有账**时出现；没有 ⇒ 显示引导语 | 首月没有上月，给按钮点了也没用 | —— | —— |
| D7 | 首月铺行条件 = 「上月无账 **且** 本月未填」 | 有上月就走复制，不重复铺行 | —— | 改 `ensureRecurring()` 首行判断 |

**自定值声明（不参与任何计算）**：`recurringFixed = ['房租','物业费','宽带网费','工资绩效']`、
`recurringVariable = ['水费','电费','燃气费']` 为**自定值**，来自"餐饮门店每月必有且占比大"的常识判断，
**不参与任何金额计算**，误设只影响"铺哪些空行"，**不会算错钱**。

## 三 能力定义

### 3.1 常规科目预置（首月）

- 触发：进入录入页，装配完成后若 **上月无账 且 本月未填任何金额** ⇒ 铺行。
- 行为：对费用各大类，把 `g.items` 中命中常规科目名单的项**直接铺成行**（`amountYuan: ''`、`recurring: true`），
  并把该大类置为 `expanded: true`（铺了就得让人看见，否则等于没铺）。
- 顶部给一句说明（`recurringHint`）："这几项每月都有，已经帮你列好了，金额自己填"。

### 3.2 上月一键复制

- 触发：`prevHasData === true` 时显示「复制上月」按钮。
- 行为：`api.call('getLedger', { month: prevMonth })` → `rebuildFromItems()` 重建两组 → `markRecurringTags()` 打标 → 覆盖当前行。
- 顶部横幅：`已带出 <月> 共 N 项，其中 M 项要核对`（**js 预计算**，wxml 不做法调用）。
- 行标记：固定项显示「沿用」，波动项显示「要核对」（只读派生字段 `tag`，**不入库**）。
- 二次确认：本月已填 ⇒ `wx.showModal`（按钮文案 ≤4 字符）。

### 3.3 明确的「不做」

- ❌ 不复制库存期初 / 摊销 / 一次性投入（D4）
- ❌ 不自动填任何金额（D2）
- ❌ 不做「固定支出档案」（房租等做成合同档案、每月自动带入）—— 会引入"档案改了历史月怎么算"的版本问题
  （正是成本卡踩过的坑），留待一期后议
- ❌ 不做缺项提醒（保存前检查房租/水电是否漏填）—— ~~**本轮未做**~~ → **round217 已补做**
  （见 `开发规范v1.2_ModuleM1增量_费用口径可见性与缺项软提示.md`）；本条只记录 round189 当时的范围
