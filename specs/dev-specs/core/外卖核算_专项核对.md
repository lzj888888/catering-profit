### 4.2 本轮的相反证据（**L3 · 淘宝闪购账单 Excel**）

- E2 恒等成立：**`结算金额 = 商品金额 O + 打包费 P + 平台服务费 Q + 补贴`**
- ⇒ 在淘宝闪购账单里，商品金额 **O 不含**打包费，**P 是独立列且是加项**
- 打包费合计 **167.00**，若当减项处理会逐行差 2.00、汇总差 167.00（脚本初版正是这么错的）

### 4.3 当时判定（**留档，勿据此行动**）

两者**可能都对**，因为：

1. **平台不同** —— round99 的 A/B/**美团**/C 与淘宝闪购是不同平台，口径本就可能不同；
2. **层级不同** —— 订单详情页那一栏 vs 账单 Excel 的「商品金额」列，**可能压根不是同一个东西**；
3. round99 自述平台 A / C **确切名称未自证**（图上无平台字样，按界面特征命名）。

**⇒ 不得一刀切。** 当前状态：**按平台分别登记，不得写死。**

### 4.4 若美团确属"含"，风险是什么

我方收入口径 = `商品总价 + 打包费 + 商家承担补贴`。
若美团账单给的「商品总价」**已含打包费**，客户再单独填一个打包费 ⇒ **打包费算两遍，收入虚高**。

- 本店测度：打包费占比很小（2.55%），但**方向错误、会累积**；
- 该风险**正是** A.11.4(c) 专项检测（差额恰等于打包费）所覆盖的场景 ⇒ 现有防线仍在，**不得删**。

## 5 抄数陷阱（三条，每条都会**静默算错钱**）

### 陷阱 1 · 概览页「活动补贴」≠ 账单「商家活动成本」
- 概览页 384 = **总补贴**（含平台承担）
- 账单「商家活动成本」= **198**（仅商家承担）
- 差 186 ⇒ **抄错页面就错，且不报错**

### 陷阱 2 · 商家承担补贴在账单里是**三列**
```
商家活动补贴 −791.68 + 商家代金券补贴 −831.02 + 商家配送费活动补贴 −447.00 = −2069.70
```
只抄「商家活动补贴」一列 ⇒ **少扣 1278.02 元，利润虚高**（本店占优惠前 19.4%）

### 陷阱 3 · 平台承担补贴**不要填**
- 平台承担 744.09 **不进商家到手**
- 填进来 ⇒ 多扣 ⇒ 利润虚低（与陷阱 2 反向）

> 界面侧防线：字段显示名「**商家承担全部补贴（合计）**」+ 框下口径小字 + 专段顶部防双记句（R161-2/-3 已落）

## 9 口径已代码化（**R181l，2026-10-01 —— 别再只靠人工脚本手算**）

§3 的人工勾稽路径**降级为「取证工具」**；生产侧口径现在是**代码单源**：

| 单源 | 位置 | 作用 |
|---|---|---|
| **解析** | `utils/billParse.js`（**零 `require`** 纯函数） | `detectPlatform` / `guessHeader` / `parseBillMatrix` / `toNum`；入参=工作表矩阵 |
| **门禁** | `utils/gradeGate.js` | 甲级三门（通道连通 + Schema + 关键指标非空）**fail-closed**，不过直接阻断 |
| **入库** | `cloudfunctions/importSalesBill/` | 选文件 → 云存储 → 解析 → 甲级 → 落 `external_sales_daily`（确定性 `_id` ⇒ 重放幂等） |
| **回归** | `tools/selftest_bill_parse.js`（15 断言）· `tools/selftest_grade_gate.js`（11 断言） | **两锚点原样复现**：淘宝 156 行 / 377965 分 · 美团 97→50 行 / 182664 分 |

**账单级落库口径**（详见 `review/PLAN_2026-10-01_销量数据替代方案_去开放平台.md §四-bis`）：

```
external_ref_id = 'BILL:<platform>:<bizDate>'              // 合成键，与菜品级键空间不冲突
dish_key        = ''                                       // 账单级无菜品身份
qty             = 有效订单数（绝不进金额）
amount          = 到手金额（分）
_id             = 'BILL_<shop_id>_<platform>_<bizDate>'   // 确定性主键 ⇒ 重放幂等
```

已落地的四条**硬约束**（实测踩过，别回退）：
1. 🔴 **美团「账单金额」≠ 外卖收入** ⇒ **必须先按「交易类型=外卖订单」筛行**（不按订单状态、行键不用订单号）；
2. 🔴 **复合列 × 拆分列只许取一组**（取拆分列，别名表**永不映射复合列**）；
3. 🔴 **退单行符号是冲回** ⇒ 逐行校验**带符号相加**，取绝对值会把退单全部误判；
4. 🔴 **`openpyxl read_only=True` 少算 1 行** ⇒ 判行数用非 `read_only` 的 `ws.max_row`。

🔴 **单一事实来源**：口径若有变更，**先改 `utils/billParse.js` 并跑 `selftest_bill_parse`**，再回填本文件 ——
顺序颠倒就会出现「代码改了、文档没改」的静默漂移（R164 已实证过一次这类漂移的代价）。
