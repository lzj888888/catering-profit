## 4 判定规则（替代 v1.6 §3.4）

```
detectShape(matrix):
  A ← 列名含 '菜品名称' 且 含 '销售数量' 且 R2 含 '销售方式'
  B ← 列名含 '套餐'     且 含 '单品名称'
  C ← 列名含 ('商品名称' 或 '菜品名称')                    # C-1 放宽
      且 列名含 ('商品销量' 或 '销量')                      # C-1 🔴 真样例是 '销量'
      且 列名含 '销售额'
      且 R2 不含 '销售方式'                                # C-1b 冗余防御（见 §4.2）
  命中 1 个 → 返回 { shape, headerRow }；命中 0 或 ≥2 → null（fail-closed）
```

### 4.1 表头行（C-2）

| 形态 | 表头行 | 数据起始 |
|---|---|---|
| A | R3（**两行**：R3 一级 + R4 二级） | R5 |
| B | R3（单行） | R4 |
| **C** | **R1（单行）** | **R2** |

🔴 `detectShape` 必须**同时扫描 R1 与 R3**（否则形态 C 的表头在 R1、永远扫不到）。

### 4.2 🔴「不含 `销售方式`」是**冗余防御**，不是隔离的实际承担者

锚点 C-1i~C-1l 实测：

- 形态 A 表头**不含** `销量` / `商品销量`（它用 `销售数量`）；
- 形态 C 表头**不含** `销售数量`（它用 `销量`）。

⇒ 两套列名**天然不重叠**，即使删掉该区分项，形态 A 也不会被误判成 C（锚点 C-1h 实测仍返回 `dish_sales`）。

**仍予保留**的理由：将来若某张表同时含两套列名，该区分项是唯一防线；代价仅为一个条件。

## 5 解析与落库规则

### 5.1 白名单取列（C-4）

只取 `日期` / `门店编号` / `商品名称` / `销量` / `销售额`；其余列**丢弃且不报错**。
理由：漏斗/互动列的**去重口径未经核对**，入库即造脏；与「零新建集合」一致。

### 5.2 `amount` 口径（C-3，替代 v1.6 §5.3 对本形态的适用）

```
形态 C: amount_fen = Math.round(销售额 × 100)
```
🔴 **`订单交易额` 严禁取用**：它是**整单口径**（一单多菜时为整单额）⇒ 取用会**重复计钱**
（实测 Σ 2974.91 vs 正确的 1823.08，**虚增 63%**）。
⚠️ 该列**看起来很像收入**，规范必须明文禁用并给理由，否则下一批实现者会误用。

### 5.3 `qty`（沿用 v1.6 §5.2）

`qty = Math.round(toNum(销量))`。🔴 **销量列全为文本** ⇒ 必须先 `toNum()`
（不许 `Number.isFinite(原值)` 直接判空，见 v1.6 §4.5）。真样例无非整数 qty ⇒ 本形态不触发取整告警，但兜底保留。

### 5.4 `biz_date`（C-7）

形态 C **按行**取 `日期` 列（`YYYY-MM-DD`），`_id` 序列 = 该 `(biz_date, 商品)` 组内行序。
⇒ **一表多天展开为多组**（本例 **7 组**），不是 1 组。

### 5.5 禁止补零（C-6）

**无行 = 无销售，不补零行**。理由：补零会与「真卖 0 份」不可区分 ⇒ 破坏 v1.6 §5.1 幂等（重导时 `_id` 序列会变）。

### 5.6 新增告警类 `zeroAmountQty`（C-5）

`amount=0 且 qty>0` 的行**单列**为 `zeroAmountQty`（含 原名 / qty / 0 元），**不静默归零**、**不进 `unmatched`**。
复盘页对这类行加标注 **「口味询问类 SKU，不计营收」**。
理由：实测该类占全表销量 **36.4%**，若不复核会出现「销量第一、营收为零」的行 ⇒ 用户会以为程序算错。
