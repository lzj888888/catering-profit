# 14_种子数据与验收脚本规范（seed_demo，与批次 0 配套）

> **定位**：写码阶段「验收提效」配套件。把《02_模拟测试数据集.md》（验收唯一标准）的 S1~S4 场景，
> 落地为**机器可消费、可一键复现**的种子数据与自检脚本。与批次 0 §2.8 `initDb` 建库脚本、§2.10 验收提效小节配套。
> **最后更新**：2026-09-11

---

## 1. 为什么需要它

- 《02_模拟测试数据集》是「人读」的验收标准（表格 + 文案），写码后验收需**手动造数**才能跑通 22 项清单。
- 本规范把同一份数据抽成**结构化单一真相源**（`seed_data.js`），并配两个消费方：
  - `verify_seed_data.js`：本机即可跑，断言 22 项验收锚点全绿（写码前就能验证数据正确性）。
  - `seed_demo.js`：云函数，把数据灌进 dev 环境，验收时**无需手动造数**。
- 因为两个消费方都引用同一份 `seed_data.js`，所以「插进云库的数据」必然 == 「算出来能对上的数据」。

依赖的四个计算原型（同为验收算法基线）：

> 🔢 验收自检口径（唯一声明处）：`verify_seed_data.js` 本机实跑 **48** 通过 / **0** 失败（误差红线 ≤ 0.01 元）。
> 断言数增减后**本行必须同步**，否则「期望通过数」被写低 ⇒ 断言被删也照旧判绿（验收静默放行）。

## 3. seed_data.js 结构

```js
// 金额单位：元（云函数侧按 ×100 转分）。预期值取自 02_模拟测试数据集.md，误差 ≤ 0.01 元即通过。
S1 = { month:'2026-07', inventoryOn:false, amortYuan:0,
       incomes:[{cat,sub,amountYuan}...], expenses:[...], directCostYuan:22000,
       expected:{ income:64000, expense:32840, gross:42000, grossMargin:65.625, bizRef:9160, full:9160 } }

S2 = { month:'2026-08', inventoryOn:true, beginInvYuan:5000, purchaseYuan:25000, endInvYuan:7000,
       amortYuan:4683.33, incomes, expenses, directCostYuan:22000,
       amortAssets:[{装修/加盟费/冰柜}], // 2026-08 当月摊销合计 4,683.33
       expected:{ realCost:23000, amort:4683.33, bizRef:9160, full:3476.67, diff:5683.33 } }

S2b = { assets:[ 旧空调(终止2026-08), 招牌制作(自然到期2026-12) ], expected:{...边界值} }

S3 = { materials:[11 条原料], 
       cards:{ gongbao(单份,9.75), hongyou(批量预制→虚拟原料4.48), mala(单份,引虚拟,12.35) },
       refresh:{ 鸡胸肉20元/斤→v2=12.08 }, cycle:{A:['B'],B:['A']} }

S4 = { 沙盘输入(房租8000/物业500/人工12000/其他800/变动35+8+2/目标15000),
       expected:{ fixed:21300, compVar:45, margin:55, beMonthly:38727.27, beDaily:1290.91, targetMonthly:66000, targetDaily:2200 } }
```

> **改验收数据只改这一处**：修正某个锚点 / 新增场景，只在 `seed_data.js` 改，verify 与 seed_demo 自动同步。

## 4. 字段映射表（seed_data → 云集合）

> **字段命名遵循全局约定**：数据库 / 云函数层统一使用 `snake_case`；前端适配层转换为 `camelCase`；业务层禁止混用两套命名。本规范的映射表及 `seed_demo.js` 一律按 `snake_case` 落库，与 `core/10 §2.9` 字段命名约定一致。

| seed_data 段 | 目标集合 | 关键字段（snake_case，分整数） |
|---|---|---|
| `S1/S2.incomes` | `shop_monthly_income` | shop_id, month, cat, sub, amount_fen |
| `S1/S2.expenses` | `shop_monthly_expense` | shop_id, month, cat, sub, amount_fen |
| `S1/S2` 汇总 | `shop_monthly_account` | shop_id, month, income_total_fen, expense_total_fen, direct_cost_fen, inventory_on, amort_on |
| `S2` 库存 | `shop_inventory` | shop_id, month, begin_fen, purchase_fen, end_fen, real_cost_fen |
| `S2.amortAssets` + `S2b.assets` | `shop_amortize` | asset_id, shop_id, name, total_value(分), start_month, total_months, terminate_month, monthly_amount(分) |
| `S3.materials` + 红油底料虚拟原料 | `shop_material` | id, shop_id, name, purchase_unit, purchase_price(分), convert_factor, yield_rate, is_virtual |
| `S3.cards.*` | `shop_cost_card` + `shop_cost_card_line` | 主表(id/card_id/version/calc_mode/loss_rate/aux_cost(分)/total_cost(分)/is_latest)；明细行(quantity/net_unit_cost/line_net_cost(分)/快照字段) |
| `S4` | `shop_sandbox` | scheme_name, rent_yuan(分)…var_food_pct…target_profit_yuan(分) |

> 字段名以 `core/10_云函数清单与接口契约.md` §8 与 Module A / M1 / M3 字段字典为准；若 inscode 最终生成字段名有出入，微调 `seed_demo.js` 即可（不影响已验证的 `seed_data.js` 正确性）。

## 5. 部署与运行步骤

### 5.1 本机自检（写码前即可跑，零依赖云环境）
```bash
cd specs/dev-specs/prototype
node verify_seed_data.js
# 期望输出：验收自检结果：48 通过 / 0 失败（误差红线 ≤ 0.01 元）
```

### 5.2 云函数灌库（写码后，dev 环境）
1. 先部署并跑一次 `initDb`（建 25 集合 + 索引 + 套餐种子，见批次 0 §2.8）。
2. 在云开发控制台**新建云函数 `seedDemo`**，把 `seed_demo.js` 内容贴入，`package.json` 依赖加 `wx-server-sdk`。
3. **测试调用** 一次（幂等：检测到 demo 店已有原料即跳过）。
4. 前端/云函数按《02_模拟测试数据集》22 项清单逐项核对，数据已在 `shop_seed_demo` 店里就绪。

> **【生产环境禁令】prod 环境禁止部署 `seedDemo` 云函数**，避免演示数据误灌入污染真实业务数据。该云函数仅用于 dev 环境一键灌入验收演示数据；生产环境一旦误部署并触发，会把整店演示数据写入真实业务库。上线 checklist 中须明确：只部署 `initDb` 与业务云函数，`seedDemo` 永不进 prod。

### 5.3 隔离与解锁策略
- 所有数据归属固定 demo 测试店：`user_id=user_seed_demo` / `shop_id=shop_seed_demo`，**与真实用户数据完全隔离**。
- `shop_entitlement.expire_at` 设为远到期（2099-12-31），即**解锁真实利润 + 导出**，解除 M1/M2/M3 免费配额限制——**验收的是计算逻辑，不是配额 UI**；生产环境仍按配额维度（M1=1 账套 / M3=3 张；M2 不限套）走硬上限，**计数仅包含 `is_deleted=false` 的有效数据，已软删除数据不占用配额**。
- 清理：验收完毕可整店软删 `shop_seed_demo` 全部集合记录（或直接另开环境）。

## 6. 精度与行为纪律（写码必须遵守）

1. **金额一律分整数**：`seed_demo.js` 插入时用 `toFen`（×100 取整）；`verify_seed_data.js` 断言前先 `fenRound`（四舍五入至分）再反推毛利/毛利率——**不得用原始双精度浮点算百分比**（曾出现 65.17 vs 65.18 虚假偏差）。
2. **循环引用拦截（M3）**：是「保存半成品时」的校验逻辑，seed **不预置违规数据**；验收时由前端/云函数 `BOM_CYCLE_DETECTED` 拦截表现。
3. **成本卡刷新（3-R）**：是「点同步至原料最新价格」的运行时动作；seed 只预置宫保鸡丁 v1 快照（鸡胸肉 15 元/斤），验收时手动改原料→点同步→断言生成 v2=12.08、v1=9.75 保留。
4. **口径锁**：S2 经营参考利润仍用直接填 22,000（不改用倒轧 23,000），seed 严格按此写入。

## 7. 与《02_模拟测试数据集》的关系

- `02_模拟测试数据集.md` 是**人读权威源**（含全部公式、检查点、22 项清单）。
- 本规范的 `seed_data.js` 是其**机器消费版**，两者锚点必须一致；若发现偏差，**以《02_模拟测试数据集》为准**并同步回 `seed_data.js` 后重跑 verify。
