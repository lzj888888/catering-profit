## M2.1 定位与数据隔离

- 沙盘 = **纯假设测算**，不读取 M1 任何真实核算数据（营收/费用/库存/摊销台账均不碰）。
- "从 M1 复制"动作 = 仅把 M1 最近月份的**固定费用 4 项**（房租/物业/工资/其他杂费）快照复制进本方案，**复制后两处彻底断开**（改 M1 不影响沙盘，改沙盘不影响 M1）。
- 沙盘结果**不可**回写 M1、不可参与任何盈利计算。

## M2.2 方案管理

- 多套方案并存，每套独立参数与结果。
- **方案不限套（v1.4 终稿裁定：M2 永久全免费，正算+反推全开、方案不限套、永不弹付费窗）**。原规划"免费版上限 3 套 + 弹升级提示"已作废（与 v1.4 第一项拍板冲突）。为体验可加"副本"后缀，但**不做数量阻断、不弹付费窗**。
- 复制：复制整套参数生成新方案（名称自动加"副本"）。
- 删除：**二次确认弹窗** + **软删除 30 天**（见 M2.9），30 天内可恢复。
- 未保存切换方案：提示"有未保存修改，是否放弃"。

## M2.3 成本字段（v2：结构化清单 —— 选类型 + 填数）

> 🔄 **2026-09-23 李老师拍板改造（v2）**：v1 的「固定 4 项 + 变动 3 个率」作废 ——
>   原写法把「营销费用率 / 其他变动率」直接摆给用户，餐饮小白**不知道"率"里装了什么**；
>   而加盟费 / 装修 / 固定资产 / 管理费**无处安放**。v2 改为与 M1 同款的「选类型 + 填数」心智。
>   入参由"平坦字段"改为**结构化清单**（`build_items` / `fixed_items` / `var_items`），
>   白名单枚举单源在 `cloudfunctions/common/indicatorRef.js`（校验层不得自行 hardcode 枚举）。

**① 一次性建店投入 `build_items[{key, fen, years}]`** —— 按年限摊到每月

| key | 名称 | 默认摊销年限 |
|---|---|---|
| franchise | 加盟费 | 3 |
| decor | 装修 | 3 |
| equip | 设备资产 | 5 |
| other | 其他投入 | 3 |

**② 每月固定支出 `fixed_items[{key, fen}]`**

| key | 名称 |
|---|---|
| rent | 房租 |
| labor | 人工 |
| utility | 水电气 |
| manage | 管理费 |
| other | 其他固定 |

**③ 跟营业额挂钩的费用 `var_items[{key, pct}]`**

| key | 名称 |
|---|---|
| takeawayComm | 外卖平台佣金 |
| grouponComm | 团购佣金 |
| cardFee | 刷卡手续费 |
| other | 其他 |

**④ 菜品毛利率 `gross_margin_pct`（%）** —— 见 M2.4；**⑤ 目标月利润 `target_profit_fen`（分）**

> 🔴 **为什么"挂钩类"必须填占比而不是金额（口径裁定，务必遵守）**：佣金 / 扣点是**随流水正比增长**的。
>   若让用户填固定金额，它会被当作固定成本 ⇒ **保本点被算低、结论偏乐观** ——
>   而"这店到底能不能开"恰恰是最需要保守的地方。故费用清单**分两类**：
>   **固定类填金额、挂钩类填占比**。（本条为 v2 拍板项③的落地口径，改前须李老师同意。）

> **固定人工口径（不变，与豆包对齐）**：只含**每月固定**的人工支出（固定底薪 + 社保 + 宿舍 + 员工餐）；
>   **提成 / 奖金属变动部分**，应归入"跟营业额挂钩"那一类，不计入固定人工。
>   豆包原描述"仅固定底薪"过简，已按此口径补全。

> 设计原则（v2 修正）：沙盘仍是**粗算**，不追求拆十几项；但 v2 允许用户**自己决定拆几项**
>   —— 想粗就只填房租 + 人工，想细则把管理费 / 水电气也拆出来，**输入快 > 精细**这一取向不变。

## M2.4 菜品毛利率 + 红警（v2）

| 字段 | 类型 | 说明 |
|---|---|---|
| 菜品毛利率 `gross_margin_pct` | % | **v2 新口径**：由 v1 的"菜品变动成本率"**翻转为毛利率** —— 餐饮从业者对毛利率的熟悉度远高于成本率（拍板项②） |
| 综合变动成本率 | 派生 | `= (100 − 菜品毛利率) + Σ 挂钩费率` |
| 跟营业额挂钩的费用 | % × N | 见 M2.3 ③（外卖佣金 / 团购佣金 / 刷卡手续费 / 其他） |

- 🔴 **口径统一铁律（round111 李老师拍板）：对外一律「毛利率」，用户可见处**不得出现**「食材成本率」。**
  `食材成本率 = 100 − 菜品毛利率` 只是**引擎内部中间量**（用于算综合变动成本率，见 M2.5），
  **不进任何用户可见面** —— 术语（`terms.js`）、参考带、滑杆旁小字、解读文案、页面举例**全部用毛利率**。
  理由：目标用户是餐饮小白，"食材成本率"听着就绕；"毛利率"是餐饮人日常语言（拍板项②的延伸）。
  > ⚠️ 本行**推翻了 v2 草案原文**（原写"等价换算（页面必须同时显示）：例 填毛利率 65% ⇒ 页面同时显示
  > '食材成本占售价 35%'，不显示换算值会误导老用户以为换了口径"）。撤销理由：① 老用户习惯前提不成立
  > —— M2 v1 **从未上线给真实用户**；② 同时显示两个方向相反的率，正是"客户看不懂"的主因。
  > **但引擎里那个中间量不能删**（删了综合变动成本率算错、保本点跟着错），只是不再出到前端。
- **红警（唯一强制指标）**：综合变动成本率 **≥ 100%** ⇒ `red_alert=true`，
  红色提示"当前结构无法盈利"，**不计算负数保本营业额**。
- 等价：边际贡献率 ≤ 0 即红警。
- ⚠️ **红绿灯口径裁定**（不变，消除单独版本 L56 的"待决"）：沙盘是假设测算、**无实际营收对比对象**，
  "保本线 <70%绿/70–100%黄/>100%红"无意义 ⇒ **废弃**，统一采用上述唯一红警。记录在案，不再待决。

## M2.5 核心计算引擎

```
月摊销         = Σ(建店投入_i ÷ (年限_i × 12))        ← 逐项高精度求和，仅最后一步取整到分
固定成本合计   = Σ 每月固定支出 + 月摊销
食材成本率     = 100 − 菜品毛利率                      ← ⚠️ **引擎内部中间量，不出前端**（见 M2.4 口径铁律）
综合变动成本率 = 食材成本率 + Σ 跟营业额挂钩费率
边际贡献率     = 1 − 综合变动成本率 ÷ 100
保本月营业额   = 固定成本合计 ÷ 边际贡献率
保本日均营业额 = 保本月营业额 ÷ 30                    ← 固定÷30，不按当月实际天数
目标利润月营收 = (固定成本合计 + 目标利润) ÷ 边际贡献率
目标利润日均   = 目标利润月营收 ÷ 30
收回投入(月)   = 建店总投入 ÷ 目标月利润              ← 目标利润 ≤ 0 ⇒ 不计算（不编造）
```

> 🔄 **v2（2026-09-23）相对 v1 的公式变化**：① 综合变动成本率不再由三个"率"相加，
>   而是 `(100 − 菜品毛利率) + Σ 挂钩费率`；② 固定成本新增**建店投入摊销**（v1 是手填一个模拟摊销额，
>   v2 由用户填各笔投入 + 年限后自动摊）；③ 新增**收回投入**与**餐饮指标对照**。
>   ⚠️ 浮点陷阱：保留 1 位小数必须带十进制容差（`Math.round(n*10 + 1e-9)/10`）——
>   实测 `25 × 1.15 = 28.749999999999996`，裸 round 得 28.7 而手算应为 28.8（selftest E3 抓出）。
>
> 🔄 **round111 追加（公式本身未变，变的是**对外口径**）**：指标对照的 `grossMargin` 项**直接取用户填的
>   毛利率**（不再 `100 − x` 换算成成本率后再对照）。`食材成本率` 这一中间量仍参与"综合变动成本率"
>   的计算（**不可删 —— 删了保本点会算错**），但**只活在引擎内部**：不返回给前端渲染、不进术语表、
>   不进解读文案。`grossMargin` 的 dir 是 `gain`（越高越好），是本库唯一方向相反的指标。

- 全部 **Service 层计算**，Controller 只展示。
- 精度：金额 Decimal 分存储，除法四舍五入至分（同 M1/M3 红线）。

## M2.7 交互规则

- **实时重算**：任意参数变更立即重算，无需点"计算"按钮（S4 验收点）。

## M2.12【修正新增·反推测算子功能】（原始规划核心，不可砍）

> **修正项 B**：豆包 11 节结构里**完全缺失"反推"**，仅做了正算（保本/目标/日均）。但本模块原名"选址**反推**"，原始定位（单独版本 L64）明确要求"给定目标月盈利/客单价/毛利率，反推所需客流、翻台、租金上限、面积"。此功能必须保留，列为 v1.1 增强，但**规范层面锁定其存在**，防止被永久删除。

**输入（反推模式）**：在正算参数基础上，额外输入 `客单价`、`预估毛利率`、`座位数`、`每月营业天数`、`目标租金率`。
**输出与公式**：
```
目标月营收 R        = (固定F + 目标利润P) ÷ (1 − 综合变动率v)   [同M2.5]
所需月客流          = R ÷ 客单价
所需日均客流        = 月客流 ÷ 30
所需翻台次数        = 月客流 ÷ (座位数 × 每月营业天数)
租金上限            = R × 目标租金率
面积上限(可选)      = R ÷ 坪效(营收/㎡)   [坪效为可选假设]
```
**交付节奏**：v1.0 先交付正算（S4 已测）；**v1.1 必须补 M2.12 反推**，否则模块名"选址盈利沙盘"丧失"反推"内核。
