# 店算 · 微信小程序审核自查清单（2026 版）

> **用途**：提交审核前逐条过一遍，避免卡审返工。本清单基于微信官方《小程序平台常见拒绝情形》《微信小程序平台运营规范 5.13》、中央网信办 2025 个人信息保护专项行动、以及 2026 年社区审核 FAQ 整理。
> **结论速览**：店算 v1.0 在**类目、虚拟支付、文案**上风险低；但**隐私弹窗+指引、账号注销**是当前 8 批喂投包里**缺失的硬门槛**，上线前必须补；虚拟支付保持关闭是正确决策。

---

## 1. 服务类目（必配，须与功能匹配）

| 推荐类目 | 适用 | 资质要求 | 说明 |
|---|---|---|---|
| **工具 > 记账** | 主类目（首选） | 通常无资质，选后即生效 | 店算本质是"餐饮经营记账/算账工具"，最贴合 |
| 商业服务 > 一般财务服务 | 企业主体补充 | 可能需营业执照经营范围含财务/咨询 | 企业主体可选，强化"商业服务"定位 |
| 工具 > 办公 / 企业管理 | 备选 | 无资质 | 仅当主类目受限时补充 |

- 一个小程序可选 **5 个类目**，每月 5 次修改机会。
- **绝对避免**：选实物/餐饮类目却卖虚拟功能；类目与简介功能不符。
- 店算 v1.0 选 `工具 > 记账` 即合规，无需额外资质，可立即提审。

## 2. 隐私合规（2023-09 起**强制**，缺失直接驳回）🔴

> 8 批喂投包**当前未覆盖此项**，须在批次 0/7 补齐（详见批次 7 §2.9 隐私合规硬门槛）。

**必做清单**：
1. **配置《小程序用户隐私保护指引》**：微信公众平台 → 设置 → 服务内容声明 → 用户隐私保护指引，如实勾选收集的信息类型（如 openid/昵称头像/存储/网络状态）并写明用途。
2. **app.json 声明 `requiredPrivateInfos`**：用到的隐私接口须在此声明（如 `getUserInfo` 等）。
3. **首次启动弹隐私协议**：用 `wx.getPrivacySetting` 判断是否需授权；用 `wx.onNeedPrivacyAuthorization` 注册回调，`wx.requirePrivacyAuthorize` 主动拉起弹窗。未同意前相关接口不得调用。
4. **撤回同意入口**：「我的」页提供"隐私协议查看"与"撤回授权"入口。
5. **合规红线**：
   - 禁止默认勾选"同意"；
   - 禁止把隐私同意与其他业务操作绑定（如"同意才能用"须可跳过）；
   - 同会话最多弹 **2 次**，拒绝后不得反复骚扰；
   - 隐私协议内容须与实际代码使用的接口**一一对应**。

## 3. 账号注销（个人信息保护法 + 微信审核**必须**）🔴

> 当前 v1.0 计划"不做注销（排 v1.1+）"——**此为审核风险项**，必须改为 v1.0 提供轻量注销入口。

- **要求**：有账号体系的小程序必须提供便捷注销入口，≤3 步，注销后删除或匿名化处理个人信息，承诺 **15 个工作日内**完成。
- **店算轻量方案**（建议写入批次 7）：
  - 「我的 → 账号与安全 → 注销账号」入口；
  - 二次确认弹窗说明数据后果；
  - 后端：软删 `user` + 匿名化 `openid`/手机号/昵称 → 关联 `shop`/`shop_entitlement` 置 `is_deleted=true` 或由定时任务脱敏；
  - 前端注销后立即退出登录、清本地缓存。
- 不做"硬删全量业务数据"也合规，关键是**提供入口 + 处理 PII**。

## 4. 虚拟支付与 iOS 红线（v1.0 策略正确）✅

- **微信运营规范 5.13**：虚拟商品（功能解锁/会员/订阅）的购买与支付须接入**小程序虚拟支付**；**不得引导至 H5 / 公众号 / App / 外链完成支付**。iOS 端尤其严格，直接调微信支付买虚拟商品 100% 驳回。
- **店算 v1.0 正确决策**：`enable_real_payment=false`，当前阶段**完全不接真实支付**，权益由后台 `source=manual` 发放，前端展示逻辑复用。这**彻底绕开 iOS 虚拟支付雷区**，无需类目/资质/虚拟支付 API。
- **若未来开启真实支付**：
  - iOS 必须走**微信小程序虚拟支付 API**（非 H5 引导、非 App、非公众号）；
  - 安卓走普通微信支付；
  - 页面**禁止出现**"付费/会员/订阅/立即订阅"等敏感词（已用外显四词「开通真实利润」规避）；
  - iOS 端不展示价格/已购状态/支付按钮（当前批次 5 已对齐：iOS 仅一次性套餐、不可用时引导安卓——注：引导 iOS 去 H5 付款本身也违规，故 v1.0 直接关闭支付最稳妥）。
- **v1.0 结论**：保持支付关闭，私域手动发权益，等营业执照下来 + 虚拟支付 API 就绪再评估。

## 5. 文案 / 功能 / 简介一致性

- 外显四词已拍板并锁死：专业模式=「真实利润」、按钮=「开通真实利润」（禁会员/订阅）、收回投入期=「约X个月收回投入」、简介=「开店算账工具，算清每月能剩多少」。
- 简介写的功能点，页面里都要能找到；首页 2 次点击内可达核心页（M1/M2/M3 入口）。
- 有账号体系须提供**可体验全部的测试账号**给审核员。
- 无死链、无未实现页面、无崩溃。

## 6. 提审前自检清单（勾选）

- [ ] 类目已选 `工具 > 记账`（企业可加 `商业服务 > 一般财务服务`），无遗漏
- [ ] 《用户隐私保护指引》已配置且覆盖实际接口
- [ ] app.json `requiredPrivateInfos` 已声明
- [ ] 首次启动隐私弹窗已集成（`onNeedPrivacyAuthorization` + `requirePrivacyAuthorize`）
- [ ] 「我的」页有隐私协议查看 + 撤回授权入口
- [ ] 提供账号注销入口（≤3 步，后端匿名化 PII）
- [ ] 全站无"强制分享才能用""分享得红包"逻辑
- [ ] 虚拟支付保持关闭（`enable_real_payment=false`），无 iOS 付款引导
- [ ] 全站无"付费/会员/订阅"敏感词（仅用「开通真实利润」）
- [ ] 简介功能点页面均可达，提供测试账号
- [ ] 无死链、无未实现页面、无崩溃
