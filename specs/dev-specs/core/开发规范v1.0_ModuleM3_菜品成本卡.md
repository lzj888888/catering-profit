## M3.1 定位与数据隔离

### 核心定位
- **纯理论 BOM 配方测算**：基于原料配方计算单品理论成本和毛利率
- **归属店铺 ID**：所有原料档案、成本卡绑定 `shop_id`，店铺之间完全隔离
- **不读取 A 模块经营数据**：完全不碰 A 模块的库存消耗、月度账等真实经营数据
- **与 A / M1 模块毛利的区别**：
  - M3 成本卡 = 理论配方成本（按标准配方算，假设没有浪费）
  - M1 月度毛利 = 真实经营毛利（含后厨浪费、盘点损耗）
  - 两者通常存在差异，页面必须显著提示

### 页面全局提示（必须常驻）
> ⚠️ 本模块输出为理论配方成本。已包含原料粗加工出成、菜品制作损耗；不包含门店整体后厨浪费、盘点损耗。真实门店整体毛利请参考月度盈利核算（M1），两者通常会存在差异。

## M3.2 原材料全局档案库（店铺内部）

### 原料唯一标识
- **原料唯一标识 = 原料名称 + 品牌/规格**
- 支持多品牌同款原料共存（如"味精-梅花牌"、"味精-太太乐"）
- 支持多款同品类原料共存（如"酱油-生抽"、"酱油-老抽"）

### 原料档案字段
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| material_id | string | 系统生成 | 原料唯一 ID |
| shop_id | string | 系统生成 | 所属店铺 |
| 原料名称 | string | 是 | 如"鸡胸肉" |
| 品牌/规格 | string | 否 | 如"泰森牌/冷冻" |
| 采购单位 | string | 是 | 下拉：斤/公斤/包/瓶/个，支持自定义新增 |
| 采购单价 | number(分) | 是 | 对应采购单位的价格 |
| 换算系数 | number | 是 | 换算到底层基准单位 g，如 1 斤=500 |
| 净料出成率% | number | 是 | 默认 100，削皮去骨粗加工后可用比例 |
| is_virtual | boolean | 系统生成 | 是否半成品虚拟原料（自动生成，不可手动建） |
| created_at | datetime | 系统生成 | |
| updated_at | datetime | 系统生成 | |
| is_deleted | bool | 系统生成 | 软删除标记 |
| delete_at | bigint | 系统生成 | 软删除时间戳，30 天后物理清理 |

### 自动计算字段（只读）
```
采购每克成本 = 采购单价 ÷ 换算系数
净料每克成本 = 采购每克成本 ÷ (出成率 ÷ 100)
```

### 原料档案操作
- 新增、编辑、删除（删除时检查是否被成本卡引用，被引用则提示但允许删除，删除后已保存的成本卡快照不受影响）
- 列表展示：名称、品牌规格、采购单位、采购单价、净料每克成本
- 搜索：按名称模糊搜索
- ⚠️ **删除 = 软删除（is_deleted=true，30 天内可恢复）**，与成本卡删除策略一致（见 M3.10）

### 半成品虚拟原料（自动生成）
- 批量预制半成品保存后，**自动生成一条虚拟原料**存入原料档案
- 虚拟原料标记 `is_virtual=true`，名称=半成品菜品名称，采购单位=份，单价=单份半成品成本
- ⚠️ **虚拟原料字段语义（防开发困惑）**：虚拟原料的 `convert_factor`（换算系数）= **1**（单位是"份"而非"克"，无需换算到 g）；其 `net_unit_cost` 字段**实际存储的是"每份成本"**，不是每克成本。计算引用成本时，行净料成本 = 用量(份数) × 该"每份成本"。
- 虚拟原料不可手动编辑、不可手动删除（只能通过删除半成品成本卡级联删除）
- 虚拟原料可以被其他成本卡引用（实现 BOM 嵌套）
- ⚠️ **虚拟原料单价同步规则**：当半成品成本卡重新同步/另存新版（生成新版本）时，须同步将 `shop_material(is_virtual=true)` 的 `purchase_price` 更新为**新的单份半成品成本**，使**新创建**的引用卡拿到新价；已保存的引用卡（如麻辣香锅）仍用各自保存时的快照，不受影响，需手动对其点"同步至原料最新价格"才会更新。

## M3.3 成本卡主表

### 成本卡字段
| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| card_id | string | 系统生成 | 同一道菜不同版本共享的逻辑卡号 |
| version | int | 系统生成 | 版本号，从 1 开始，另存新版时 +1 |
| shop_id | string | 系统生成 | 所属店铺 |
| 菜品名称 | string | 是 | |
| 菜品分类 | string | 是 | 热菜/凉菜/锅底/小吃/饮品，支持自定义 |
| 标签 | string | 否 | 引流菜/高毛利菜/爆款，支持自定义，可多选 |
| 核算模式 | enum | 是 | A=单份菜品【默认】/ B=批量预制 |
| 本批次总产出份数 | int | 模式 B 必填 | 模式 B 专属，整批产出多少份 |
| 菜品制作损耗率% | number | 是 | 默认 0，下锅炒制装盘损耗，区别于原料出成率 |
| 辅料综合分摊成本 | number(分) | 是 | 默认 0，微量油盐调料直接填分摊总金额。**⚠️ 口径随核算模式变（v1.6 修正）**：模式 A = **单份金额（元/份）**；模式 B = **整批总金额（元/批）**，**不是"单份×份数"**。详见 M3.5 红字警告 |
| 建议挂牌售价 | number(分) | 否 | |
| 活动特价 | number(分) | 否 | |
| is_latest | boolean | 系统生成 | 是否最新版本 |
| parent_card_id | string | 系统生成 | 复制/另存新版时关联原卡 ID |
| created_at | datetime | 系统生成 | |
| created_by | string | 系统生成 | |
| is_deleted | bool | 系统生成 | 软删除标记 |
| delete_at | bigint | 系统生成 | 软删除时间戳，30 天后物理清理 |

> 注：成本卡主表**没有独立自增主键语义冲突**——`card_id` 是逻辑卡号（跨版本共享），每条版本记录由 `(card_id, version)` 唯一确定；如需物理行主键可加 `id` 行号，详见 M3.12 Schema。

### 核算模式 A：单份菜品（默认）
- 明细物料按"单份用量"录入
- 直接计算单份成本
- 适用于直接出餐的菜品

### 核算模式 B：批量预制（半成品）
- 明细物料按"整批次用量"录入
- 必须填写"本批次总产出份数"
- 整批总成本 ÷ 产出份数 = 单份半成品成本
- 保存后自动生成虚拟原料（见 M3.2）
- 适用于酱料、浇头、底料等批量制作的半成品
- **BOM 最多 2 层**：半成品可以被菜品引用，但半成品不能再引用半成品（防止层级过深）

### 明细物料行（成本卡子表）
| 字段 | 类型 | 说明 |
|---|---|---|
| line_id | string | 行 ID |
| cost_card_row_id | string | 关联 `shop_cost_card` 具体版本行的主键 id（非逻辑 card_id） |
| material_id | string | 关联原料 ID（临时手工录入时为空） |
| 原料名称快照 | string | 保存时复制原料名称 |
| 品牌规格快照 | string | 保存时复制 |
| 采购单位快照 | string | 保存时复制 |
| 采购单价快照 | number(分) | 保存时复制 |
| 换算系数快照 | number | 保存时复制 |
| 出成率快照 | number | 保存时复制 |
| 净料单位成本快照 | number | 保存时复制（单位=g 或 份，依本行单位） |
| 用量 | number | 克（或份，当引用半成品虚拟原料时单位为份） |
| 行净料成本 | number(分) | 用量 × 净料单位成本快照（自动算） |
| 录入方式 | enum | 1=从原料档案选择 / 2=临时手工录入 |
| sort_order | int | 排序 |

### 两种录入方式
1. **从原料档案选择**：选择后自动带入换算系数、出成率、净料成本，用户只填用量
2. **临时手工录入**：用户手动填原料名称、用量、单价、出成率，仅当前成本卡生效，**不存入全局原料档案**

### 保存快照机制（核心红线）
> **保存成本卡瞬间，复制所有原料的单价、出成率、换算系数、净料单位成本存入本卡明细行的快照字段。**
>
> 之后修改原料档案，**不会自动更新**已保存的成本卡。历史成本卡永远保留保存时的成本数据。

## M3.4 版本快照机制（只 INSERT 不 UPDATE）

### 核心原则
- **成本卡修改 = 另存新版本，不覆盖旧版本**
- 数据库层面：成本卡主表**只 INSERT，不 UPDATE**（除 `is_latest` 标记字段的翻转）
- 每次保存生成一个新的 version 记录，旧版本保留可查

### 版本规则
1. **新建成本卡**：version=1，is_latest=true
2. **编辑并保存**：不修改原记录，新增一条记录，version=原最新版+1；原最新版 is_latest=false，新版 is_latest=true；parent_card_id 指向原版本行 id
3. **另存新版本**：用户主动点击"另存新版本"按钮，效果同上
4. **同步原料最新价格**：本质也是另存新版本（用最新原料价格重新计算，生成新版）
5. **复制成本卡**：生成一张全新的成本卡（新 card_id，version=1），parent_card_id 指向被复制的卡

**编辑权限（明确）**：只能编辑**最新版本**（`is_latest=true`）的明细与字段；历史版本一律**只读**，不可直接修改。如需基于历史版本修改，必须先「恢复为最新版」（见版本历史）或「复制」生成新卡后再改。

**`id` 与 `card_id` 的关系**：每条版本记录都有独立物理主键 `id`（见 M3.12）；`card_id` 是逻辑卡号，同一道菜的不同版本**共享同一 `card_id`**。列表页展示/去重要按 `card_id` 分组、取 `is_latest=true` 的那一条。

### 版本历史
- 成本卡详情页可查看"版本历史"，列出所有版本（版本号、修改时间、修改人、总成本变化）
- 点击历史版本可查看当时的完整数据（只读）
- 可将某个历史版本"恢复为最新版"（本质又是一次 INSERT，生成新版本，数据来自历史版本）

### 为什么这么设计
- 原料价格会变，但历史成本卡应该保留"当时做这道菜花了多少钱"的记录
- 如果自动 UPDATE，上个月的成本和这个月的成本会混在一起，没法对比
- 只 INSERT 不 UPDATE，保证所有历史数据可追溯、不可篡改

## M3.5 核心计算引擎

### 单品原材料总成本
```
明细净料成本合计 = Σ(每行用量 × 该行净料单位成本快照)

单品原材料总成本 = (明细净料成本合计 + 辅料综合分摊成本) ÷ (1 − 菜品制作损耗率 ÷ 100)
```

> ⚠️ **建模假设（写码必须沿用，不得"优化"）**：辅料综合分摊成本与原料净料成本**一并**按 `(1 − 制作损耗率)` 放大，即假定辅料在烹制中同样存在损耗。该口径与《02_模拟测试数据集》S3 锁定的 **9.75** 严格一致；若改为"只对原料放大、辅料不放大"，则 9.75 → 9.73，**破坏验收锚点**，禁止。

### 模式 B（批量预制）额外计算
```
整批总成本 = (整批明细净料成本合计 + 辅料综合分摊成本) ÷ (1 − 制作损耗率 ÷ 100)
单份半成品成本 = 整批总成本 ÷ 本批次总产出份数
```

> 🔴 **模式 B 辅料口径警告（v1.6 新增，写码必看）**
> 模式 B 的 `辅料综合分摊成本` 存的是**整批辅料总额**，**不要乘以产出份数**。
> 依据《02_模拟测试数据集》S3.3：红油底料整批明细净料 42.80 + **辅料 2.00（整批）** = 44.80，÷ 10 份 = 单份 **4.48**。
> 若误按"单份辅料 2.00 × 10 份"计算，整批会变成 62.80、单份 6.28，**同时破坏 S3 的 4.48 与 12.35 两个锚点**。
> 页面录入提示语必须随模式切换：模式 A 显示"(元/份)"，模式 B 显示"(元/整批)"。

### 售价与毛利
```
单品毛利（挂牌价） = 建议挂牌售价 − 单品原材料总成本
单品毛利率（挂牌价） = 单品毛利 ÷ 建议挂牌售价 × 100%

单品毛利（活动价） = 活动特价 − 单品原材料总成本
单品毛利率（活动价） = 单品毛利 ÷ 活动特价 × 100%
```

### 反算功能（目标毛利率倒推售价）
- 用户输入"目标毛利率%"，系统反推建议售价
- 公式：`建议售价 = 单品原材料总成本 ÷ (1 − 目标毛利率 ÷ 100)`
- 反算结果填入"建议挂牌售价"字段（用户可再手动调整）
- 示例：成本 9.75 元，目标毛利率 60% → 售价 = 9.75 ÷ (1 − 60%) = 24.38 元

### 计算规则
- 所有金额内部以"分"为单位存储和计算
- 除法四舍五入到分
- 制作损耗率 = 0 时，分母 = 1，不影响
- 售价为 0 时，毛利和毛利率显示"—"（未定价）

## M3.6 BOM 嵌套与循环引用拦截

### BOM 层级限制
- **最多 2 层 BOM**：
  - 第 1 层：批量预制半成品（红油底料、酱料等）
  - 第 2 层：使用半成品的成品菜（麻辣香锅等）
- **半成品不能引用半成品**：即第 1 层的半成品明细里不能再选半成品虚拟原料
- 成品菜可以引用多个半成品

### 循环引用拦截（保存时强制校验）
- **检测场景**：半成品 A 引用半成品 B，半成品 B 又引用半成品 A（直接循环）
- **检测算法**：保存半成品时，递归遍历其引用的所有原料，如果发现引用链中出现自身 ID，判定为循环引用
- **拦截动作**：
  - 弹窗提示："⚠️ 检测到半成品循环引用（A→B→A），禁止保存"
  - 保存被拦截，数据不入库
  - 错误码 `BOM_CYCLE_DETECTED`
- **即使 BOM 只有 2 层也要做这个校验**，防御性编程（与"半成品不能引用半成品"规则双保险）
- 注：在严格的 2 层限制下循环引用**理论上不可能发生**（半成品不能引半成品，闭环无法形成）；保留此校验是防『层级限制被绕过 / 未来放开层级』时的隐患，属稳健性兜底，**不可删**

### 半成品虚拟原料引用规则
- 成品菜（模式 A）的明细可以选择半成品虚拟原料，单位为"份"
- 半成品（模式 B）的明细**不能**选择半成品虚拟原料（保存时校验拦截）
- 引用半成品时，行净料成本 = 用量(份数) × 半成品单份成本快照

## M3.10 安全与数据校验

### Service 层二次重算
- 保存成本卡时，Service 层用传入的明细数据**重新完整计算**总成本、毛利、毛利率
- 不信任前端传入的计算结果，防止抓包篡改
- 计算结果与前端不一致时，以 Service 层计算为准

### 快照完整性校验
- 保存时检查每一行明细的快照字段是否完整（名称、单价、换算、出成率、净料单位成本都不能为空）
- 从原料档案选择的行，快照值必须与保存时原料档案的当前值一致（防止前端传假数据）

### 软删除
- 成本卡 / 原料档案删除 = 软删除（is_deleted=true，delete_at 记录时间）
- 30 天内可恢复，30 天后物理删除
- 删除成本卡时关联的明细行同步软删除

### 操作日志
- 新建/编辑/删除/复制/另存新版/同步价格/导出 都记录 `audit_log`
- 记录：操作人、时间、成本卡 ID、版本号、操作类型、关键值变化

## M3.11 测试锚点（对应 S3 场景 3）

> **权威来源**：以下锚点的**完整输入（含采购单价）以《02_模拟测试数据集.md》场景 3（S3）为唯一验收标准**。本节为便于速查的摘要，任何差异以 S3 为准。

### 3.11.1 单份菜品：宫保鸡丁（完整输入）
**原料单价（来自 S3.1）**：鸡胸肉 15元/斤/500g/出成90% → 净料 0.03333 元/g；花生米 10/500/100%；干辣椒 20/500/100%；葱姜蒜 5/500/100%；调料油 10/500/100%。
**输入**：鸡胸肉 200g、花生米 50g、干辣椒 10g、葱姜蒜 30g、调料油 20g、辅料 0.5 元、损耗 5%、售价 28 元
**预期输出**：

### 3.11.3 半成品嵌套：麻辣香锅（第 2 层 BOM）
**输入**：红油底料 1 份(4.48)、时蔬拼盘 500g(3元/斤)、肉丸 100g(20元/斤)、辅料 0.5 元、损耗 3%、售价 38 元

**预期**：保存 B 时检测到循环，弹窗拦截（错误码 `BOM_CYCLE_DETECTED`），数据不入库

## M3.12 数据库 Schema

```sql
-- 原料档案
shop_material (
  id              STRING PK,
  shop_id         STRING,
  name            STRING,           -- 原料名称
  brand_spec      STRING,           -- 品牌/规格
  purchase_unit   STRING,           -- 采购单位
  purchase_price  INT(分),          -- 采购单价
  convert_factor  DECIMAL(10,4),    -- 换算系数→g
  yield_rate      DECIMAL(5,2),     -- 净料出成率%
  is_virtual      BOOL DEFAULT false, -- 是否半成品虚拟原料
  created_at      BIGINT,
  updated_at      BIGINT,
  is_deleted      BOOL DEFAULT false,
  delete_at       BIGINT            -- 软删时间戳,30天后清理
)

-- 成本卡主表（只INSERT不UPDATE，除is_latest翻转）
shop_cost_card (
  id              STRING PK,        -- 物理行主键（每条版本一行）
  card_id         STRING,           -- 逻辑卡号（同菜不同版本共享）
  version         INT,              -- 版本号
  shop_id         STRING,
  name            STRING,           -- 菜品名称
  category        STRING,           -- 分类
  tags            STRING,           -- 标签，逗号分隔
  calc_mode       TINYINT,          -- 1=单份 2=批量预制
  batch_output    INT,              -- 模式B产出份数
  loss_rate       DECIMAL(5,2),     -- 制作损耗率%
  aux_cost        INT(分),          -- 辅料分摊成本
  price_list      INT(分),          -- 挂牌售价
  price_promo     INT(分),          -- 活动特价
  total_cost      INT(分),          -- 单品原材料总成本（由Service层计算写入，前端不可传入；冗余存储便于列表查询）
  is_latest       BOOL,             -- 是否最新版本
  parent_card_id  STRING,           -- 复制/另存来源
  created_by      STRING,
  created_at      BIGINT,
  is_deleted      BOOL DEFAULT false,
  delete_at       BIGINT
)
-- 索引：(shop_id, card_id, version)、(shop_id, is_latest, is_deleted)

-- 成本卡明细行（快照）
shop_cost_card_line (
  id              STRING PK,
  cost_card_row_id STRING,          -- 关联 shop_cost_card.id（具体版本行的主键，非逻辑card_id）
  material_id     STRING,           -- 关联原料，临时录入为空
  material_name   STRING,           -- 快照：原料名称
  brand_spec      STRING,           -- 快照
  purchase_unit   STRING,           -- 快照
  purchase_price  INT(分),          -- 快照
  convert_factor  DECIMAL(10,4),    -- 快照
  yield_rate      DECIMAL(5,2),     -- 快照
  net_unit_cost   DECIMAL(10,6),    -- 快照：净料单位成本（g 或 份，依本行单位）
  quantity        DECIMAL(10,4),    -- 用量（g 或 份）
  line_net_cost   INT(分),          -- 该行净料成本
  input_type      TINYINT,          -- 1=档案选择 2=临时录入
  sort_order      INT
)
```
