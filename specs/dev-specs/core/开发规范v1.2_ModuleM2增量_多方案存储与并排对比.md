### 1-4 勘误 1 —— `param_json` 的**命名口径**（🔴 本文件最硬的一条）

| | 说法 | 出处 |
|---|---|---|

## 二 统一设计原则（为什么引擎零改动）

**本期只在 `calcSandbox` 外面包一层"存储 + 展示"，引擎与其既有算子一行不动。**

- 存储：`param_json` 存**全量入参**（14 字段）；
- 展示：`result_snapshot_json` 存**一次性出参**，**只用于列表 / 对比卡片的快速渲染**；
- 权威：**加载一律用 `param_json` 调 `calcSandbox` 实时重算**，快照绝不参与计算。
⇒ **恒等性由构造成立**（入参逐字节相同 ⇒ 出参必然相同）；锚点只需证明这条（§十 ②-A / ②-B）。

## 三 接口面（本期新增 **2 个**云函数）

### 3.1 `getPlan` —— 方案列表 / 详情（**读**）

| 项 | 内容 |
|---|---|
| 用途 | 列表（当前店全部未删方案，按 `sandbox_id` 分组取各 `sandbox_id` 的最新 `version`）／详情（单个 `sandbox_id` + 指定 `version`） |
| 入参 | `{ shop_id, plan_id?, version?, include_deleted? }` —— `plan_id` 即 `sandbox_id`；缺 `plan_id` ⇒ 返回列表 |
| 出参 | `{ list:[{ sandbox_id, version, name, sandbox_type, param_json, result_snapshot_json, engine_version, updated_at }] }` |
| 鉴权 | **A 类 · user + shop**（`resolveAuth` + `assertShopOwner`） |
| 幂等 | 不适用（**只读**） |
| 上限 | 🔴 列表查询**必须有显式上限**（单源 `common/dataAdapter.js::LIST_LIMIT`）；详情按 `sandbox_id` + `max(version)` 取单条 |

### 3.2 `savePlan` —— 保存 / 复制 / 软删（**写**）

| 项 | 内容 |
|---|---|
| 用途 | ① 保存（新建版本）；② 复制（新 `sandbox_id`，`version` 从 1 起）；③ 软删（`plan._delete === true`） |
| 入参 | `{ shop_id, plan:{ sandbox_id?, name, sandbox_type, param_json, is_copy? }, client_request_id }` |
| 出参 | `{ plan_id, sandbox_id, version }` |
| 鉴权 | **A 类 · user + shop + 幂等** |
| 🔴 幂等 | 必须走**单源**：`common.idempotency.findPriorResult(db, shopId, clientRequestId)`（查重）+ `common.audit.writeAudit(db, {action:'SAVE_PLAN', …})`（登记）。两处键**同源**（`shopKey()`）—— 各自拼串会出现「登记了却查不到」的静默失效 |
| 🔴 版本化只增 | **每次保存 = 新建一条**（**绝不 UPDATE**）；`version` = 同 `sandbox_id` 内 `max(version) + 1`；同 `sandbox_id` 的**旧版本软删**（`is_deleted=true` + `delete_at`） |
| 🔴 新 `sandbox_id` 生成 | 复制 / 首次保存时由**服务端**生成（不得由前端传入，防越权与撞号） |
| 🔴 快照写入 | `result_snapshot_json` **仅在本次调用**由服务端调 `calcSandbox`（+`calcSandboxReverse`，若 `mode='reverse'`）产出并写入，**不接受前端传入的快照**（前端传的快照可伪造 ⇒ 违反「结果权威源是云函数」） |
| 🔴 引擎怎么拿到 | 云函数**不能跨包 `require`**（本仓既有约束）⇒ 本函数目录**内联一份 `service.js`**，且**必须与 `cloudfunctions/calcSandbox/service.js` 逐字节相同**（`md5` 相等）。可行性已实核：该引擎是**零依赖纯函数**（只用内置 `Number`/`Array`，不 `require('./common')`）⇒ 可做到逐字节副本（比 `getLedger` 内联 `calcMonthlyProfit` 的"同源"更严——那两份 md5 实为不同） |

### 3.3 为什么**只有 2 个**（不是 R218 估的 3 个）

| 能力 | 落法 | 是否需新函数 |
|---|---|---|
| 保存 / 复制 | `savePlan` | 否 |
| **软删** | `savePlan` 的 `plan._delete` 分支（**对齐既有先例** `cloudfunctions/saveCostCard/index.js:119-123`） | **否** |
| **并排对比** | **纯前端**（`getPlan` 一次取回 N 个 `param_json` + 快照，前端并排渲染） | **否** |
| 导出 | **不在本期**（§十四） | — |

⇒ **2 个函数**，把「新增云函数牵动五处」的成本压到最小。

## 四 数据模型

### 4.1 Schema 变更（引 v1.1 §4.1，本文件不重复）

新增字段：`sandbox_id` / `version` / `sandbox_type` / `param_json` / `result_snapshot_json` / `engine_version`（6 个），
旧平坦字段降为历史只读兼容。

### 4.2 `param_json` 形状（🔴 **以本表为准** · 一律 `snake_case`）

```json
{
  "mode": "forward|reverse",
  "city_tier": "tier23", "biz_type": "dining",
  "build_items": [], "fixed_items": [], "var_items": [],
  "gross_margin_pct": 65, "target_profit_fen": 1500000, "expected_revenue_fen": 0,
  "rev_price_fen": 4500, "seats": 20, "open_days": 30,
  "target_rent_rate": 12, "pixel_eff_fen": 4000
}
```

🔴 **14 个字段一个不能少** —— 缺一个就可能让整块派生量失效（实跑证据，§十 反例 2）：

| 缺谁 | 后果（实跑） |
|---|---|
| `seats` | 翻台 = `null`（divisor 变 0） |
| `pixel_eff_fen` | 面积上限 = `null`（坪效 ≤ 0 时不编造） |
| `gross_margin_pct`（或整个走 camelCase） | 目标月营收 = `null`、综合变动率 = 100% |

### 4.3 `param_json` → 引擎入参 `clean` 映射（**落地单源**）

| `param_json`（存库形态 · snake） | 引擎入参 `clean`（`validate.js:181-191` 客观形状） |
|---|---|
| `mode` | `mode` |
| `city_tier` | `cityTier` |
| `biz_type` | `bizType` |
| `build_items` | `buildItems` |
| `fixed_items` | `fixedItems` |
| `var_items` | `varItems` |
| `gross_margin_pct` | `grossMarginPct` |
| `target_profit_fen` | `targetProfitFen` |
| `expected_revenue_fen` | `expectedRevenueFen` |
| `rev_price_fen` | `rev_price_fen` |
| `seats` | `seats` |
| `open_days` | `open_days` |
| `target_rent_rate` | `target_rent_rate` |
| `pixel_eff_fen` | `pixel_eff_fen` |

🔴 本表是**唯一**转换处（服务端）。**前端不得转换**（`core/10 §8` 红线 2：转换只在 DataAdapter / 适配层）。

### 4.4 版本化只增与 `sandbox_id` 分组（引 v1.1 §4.1，钉 3 条）

1. 🔴 **`sandbox_id` 是必需的分组键** —— 缺了它，同一沙盘存 5 次 = 5 条"看起来无关"的记录 ⇒ 列表页显示成 5 个沙盘；
2. 🔴 **只 INSERT 不 UPDATE**；旧版本**软删**（`is_deleted=true` + `delete_at`），`is_deleted` **只对同 `sandbox_id` 的旧版本**生效；
3. 🔴 **`version` 在服务端算**（`max(version)+1`），前端不得传。

### 4.5 列表查询上限

🔴 必须有**显式上限**，单源 `common/dataAdapter.js::LIST_LIMIT`；
「要全部行」的场景一律走 `da.listAll()`（短页 = 到底判据），**不得**依赖聚合绕过上限。
