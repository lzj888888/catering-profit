# 实施顺序（严格按阶段推进，不许跳步）

## 阶段 0 · 地基
- 建全部数据表（见 `01_架构总览.md` 第 1.6 节）。标注"已锁定"的表严格照做；标注"草案"的表按草案建，有更好设计可提出但要说明理由。
- 打通 `shop_id` 隔离：所有查询/写入强制带 `shop_id`，建复合索引。
- 建 `audit_log` 与统一软删除机制（`is_deleted` + `delete_at`，30 天清理）。

## 阶段 1 · POC 先验证三个复杂逻辑（**不要跳过**）
在写完整页面前，先用最小代码验证这三处最容易写错的地方，跑通了再全量开发：

1. **摊销并行 + 边界"含两端"**
   - 3 条资产并行（120,000/36、30,000/24、6,000/60）
   - 区间 `[开始月, 截止月]` **两端都含**；开始当月即摊、终止当月仍摊、到期当月仍摊、次月起停
   - 末月尾差倒挤，保证总和严格 = 原值
   - 终止产生残值 → 转"资产处置损失"
   - 验收：测试集 **2b 逐月断言表**

2. **BOM 两层 + 循环引用拦截**
   - 半成品 → 成品菜，最多 2 层；半成品**不能**引半成品
   - 保存时递归检测引用链出现自身 → 拦截，错误码 `BOM_CYCLE_DETECTED`
   - 验收：测试集 **3.3 / 3.4 / 3.5**

3. **双利润口径锁**
   - 开库存后，**经营参考利润仍用"用户直接填的消耗"**，只有全要素真实利润用倒轧值
   - 两者差异必须 = 库存差 + 摊销
   - 验收：测试集 **S2**（经营参考 9,160 / 全要素 3,476.67）

# 12 条全局铁律（违反即打回重写）

1. 金额 = **整数分**（INT），禁 JS Number 原生浮点运算；展示 ÷100 保留 2 位
2. 重量 = **克**（采购单位经 `换算系数` 换算到 g）
3. 时间 = **Unix 毫秒**；记账年月 = **`YYYY-MM` 字符串**
4. 百分比 = `DECIMAL(5,2)`（35.00 表示 35%，不是 0.35）
5. **shop_id 隔离**：所有查询/写入强制带 `shop_id`，复合索引
6. **计算下沉云函数**：禁前端算毛利/摊销/成本/保本
7. **配置读表，禁硬编码**：套餐价格、功能限额一律读 `subscription_plan` / `feature_permissions`
8. **归档不可改**：`is_archive=true` 后禁 update 主记录金额，错账只新增调整记录
9. **操作必留痕**：影响利润/成本的操作写 `audit_log`，只 INSERT 不可删改
10. **删除 = 软删除**：`is_deleted` + `delete_at`，30 天内可恢复
11. **待结算不进利润**：外卖/团购待结算是现金流指标，绝不进入毛利/净利
12. **开关纪律**："收入的开关""其他方面接触的开关"等配置项**原貌保留**，不得清理/合并/删减

## 补充铁律（模块级）

- **毛利铁律**：毛利 = 收入 − 营业成本（**仅食材耗材**）。**房租/人工绝不算进营业成本**
- **双口径锁**：开库存后经营参考仍用直接填消耗（见阶段 1 第 3 条）
- **成本卡只 INSERT 不 UPDATE**
- **辅料同损耗口径**：辅料与原料**一并**按 `(1−制作损耗率)` 放大。此口径锁定测试值 **9.75**，若你"优化"成只对原料放大，结果会变 9.73 → **直接判定不通过**
- **Service 二次重算**：前端传来的 `total_cost` / 利润 / 毛利率等计算结果**一律丢弃不采信**，由 Service 层用原始录入数据重算
- **M2 / M3 不得读取或回写 M1 真实经营数据**
- **多端适配必过**：所有页面必须满足《多端适配核对表》**AD-1~AD-21**（见 `04_核对清单.md` 第 F 章）：深色模式、大字体、字号/按钮下限、日期跳变、iOS 小数键盘收起、输入防抖、弱网缓存、换机同步、隐私单独同意、虚拟支付双端费率等。**生成后须真机逐条实测，不得只看代码**
- **文案禁止硬编码**：所有页面标题/按钮/弹窗一律从 `i18n/terms.js` 文案表取词（依据 `06_工程治理与运维规范` §9.3 + `外显话术库与按钮文案_v1.1.md`）。付费按钮**必须带功能名**（如「开通真实利润」），**禁止**「开通会员」「立即订阅」
