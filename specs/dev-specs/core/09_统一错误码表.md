# 统一错误码表（锁定版 · 可作写码 AI 输入基线）

> 创建：2026-09-11（补「收口体检」P1-①）
> 用途：所有云函数、所有批次**共用同一套错误码**；前端**禁止自定义错误码 / 硬编码错误文案**，一律按 `code` 从 `i18n/terms.js` 映射展示文案。
> 配套：本表与 `10_云函数清单与接口契约.md`、`prototype/init_db.js` 同步锁死。

---

## 0. 返回格式（全局统一）

所有云函数统一返回：

```json
{ "code": "SUCCESS", "msg": "ok", "data": { } }
```

- `code`：下表中的字符串常量（**不得新增未列于此的码**，确需新增须同步更新本表 + `i18n/terms.js`）。
- `msg`：机器可读短描述（英文/拼音均可），**不直接展示给用户**；用户看到的文案由前端按 `code` 映射 `i18n`。
- `data`：业务数据；失败时可为空。

## 1. 错误码全集

### 1.1 基础 / 鉴权（批次 0 地基）

| code | 含义 | 触发场景 | i18n key |
|---|---|---|---|
| `SUCCESS` | 成功 | 正常返回 | `OK` |
| `UNAUTHORIZED` | 无法识别用户 | 无 OPENID / 未登录 | `ERR.UNAUTHORIZED` |
| `USER_NOT_FOUND` | openid 未建档 | 理论上**极少触发**（批次 0 鉴权中间件在首次进入已自动建档 `user`+`shop`+`entitlement`）；仅当建档异常/失败时返回 | `ERR.USER_NOT_FOUND` |
| `FORBIDDEN` | 无权访问该资源 | `shop.user_id !== 当前user.id`（越权） | `ERR.FORBIDDEN` |
| `RATE_LIMITED` | 触发限流 | 写操作 > 60 次/分钟（openid 维度） | `ERR.RATE_LIMITED` |
| `INVALID_PARAM` | 参数校验失败 | 金额为负 / 日期非法 / 必填为空 / 枚举越界 | `ERR.INVALID_PARAM` |

> 🔢 限流阈值口径（唯一声明处）：`RATE_LIMITED` 触发阈值 = **60** 次/分钟（窗口 **60000** ms，openid 维度）；
> 代码单源 `cloudfunctions/common/rateLimit.js` 的 `MAX_WRITES` / `WINDOW_MS`，42 份扁平副本 `cx_rateLimit.js` 须同值，
> 由 `tools/check_rate_limit_params.js`（R113）双向比对。改任一侧而另一侧不跟 ⇒ 门禁当场判红。

### 1.2 资源 / 业务状态

|---|---|---|---|

| `SOFT_DELETED` | 资源已软删 | 操作 `is_deleted=true` 的记录 | `ERR.SOFT_DELETED` |
| `ARCHIVED_LOCKED` | 归档月只读 | 修改 `is_archive=true` 的月度数据 | `ERR.ARCHIVED_LOCKED` |
| `SNAPSHOT_IMMUTABLE` | 历史快照不可改 | 尝试 UPDATE 成本卡历史版本 | `ERR.SNAPSHOT_IMMUTABLE` |

### 1.3 配额 / 付费（对齐 v1.4）

| code | 含义 | 触发场景 | i18n key |
|---|---|---|---|
| `FREE_LIMIT_EXCEEDED` | 超出免费配额 | M1 账套 >1（`shop` 有效店铺数）、M3 成本卡 >5（按 `shop_id` 统计、按 `card_id` 去重，仅 `is_deleted=false` 计数）；**M2 永久全免费不限套**；硬上限另见 `HARD_CAP_EXCEEDED` | `ERR.FREE_LIMIT` |
| `HARD_CAP_EXCEEDED` | 触发系统硬上限 | 防滥用总闸（付费用户亦不可超）：M1 账套 200、M3 成本卡 2000、摊销资产 200 | `ERR.HARD_CAP` |
| `FEATURE_LOCKED` | 功能未开通 | 真实利润/导出等需权限功能，但 `expire_at` 已过 | `ERR.FEATURE_LOCKED` |
| `PLAN_MISMATCH` | 套餐不匹配 | 订单套餐与权益预期不符（内部对账用） | `ERR.PLAN_MISMATCH` |

### 1.4 M2/M3 业务算法

| code | 含义 | 触发场景 | i18n key |
|---|---|---|---|
| `BOM_CYCLE_DETECTED` | BOM 循环引用 | 半成品依赖链出现自身（深度 ≥2 层） | `ERR.BOM_CYCLE` |
| `BOM_DEPTH_EXCEEDED` | BOM 嵌套过深 | 依赖超过 2 层业务上限（检测冗余 5 层） | `ERR.BOM_DEPTH` |
| `M2_RED_ALERT` | 沙盘红警 | 综合变动成本率 ≥100%，不计算负数保本 | `ERR.M2_RED_ALERT` |
| `AMORT_TERMINATED` | 资产已终止 | 查询已终止/已到期资产的摊销（返回 0，非错误） | `OK` |

> ⚠️ **红警不通过响应 `code` 返回本码**：沙盘红警是正常业务态，云函数应返回 `SUCCESS` 且 `data.redAlert=true`，前端据此展示"当前结构无法盈利"提示文案；**不要**把 `M2_RED_ALERT` 当作 `code` 返回（否则会弹错误窗）。本码仅作语义标识/内部日志用途。详见 §2.4 铁律 4。
> ⚠️ **表格结构纪律**：上表 4 行须紧邻表头连续排列，**禁止**把表格行写在引用块（`>`）之后 —— 引用块会切断表格，被挤出的行在 Markdown 中不再渲染为表行（本表 `AMORT_TERMINATED` 曾因此被挤出，2026-09-12 修正）。

## 2. 使用铁律（写进各批次强制项）

1. **只用本表码**：禁止各批次自造错误码（如 `ERR_xxx`、`1001`）。确需新增 → 先改本表 + `i18n/terms.js`。
2. **文案走 i18n**：`msg` 不展示给用户；前端 `switch(code)` 或直接用 `i18n.t('ERR.XXX')`，**禁硬编码中文提示**。
3. **幂等命中当成功**：`ORDER_DUPLICATE` / `ADMIN_OP_IDEMPOTENT` 返回 `code=SUCCESS`（i18n key `OK`，前端不展示文案；**勿写成 `code=OK`** —— `OK` 是 i18n key 不是 wire code），不报错、不重复处理。
4. **红警非错误**：M2 红警 `M2_RED_ALERT` 是正常业务态，返回成功 + `data.redAlert=true`，前端展示提示文案，不弹错误窗。
5. **鉴权最先做**：`auth` 中间件在 Controller 最前，未过即返回 `UNAUTHORIZED`/`FORBIDDEN`，**不进入业务逻辑**。

## 3. 前端文案映射表（i18n key → 中文展示，落地于 `i18n/terms.js` 的 `ERROR_MESSAGES`）

> 前端**禁止**在 wxml/wxss 硬编码中文提示；一律 `const msg = msgOf(res.code)`（`msgOf` 定义在 `i18n/terms.js`）。下表为 i18n key 的单一来源，改动须同步 `i18n/terms.js`。
>
> ⚠️ **wire code ≠ i18n key（易错，务必注意）**：后端返回的 `res.code` 是 §1 左列的 wire code（如 `FREE_LIMIT_EXCEEDED`），本表左列是 i18n key（如 `ERR.FREE_LIMIT`）。**直接写 `ERROR_MESSAGES[res.code]` 会 100% miss 并回落成「系统异常，请稍后重试」**，导致所有业务提示失效。取值必须经 `CODE_TO_I18N` 转换 —— 用 `msgOf(res.code)`，或 `ERROR_MESSAGES[CODE_TO_I18N[res.code] || 'ERR.SYSTEM']`。三向一致性（§1 code 列 ↔ §3 i18n key 列 ↔ terms.js 键集合）由 `prototype/check_error_codes.js` 机械断言。
