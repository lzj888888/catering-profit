> 创建：2026-09-11（补「收口体检」P1-②）
> 用途：单一文档列出**全部云函数 → 入参 / 出参 / 归属批次 / 鉴权**，防止前端（批次 4/7）与后端（批次 1/2/3/5/6）各自生成导致命名/字段错位。
> 🔢 **全集口径（唯一声明处）**：本表共登记 **42** 个已部署云函数（`cloudfunctions/` 下除 `_adminCore` / `common` 两个非函数目录之外的全部目录）。该数字与目录的**双向一致**由 `tools/check_fn_inventory.js`（R98）机器校验 —— 新增/删除云函数后**只改这一处**，改错即转红。⚠️ 其它文档里的「N 个函数」多为**子集或历史快照**（如「只部署了 2 个」= 2026-09-18 实测快照、「44 个」= 目录数、「补 6 个函数自测」= 批次子集），**不是**全集口径，守卫不判它们；引用全集请以本行为准。
> 配套：与本表同时锁定的 `09_统一错误码表.md`、`prototype/init_db.js`。
> 通用约定：**所有函数经批次 0 鉴权中间件**（除 `initDb`/`payCallback` 见注）；所有写操作带 `client_request_id` 幂等；金额分、时间 Unix 毫秒 UTC、月份 YYYY-MM；返回格式见错误码表。
>
> 🔴 **本表字段名一律 `snake_case`（云函数契约层形态）＋ 金额一律「分」整数**（`*_fen`）——对齐批次 0 §2.9 与 §8.2，并与批次 1 已上线实现 `cloudfunctions/calcMonthlyProfit/index.js:90-137` 逐字一致。
> 本表**不列大写小驼峰形态**：前端 `camelCase` 由 DataAdapter / 前端适配层转换（§8.2），**禁止**在 Service / 业务逻辑层混用。
> 本表**不出现 `*_yuan` 入参**：backend receive "分" integer；元仅为 UI 展示单位（`prototype/` 下的原型验算脚本属另一套内部形态，不在本契约约束面内）。

## 0. 通用入参 / 出参约定

- **鉴权注入**：`cloud.getWXContext()` 取 OPENID → 中间件解析出 `user.id` 与 `shop_id`（业务请求体可带 `shop_id`，但**权限主体以 `user_id` 判定**）。
- **标准响应**：`{ code, msg, data }`（详见 `09_统一错误码表.md`）。
- **分页**：列表类入参 `{ page, page_size }`，出参 `{ list, total }`。
- **首次建档（批次 0 负责）**：用户首次进入、鉴权中间件解析出 OPENID 后，**必须自动建档** `user`（openid→user_id）、一个默认 `shop`、以及 `shop_entitlement`（`user_id` 唯一，`expire_at=0`，视为免费档）。后续 `payQueryEntitlement` 对该记录返回 `is_active:false`，**不要**因查不到而报 `RESOURCE_NOT_FOUND`。

> 锚点：POC4/S4（固定 21,300 / 变动率 45% / 边际 55% / 保本 38,727.27 / 日均 1,290.91 / 目标 66,000 / 日均 2,200；红警≥100%→null）。**v1.0 仅正算，反推（M2.12）排 v1.1**。
>
> ⚠️ **单位口径**：上表 `*_fen` 均为「分」整数（原表写作 `rentYuan` 等「元」，与「金额一律分、禁浮点」铁律冲突，已随 R20 一并纠正）。锚点数值仍以「元」表述（保本 38,727.27 元 = `break_even_monthly_fen = 3872727`），**对照时按 ×100 换算**。`prototype/calcM2.js` 内部沿用「元」入参的另一套验算形态，属 POC 验算脚本，**不是**契约，批次 4 实现以本表为准。
>
> ⚠️ **百分比 / 比率命名口径（R41，2026-09-17 立）** —— 曾出现同一返回体内 `composite_var_rate_pct`（百分数 45）与 `margin_rate_pct`（比率 0.55）同名后缀、单位相反，消费者照名字直用会静默显示错值（0.6% 而非 55%）。现立三条：
> 1. **`_pct` 恒为百分数**：`45` 表示 45%，`gross_margin_pct = 65.18` 表示 65.18%。
> 2. **`_ratio` 恒为比率**：`0.55` 表示 55%，显示前必须 ×100。**禁止**把比率塞进 `_pct` 字段。
> 3. **其余语义字段不得带这两个后缀**，避免暗示单位。跨层同义字段在本表成对登记，例如 `loss_pct`（wire 入参）↔ `loss_rate`（DB 列）—— **两者均为百分数**，属层间命名映射，**非**单位差异。

## 8. 命名与字段一致性红线

1. **函数名即契约**：前端按本表函数名 `callFunction`，**不得自造**。本文档已统一为 `calcMonthlyProfit`/`calcAmortize`/`calcSandbox`/`calcBom`（无模块前缀，与批次 1/2/3/4 指令一致）；M3 另含 `getMaterial`/`saveMaterial`/`getCostCard`/`saveCostCard`/`syncCostCard`/`detectCycle`（对齐批次 3 命名约定）。任何批次生成的函数名若与本文档不符，以本文档为准统一改名。
2. **字段名锁死 + 命名映射**：数据库 / 云函数出入参一律 `snake_case`（`expire_at`、`is_deleted`、`client_request_id`、`shop_id`、金额后缀 `_fen`、时间后缀 `_at`），前端 JS/WXML 一律 `camelCase`（`expireAt`、`clientRequestId`、`planId`）；`snake_case ↔ camelCase` 转换**只在 DataAdapter 层或前端适配层**做，业务逻辑/Service 层禁止混用。前后端绑定的字段名必须一致。详见批次 0 §2.9。
   > ⚠️ **本表第 1~7 章列出的入参 / 出参 = 云函数契约层形态（`snake_case` + 金额 `*_fen`）**，不是前端形态；前端侧需经 DataAdapter / 前端适配层转 `camelCase`。**禁止**以"前端调用形态"为由在本表里留存 camelCase 入参 —— 那是 R20 要消除的错位来源。
3. **主体维度**：权限/订阅/订单主体=`user_id`；`shop_id` 仅业务关联；免费配额按 `shop.is_deleted=false` 计数。
4. **计算下沉**：所有 `*Calc*` 函数为 Service 层纯逻辑，前端**只展示**其返回值，不重算。
