## 0 一句话结论

> **三平台的外卖账是同一副骨架：`商家到手 = 优惠前总额 − 商家承担补贴 − 佣金 − 配送服务费 − 其他支出`。**
> 我方 §A.11 的配平式与它同构，**不用改**；真正要补的是「有效订单数」这个**第 4 个必填**，
> 以及把「商家承担补贴 = 三列相加」这件事钉在输入框边上（只抄一列 ⇒ 本店 8 月少扣 1278.02 元）。

## 3 `qty` 字段契约

```
sub_items[]: { sub_item: string, amount_fen: int(分, ≥0), qty?: int(单, ≥0) }
```

- **可选**：不传即不存（老客户端、老数据均不受影响）；
- **严格**：传了就必须是**非负整数**（不接受字符串，与 `amount_fen` 同严）—— 静默丢弃用户填的订单数比报错更糟；
- **回读**：`getLedger` 出参 `sub_items[].qty` 同名返回；库内无该字段的行**不带该键**（前端按「未填」处理）；
- **落点**：`saveLedger/validate.js`（校验）→ `saveLedger/index.js`（落库映射）→ `getLedger/index.js`（出参，两处映射）。

## 4 硬约束：qty 绝不进金额

> **qty 是一维数量，与金额相加没有意义。**
> 禁止出现在：`subtotalOf` / `reconcile` / 任何金额求和 / 大类金额汇总（`sum += amt`）。
> 由 `tools/selftest_r85.js` A26-4 机器把守（含源码级反查），并由 R162 变异回灌 M1 证明其有效。

## 6 抄数口径（必须钉在界面上）

1. **只抄商家承担部分**，平台承担部分不要填（概览页「活动补贴 384」是总额，账单「商家活动成本 198」才是商家承担，差 186）。
2. **商家承担补贴是三列**，只抄「商家活动补贴」一列 ⇒ 少扣 1278.02 元、利润虚高。
3. **按账单日期 / 订单完成时间归月**，不要按「结算日期」（账期 3 天 ⇒ 结算日跨月）。
4. **有效订单不含退单**。
5. **防多填**（R163 补）：平台承担补贴**不得**抄进收入侧 —— 它不进商家到手，填了会多扣、利润虚低。
   与第 1 条是同一件事的两侧：少抄 ⇒ 虚高，多填 ⇒ 虚低。
6. **打包费是加项、不是减项**（R163-A 实测）：`到手 = 商品金额 + 打包费 − 商家补贴 − 佣金 − 配送服务费 − 其他`。
   漏把它当加项 ⇒ 逐行差恒等于单均打包费、汇总差恒等于打包费合计（本店 167.00 / 2.00）。
   我方 §A.11 配平式里的「外卖收入合计」已含打包费，**与平台同构，无错**；要防的是客户把打包费又填进费用页。
7. **退单行符号是冲回**（R163-B 实测）：退单行的补贴/佣金为**正数返还**，不是扣减；
   校验脚本必须**带符号相加**，不得一律取绝对值相减（本店 6 行退单，用绝对值会全部判为不符）。

## 7 机器对账等式（R163 · 已用 156 行逐行自证）

```
到手（结算金额）= 商品金额 + 打包费
                + Σ商家侧补贴（活动 + 代金券 + 配送费活动）
                + 佣金（技术服务费）
                + 配送服务费
                + 其他支出
                （各扣减项在淘宝账单里本身记负数 ⇒ 原样相加）
```

- 自证：淘宝闪购 2026-08，156 行**逐行零误差**；加总 `6418.08 + 167.00 − 2069.70 − 158.71 − 577.02 = 3779.65` ≡ 实际到手。
- **符号约定不硬编码**：先扫 `gross>0` 的正常行，看扣减列多数为负 ⇒ 原样相加；多数为正 ⇒ 取反相减。
  退单行天然反号，**不参与探测**。美团若记正数，同一脚本无需改码。
- 工具：`review/evidence/r163_waimai/parse_bill.py`（零依赖，zipfile + xml.etree）。

## 8 配平校验式的**实现修正**（R164 · 真值证伪）

**锁定版 A.11.4(b) 的式子字面不改**：`应有商家应收款 ≈ 外卖收入合计 − 商家活动补贴 − 佣金 − 配送服务费 − 配送补贴`。

但**实现**必须分两步，否则补贴一次都没扣：

```
优惠前总额   = 外卖收入合计 − 补贴框的值      // 收入侧三框相加里本来就含了补贴，先按原符号抵消掉
应有到手     = 优惠前总额 − |补贴框的值| − 佣金 − 配送服务费 − 配送补贴
                          ↑ 取绝对值：客户填正数（补贴金额）或填负数（照抄账单）都得同一个答案
```

**为什么必须这样（真值证伪，非推测）** —— 8 月实测账单：
商品 6418.08 / 打包 167.00 / 商家补贴 2069.70 / 佣金 158.71 / 配送 577.02 / 真实到手 3779.65

| 实现 | expected | 与真实到手的差 |
|---|---|---|
| 只减一次补贴（修前） | 5849.35 | **−2069.70（≡ 一个补贴额）⇒ 恒定误报"漏填 2069.70"，客户改无可改** |
| 两步走 + 绝对值（修后） | **3779.65** | 0 ✔ |

规范 A.11.4(b) 的注解写的是「因收入口径含商家活动补贴、费用侧又把同一笔自动带出，**两者相抵**」——
这句话描述的**正是这个缺陷**：相抵之后补贴就一次都没扣。式子只在「收入合计不含补贴」的前提下才成立。

> 🔴 **仍未解决（更严重，需李老师拍板，见 NOTE_2026-09-28_round164）**：
> 收入侧三框相加含补贴、费用侧又自动带出同一笔 ⇒ **补贴在利润计算里同样被抵消（或双扣）**。
> 填正数 ⇒ 利润虚高一个补贴额；填负数 ⇒ 利润虚低一个补贴额 —— **无论客户怎么填都错**。
> 本条修正**只动了配平校验（软提示）**，未动利润口径。
