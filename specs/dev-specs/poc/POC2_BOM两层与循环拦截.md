# 任务

实现「**菜品成本卡计算 + BOM 两层嵌套 + 循环引用拦截**」这一**个**能力的 POC。**只做这一件事**，不做页面、不做数据库、不做其他模块。

# 项目背景

微信小程序 + 微信云开发的餐饮算账工具，给中小餐饮老板用。
**金额一律用「分」为单位的整数存储与计算**（1 元 = 100 分），展示 ÷100 保留 2 位。**重量单位统一为「克（g）」**。禁止浮点存金额。

# 本次范围（严格限定）

纯计算 + 校验模块（云函数即可）：

- `calcDishCost(card)` → 计算单品原材料总成本、毛利、毛利率
- `detectBomCycle(card, allCards)` → 检测半成品循环引用
- 批量预制（半成品）保存后，**自动生成虚拟原料**
- 原料价格变动时，**已保存的成本卡不受影响**（快照机制）

# 规则（必须严格遵守）

## 一、原料成本

```
采购每克成本 = 采购单价 ÷ 换算系数（换算到 g）
净料单位成本 = 采购每克成本 ÷ (出成率 ÷ 100)
```

## 二、单品成本（核心公式）

```
明细净料成本合计 = Σ(每行用量 × 该行净料单位成本快照)

单品原材料总成本 = (明细净料成本合计 + 辅料综合分摊成本) ÷ (1 − 菜品制作损耗率 ÷ 100)
```

> ⚠️ **建模假设（不得"优化"）**：**辅料与原料一并按 `(1 − 制作损耗率)` 放大**（假定辅料在烹制中同样有损耗）。
> 如果把辅料排除在放大之外，下面的测试用例会从 **9.75 变成 9.73** —— 那就是错的，必须改回来。

## 三、批量预制（模式 B）

```
整批总成本 = (整批明细净料成本合计 + 辅料) ÷ (1 − 制作损耗率 ÷ 100)
单份半成品成本 = 整批总成本 ÷ 本批次总产出份数
```

保存后**自动生成虚拟原料**：`is_virtual = true`，名称 = 半成品名，**采购单位 = 份**，**换算系数 = 1**，`净料单位成本` 字段**实际存的是「每份成本」**（不是每克）。

## 四、BOM 层级与循环引用

- **最多 2 层**：成品菜可以引用半成品；**半成品不能再引用半成品**
- 保存时递归遍历引用链，**若链中出现自身 ID → 拦截**，抛错误码 `BOM_CYCLE_DETECTED`，数据不入库
- 严格 2 层时循环理论上不可能发生，但**此校验必须保留**（防止层级校验被绕过、防止未来放开层级）

## 五、快照机制（核心红线）

- 保存成本卡瞬间，**复制**原料的单价 / 换算系数 / 出成率 / 净料单位成本到明细行的快照字段
- 之后修改原料档案，**不自动更新**已保存的成本卡
- 只有用户手动点「同步至原料最新价格」才更新，且**生成新版本**，旧版本保留

## 用例 A · 单份菜品：宫保鸡丁（第 0 层）

单份模式，制作损耗率 **5%**，辅料 **0.50 元/份**，建议售价 **28 元**

| 原料 | 用量(g) | 净料成本(元) |
|---|---|---|
| 鸡胸肉 | 200 | 6.6667 |
| 花生米 | 50 | 1.0000 |
| 干辣椒 | 10 | 0.4000 |
| 葱姜蒜 | 30 | 0.3000 |
| 调料油 | 20 | 0.4000 |
| **明细合计** | | **8.7667** |

**预期**：
- 单品原材料总成本 = (8.7667 + 0.50) ÷ 0.95 = **9.75** ⚠️（不是 9.73）
- 单品毛利 = 28 − 9.75 = **18.25**
- 单品毛利率 = **65.18%**
- 反算：目标毛利率 60% → 售价 = 9.75 ÷ (1 − 60%) = **24.38**

## 用例 B · 批量预制：红油底料（第 1 层）

批量模式，产出 **10 份**，损耗率 **0%**，辅料 **2.00 元（整批）**

| 原料 | 用量(g) | 净料成本(元) |
|---|---|---|
| 牛油 | 500 | 20.00 |
| 干辣椒 | 200 | 8.00 |
| 花椒 | 50 | 4.00 |
| 豆瓣酱 | 300 | 4.80 |
| 香料 | 50 | 6.00 |
| **原料合计** | | **42.80** |

**预期**：
- 整批总成本 = (42.80 + 2.00) ÷ 1 = **44.80**
- 单份半成品成本 = 44.80 ÷ 10 = **4.48**
- 自动生成虚拟原料「红油底料」：单位 = 份，换算系数 = 1，净料单位成本 = **4.48**（即每份成本）

## 用例 C · 引用半成品：麻辣香锅（第 2 层）

单份模式，损耗率 **3%**，辅料 **0.50 元/份**，售价 **38 元**

| 原料 | 用量 | 净料成本(元) |
|---|---|---|
| 红油底料（虚拟原料） | **1 份** | 4.48 |
| 时蔬拼盘 | 500 g | 3.00 |
| 肉丸 | 100 g | 4.00 |
| **明细合计** | | **11.48** |

**预期**：
- 单品原材料总成本 = (11.48 + 0.50) ÷ 0.97 = **12.35**
- 单品毛利 = 38 − 12.35 = **25.65**
- 单品毛利率 = **67.50%**

## 用例 D · 循环引用拦截

创建半成品 A 引用半成品 B；再创建半成品 B 引用半成品 A。
**预期**：保存 B 时检测到循环，抛 `BOM_CYCLE_DETECTED`，**数据不入库**。

## 用例 E · 快照与手动刷新

1. 保存宫保鸡丁（鸡胸肉 15 元/斤，净料 0.03333）→ 总成本 **9.75**
2. 修改原料档案：鸡胸肉 15 → **20 元/斤**（净料变 0.04444）
3. 重新打开宫保鸡丁 → **总成本仍应为 9.75**（快照不受影响）
4. 点「同步至原料最新价格」→ 生成**新版本**：
   - 鸡胸肉新成本 = 200 × 0.04444 = 8.8889
   - 明细合计 = 8.8889 + 1.00 + 0.40 + 0.30 + 0.40 = 10.9889
   - 新总成本 = (10.9889 + 0.50) ÷ 0.95 = **12.09**
   - **旧版本 v1（9.75）必须仍可查**（只新增，不覆盖）
