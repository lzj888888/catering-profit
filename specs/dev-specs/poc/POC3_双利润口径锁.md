# 任务

实现「**月度双利润计算引擎**」这一**个**能力的 POC。**只做这一件事**，不做页面、不做数据库、不做摊销台账（摊销另有 POC）、不做其他模块。

# 项目背景

微信小程序 + 微信云开发的餐饮算账工具，给中小餐饮老板用。
**金额一律用「分」为单位的整数存储与计算**（1 元 = 100 分），展示 ÷100 保留 2 位。禁止浮点存金额。

老板最关心的一句话是"这个月到底赚了多少"，所以**利润必须准**，而且**两个口径不能混**。

# 本次范围（严格限定）

一个纯计算模块（云函数即可）：

```
calcMonthlyProfit(input) → {
  营业收入, 食材成本, 菜品毛利, 毛利率,
  经营参考利润, 全要素真实利润, 两利润差异
}
```

摊销金额本次**由外部传入一个数**（摊销的计算规则另有 POC，这里不重复实现）。

# 规则（必须严格遵守）

## 一、毛利铁律

```
菜品毛利 = 营业收入 − 食材成本
```

⚠️ **食材成本只含「食材耗材」。房租、人工、水电等一律不算进营业成本** —— 它们属于费用，不是成本。

## 二、食材消耗的两种取数

- **库存开关关闭**：直接取用户填的「当月食材耗材总消耗」
- **库存开关开启**：倒轧计算
  ```
  真实食材消耗 = 期初存货 + 本期采购 − 期末盘点
  ```

## 三、两个利润口径（本 POC 的核心考点）

```
🟢 经营参考利润 = 营业收入 − 总费用 − 【直接填的总消耗】（不含摊销）

🔵 全要素真实利润 = 营业收入 − 总费用 − 【真实消耗】− 当月摊销总费用

两利润差异 = (真实消耗 − 直接填消耗) + 当月摊销
```

## 四、⚠️ 口径锁（最容易写错，重点验证）

> **即使开启了库存开关，「经营参考利润」仍然必须使用「用户直接填的总消耗」，不能改用倒轧值。**
> 只有「全要素真实利润」才改用倒轧值。

老板习惯看"经营参考"这个口径，它不该因为开了库存开关就跳变。这是**刻意设计**，不是 bug，**不要"修正"它**。

## 五、待结算不进利润

外卖 / 团购的「待结算金额」是现金流指标，**绝不进入毛利或利润计算**。

# 测试数据

## 场景 S1 · 基础双利润（库存关、摊销关）

## 场景 S2 · 库存 + 摊销（口径锁验证）

**记账月**：2026-08　**库存开关 = 开**　**摊销开关 = 开**
**收入与费用**：与 S1 完全相同（收入 64,000，费用 32,840，不含摊销）

库存：

| 项目 | 金额(元) |
|---|---|
| 期初存货 | 5,000 |
| 本期采购 | 25,000 |
| 期末盘点 | 7,000 |
| **本期真实消耗** | **23,000**（系统算：5,000 + 25,000 − 7,000） |

**当月摊销总费用（外部传入）= 4,683.33**（三条资产并行，摊销算法另有 POC）

**⚠️ 关键**：老板直接填的「当月食材耗材总消耗」仍是 **22,000**（与 S1 相同）。

**预期输出**：

| 指标 | 预期值 | 公式 |
|---|---|---|
| 本期真实消耗 | **23,000** | 5,000 + 25,000 − 7,000 |
| 🟢 经营参考利润 | **9,160** | 64,000 − **22,000** − 32,840（**用直接填值，不是 23,000**） |
| 🔵 全要素真实利润 | **3,476.67** | 64,000 − **23,000** − 32,840 − 4,683.33 |
| 两利润差异 | **5,683.33** | 库存差 1,000 + 摊销 4,683.33 |

> ❌ 如果你算出经营参考 = 8,160（即用了 23,000），说明**违反了口径锁**，必须改回用 22,000。

## 选做 · 2-R 连锁重算（验证期初结转依赖）

在 S2 基础上：把 **2026-07** 的期末盘点从 5,000 改为 3,000 → 2026-08 期初变为 3,000 → 真实消耗 = 3,000 + 25,000 − 7,000 = **21,000**
→ 2026-08 全要素 = 64,000 − 21,000 − 32,840 − 4,683.33 = **5,476.67**
（本次**只需验证数值计算正确**，弹确认、留痕、历史快照保留等交互留到全量开发）

# 明确禁止

- ❌ 不用整数分存金额
- ❌ 把房租 / 人工 / 水电算进「食材成本」（毛利会失真）
- ❌ **开库存后把经营参考利润改用倒轧值**（违反口径锁）
- ❌ 把待结算金额算进利润
- ❌ 让收入合计 / 费用合计可以被手动编辑（必须系统汇总）
- ❌ 做前端页面 / 数据库写入 / 摊销算法（本次只验证双利润引擎）
