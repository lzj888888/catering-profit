## 三、审核测试账号说明（重点：本工具没有账号密码）

**结论：不需要提供账号密码。** 本工具使用**微信授权登录**（云开发 `resolveAuth` 取 openid），
没有注册页、没有短信验证码、没有用户名密码 —— 审核员用自己的微信打开即可完整使用全部功能。

出处：`cloudfunctions/common/auth.js`（`resolveAuth`）；页面侧无登录页（33 个页面里无 login/register）。

**审核员首次打开的路径（建议写进审核备注）**：

1. 打开小程序 → 首页（店铺入口）；
2. 若该微信**从未用过**：按首页引导新建一家店（填店名即可，无需资质材料）；
3. 进入「月度」→「录入」填当月收入与费用 → 保存 → 看「结果」页；
4. 「菜品」→ 新建成本卡 → 填原料与售价 → 看毛利；
5. 「开店测算」→ 填固定成本与变动成本率 → 看保本营业额。

⚠️ **需要李老师确认 1 件事**：生产环境是否有**演示数据**。
若提交审核时环境是空的，审核员首屏是空态引导。两种处理，二选一：
- **A（推荐）**：发布前在 prod 跑一次 `seedDemo`（灌演示店，权益设为验收期长期有效），审核员一进去就有内容；
- **B**：保持空态，在审核备注里写明「按首页引导新建店铺即可，无需任何账号或资质材料」。

> 注：`seedDemo` 受环境门禁保护（仅 dev 放行，`core/06` 铁律），**在 prod 跑需要先确认该政策是否解除**，
> 属李老师决策面，我不代跑。

## 六、付费能力在「提审期」的行为（重要，避免审核误会）

> 🔴 **主体 = 个人**（李老师 2026-11-02 确认）。个人主体**开不了普通微信支付商户号**，
> 唯一合规收费通道是「个人虚拟支付」（需微信认证 + 备案 + 类目含「工具」，2026-08 起开放）。
> ⇒ 提审版本**不展示任何收费入口**，但**功能全部免费开放**。
>
> 🔴 这里刻意区分两件事：**「暂不收费」≠「功能不可用」**。
> 早期实现曾把闸门挂在付费出口上，导致外卖算不了、套餐存不了、复盘整页锁死、导出点不动
> —— 那是把功能砍了，不是把收费关了。现行口径见下表。

| 场景 | 提审期实际行为 | 出处 |
|---|---|---|
| 外卖 / 团购 / 套餐 / 复盘 / 导出 / 多店 | **正常可用**（免费期一律视为已开通） | `utils/entitlement.js::fetchEntitlement` 短路；云端 `common/entitlement.js::hasFeature` 短路 |
| 任何购买入口 | **不存在**：无价格、无购买按钮、无支付、无客服引导 | `utils/paywall.js::openPaywall` 关闭态 |
| 配额上限（1 家店 / 20 道菜） | 提示「当前版本最多支持 N …」，**不含价格与购买引导** | `utils/paywall.js::showFreeLimit` |
| 订单页 / 续费 | 入口不展示；直调也不建单 | `subpkg/tools/pay/orders.js::load/onRenew` |

⇒ **结论**：个人主体 + 提审期免费开放 ⇒ 不影响提审，也不影响功能完整性。
   审核员能看到的是一个**功能完整、无任何收费信息**的工具。
   接好个人虚拟支付后，把前端 `PAYWALL_ENABLED` 改 `true`、云端 `FREE_ACCESS` 改 `false`，
   重新部署受影响云函数即恢复售卖；**其余代码一行不改**。
   守卫 `tools/check_paywall_coverage.js` L9-⑦/⑧ 双向守「关闭态功能仍可用」与「前后端开关同源」。
   ⚠️ 简介/截图按**已开放功能**写即可（付费域此时确实可用），但仍不得出现价格、会员、订阅字样。
