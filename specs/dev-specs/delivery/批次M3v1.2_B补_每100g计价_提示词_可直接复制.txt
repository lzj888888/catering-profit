## 1. 本批要解决的问题（一段话）

麻辣烫 / 卤味 / 凉菜**按重量卖**，计价单位是「100g」，不是"份"。
现有规格机制（`half` 半份 / `small` 小份）是按 `line_kind` **缩放用量** —— 它**表达不了"计价单位不是份"**。
所以这类店要么成本录不准，要么只能拿"一份"硬凑。
本批补一个**恒等规格**：成本照旧（全 1 系数），**差异只在展示层**（页面显示「¥X / 100g」并给一句口径说明）。

## 2. 精确需求（6 处，逐条照做）

### 2.1 服务端单源：加一个规格预设

文件：`cloudfunctions/common/specDerive.js`

在 `SPEC_PRESETS` 数组里**追加一条**（保持现有 `half` / `small` 两条**原样不动**，**不要改它们的顺序与内容**）：

```js
{ spec_key: 'per100g', name: '每100g', coef: { main: 1, aux: 1, season: 1, semi: 1, pack: 1 }, unit_label: '100g' },
```

要点：
- `spec_key` 必须是 **`per100g`**（全小写、无下划线），**一字不差**。
- `coef` **五项全为数字 1**（`main`/`aux`/`season`/`semi`/`pack`，与 `LINE_KINDS` 的键集一致）。
- 新增字段 `unit_label: '100g'` —— 它是**展示单位**（页面拼「¥6.80 / 100g」用），**不参与任何金额计算**。
- **不要**新增 `price_fen` 到这个预设里：预设是**模板**，具体售价属于**每张卡**的数据（见 2.4）。

### 2.2 前端文案（**双副本 + 页面映射 = 三处**，缺一处门禁就会红）

🔴 规矩：新可见文案要落**三处** ——
① `miniprogram/i18n/terms.js`（前端单源）② `specs/dev-specs/i18n/terms.js`（副本，**必须与 ① 逐字节一致**，改完 `cp` 过去并核对 md5 相同）
③ 页面 `.js` 的 `t: { ... }` 映射（否则 WXML 取到 `undefined` ⇒ **静默渲染成空白**，不报错不警告）。

**① + ②：在两个 `terms.js` 的 `TERMS.card.specLabel` 里各加一个键**

```js
specLabel: { half: '半份', small: '小份', per100g: '每100g' },
```

> ⚠️ **这一条是硬约束**：`tools/check_spec_derive.js` 的 **L5-②** 会逐键比对
> 「`terms.specLabel` 的键集」≡「服务端 `SPEC_PRESETS` 的 `spec_key` 集合」。
> 只加服务端不加这里（或反过来）⇒ **门禁立刻转红**。这正是设计意图：**键名漂了 = 系数查不到 = 规格试算静默等于全份**。

**再各加两条展示文案**（`TERMS.card` 命名空间内，**不要新建顶层命名空间**）：

```js
specPer100gUnit: '100g',
specPer100gNote: '按 100g 计价，实际按称重结算',
```

**③：页面 `t` 映射** —— 在 `pages/card/edit.js` 的 `t: { ... }` 里把上面用到的键映射出来（键名与 terms 一致）。

### 2.3 页面展示：规格行显示「¥X / 100g」

文件：`pages/card/edit.wxml` + `pages/card/edit.js`

### 2.4 落库（`specs_json`）—— 不改结构，只是多一个合法取值

`shop_cost_card.specs_json` 的**结构不变**，本批只是让它多接受一个 `spec_key` 取值。
每张卡里该规格条目的 `price_fen` = **用户填的「每 100g 售价」（分）**，`unit_label = '100g'`。
校验（`sanitizeSpecs` / `sanitizeCoef`）需放行这个新键 —— **放行即可，不要放宽其它校验**。

### 2.5 补一条守卫：R141（**本批必须挂，不许留到以后**）

新建 `tools/check_spec_per100g_identity.js`，判据（**必须含反恒真**）：

- **P1**：服务端 `SPEC_PRESETS` 里确实存在 `spec_key === 'per100g'` 的条目（**删掉即红**）。
- **P2**：该条目的 `coef` 五项**必须全部 === 1**（改任一项 ≠ 1 ⇒ **必须转红**）。
- **P3**：**正负互证** —— 脚本内部用同一套判定跑一个**故意带 `coef.main = 0.9` 的合成条目**，该合成条目**必须被判为"不合规"**

> 🔴 只写"存在性"检查 = **假守卫**（永远绿）。P2/P3 是这条守卫的**全部价值**，不许省。

⚠️ 新建守卫文件后，**先 `git add` 再跑门禁**（否则 `suite-tracked` 会报"新 selftest 未登记"）。
⚠️ 本批**不要**自行把它加进 `verify_all.js` 的 `SUITES` —— 登记动作由门禁方统一做（会走 8 处同步清单）。
