# 批次 3 / 8 · POC2 BOM 两层嵌套、循环拦截与成本快照（云函数）

## 1. 批次定位
第 3 批，基于批次 0 地基。**核心目标**：菜品成本卡算法（BOM 两层 + 循环引用拦截 + 快照版本）。历史最高频算错点：辅料损耗口径。

### 2.2 公式
```
采购每克成本 = 采购单价 ÷ 换算系数（换算到 g）
净料单位成本 = 采购每克成本 ÷ (出成率 ÷ 100)

明细净料成本合计 = Σ(每行用量 × 该行净料单位成本快照)
单品原材料总成本 = (明细净料成本合计 + 辅料综合分摊成本) ÷ (1 − 制作损耗率 ÷ 100)
```
> ⚠️ **建模假设（不得"优化"）**：辅料与原料**一并**按 `(1 − 制作损耗率)` 放大。若把辅料排除，宫保会从 9.75 变 **9.73** —— 那就是错的。

**批量（模式 B）**：
```
整批总成本 = (整批明细净料成本合计 + 辅料) ÷ (1 − 制作损耗率 ÷ 100)
单份半成品成本 = 整批总成本 ÷ 本批次总产出份数
```
保存后**自动生成虚拟原料**：`is_virtual=true`，单位=份，换算系数=1，存的是「每份成本」。

### 2.3 用例
- **A · 宫保鸡丁**（单份，第0层）：损耗率 5%，辅料 0.50 元/份，售价 28 元。明细：鸡胸肉 200g(6.66) / 花生米 50g(1.00) / 干辣椒 10g(0.40) / 葱姜蒜 30g(0.30) / 调料油 20g(0.40) → 明细合计 **8.76**
- **B · 红油底料**（批量，第1层）：产出 10 份，损耗率 0%，辅料 2.00 元（整批）。牛油500g(20.00)/干辣椒200g(8.00)/花椒50g(4.00)/豆瓣酱300g(4.80)/香料50g(6.00) → 原料合计 **42.80**
- **C · 麻辣香锅**（引用半成品，第2层）：损耗率 3%，辅料 0.50 元/份，售价 38 元。红油底料 1份(4.48) / 时蔬拼盘 500g(3.00) / 肉丸 100g(4.00) → 明细合计 **11.48**
- **D · 循环引用拦截**：半成品 A 引用 B，再让 B 引用 A → 保存 B 时检测循环，抛 `BOM_CYCLE_DETECTED`，**数据不入库**
- **E · 快照与手动刷新**：保存后改原料价，旧卡成本**不变**；点「同步至原料最新价格」生成**新版本**，旧版本仍可查

### 2.4 写入表、版本与快照说明（对齐第 8 章锁定表与全局规则）
- **存储表（表名/字段必须与第 8 章清单 100% 一致，不得改名/改类型）**：
  - 计算结果写入 `shop_cost_card`（成本卡主表，**只 INSERT 不 UPDATE**）、`shop_cost_card_line`（成本卡明细行，**存净料单位成本快照**）；
  - 批量模式自动生成的虚拟原料写入 `shop_material` 表，标记 `is_virtual=true`（单位=份，换算系数=1，存「每份成本」）。
- **快照字段语义（快照隔离的核心，不得简化）**：成本卡明细行必须**完整存储当时的净料单位成本快照值**，不得仅存储原料 ID 做关联查询——这是快照隔离的本质，保证原料价格后续变动不影响历史成本卡。
- **成本卡版本规则**：每次「同步至原料最新价格」生成新版本时，版本号按自然数递增（v1 → v2 → v3…）；同一成本卡的所有历史版本通过 `card_code` 字段关联，查询默认返回最新版本，旧版本仍可通过版本历史查看。

### 2.5 云函数命名约定（锁死，前端批次 4 按此调用）

本批生成的所有云函数**必须**使用以下名称（无 `m3` 前缀；与 `10_云函数清单与接口契约.md` §3 完全一致），前端（批次 4 的 M3 页面）按此名 `callFunction`：

| `detectCycle` | 循环引用检测（DFS 深度≤5） |

## 3. 强制遵守
- 金额**分（INT）**；中间计算保高精度，**总成本 round 到整数分**（口径 B：中间保精度，最终 round 到分）
- **成本卡只 INSERT 不 UPDATE**（改 = 另存新版本）；版本号自然数递增，经 `card_code` 关联历史版本
- **BOM 限 2 层**，循环引用必须拦截；循环检测采用**递归深度优先遍历，最大深度限制 5 层**，检测到依赖环立即抛 `BOM_CYCLE_DETECTED`、终止保存、**数据不入库**（2 层为业务上限，5 层检测做冗余兜底）
- 云函数过批次 0 鉴权，带 `shop_id`
- **分层归属**：核心计算函数为 **Service 层纯逻辑**，不直接接触数据库与前端请求；Controller 层调用前**必须先过批次 0 鉴权中间件 + 参数校验 + `shop_id` 归属校验**，再把干净数据传入 Service
- **软删除默认过滤**：已软删除（`is_deleted=true`）的原料、成本卡**默认不参与计算与查询**，由 DataAdapter 层统一注入过滤条件，业务层无需单独处理

## 4. ✅ 明确禁止
- ❌ 不做前端页面
- ❌ 不把辅料排除在损耗放大之外（会得到 9.73，错误）
- ❌ 不做自动联动更新（必须手动同步才生成新版本）
- ❌ 不用 UPDATE 覆盖历史版本

- ❌ 不实现双利润/摊销（批次 1/2 已做）
