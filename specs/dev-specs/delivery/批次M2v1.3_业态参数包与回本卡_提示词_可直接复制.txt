## 1. 本批要解决的问题（一段话）

现在 M2 沙盘对**餐饮小白**门槛太高：要填毛利率、水电占比、坪效、翻台率……他填不出来。
本批引入 **「业态参数包」**：小白只填 **5 个数**（业态 / 面积 / 月租金 / 员工数 / 目标利润），
其余参数**整套**由参数包供给；参数包的每一项带 **`cost_meta` 成本形态**
（固定 / 面积线性 / 人头线性 / 营收比例 / 阶梯），由 **`assembleItems()`** 装配成**金额**喂引擎。

再补两件展示物：**回本参考卡**（M2 底部只读，两口径）与 **对比表导出**（图片免费 / Excel 付费）。

🔴 **引擎零改动** —— 与 v1.1「反推 = 剔 `rent` + 加租金率」完全同构。

### 3.2 `costMeta` 五形态（🔴 本批最高风险点）

| 形态 | 必填参数 | 装配式（`assembleItems()` 内） | 落点 |
|---|---|---|---|
| `fixed` | `defaultYuan`（**仅"参数包供给"的项需要**） | 用户填了 ⇒ 用它；没填 ⇒ `defaultYuan × 对应系数的 coef` | `fixed_items` |
| `area_linear` | `baseYuan` + `perSqmYuan` | `base + perSqm × 面积`（🔴 **不乘**系数） | `fixed_items` |
| `headcount_linear` | 无（单价取 `params.laborUnitYuan.v`） | `单价 × coef.labor × 人数` | `fixed_items` |
| `revenue_rate` | `pct` | **直接给 `pct`**（不换算成金额） | `var_items` |
| `step` | `steps: [{upToYuan, yuan}]` | 按**租金档**查表命中的 `yuan` | `fixed_items` |

🔴 **`fixed` 必须带 `defaultYuan`** —— L1 小白只填 5 个数，`utility` / `other` / `manage` 这类
他**不会填**，必须由参数包供给 ⇒ **参数包里得有地方存这个数**。
取值优先级：**用户填 > `defaultYuan`**（二选一，**不叠加**）。

🔴 **`area_linear` / `step` 本期「无预设使用」**（§3.4 的 6 个预设只用到前三种）——
它们是**能力储备**，但 **`assembleItems()` 必须实现这两种形态**，且**必须自测**（§9.1）。

### 3.3 `buildRef`（建店投入**参考** · 必读）

```js
buildRef: [ { key: 'other', fen: 26200000, years: 3.579234972677596, src: 'P' } ],
```

- 🔴 **折旧/建店投入只能走这里** → 装配进引擎的 `buildItems`，由**引擎**算摊销。
- 用户填了真实建店投入 ⇒ **用用户的**；没填 ⇒ 用 `buildRef`。**两条路二选一，不得叠加**。
- 📌 **年限必须写足小数位**：写 `3.5792` 会把摊销算成 6,101 元、保本漂 0.2 元（实测）。

## 4. 入参装配（`assembleItems` · 🔴 唯一入口）

### 4.1 签名与输出

```js
// utils/bizPreset.js
function assembleItems(preset, input, coef) {
  // input: { area, headcount, rentYuan, fixedYuan:{}, buildItems:[] }
  // coef:  { rent, labor }  ← 城市系数（见 §4.3）
  // 返回: { fixedItems: [{key, fen}], varItems: [{key, pct}] }
}
```

🔴 **输出只有这两种形状**，与引擎入参**完全同形**。
🔴 **本函数内不得出现任何保本 / 毛利 / 摊销算式** —— 它只做"用户输入 + 参数包 → 引擎入参"。

### 4.2 形态运算规则（照抄）

```
fixed      → 用户填了 input.fixedYuan[key] ⇒ 用它的值（**不乘** coef，因 src='U'）
             没填且该形态项有 defaultYuan ⇒ 用 defaultYuan × coef[key]（coef 无该键 ⇒ ×1）
area_linear→ fixedItems.push({key, fen: 分(baseYuan + perSqmYuan × area)})   ← **不乘** coef
headcount  → fixedItems.push({key, fen: 分(params.laborUnitYuan.v × coef.labor × headcount)})
revenue_rate→ varItems.push({key, pct})            ← 直接给 pct，不换算成金额
step       → fixedItems.push({key, fen: 分(按 rentYuan 查 steps 表命中的 yuan)})   ← **不乘** coef
```

🔴 **金额一律「分」整数**（`Math.round(元 × 100)`）；**占比一律百分数**（5 表示 5%）。

### 4.3 🔴 城市系数怎么乘（**最容易写错的一条**）

| 形态 / 值来源 | 乘不乘 `coef` | 例 |
|---|---|---|
| `fixed` · **用户填**（`src:'U'`） | ❌ **不乘** | 房租是用户所在城市的**实际值**，再乘就错了 |
| `fixed` · **参数包供给**（走 `defaultYuan`） | ✅ **乘** `coef[对应项]` | 人工 × `coef.labor`；估算型房租 × `coef.rent` |
| `area_linear` | ❌ **不乘** | 参数已是元/㎡ **绝对成本**；城市差异应由**分城参数包**承担，乘系数 = **双重折算** |
| `headcount_linear` | ✅ 乘 `coef.labor` | 人工单价是**二三线基准** |
| `revenue_rate` | ❌ 不乘 | 占比本身与城市无关 |
| `step` | ❌ 不乘 | 档位金额已是绝对元 |

🔴 **系数不得硬编码**：从 `cloudfunctions/common/indicatorRef.js::CITY_TIERS` 取
（`tier1 {rent:1.20, labor:1.15}` / `tier23 {rent:1.00, labor:1.00}` / `county {rent:0.75, labor:0.85}`）。
若前端不便 require 云函数代码，**允许在前端常量里复刻这三个数**，但 🔴 **必须加注释标明单源出处**，
且**不得只写 rent 漏掉 labor**（实测：漏乘 labor ⇒ 一线固定成本退回与二三线相同，保本偏低）。

## 6. 回本卡（M2 结果区**底部** · 只读预览）

### 6.1 两口径（**都要显示**，默认项加粗）

| 口径 | 算式 | 数据来源 | 大白话文案 |
|---|---|---|---|
| **投资回本** | `build_total_fen ÷ target_profit_fen` | 🔴 **直接读引擎出参 `payback_months`** | 「**几年能回本**」 |
| **现金收回** | `build_total_fen ÷ (target_profit_fen + build_amort_monthly_fen)` | 三项**全是引擎出参/入参** | 「**几年能收回现金**」 |

🔴 **禁用名词**：「会计口径 / 现金流口径」（用户听不懂）。
🔴 `cash` 口径是**唯一**允许的展示派生（一次除法），**不回写、不参与引擎**。
🔴 `target_profit_fen ≤ 0` ⇒ 引擎 `payback_months` 为 `null` ⇒ 显示「填了目标利润才能算回本」，**不编造**。
