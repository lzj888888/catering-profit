# 批次 2 / 8 · POC1 摊销边界与尾差残值（云函数）

## 1. 批次定位
第 2 批，基于批次 0 地基。**核心目标**：实现摊销计算，为批次 1 的"当月摊销总费用"提供数据来源。摊销末月尾差是**最高频算错点**。

## 2. 完整需求
实现 `calcAmortize(asset, target_month)`，规则如下：

1. **月摊销额 = `round(原值 ÷ 总月数, 2)`**（四舍五入到分）
2. **末月摊销额 = `原值 − 前(N−1)期合计`** —— **尾差倒挤**，保证 N 期总和严格等于原值
3. **实际摊销区间 = `[摊销开始月, 截止月]`，两端都含**
   - 截止月 = 若设了「终止年月」且早于自然到期 → 取终止年月；否则 = `摊销开始月 + 总月数 − 1`
4. **四条推论**：① 摊销开始**当月即摊** ② 终止**当月仍摊** ③ 到期**当月仍摊** ④ **次月起停止**
5. **提前终止**：未摊余额 = `原值 − 已摊合计`，作为「资产处置/报废损失」一次性计入当期，**不继续摊**
6. 区间外的月份摊销额 = **0**
7. **多资产并行**：每个资产**独立计算末月尾差倒挤**，**不得多个资产合并后统一算总尾差**；三资产合计 = 各资产当月摊销额相加（对齐验收锚点 4,683.33）。
8. **软删除资产默认排除**：`is_deleted=true` 的摊销资产不参与计算，由 DataAdapter 层统一过滤，业务层无需单独处理。

## 3. 强制遵守
- 金额一律**分（INT）**，末月尾差倒挤到分
- 年月用 `YYYY-MM` 字符串，区间**含两端**
- 云函数必须过批次 0 鉴权中间件，带 `shop_id`
- 写入 `shop_amortize` 表
- **分层归属**：`calcAmortize` 是 **Service 层纯计算函数**，不直接接触数据库与前端请求；Controller 层调用前**必须先过鉴权中间件 + 参数校验**，再把干净数据传入 Service。
- **时间工具复用**：月份区间计算、月份增减**统一调用批次 0 的时间工具函数**，**禁止自定义月份计算逻辑**，确保时区、格式、月中基准时刻全局一致。
- **输出对接批次 1**：函数返回结构包含 `total_amount_fen`（当月摊销总费用，分整数）+ `details`（各资产摊销明细）；数值格式与批次 1 `calcMonthlyProfit` 的「当月摊销总费用」输入**完全对齐，可直接传入**。

## 4. ✅ 明确禁止
- ❌ 不做前端页面
- ❌ **不做尾差倒挤**（末月直接沿用月摊额）——这是最高频错误
- ❌ 不把终止/到期当月排除在外（必须含两端）
- ❌ 不把已报废资产继续摊销
- ❌ 不实现双利润计算（那是批次 1）

## 5. 验收标准（4 条锚点，误差 ≤ 0.01）

| 数字 | 应为 | 错了说明什么 |
|---|---|---|
| 旧空调残值（2026-08 报废） | **9,333.36** | 终止区间算错（多摊/少摊期数） |
| 招牌已摊合计 | **6,000.00** | 尾差没吸收，总和不等于原值 |
| 2026-08 三资产合计 | **4,683.33** | 并行计算或"开始当月即摊"判断错 |
| 装修末月（2028-12） | **3,333.45** | ❌ 若输出 3,333.33 = **没做尾差倒挤** |

**手算核对**：
- 旧空调：月摊 = 12,000÷36 = 333.33；摊 8 期（01~08），已摊 2,666.64；残值 = 12,000−2,666.64 = **9,333.36**
- 装修第 36 期 = 120,000 − 3,333.33×35 = **3,333.45**（⚠️ 是 .45 不是 .33）
