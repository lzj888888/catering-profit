## §2 逐文件要求

### 2.1 `cloudfunctions/importSalesBill/service.js` —— 新增 `parseDishSalesC()`

**位置**：紧邻既有 `parseDishSales()`（形态 A），风格照抄它。

**签名**：`function parseDishSalesC(sheetRows, opts)`
- `opts.platform` 🔴 **必填** —— 见 §2.2，**不许按文件名猜**。

**返回**：`{ shape:'C', rows, groups, totals, nonInt, zeroAmountQty, unmatched }`

| 字段 | 说明 |
|---|---|
| `rows` | `{ bizDate, name, dishKey, qty(整数), amountFen(整数分) }[]` |
| `groups` | 🔴 **按 `bizDate` 分组** ⇒ `{ bizDate, rows }[]`（一表多天 ⇒ **N 组**） |
| `totals` | `{ qty, amountFen }` |
| `nonInt` | 非整数 qty 行（**本样例 0 行**，但保留兜底） |
| `zeroAmountQty` | 🔴 **新增类**：`amount=0 且 qty>0` 的行 → `{ name, qty }[]` |
| `unmatched` | 空格名/空 key 行 |

**实现要点（逐条硬要求）**：

1. **表头在 R1**（`sheetRows[0]`），**不是 R3**。先 `toStr()` 全部表头再 `indexOf` 定位列号。
2. 🔴 **白名单取列**：只取上述 5 列；**其余 13 列丢弃且不报错**（不许"顺手也存进去"）。
3. 🔴 **`销量` 必须先 `toNum()`**（全文本列）——**不许**直接用 `Number.isFinite` 判，会把 `"43"` 误杀。
4. 🔴 **`amount_fen = Math.round(销售额 × 100)`** —— 🔴 **禁止**用 `订单交易额`
   （它是**整单口径**，一单多菜时分摊后仍为整单额 ⇒ **重复计钱**，实测 Σ 1823.08 vs 2974.91）。
   规范红线 **R232-1**。
5. 🔴 **`biz_date` 按「行内 `日期`」取**（**不是** R2 参数行 —— 形态 C **无参数行**）。
   归一成 `YYYY-MM-DD`（接受 `2026/9/7`、`2026-09-07` 等形态；月份/日补零）。
6. 🔴 **禁止补零行**（规范红线 **R232-2**）：**无行 = 无销售**，不许按 51×7 网格补 0。
   理由：补零会与「真卖 0 份」不可区分 ⇒ 破坏 §5.1 幂等（`_id` 序列会变）。
7. **`dishKey` 生成**：必须走单源 `normalizeDishName()`（**从 `common/dishKey` 取，不内联副本**）。
   🔴 C-9 事故：写侧/读侧两副本分叉 ⇒ **全菜匹配不上且无报错**。
8. **空 `dish_key` 跳过**（不计入、不报错）—— 与形态 A 同口径。
9. **`zeroAmountQty` 单列**，**不得**归入 `unmatched`（规范 **C-5**）。
