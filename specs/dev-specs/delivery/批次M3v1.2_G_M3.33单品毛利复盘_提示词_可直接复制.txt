## §1 背景与定案

### 1.1 能力（v1.2 §M3.33 · D23）

| 能力 | 输入 | 输出 | 定位 |
|---|---|---|---|
| **M3.21 率对率对账**（v1.1 已有）| M1 月度整笔（**无销量**）| 差值(pp) + 折算金额 | 月度体检（粗）|
| **M3.33 复盘**（本批）| **导入销售明细**（有销量）| 单品毛利排行榜 + 毛利率标红 | 单品体检（细）|

🔴 **两者并存、不互替** —— 不许用 M3.33 去"替换" M3.21。

### 1.2 🔴 存储落法（K3 已裁决 = 候选③）

- **明细** → `external_sales_daily`（R174 已落库，27 集合内，`source='excel'`）
- **批次摘要** → `shop_switch.m3_review_last`
- ⇒ **零新建集合、索引零新增**；`shop_switch` 仅管理端可写（天然防前端篡改），读法照抄 `getAmortSchedule/index.js:62` 与 `calcMonthlyProfit/index.js:72`。

### 1.3 ✅ 已知的两条外部事实（影响实现，来自美团官方文档）

1. 🔴 **单品金额之和 ≠ 总营收**（官方明写）：抹零 / 减免 / 免找零 / 会员优惠、外卖红包 / 满减**都无法分摊到菜品**
   ⇒ **不许拿「单品营收之和 == 总营收」做校验或报错**（它本来就不相等）。
2. 🔴 **菜名可能是 `-`**：门店绑了外卖但没建「外卖菜品 ↔ 店内菜品」映射时，收银导出的外卖菜名**显示为 `-`**
   ⇒ `-` **不许当菜名入库**，必须落到"未匹配"清单里提示用户。

## §2 改动

### 2.1 ⛔【待补 · 不要自行发挥】表结构解析 + 列映射

补齐前**必须**拿到真表，并逐项核完这 6 项（核对表见 `review/PLAN_2026-10-01_销量样例获取指南_分渠道导出路径.md` §四-附）：

| # | 核什么 |
|---|---|
| 1 | 表头在第几行（上面有无门店名 / 日期标题行） |
| 2 | 有无**小计行 / 合计行**（不排除 ⇒ **小计行会静默变成一道菜进排名**） |
| 3 | 规格（大份 / 小份）是**独立列**还是**独立行** |
| 4 | 🔴 **金额单位**（元 / 分 / 厘）—— 用一行已知数据反推，**不得假定** |
| 5 | 「店内 vs 外卖」是**一列区分**还是**两张表** |
| 6 | 套餐**是否已拆明细**（若是「拉面套餐 1 份」⇒ 未拆） |

**映射交互的硬要求**：
- 导入页把表头**列出来由用户点选**哪列是菜名 / 份数 / 金额 ⇒ 🔴 **不猜列名**；
- 未匹配行**单列**并提示，🔴 **不许静默归零**（round116 同族病）。

### 2.2 落库（K3 候选③）

- 明细写 `external_sales_daily`，沿用阶段① 已验证的确定性主键形态：
  `_id = 'SALE_<shop_id>_<source>_<biz_date>_<seq>'`（具体形态以阶段① `BILL_<shop>_<platform>_<bizDate>` 为参照，
  🔴 **必须保证同一份表重复导入覆盖同一文档**，即幂等）。
- `external_ref_id` 在**菜品级**用**真菜品名/ID**（阶段① 是合成键 `BILL:<platform>:<biz_date>`，两者键空间不冲突）。
- 摘要写 `shop_switch.m3_review_last`（批次时间 / 来源 / 行数 / 未匹配数）。

### 2.3 菜品名映射（`shop_dish_mapping`）

- 首次**自动匹配** + **手工确认**，确认后**保存复用**；
- 🔴 **未匹配行单列提示，不许静默归零**；
- 🔴 菜名为 `-` 的行 → 归入未匹配（见 §1.3-2）；
- 唯一键 `(shop_id, platform, external_ref_id)` 已存在（R174），直接复用，不要改索引。

### 2.4 计算（口径写死，不许自由发挥）

```
单品总物料成本 = 销售份数 × 该卡 unit_cost_fen（锁定的标准成本）
单品毛利       = 单品营收 − 单品总物料成本
单品毛利率     = 单品毛利 ÷ 单品营收
```

🔴 五条硬约束（v1.2 §M3.33 原文）：
1. **两个来源分开呈现**（堂食收银 + 外卖平台）——只导一边会系统性漏掉另一半；
2. 菜品名映射**必须显式确认**、未匹配不静默归零；
3. **不回写**：结果不回写 M3 成本卡、不自动写 M1；
4. **毛利率阈值用户自定义**（默认值仅占位，🔴 **不做成"警戒线"**，R128 同族）；
5. **成本用"卡内锁定值"**（不是原料现价）⇒ 若卡用了旧价，页面**须提示「该卡成本为 X 月快照」**。

### 2.5 结果页

- 两个来源**分开**呈现（堂食 / 外卖），不混在一张榜里；
- 单品毛利排行榜 + 毛利率标红（阈值来自 §2.4-4 的用户自定义值）；
- 未匹配菜品**单列区域**展示，带"去映射"入口；
- 页面须带【事后复盘】口径文案（v1.2 §M3.35 已给原文，落 `terms.js` 的 `card` 命名空间，**不新建顶层命名空间**）。

### 2.6 付费墙

- 付费键 **`m3_dishreview`**；
- 单源 = `cloudfunctions/common/entitlement.js::PAID_FEATURES`（当前 `['export','m3_combo','m3_takeaway']`）；
- 判定用法照抄 `saveCostCard/index.js:120` 的 `await common.hasFeature(db, userId, 'm3_combo')`；
- ⚠️ `cloudfunctions/exportData/selftest.js:36-37` 那条是**包含式**断言（`.every`），加键不会转红 —— 但**注释里的键清单要同步**，别让下一个人读到旧清单。
