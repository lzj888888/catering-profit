# 批次 6 / 8 · 极简管理后台 H5（用户查询 + 手动调权 + 订单管理 + 退款标记 + 导出对账）

## 1. 批次定位
第 6 批，**独立部署**的管理端，**不污染小程序包体**。**核心目标**：支撑私域收款时代的手动发权益、手动退款、对账——**没有它只能直接改数据库**，效率低且无留痕。

## 2. 完整需求

### 2.1 形态
云开发静态托管的**独立 H5 管理页** + 一组 `admin*` 云函数；管理员用**独立账号**（非微信 openid）登录。UI 极简即可，能操作就行。

### 2.2 五个 P0 功能
1. **用户查询**：按 openid / 手机号 查 user + 其下 shop + `entitlement.expire_at` + 当前档位
2. **手动发放/调整权益**：`source=manual`，**必填原因**
3. **订单管理**：订单列表 + **私域订单手动录入**（金额/套餐/支付方式/时间/备注）
4. **退款标记**：写 `order_refund`，**权收数据留**（标记已退款，权益回收，数据保留）
5. **数据导出（对账）**：导出订单/权益明细 CSV（时间范围 + 导出人）

### 2.3 🔴 `expire_at` 计算规则（对齐 v1.4 §10.10）
| 当前状态 | 规则 |
|---|---|
| 权益**未到期** | 在**原 `expire_at` 基础上累加**天数，**不覆盖** |
| 权益**已过期** | 从**操作当日**起计算新有效期（**不顺延**原到期） |

- 所有操作写 `audit_log`，记录**前值/后值/原因/操作人**
- 有效期用**服务端 UTC**

### 2.4 🔴 `plan_id` 解耦
`plan_id` **仅用于后台对账与统计**；**业务鉴权层与前端一律不读 plan_id**（权限只读 `expire_at`）。

### 2.5 管理端鉴权（独立，禁复用用户端）
- 所有 `admin*` 云函数统一走 **`adminAuth` 中间件**，校验 token 有效性与角色权限；**禁止绕过鉴权直接访问业务逻辑**
- 角色权限隔离：运营账号**不可**访问管理员管理、全量导出等高危功能
- 账号 + 密码，密码**加盐哈希**存储（禁明文、禁裸 MD5）
- 登录成功生成 **7 天有效 token**，每次请求携带校验
- **禁止复用微信 openid 鉴权**
- **密码错误 5 次锁定账号 30 分钟**
- 登录成功/失败均写 `admin_login_log`（时间/IP/结果）
- 角色：超级管理员 / 运营两级；运营不能改管理员账号

### 2.6 退款与权益回收（「权收数据留」）
- 标记退款后，对应订单关联的权益**立即回收**：将用户 `expire_at` **回退至退款生效前的状态**；历史订单、数据与操作记录**永久保留、不做删除**。
- 退款操作写入 `audit_log`，action 为 **`ADMIN_REFUND`**，记录前后值与原因。

### 2.7 私域订单联动权益发放
- 手动录入私域订单并标记「已支付」后，系统**自动**按对应套餐天数更新用户 `expire_at`（`source=manual`），**无需单独再走调权流程**。
- 同步生成订单记录 + 权益变更审计日志。

### 2.8 表名对齐第 8 章
- 订单数据写入 `shop_payment_flow`，退款记录写入 `order_refund`，管理员账号与登录日志对应 `admin_user` / `admin_login_log`；**表名与字段必须与第 8 章清单完全一致，禁止新建额外表**。

### 2.9 导出权限与留痕
- 数据导出按角色控制权限：**仅超级管理员可导出全量数据，运营仅可导出订单明细**。
- 所有导出操作写入 `audit_log`，记录导出人、导出时间、数据范围，操作留痕可追溯。

## 3. 强制遵守
- 所有后台操作写 `audit_log`，action 前缀 `ADMIN_`
- 有效期服务端 UTC
- 表：`admin_user` / `admin_login_log` / `order_refund`（已在批次 0 建好）
- 所有 `admin*` 云函数过 `adminAuth` 中间件（token + 角色权限拦截）
- 退款 action=`ADMIN_REFUND`，把 `expire_at` 回退至退款前状态、**数据/订单/记录不删**
- 私域订单标记「已支付」**自动**发权益（`expire_at` 按套餐天数，`source=manual`），不同步走调权
- 表对齐第 8 章（`shop_payment_flow` / `order_refund` / `admin_user` / `admin_login_log`），**禁止新建额外表**
- 导出按角色控权：**全量仅超级管理员**，运营仅订单明细；导出写 `audit_log`（人/时间/范围）
- 所有写操作（调权 / 录单 / 退款）校验 `client_request_id` 幂等，重复提交不重复处理、不重复留痕

## 4. ✅ 明确禁止
- ❌ **不复用微信 openid 做管理端鉴权**（必须独立账号体系）
- ❌ 不明文存密码、不用裸 MD5
- ❌ 不在"未到期"时**覆盖**原 expire_at（必须累加）
- ❌ 不让业务层/前端读取 `plan_id`
- ❌ 不跳过操作留痕
- ❌ 不做复杂 UI / 不做数据大屏（极简即可）
- ❌ 不修改用户端任何代码
- ❌ 不让运营账号访问管理员管理 / 全量导出（角色隔离）
- ❌ 不在标记退款时删除订单 / 数据 / 记录（仅回收权益）
- ❌ 不新建未在第 8 章清单中的表
- ❌ 不重复处理同一 `client_request_id` 的写操作（必须幂等）

## 5. 验收标准
1. 用错误密码连试 5 次 → 账号锁定 30 分钟
2. 管理端登录态 7 天后失效，需重新登录
3. 给**未到期**用户加 30 天 → 新 expire_at = 原值 + 30 天（**不是**从今天+30）
4. 给**已过期**用户加 30 天 → 新 expire_at = 今天 + 30 天
5. 每次调权在 `audit_log` 能看到前后值与操作人
6. 手动录入一笔私域订单 → 订单列表可见，用户端权益同步生效
7. 标记退款 → 权益回收、数据保留、`order_refund` 有记录
8. 导出 CSV 能打开且字段完整
