R263：M3 枢纽页「三步走 + 分层 + 空状态」改版（真机反馈「进来一脸懵」）

背景（李老师 2026-10-10 真机反馈）：
进 M3「配方」枢纽页「不知道这个模块能做什么、怎么做、结果去哪里看 —— 进来一脸懵」。
根因不是缺功能，是**呈现**：5 张分区卡**平级**摆着，没有任何"先做哪步 / 做完结果在哪"的线索。

改了什么（纯呈现层，零新增云函数、零改动算法）：
- pages/m3/hub.wxml：
  ① 顶部加「三步走」引导条（建卡 → 导入销量 → 看毛利榜），位置**必须在第一张卡之前**；
  ② 卡片分两层：「先做这两步」（成本卡 / 原料库）+「有成本卡之后」（单均测算 / 毛利复盘 / 对账），
     顺序贴合三步走的 ②③；
  ③ 空状态（cardCount === 0）只给**一件事**：「从一张成本卡开始」+ 去建卡按钮。
- pages/m3/hub.wxss：引导条 / 分层标题 / 空状态三块样式（字号≥28rpx、色值走 app.wxss 单源）。
- miniprogram/i18n/terms.js（+ specs 副本 md5 一致）：
  · hub.takeawayTitle「外卖菜品成本及利润」→「外卖单均测算」——
    🔴 原名与**页面自己的标题**（TERMS.ledger.takeaway.title）不一致 ⇒ 点进去标题换了个名字，
    用户以为走错页；且把"导入"这个后台动作摆进了功能名。
  · 新增 7 个键（flowTitle / flowSteps / secStart / secAfter / emptyTitle / emptyDesc / emptyBtn）。
- pages/m3/hub.js：t:{} 登记 7 个新键（漏登记 ⇒ 引导条静默空白）。

新守卫 tools/check_hub_guide.js（17 断言）：
  G1 三步走块真渲染（flowSteps 是 ≥3 项非空数组）
  G2 空状态判据必须**严格** === 0（`<= 0` 会把"没读到(-1)"误判成空状态）+ data 初值 -1 且失败路径不写 cardCount
  G3 两个分层标题都渲染
  G4 **位置不变式**：引导块 / 空状态块下标都必须 < 第一张卡下标（挪到卡后 = 问题原样复现）
  G5 i18n 双副本 md5 全等 + 页面 t:{} 七键登记齐
  G6 卡名 ≡ 页面标题（hub.takeawayTitle ≡ ledger.takeaway.title）
  S 三道自失效护栏（扫描面非空 / 分区卡 ≥5 张 / terms.hub 键数 ≥20）
  ⚠️ G2-2 首版误红：页内另有合法的 `cardCount >= 0`（显示卡数），扫全文件会把它误判成宽松写法
     ⇒ 判据改为只盯**空状态那一处**表达式。

变异回灌 4/4 点名转红（还原 md5 全等）：
  M1 放宽成 `<= 0` ⇒ G2-1 红；M2 引导块挪到卡后 ⇒ G4-1 红；
  M3 卡名改回旧名 ⇒ G6-1 红；M4 漏登记 flowSteps ⇒ G5-2 红。
